    x86-එදිරිව-RISC සටන (Post 19) 1990 ගණන්වල අග භාගය වන විට desktop සහ server බොහෝ දුරට පදිංචි කළේය. තරඟය අවසන් නොවීය — එය ගමන් කළේය. Mobile, embedded, සහ edge තනි-ත්‍රෙඩ් උච්චයට වඩා watts ගැන වැඩි සැලකිල්ලක් දක්වයි, සහ ISA එකක් වටා ඇති ව්‍යාපාර ආකෘතිය කේතනය තරම්ම වැදගත් බව පෙනී ගියේය.

    ARM Holdings ISA එක නිර්මාණය කර එය license කරයි — නිෂ්පාදනයට සූදානම් cores, හෝ සමාගමකට තමන්ගේම ARM-අනුකූල core එකක් නිර්මාණය කිරීමට ඉඩ දෙන architecture licenses (Apple ගේ සිලිකන් අන්තිමයේ කැපී පෙනෙන උදාහරණයයි). ආකෘතිය ARM fab එකක් ධාවනය නොකර ISA එක නිෂ්පාදකයන් බොහෝ දෙනෙකු හරහා පැතිරවීය.

    තාක්ෂණිකව, ARM mobile යුගයට ඇතුළු වූයේ දැනටමත් බල කාර්යක්ෂමතාව සඳහා සුසර කර තිබියදීය — RISC-පෙළපතේ සරල decode එක, පළමු වරට විශාල පරිමාණයෙන් performance-per-watt ගැන සැලකිලිමත් වූ වෙළඳපොළක් හමුවීම. එය වාසනාව නොවීය; එය දශක ගණනක එම නිර්මාණ විනය බැටරි-බලිත උපාංග හමුවීමයි.

    එකම පාඩම, එක් තට්ටුවක් ගැඹුරට#

RISC-V වාණිජව මුල් අවධියේය, royalty-free නම්‍යතාවය පරිණත මෘදුකාංග තොගයක් පරාජය කරන තැන්වල වේගයෙන්ම වර්ධනය වේ.

    Post 19 හි රටාව නැවතත්: කොටසක ජයග්‍රාහකයා හුදකලාව හොඳම ISA එක නොවේ — එය එම කොටස මිලදී ගන්නා දෙයට ආර්ථිකය ගැලපෙන එකයි. ARM mobile ජයග්‍රහණය කළේ watts සහ දුරකථන සාදන්නන්ට යටින් අභිරුචිකරණය කළ හැකි licensing ආකෘතියක් මතය. RISC-V නොමිලේ සහ විවෘත යන්න වර්ධනය වන අවස්ථා කට්ටලයක් සඳහා එයටත් වඩා ජය ගනී යැයි ඔට්ටු අල්ලයි. එය x86 හෝ ARM පරිමාණයට ළඟා වේද යන්න තවමත් විවෘතය.

    Lab එක නව tab එකක විවෘත කරන්න ↗

    ගැඹුරින්: ISA එකක් කේතනය කිරීම සහ license කිරීම — RISC-V උපදෙස් අතින් සාදමු#

    සිංහල මූලාශ්‍ර පිළිබඳ සටහන: ARM හෝ RISC-V ගෘහ නිර්මාණය ගැන සිංහල විකිපීඩියා ලිපියක් හෝ සිංහල පාඩමක් අපට හමු නොවීය. “RISC-V sinhala”, “ARM processor architecture sinhala” ලෙස YouTube හි සෙවූ විට ලැබුණේ අදාළ නැති වීඩියෝ පමණි. NIE A/L ICT ගුරු මාර්ගෝපදේශවලද ISA කේතනය ගැන කොටසක් නැත. එබැවින් මෙම කොටස RISC-V හි නිල පිරිවිතරයෙන් (specification) සහ එය නිර්මාණය කළ Berkeley කණ්ඩායමේ තාක්ෂණික වාර්තාවෙන් කෙලින්ම ගත් කරුණු මත මුල සිට ගොඩනඟයි.

    1. මූලික පද#

    • උපදෙස් කට්ටල ගෘහ නිර්මාණය (instruction set architecture, ISA): මෘදුකාංගය සහ දෘඪාංගය අතර ගිවිසුම. ඇති උපදෙස් මොනවාද, ඒවා bits වලින් ලියන්නේ කෙසේද, රෙජිස්ටර කීයක් තිබේද යන්න එයින් තීරණය වේ.
    • ක්‍රියාත්මක කිරීම (implementation): එම ගිවිසුම පිළිපදින සැබෑ චිපය. එක ISA එකකට ක්‍රියාත්මක කිරීම් බොහොමයක් තිබිය හැකිය.
    • Core license එදිරිව architecture license: core license එකකින් ලැබෙන්නේ ARM විසින්ම නිර්මාණය කළ core එකක් භාවිතා කිරීමේ අයිතියයි. architecture license එකකින් ලැබෙන්නේ ISA එකට අනුකූලව තමන්ගේම core එකක් නිර්මාණය කිරීමේ අයිතියයි (Apple මෙන්).
    • විවෘත ISA (open ISA): ඕනෑම කෙනෙකුට අවසර හෝ royalty (එක් චිපයකට ගෙවන ගාස්තුව) නොමැතිව ක්‍රියාත්මක කළ හැකි ISA එකක්.
    • දිගුව (extension): මූලික ISA එකට එකතු කළ හැකි විකල්ප උපදෙස් කණ්ඩායමක්.

    2. License ආකෘතියේ අංක#

    RISC-V හි නිර්මාපකයන් දෙදෙනා වන Krste Asanović සහ David Patterson 2014 දී ලියූ “Instruction Sets Should Be Free: The Case For RISC-V” වාර්තාවේ (පිටුව 1) මෙම කරුණු සඳහන් වේ:

    • ISA license එකක් සඳහා සාකච්ඡා මාස 6–24 ක් ගත වන අතර, එයට ඩොලර් මිලියන 1–10 ක් වැය විය හැකිය. එම නිසා විශ්වවිද්‍යාල සහ කුඩා පරිමාවෙන් නිපදවන අයට එය කළ නොහැකිය.
    • ARM license එකකින් සාමාන්‍යයෙන් ලැබෙන්නේ ARM හි නිර්මාණ භාවිතා කිරීමේ අයිතිය පමණි. නව ARM cores නිර්මාණය කිරීමට ඉඩ දෙන license ඇත්තේ විශාල සමාගම් ≈15 කට පමණි.
    • 2013 දී ARM චිප බිලියන 10 කට වඩා නිකුත් කළ අතර, 80x86 චිප නිකුත් කළේ බිලියන 0.3 කි. එනම් ARM ඒකක ගණන x86 මෙන් 10 ÷ 0.3 ≈ 33 ගුණයකට වඩා වැඩිය.

    ගණනය කළ උදාහරණය (ආදර්ශ අංක): එක් වරක් ගෙවන license ගාස්තුව නිපදවන චිප ගණනින් බෙදූ විට, එක් චිපයකට වැටෙන කොටස මෙසේය (මෙහි royalty ඇතුළත් නැත):

    නිපදවන චිප $1M ගාස්තුව $10M ගාස්තුව
    100,000 චිපයකට $10 චිපයකට $100
    10,000,000 $0.10 $1
    1,000,000,000 $0.001 $0.01

    එම වාර්තාවම IoT උපාංගයක (device) මිල ඩොලර් 1 තරම් අඩු විය හැකි බව කියයි (“could cost as little as $1”). ප්‍රොසෙසරය ඊටත් ලාභ විය යුතුය. එසේ නම්, චිප 100,000 ක් නිපදවන කුඩා සමාගමකට $1M ගාස්තුව චිපයේ මිල මෙන් 10 ගුණයකි. බිලියනයක් නිපදවන දුරකථන සමාගමකට එය ශත භාගයකි. එබැවින් license ආකෘතිය විශාල පරිමාවකට ගැළපෙන අතර, විවෘත ISA එකක් කුඩා පරිමාවකට ගැළපේ. පෝස්ට් එකේ “ආර්ථිකය ගැළපෙන එක ජය ගනී” යන තර්කය අංකවලින් පෙනෙන්නේ එලෙසිනි.

    3. RV32I: bits 32 ක උපදෙසක ඇතුළත#

    RISC-V පිරිවිතරයේ (Volume I, Unprivileged ISA, 20191213 අනුවාදය) මූලික පූර්ණ සංඛ්‍යා ISA එක වන RV32I ගැන කරුණු:

    • රෙජිස්ටර 32 කි (x0–x31); එක් එක් රෙජිස්ටරය bits 32 කි. x0 සෑම විටම 0 වේ (“hardwired with all bits equal to 0”, පිටුව 13).
    • RV32I හි ඇත්තේ අද්විතීය උපදෙස් 40 කි (පිටුව 13).
    • සෑම උපදෙසක්ම bits 32 කි. මූලික ආකෘති (formats) හතරකි: R, I, S, U. B සහ J යනු ඒවායේම වෙනස් කළ ප්‍රභේද දෙකකි (පිටුව 16, Figure 2.2–2.3).

    රෙජිස්ටර 32 ක් නම් කිරීමට bits 5 ක් අවශ්‍ය වේ (2⁵ = 32). R-type ආකෘතියේ ක්ෂේත්‍ර (bit 31 සිට bit 0 දක්වා):

    funct7 rs2 rs1 funct3 rd opcode
    bits 31–25 (7) 24–20 (5) 19–15 (5) 14–12 (3) 11–7 (5) 6–0 (7)
    • rs1, rs2 යනු ප්‍රභව (source) රෙජිස්ටර දෙකයි. rd යනු ගමනාන්ත (destination) රෙජිස්ටරයයි.
    • පිරිවිතරය (පිටුව 15) කියන පරිදි, rs1, rs2 සහ rd සෑම ආකෘතියකම එකම ස්ථානයේ තබා ඇත්තේ decode කිරීම සරල කිරීමටය.
    • සියලු immediate අගයන්හි සලකුණු bit එක (sign bit) සෑම විටම bit 31 හි ඇත.

    ගණනය කළ උදාහරණය 1: add x3, x1, x2 (x3 = x1 + x2)

    පිටුව 130 හි opcode වගුවෙන්: ADD යනු funct7 = 0000000, funct3 = 000, opcode = 0110011 වේ.

    funct7 rs2 = x2 rs1 = x1 funct3 rd = x3 opcode
    0000000 00010 00001 000 00011 0110011

    bits එකට ලියූ විට 0000 0000 0010 0000 1000 0001 1011 0011 → hex 0x002081B3.

    ගණනය කළ උදාහරණය 2: sub x5, x6, x7

    SUB වෙනස් වන්නේ funct7 = 0100000 වීමෙන් පමණි (bit 30 = 1). ප්‍රතිඵලය 0x407302B3. එකතු කිරීම සහ අඩු කිරීම එකම opcode එක බෙදා ගන්නා අතර, එක් bit එකකින් වෙන් වේ.

    ගණනය කළ උදාහරණය 3: I-type සහ x0 උපක්‍රමය

    addi x5, x0, 12 යනු x5 = 0 + 12 වේ. ADDI හි ක්ෂේත්‍ර මෙසේය: imm[11:0] = 000000001100, rs1 = 00000, funct3 = 000, rd = 00101, opcode = 0010011. ප්‍රතිඵලය 0x00C00293. වෙනම “load immediate” උපදෙසක් නැත. x0 සෑම විටම 0 නිසා ADDI එම කාර්යය කරයි. උපදෙස් 40 කට සීමා වීමට හැකි වන්නේ මෙවැනි උපක්‍රම නිසාය.

    Decode කිරීම (ආපසු): 0x00A00093 → binary 000000001010 00000 000 00001 0010011 → opcode 0010011 (OP-IMM), funct3 000 (ADDI), rd = x1, rs1 = x0, imm = 10 → addi x1, x0, 10.

    4. මොඩියුලර් දිගු සහ කේත ප්‍රමාණය#

    RISC-V කුඩා මූලික කට්ටලයක් වටා දිගු එකතු කරයි:

    • M (ගුණ කිරීම/බෙදීම), A (atomic), F සහ D (single/double floating point), C (compressed, bits 16).
    • පිරිවිතරය IMAFD සහ Zicsr, Zifencei එකතුවට “G” (general-purpose) යන කෙටි නාමය භාවිතා කරයි (පිටුව 129).

    C දිගුව ගැන පිරිවිතරය (පිටුව 97) මෙසේ කියයි: සාමාන්‍යයෙන් වැඩසටහනක උපදෙස්වලින් 50%–60% ක් bits 16 RVC උපදෙස්වලින් ප්‍රතිස්ථාපනය කළ හැකි අතර, එයින් කේත ප්‍රමාණය 25%–30% කින් අඩු වේ. Asanović සහ Patterson ද (පිටුව 1) ARM Thumb සහ MIPS16 එකම අරමුණින් bits 16 ආකෘති එකතු කළ බව සඳහන් කරයි.

    ගණනය කළ උදාහරණය 4: උපදෙස් 1000 ක වැඩසටහනක් ගනිමු.

    • සියල්ල bits 32 නම්: 1000 × 4 = බයිට් 4000.
    • 55% ක් bits 16 කට හැකිළුවොත්: 550 × 2 + 450 × 4 = 1100 + 1800 = බයිට් 2900.
    • අඩු වීම: (4000 − 2900) ÷ 4000 = 27.5%. මෙය පිරිවිතරයේ 25%–30% පරාසයට ගැළපේ.
    • සාමාන්‍ය සූත්‍රය: හැකිළූ භාගය p නම්, අඩු වීම = p × 2 ÷ 4 = p/2. එබැවින් 50% → 25%, 60% → 30%.

    5. දැන්ම උත්සාහ කරන්න (මෙම පිටුවේ mini-cpu lab එක)#

    ඉහත ඇති mini-cpu lab එකේ ADD 15 ලියා Assemble කර, ඉන්පසු Step කරන්න. DECODE පේළියේ “opcode 0x2, operand 15” ලෙස පෙනේ. එනම් මුළු උපදෙස් බයිටය 0x2F වේ: ඉහළ bits 4 opcode එක (2) වන අතර පහළ bits 4 operand එක (15 = F) වේ.

    • mini-cpu හි opcode ක්ෂේත්‍රය bits 4 නිසා opcodes 16 කට පමණක් ඉඩ ඇත. lab එක ඉන් 11 ක් භාවිතා කරයි (NOP, LDA, ADD, SUB, STA, LDI, JMP, JC, JZ, OUT, HLT).
    • RV32I හි opcode එක bits 7 ක් වන අතර, funct3 (bits 3) සහ funct7 (bits 7) එකතු වූ විට බොහෝ උපදෙස් සඳහා ඉඩ ඇත.
    • mini-cpu හි operand එක මතක ලිපිනයකි (0–15). RV32I හි ගණිත උපදෙස් ක්‍රියා කරන්නේ රෙජිස්ටර මත පමණි. මතකය ස්පර්ශ කරන්නේ load/store උපදෙස් පමණි.

    6. පැන්සලෙන් අභ්‍යාසය#

    1. add x10, x11, x12 hex වලින් කේතනය කරන්න.
    2. 0x00500513 decode කරන්න.
    3. රෙජිස්ටර ක්ෂේත්‍රය bits 4 ක් පමණක් වූ නම්, රෙජිස්ටර කීයක් නම් කළ හැකිද? R-type උපදෙසක එමගින් bits කීයක් ඉතිරි වේද?
    4. වැඩසටහනක උපදෙස්වලින් 60% ක් bits 16 කට හැකිළුවොත්, කේත ප්‍රමාණය කොපමණ ප්‍රතිශතයකින් අඩු වේද? උපදෙස් 10,000 ක වැඩසටහනක ප්‍රමාණය බයිට් කීයද?
    5. $10M license ගාස්තුව චිපයකට ශත 1 ($0.01) කට වඩා අඩු වීමට චිප කීයක් නිපදවිය යුතුද?

    (පිළිතුරු: 1 → funct7 0000000, rs2 01100, rs1 01011, funct3 000, rd 01010, opcode 0110011 → 0x00C58533. 2 → imm = 5, rs1 = x0, funct3 = 000, rd = 01010 = x10, opcode 0010011 → addi x10, x0, 5 (x10 = 5). 3 → 2⁴ = 16. rs1, rs2, rd තුනෙන්ම එක bit බැගින් ඉතිරි වන නිසා bits 3 ක් ඉතිරි වේ. 4 → 60% ÷ 2 = 30%. 6000 × 2 + 4000 × 4 = බයිට් 28,000 (සම්පූර්ණ bits 32 නම් 40,000). 5 → $10,000,000 ÷ $0.01 = චිප බිලියන 1 ට වඩා.)
