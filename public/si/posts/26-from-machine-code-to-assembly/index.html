    දුරුතු 1, 2026

    Phase 3 හි සෑම උපදෙසක්ම — datapath, pipeline, ISA — අවසානයේ අමු binary ලෙස පවතී: දෘඪාංගය සෘජුව decode කරන bit රටා. කිසිවෙකු පරිමාණයෙන් එසේ වැඩසටහන් ලියන්නේ නැත. Assembly යනු එම binary උඩ ඇති පළමු abstraction එකයි. එය මිලදී ගන්නා දේ — සහ එය වෙනස් නොකරන දේ — තේරුම් ගැනීම මෘදුකාංග ඉතිහාසයේ පහළට යන සියල්ලටම වැදගත්ය.

    Assembly සැබවින්ම කුමක්ද#

    Assembly සෑම උපදෙසකටම මිනිසාට කියවිය හැකි mnemonic එකක් දෙයි — ADD, LDA, JMP — යන්ත්‍ර-කේත bit රටාවකට එකට-එක අනුරූප වේ. එය Post 27 හි භාෂා මෙන් “ඉහළ-මට්ටමේ” නොවේ; යටින් ඇති දෘඪාංග ops උඩ abstraction එකක් නැත. සෑම assembly උපදෙසක්ම හරියටම එක් යන්ත්‍ර උපදෙසකට map වේ. ඔබට ලැබෙන්නේ කියවිය හැකි බව සහ සංකේතාත්මක යොමුවයි: opcode 0101 මතක තබා ගැනීමට වඩා LDI ලියන්න; ලේබලයක් ලියා assembler එකට jump offset ගණනය කිරීමට ඉඩ දෙන්න, byte ලිපින අතින් නැවත ගණනය කිරීමට වඩා.

    Assembler එකේ රැකියාව#

    Assembler එකක් assembly පෙළ යන්ත්‍ර කේතයට පරිවර්තනය කරයි — ලේබල ලිපින වෙත විසඳා, mnemonics opcode bits වෙත, operands ISA හි කේතන ක්ෂේත්‍රවලට ඇසුරුම් කර (Post 11). යාන්ත්‍රික, බොහෝ දුරට එකට-එක. ගැඹුරු අර්ථයකින් කිසිවක් ප්‍රශස්තකරණය හෝ නැවත ව්‍යුහගත නොවේ — පූර්ණ compiler එකක් (Post 28) ඉහළ-මට්ටමේ භාෂාවක් සමඟ කරන දෙයට වඩා වෙනස්ය.

    එය සිදු විය යුතු වූයේ ඇයි#

    Assembly ට පෙර, ක්‍රමලේඛනය යනු binary ඇතුළත් කිරීම, හෝ හොඳම අවස්ථාවේ අමු hex හෝ octal opcodes — සුළු වැඩසටහන්වලට ඔබ්බෙන් කළමනාකරණය කළ නොහැකි, පරිමාණයෙන් debug කිරීමට හෝ වෙනස් කිරීමට පාහේ අසම්භව්‍ය. සංකේතාත්මක ලේබල පමණක්ම පරිවර්තනීය විය: උපදෙසක් ඇතුළත් කරන්න හෝ ඉවත් කරන්න, සහ ඔබ තවදුරටත් සෑම jump එකක්ම අතින් නැවත ගණනය නොකරයි — assembler එක ගණිතය කරයි.

    Assembly තවමත් වැදගත් වන්නේ කොහේද#

    නවීන මෘදුකාංග අතිමහත් ලෙස ඉහළ-මට්ටමේ භාෂාවලින් ලියා Post 28 හි pipeline හරහා compile කෙරේ. Assembly අතුරුදහන් වී නැත. ඉංජිනේරුවන් තවමත් compiler එකක් නිෂ්පාදනය කළ දේ හරියටම තර්ක කිරීමට එයට බැස යයි (hot loops, ආරක්ෂක සමාලෝචනය, reverse engineering), හෝ පහළම තට්ටු ලිවීමට — boot කේතය, interrupt handlers, kernel එකක කොටස් — උපදෙස්-මට්ටමේ පාලනය අවශ්‍ය වන අතර ඉහළ abstractions එය සැඟවීමට හෝ වැළැක්වීමට ඉඩ ඇති තැන්වල.

    දැන් මෙය උත්සාහ කරන්න. පහත mini-CPU lab එක මාලාවේ වඩාත්ම සෘජු අත්දැකීම් සම්බන්ධතාවයයි: මඟ පෙන්වන වැඩසටහන Assemble කරන්න, පසුව Step — එක් එක් mnemonic (LDI, ADD, STA, OUT) opcode bits මතට එකට-එක map වේ, හරියටම මෙම පෝස්ට් එක විස්තර කරන පරිදි. ඊට වඩා abstract කිසිවක් නැත.

    Lab එක නව tab එකක විවෘත කරන්න ↗

    ගැඹුරින්: assembler එකක් ඇතුළත — ලිපින, ලේබල සහ passes දෙක#

    සිංහල මූලාශ්‍ර පිළිබඳ සටහන: මෙම මාතෘකාව ගැන සිංහලෙන් ඇති ද්‍රව්‍ය:

    • අධ්‍යාපන ප්‍රකාශන දෙපාර්තමේන්තුවේ ශ්‍රේණිය 11 තොරතුරු හා සන්නිවේදන තාක්ෂණය පෙළපොත, §1.11.2 “පහළ මට්ටමේ භාෂා” (මුද්‍රිත පිටුව 45, PDF p.55). එය යන්ත්‍ර භාෂාව සහ ඇසෙම්බ්ලි භාෂාව, ඒවායේ ලක්ෂණ සහ “ඇසෙම්බ්ලි වැඩසටහන → ඇසෙම්බ්ලර් → යන්ත්‍ර භාෂා විධාන” රූප සටහන දෙයි. §1.11.5 (මුද්‍රිත පිටුව 52) භාෂා පරිවර්තක ගැන කියයි.
    • si.wikipedia හි “ඇසෙම්බ්ලි භාෂාව” ලිපිය (අක්ෂර ~1.1k).
    • YouTube හි assembly ගැන සිංහල වීඩියෝ දෙකක් (U8WQO_kxWl4, AJAyoyEv6lk). මේවා හඳුනාගත්තේ මාතෘකාවෙන් පමණි.

    ඒවායේ නැති දේ: assembler එකක් ලේබලයක් ලිපිනයක් බවට හරවන්නේ කෙසේද, passes දෙකක් අවශ්‍ය ඇයි, ඉදිරි යොමු (forward references) විසඳන හැටි සහ jump එකක bytes ගණනය කරන හැටි. මෙම කොටස ඒවා අතින් ගණනය කරයි.

    1. මූලික පද#

    • යන්ත්‍ර කේතය (machine code): CPU එක කෙලින්ම decode කරන bit රටා.
    • Mnemonic (mnemonic): opcode එකකට දෙන කෙටි නම (LDI, JZ).
    • Assembler (assembler): assembly පෙළ යන්ත්‍ර කේතයට හරවන වැඩසටහන.
    • ස්ථාන ගණකය (location counter, LC): assemble කරන විට “ඊළඟ උපදෙස කුමන ලිපිනයට යයිද” යන්න assembler එක තබා ගන්නා ගණකය.
    • ලේබලය (label): ලිපිනයකට දෙන නමකි. Salomon ට අනුව ලේබල පළමුව යෝජනා කළේ Maurice Wilkes ය. ඔහු ඒවා “floating addresses” ලෙස හැඳින්වීය (පොතේ මුද්‍රිත පිටුව 7).
    • සංකේත වගුව (symbol table): ලේබල නම් සහ ඒවායේ ලිපින ඇති වගුව.
    • ඉදිරි යොමුව (forward reference): තවම අර්ථ දක්වා නැති (පහළින් ඇති) ලේබලයක් භාවිත කිරීම.
    • සාපේක්ෂ විස්ථාපනය (relative displacement): jump එකේ ඉලක්කය සම්පූර්ණ ලිපිනයක් ලෙස නොව “මෙතැන් සිට කොපමණ දුරද” ලෙස ලිවීම.

    වැදගත්: මෙම පිටුවේ mini-CPU lab එකේ assembler එකට ලේබල නැත. Operand එක 0–15 අතර අංකයක් විය යුතුය (lab එකේ මූලාශ්‍ර කේතය). එබැවින් පහත lab වැඩසටහන්වල ඇත්තේ අංකිත ලිපින පමණි. නම් (top, done) ඇත්තේ ; ට පසු විස්තර (comments) තුළ පමණි.

    2. අතින් assemble කිරීම: mini-CPU ගණන් කිරීම#

    Lab එකේ එක් උපදෙසක් bits 8 කි: byte = opcode × 16 + operand. Opcodes: LDI = 5, STA = 4, SUB = 3, JZ = 8, JMP = 6, OUT = 14 (E), HLT = 15 (F). (Opcode වගුව සම්පූර්ණයෙන් Post 11 හි ඇත.)

    3 සිට 0 දක්වා ගණන් කරන වැඩසටහනක්:

    LDI 1     ; 0: A = 1
STA 15    ; 1: mem[15] = 1 (අඩු කරන නියතය)
LDI 3     ; 2: A = 3
OUT       ; 3: A පෙන්වන්න   <- "top"
SUB 15    ; 4: A = A - 1 (A 0 වූ විට Zero flag = 1)
JZ 7      ; 5: Zero නම් 7 ට ("done")
JMP 3     ; 6: නැතිනම් 3 ට ("top")
OUT       ; 7: 0 පෙන්වන්න   <- "done"
HLT       ; 8: නවතින්න
    ලිපිනය උපදෙස ගණනය Hex
    0 LDI 1 5×16 + 1 = 81 51
    1 STA 15 4×16 + 15 = 79 4F
    2 LDI 3 5×16 + 3 = 83 53
    3 OUT 14×16 + 0 = 224 E0
    4 SUB 15 3×16 + 15 = 63 3F
    5 JZ 7 8×16 + 7 = 135 87
    6 JMP 3 6×16 + 3 = 99 63
    7 OUT 224 E0
    8 HLT 15×16 + 0 = 240 F0

    ඉහත lab එකේ Assembly කොටුවට මෙය පිටපත් කර Assemble කළ විට මතකයේ පෙනිය යුත්තේ 51 4F 53 E0 3F 87 63 E0 F0 ය. Step ඔබමින් ගියොත් Output 3, 2, 1, 0 ලෙස වෙනස් වී, steps 16 කින් (HLT ද ඇතුළුව) නවතී. (අපි මෙය lab එකේ මූලාශ්‍ර කේතයම ධාවනය කර පරීක්ෂා කළෙමු.)

    3. ලේබල නැති විට: එක් උපදෙසක් ඇතුළු කිරීම#

    දැන් ගණන් කරන අගය mem[14] හි ද තබා ගැනීමට, ලිපිනය 3 හි OUT ට පසු STA 14 ඇතුළු කරමු. එතැන් සිට සෑම උපදෙසක්ම එක් ලිපිනයක් පහළට යයි:

    පැරණි ලිපිනය නව ලිපිනය උපදෙස
    0–3 0–3 නොවෙනස්
    — 4 STA 14 (නව)
    4 5 SUB 15
    5 6 JZ ?
    6 7 JMP ?
    7 8 OUT (“done”)
    8 9 HLT
    • “done” 7 සිට 8 ට ගියේය. එබැවින් JZ 7 → JZ 8 (byte 87 → 88) ලෙස අතින් වෙනස් කළ යුතුය.
    • “top” (3) ඇතුළු කළ ස්ථානයට ඉහළින් ඇති නිසා JMP 3 නොවෙනස්ව පවතී.
    • නීතිය: ඉලක්කය ඇතුළු කළ ලිපිනයට සමාන හෝ ඊට පසු නම් operand එක +1 කරන්න. ඊට පෙර නම් නොවෙනස්.

    නිවැරදි කළ bytes: 51 4F 53 E0 4E 3F 88 63 E0 F0. Output 3, 2, 1, 0, steps 19.

    අමතක කළොත් කුමක් වේද? JZ 7 එලෙසම තැබුවොත්, A = 0 වූ විට CPU එක 7 ට, එනම් JMP 3 වෙත පනී. එවිට 0 − 1 = 255 (bits 8 වට වීම) වී ගණන් කිරීම 255, 254, … ලෙස දිගටම යයි. වැඩසටහන කිසිදා නොනවතී. (අපේ පරීක්ෂාවේදී steps 2000 කට පසුවද HLT නොවීය.) ඇතුළු කිරීමක් එක් operand එකක් අමතක කිරීමෙන් වැඩසටහනේ හැසිරීම මුළුමනින්ම වෙනස් විය හැකිය. ලේබල විසඳන්නේ මෙම ගැටලුවයි.

    4. passes දෙකේ assembler එකක් මෙය ස්වයංක්‍රීයව කරන හැටි#

    David Salomon ගේ Assemblers and Loaders (§1.2, මුද්‍රිත පිටුව 20) passes දෙකේ assembler එක මෙසේ විස්තර කරයි: පළමු pass එකේදී එය මුළු මූලාශ්‍රයම කියවන්නේ ලේබල අර්ථ දැක්වීම් සොයා පමණි. ලේබලවලට අගයන් දී සංකේත වගුවට දමයි. දෙවන pass එකේදී එම වගුව භාවිතයෙන් උපදෙස් assemble කරයි. ලේබලවලට අගය දීමට පළමු pass එකේදීම LC එක තබා ගත යුතුය. එනම් සෑම උපදෙසකම ප්‍රමාණය දැනගත යුතුය.

    ඉහත වැඩසටහන top සහ done ලේබල ඇති assembler එකකට ලියූවා නම් (lab එක සඳහා නොවේ):

    • Pass 1 (මුල් වැඩසටහන): LC 0, 1, 2 → top = 3 … done = 7. වගුව: {top: 3, done: 7}.
    • Pass 1 (STA 14 ඇතුළු කළ පසු): {top: 3, done: 8}. මිනිසා කිසිවක් ගණනය නොකරයි.
    • Pass 2: JZ done → 8×16 + 8 = 0x88. JMP top → 0x63.

    එක් pass එකක් පමණක් නම්? Salomon (§1.3, මුද්‍රිත පිටු 24–25): ඉදිරි යොමුවක් හමු වූ විට assembler එක උපදෙස අර්ධ වශයෙන් assemble කර ලිපින ක්ෂේත්‍රය හිස්ව තබයි. ලේබලය “U” (undefined) ලෙස වගුවට දමයි. එම ලේබලය භාවිත කරන උපදෙස් සියල්ල linked list එකකින් බැඳේ. ලේබලය අර්ථ දක්වන තැනට පැමිණි විට list එක දිගේ ගොස් එක් එක් හිස් ක්ෂේත්‍රය පුරවයි. Pass එක අවසානයේ තවම “U” ඇති සංකේත දෝෂ ලෙස වාර්තා කරයි. GNU as අත්පොත (.org කොටස) ද පවසන්නේ as වැඩසටහන් එක් pass එකකින් assemble කිරීමට උත්සාහ කරන බවයි.

    5. x86 හි ලේබලයක් bytes බවට: සාපේක්ෂ jump#

    සැබෑ CPU වල jump බොහෝවිට සාපේක්ෂ වේ. අපි මෙම කේතය box එකේ GNU as (x86-64) මගින් assemble කර objdump මගින් බැලුවෙමු:

    0:  eb 04     jmp done
2:  01 d8     add eax, ebx
4:  ff c0     inc eax
6:  c3        ret          <- done
7:  ff c9     dec ecx      <- top
9:  75 fc     jne top

    Intel SDM Vol. 2A: EB cb = “JMP rel8 … RIP = RIP + 8-bit displacement sign extended” (JMP පිටුව, 3-504). 75 cb = “JNE rel8, Jump short if not equal (ZF=0)” (Jcc පිටුව, 3-499). Jump ක්‍රියාත්මක වන විට RIP දැනටමත් ඊළඟ උපදෙස පෙන්වයි. එබැවින්:

    • විස්ථාපනය = ඉලක්කය − ඊළඟ උපදෙසේ ලිපිනය.
    • jmp done: 6 − 2 = 4 → 04.
    • jne top: 7 − 11 = −4 → bits 8 two’s complement: 256 − 4 = 252 = fc.

    rel8 හට −128 සිට +127 දක්වා පමණක් යා හැක. ඉලක්කය ඊට වඩා දුර නම් bytes 5 ක E9 cd (JMP rel32) ආකාරය අවශ්‍ය වේ. අපේ පරීක්ෂාවේදී bytes 200 ක් ඉදිරියට ඇති ලේබලයකට as විසින් e9 c8 00 00 00 නිපදවීය: ලිපිනය 0x12 හි ඇති උපදෙස bytes 5 කි. ඊළඟ ලිපිනය 0x17, ඉලක්කය 0xDF, 0xDF − 0x17 = 0xC8 = 200 (little-endian නිසා c8 පළමුව). මෙයින් පෙනෙන්නේ Salomon කියන දෙයයි: උපදෙසක ප්‍රමාණය (2 ද 5 ද) ඉලක්කය කොපමණ දුරද යන්න මත රඳා පවතී. LC එක නිවැරදිව තබා ගැනීමට assembler එකට වැඩි වෙහෙසක් දැරීමට සිදු වේ.

    6. පැන්සලෙන් අභ්‍යාසය#

    1. Mini-CPU bytes ලියන්න: LDI 9, ADD 14, JZ 12 (ADD = 2).
    2. විකේතනය කරන්න: 63, 3F, 4E.
    3. §2 හි මුල් වැඩසටහනේ මුලටම (ලිපිනය 0) OUT එකක් ඇතුළු කරයි. නව JZ සහ JMP operands මොනවාද? පළමු Output අගය කුමක්ද?
    4. අභ්‍යාසය 3 හි පළමු pass එකෙන් පසු සංකේත වගුව ලියන්න.
    5. x86: bytes 2 ක jmp එකක් ලිපිනය 0x10 හි ඇත. ඉලක්කය 0x08. විස්ථාපන byte එක කුමක්ද?
    6. ලිපිනය 0x40 හි ඇති bytes 2 ක jmp එකකට (rel8) යා හැකි ඉහළම ලිපිනය කුමක්ද?

    (පිළිතුරු:

    1. 5×16 + 9 = 0x59. 2×16 + 14 = 0x2E. 8×16 + 12 = 0x8C.
    2. 0x63 = 6, 3 → JMP 3. 0x3F = 3, 15 → SUB 15. 0x4E = 4, 14 → STA 14.
    3. සියලු ලිපින +1: top = 4, done = 8. එබැවින් JZ 8, JMP 4. පළමු OUT ධාවනය වන විට A = 0 (ආරම්භයේ). එබැවින් Output 0, 3, 2, 1, 0. (Lab මූලාශ්‍රය මත පරීක්ෂා කළා: bytes E0 51 4F 53 E0 3F 88 64 E0 F0, steps 17.)
    4. {top: 4, done: 8}.
    5. ඊළඟ ලිපිනය 0x12. 0x08 − 0x12 = −10 → 256 − 10 = 246 = 0xF6 (bytes eb f6; as මගින් පරීක්ෂා කළා).
    6. ඊළඟ ලිපිනය 0x42. 0x42 + 127 = 0xC1.)
