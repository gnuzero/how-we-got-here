    Superscalar සහ Multicore

    දුරුතු 1, 2026

    Out-of-order issue, ගැඹුරු pipelines, පුළුල් superscalar පළල — මෙම අදියරේ මෙතෙක් සියල්ල එක් උපදෙස් ප්‍රවාහයකින් වැඩි Instruction-Level Parallelism (ILP) උපුටා ගනියි. 2000 දශකයේ මැද වන විට එම ප්‍රවේශය උපාය වෙනස් කිරීමට තරම් තදින් උඩුකුරුවකට හැපුණේය.

    එකවර බිත්ති දෙකක්#

    සැබෑ වැඩසටහන් අසීමිත ස්වාධීන වැඩ ලබා නොදෙයි. Branches, සැබෑ data dependencies, සහ මතක latency තනි ප්‍රවාහයකින් කොපමණ උපදෙස් සමාන්තරව ධාවනය විය හැකිද යන්න සීමා කරයි. විශාල ROBs, වැඩි reservation stations, පුළුල් issue: වර්ධනය වන ප්‍රදේශය සහ බලය සඳහා අඩුවන ප්‍රතිලාභ. එය ගෘහ නිර්මාණ බිත්තියකි.

    ඒ අතරම, dynamic බලය ආසන්න වශයෙන් capacitance, සංඛ්‍යාතය, සහ වෝල්ටීයතාවයේ වර්ගය සමඟ පරිමාණය වේ (P ≈ CV²f). ILP හි අඩුවන ලාභයට වන්දි ගෙවීමට clocks ඉහළට තල්ලු කිරීම තාපයට හැපුණේය — Post 36 විස්තරාත්මකව ආවරණය කරන clock-speed බිත්තිය. ස්වාධීන උඩුකුරු දෙකක්, 2000 දශකයේ මැද, කිසිවකට පිරිසිදු තනි විසඳුමක් නැත.

    වේගවත් වීම වෙනුවට පුළුල් වීම#

    හැරීම: එක් core එකක් චක්‍රයකට වැඩි දේ කරන්නට නවත්වන්න; එකම die එක මත, එක් එක් එකට තමන්ගේ ප්‍රවාහයක් සමඟ, තරමක් සරල cores කිහිපයක් තබන්න. Core එකක සංකීර්ණතාව සහ clocks සමතල කරන අතරතුර චිප throughput තවදුරටත් ඉහළ යා හැක — එම cores වලට භාර දිය හැකි සමාන්තර වැඩ තිබේ නම්.

    “වේගවත්” අර්ථය වෙනස් විය. තනි-ත්‍රෙඩ් වැඩසටහනක් cores අටක් එදිරිව හතරක් මත ස්වයංක්‍රීයව ජය නොගනී; එය තවමත් ආසන්න වශයෙන් එකම clock එකකින් එක් core එකක ධාවනය වේ. Multicore ලාභය දිස් වන්නේ බහු ත්‍රෙඩ් සඳහා ලියන ලද (හෝ සම්පාදනය කළ) workloads සඳහා පමණි. ILP යුගය සෑම පරම්පරාවකදීම තනි-ත්‍රෙඩ් වේගවත් වීම් “නොමිලේ” ලබා දුන්නේය; මෙම යුගය සමාන්තර-දැනුවත් මෘදුකාංග ඉල්ලයි.

    හැරීම පෙන්වන තැන්#

    එකම බලය — එක් සංකීර්ණ ඒකකයක් වෙනුවට බොහෝ සරල ඒකක — තවත් ඈතට ගෙන ගිය GPUs (Phase 9) පිටුපස ඇති දර්ශනයයි. සමාන්තර වැඩ නිවැරදිව සම්බන්ධීකරණය කිරීම තත්‍ය කාල පද්ධති (Phase 4) සහ බෙදාහැරුණු පද්ධති (Phase 7) තුළ ප්‍රධාන පන්තියේ ගැටලුවක් වන්නේ ඇයිද යන්නටද එය හේතුවකි: එක් ත්‍රෙඩ් එකක් වේගවත් කිරීමට ඊළඟ චිපය බලා සිටීම තවදුරටත් ප්‍රධාන වර්ධන මාර්ගය නොවේ.

    ගැඹුරින්: issue පළල, IPC සීමා සහ multicore සඳහා Amdahl (Hill–Marty ආකෘතිය)#

    සිංහල මූලාශ්‍ර පිළිබඳ සටහන: බහු-හර (multi-core) සකසන ගැන සිංහලෙන් නිර්වචන මට්ටමේ ද්‍රව්‍ය තිබේ.

    • NIE ශ්‍රේණිය 12 ICT ගුරු මාර්ගෝපදේශයේ PDF p.84 (මුද්‍රිත p.71) නිපුණතා 2.3 යටතේ “බහු හර සකසන (multi-core processors)” ඇතුළත් වේ.
    • PDF p.87 (මුද්‍රිත p.74) එය නිර්වචනය කරයි: එකවර උපදෙස් ක්‍රියාත්මක කරන ස්වාධීන සකසන දෙකක් හෝ වැඩි ගණනක් ඇති තනි පරිගණකයක්. අවශ්‍යතා ලෙස වැඩසටහනක කොටස් එකවර ධාවනය, සමාන්තර සැකසීම සහ උපරිම කාර්ය සාධනය ලැයිස්තු කරයි.
    • “cores” සහ “cores vs threads” ගැන පාරිභෝගික මට්ටමේ සිංහල වීඩියෝ ද ඇත (YT LucxOadyPrw, YT NhaSzwn5St8). ඒවා හඳුනා ගත්තේ මාතෘකාවෙන් පමණි.
    • Superscalar ගැන සිංහලෙන් කිසිවක් අපට හමු නොවීය.

    එම ද්‍රව්‍ය “cores වැඩි = වේගවත්” යන්නෙන් නවතී. Core එකක් පුළුල් කිරීමේ මිල, IPC සීමාව, හෝ cores කීයක් සහ කොතරම් විශාල ඒවාද යන හුවමාරුව ඒවායේ නැත. මෙම කොටස University of Pennsylvania CIS 501 දේශන සහ Hill සහ Marty ගේ 2008 ලිපිය (කතුවරුන්ගේ පිටපත) භාවිතා කරයි.

    • Branch prediction: Post 14. Register renaming / ROB: Post 16. Clock-speed බිත්තිය: Post 36. Amdahl එදිරිව Gustafson මූලික ආකාරය: Post 56. ඒවා මෙහි නැවත නොකියමු.

    1. මූලික පද#

    • Superscalar (බහු-නිකුත් / multiple issue): එක් චක්‍රයකදී උපදෙස් කිහිපයක් pipeline එකට නිකුත් කරන core එකකි.
    • නිකුත් පළල (issue width) N: චක්‍රයකට නිකුත් කළ හැකි උපරිම උපදෙස් ගණනයි (“4-wide”).
    • IPC (instructions per cycle): චක්‍රයකට සම්පූර්ණ වන උපදෙස් ගණනයි. CPI = 1/IPC.
    • ILP (instruction-level parallelism): එක් උපදෙස් ප්‍රවාහයක එකවර ධාවනය කළ හැකි ස්වාධීන වැඩ ප්‍රමාණයයි.
    • BCE (base core equivalent): Hill–Marty ආකෘතියේ සම්පත් ඒකකයයි. එනම් කුඩාම මූලික core එකකට යන චිප ප්‍රදේශය/බලයයි.

    2. පළල කොතරම් දුරට උදව් කරයිද?#

    UPenn CIS 501 (“Unit 7: Superscalar”, PDF p.2–3):

    • Scalar pipeline එකක සීමාව CPI = IPC = 1 වේ (“Flynn bottleneck”). Hazards නිසා එම සීමාවටවත් කිසි විටෙක ළඟා නොවේ.
    • N-way superscalar pipeline එකක මූලික CPI 1/N වේ. Slides (2009) වලට අනුව එකල සාමාන්‍යය “4-wide” විය (Intel Core 2, AMD Opteron).

    උපරිම ගණනය (ආදර්ශ): 3 GHz, 4-wide core එකක උපරිමය 4 × 3×10⁹ = තත්පරයට උපදෙස් 12×10⁹ වේ. එය ඉහළ සීමාවකි.

    යැපීම් දාමය පළල අහෝසි කරයි (ආදර්ශ): 4-wide core එකක් ගනිමු. එහි ALU ප්‍රමාදය චක්‍ර 1 ක් වන අතර forwarding සම්පූර්ණයි.

    උපදෙස් 8 එක් එක් උපදෙස චක්‍ර IPC
    සියල්ල ස්වාධීන අනෙක්වා මත නොයැපේ 8/4 = 2 4
    එක දාමයක් x1 = x1 + 1 වැනි, පෙර ප්‍රතිඵලය අවශ්‍යයි 8 1

    දෙවන පේළියේ issue slots 32 න් 8 ක් පමණක් භාවිතා වේ. පළල ලබා දෙන්නේ ඉඩක් පමණි. එම ඉඩ පිරවීමට ස්වාධීන වැඩ වැඩසටහනෙන්ම ලැබිය යුතුය.

    පළල stall දඬුවම විශාල කරයි (UPenn, PDF p.3): Branches 20% ක්, ඉන් 75% ක් taken, branch prediction නැත, taken branch එකකට චක්‍ර 2 ක දඬුවමක් ඇත:

    Pipeline CPI පරිපූර්ණ CPI ට සාපේක්ෂව
    Scalar 1 + 0.2 × 0.75 × 2 = 1.3 1.3 / 1 → 30% මන්දගාමී
    2-way 0.5 + 0.3 = 0.8 0.8 / 0.5 → 60% මන්දගාමී
    4-way 0.25 + 0.3 = 0.55 0.55 / 0.25 → 120% මන්දගාමී

    මෙම ගණනය දත්ත stalls නොමැති බව උපකල්පනය කරයි; slide එකම එය “overly optimistic” (අධික ලෙස ශුභවාදී) උපකල්පනයක් ලෙස හඳුන්වයි. Stall චක්‍ර එකම ප්‍රමාණයක් වුවත්, පළල වැඩි වන විට එම චක්‍රයකදී අහිමි වන issue slots ගණනද වැඩි වේ. පුළුල් cores සඳහා හොඳ branch prediction (Post 14) අනිවාර්ය වන්නේ එබැවිනි.

    පළලේ දෘඪාංග මිල (UPenn, PDF p.4):

    • 4-wide superscalar එකකට register file read ports 8 ක් සහ write ports 4 ක් අවශ්‍ය වේ.
    • Stall logic එකේ සංකීර්ණතාව N-wide යන්ත්‍රයක N² ලෙස වර්ධනය වේ.
    • Execute pipeline ගැඹුර P නම් bypass paths N² × P ලෙස වර්ධනය වේ.
    • ආදර්ශ: 2-wide සිට 4-wide දක්වා යාමේදී N² = 4 → 16 වේ. එනම් bypass/stall තර්කය ආසන්න වශයෙන් 4× වේ, නමුත් උපරිම IPC 2× පමණි.

    මෙම post එකේ “එකවර බිත්ති දෙකක්” කොටසේ ගෘහ නිර්මාණ බිත්තිය ගණනයෙන් පෙනෙන්නේ මෙසේය: සෑම පියවරකටම වැඩි මිලක් ගෙවිය යුතු අතර ලැබෙන ප්‍රතිලාභය අඩු වේ.

    3. Cores කීයක්, කොතරම් විශාලද? Hill සහ Marty (2008)#

    සමමිතික (symmetric): BCE r බැගින් cores n/r 1 / [ (1 − f)/perf(r) + f·r / (perf(r)·n) ]
    අසමමිතික (asymmetric): විශාල core 1 (BCE r) + කුඩා cores n − r 1 / [ (1 − f)/perf(r) + f / (perf(r) + n − r) ]
    ගතික (dynamic): අනුක්‍රමික කොටසට r එකතු කරයි; සමාන්තර කොටසට cores n ම 1 / [ (1 − f)/perf(r) + f/n ]

    වැඩ කළ උදාහරණය: n = 16, f = 0.9 (පයිතන් වලින් අප ගණනය කළ, perf(r) = √r):

    • අසමමිතික චිපය (විශාල core 1 + කුඩා cores) සමමිතිකයට වඩා හොඳය. ගතික චිපය (අනුක්‍රමික කොටසේදී cores ඒකාබද්ධ කළ හැකි නම්) සියල්ලටම වඩා හොඳය.

Scheduling සහ overhead වැනි අභියෝග එම ආකෘතියට ඇතුළත් නොවේ (PDF p.4, Implication 4).

    4. පැන්සලෙන් අභ්‍යාසය#

    1. 2 GHz, 2-wide core එකක උපරිම IPC සහ තත්පරයට උපරිම උපදෙස් ගණන කීයද?

    4. එම n, f, r සඳහා අසමමිතික speedup එක කීයද?
    5. 4-wide core එකක උපදෙස් 12 ක් ඇත. ඒවා ස්වාධීන දාම 3 කි (එක් දාමයකට 4 බැගින්). ALU ප්‍රමාදය චක්‍ර 1 යි. අවම චක්‍ර ගණන සහ IPC කීයද?

    (පිළිතුරු:

    1. IPC ≤ 2. 2 × 2×10⁹ = තත්පරයට 4×10⁹.
    2. 1/8 + 0.3 = 0.425. 0.425 / 0.125 = 3.4 → 240% මන්දගාමී.

    4. 1 / (0.01/2 + 0.99 / (2 + 16 − 4)) = 1 / (0.005 + 0.0707) ≈ 13.2.
