    ARPANET (Post 39) සහ TCP/IP (Post 41) packets ගමන් කරන ආකාරය විසඳුවේය. ඒවා තනිවම නිහඬ ප්‍රශ්නයකට පිළිතුරු දුන්නේ නැත: bits අදහස් කරන්නේ කුමක්දැයි කීමට අයිතිය ඇත්තේ කාටද? Port 80, IPv4 prefix එකක්, .com, ก සඳහා code point එක — දුරස්ථ ක්‍රියාකරුවන් එකම හඳුනාගැනීම් එකම ආකාරයෙන් සලකන්නේ නම් මිස ඒවායින් කිසිවක් ක්‍රියා නොකරයි. අන්තර්ජාලයේ governance කතාව එම එකඟතාවේ කතාවයි: ජාලය මත පාර්ලිමේන්තුවක් නොව, අංක, නම්, සහ encodings සඳහා බෙදාගත් ledgers කට්ටලයක්.

Jon Postel දශක තුනකට ආසන්න කාලයක් මාලාව සංස්කරණය කර, අනියම් මතක සටහන් අන්තර්ජාලය ඇත්තටම ක්‍රියා කරන ආකාරයේ කල් පවතින ප්‍රසිද්ධ වාර්තාවක් බවට පත් කළේය. පිටවීමේ දොර: RFC Editor history.

    • NIE ශ්‍රේණිය 12 ICT ගුරු මාර්ගෝපදේශයේ PDF pp.105–107 (මුද්‍රිත pp.92–94) BCD, EBCDIC, ASCII සහ Unicode (“ඒකකේත (Unicode)”) හඳුන්වයි.
    • එහි p.107 වගුව Unicode හි වාසි ලැයිස්තු කරයි: එය ප්‍රමිතිගත වී ඇත, ලෝකයේ බොහෝ භාෂා නිරූපණය කරයි, සහ ASCII සමඟ ගැළපීම රඳවා ගනී. අවාසිය ලෙස “ASCII අක්ෂර ගබඩා කිරීම සඳහා අවශ්‍ය කරන මතකයට වඩා වැඩි මතකයක් අවශ්‍ය කරයි” යන්න දක්වයි. (පහත 3 වන කොටස එය නිවැරදිව සීමා කරයි.)
    • si.wikipedia හි “යුනිකෝඩ්” ලිපිය stub එකකි. Unicode ගැන සිංහල වීඩියෝ ද ඇත (YT F1SPtWCjWU4, YT vTUelvIwK3I), සහ “font fix” ගැන කෙසේද-කරන්නේ වීඩියෝ බොහොමයක් ද ඇත (උදා. YT RTOG8oZWyJg). ඒවා හඳුනා ගත්තේ මාතෘකාවෙන් පමණි.
    • ඉතිහාසය සඳහා සිංහල භාෂාවෙන්ම ඇති ප්‍රධාන මූලාශ්‍රය Aruni Gunathilaka ගේ පරිගණකයට සිංහල සහ දෙමළ (LK Domain Registry, 2021) පොතයි.

    ඒ කිසිවක් සිංහල වචනයක් byte මට්ටමට කඩා නොපෙන්වයි: code points, UTF-8 bytes, ZWJ අනුක්‍රම, හෝ පැරණි fonts පෙළ බිඳ දැමුවේ ඇයි යන්න. මෙම පිටුවේ “Encodings” කොටස කියන්නේ “payload එකට එකම glyph අදහස් කළ යුතුය” කියාය. සිංහල සඳහා එය සැබවින්ම අදහස් කරන්නේ කුමක්දැයි මෙම කොටස පෙන්වයි. සියලු code point සහ byte අගයන් Python හි unicodedata සහ .encode('utf-8') මගින් පරීක්ෂා කරන ලදී.

    1. මූලික පද#

    UCSC 2003 වාර්තාවේ Annex A (PDF p.15) මෙම වෙනස්කම් පැහැදිලිව දක්වයි:

    • අක්ෂරය (character): අමූර්ත ඒකකයකි. උදා. “SINHALA LETTER AYANNA” (අ). එය හැඩයක් නොවේ.
    • Code point: අක්ෂරයකට දෙන අංකයයි. උදා. අ = U+0D85.
    • Glyph: තිරයේ ඇඳෙන හැඩයයි. Font එකක් යනු glyphs කට්ටලයකි.
    • කේතන ආකෘතිය (encoding form): Code point එකක් bytes බවට හරවන නීතියයි. උදා. UTF-8, UTF-16.
    • පිලි (vowel signs / dependent vowels): ා, ැ, ි, ු, ෙ වැනි ව්‍යඤ්ජනයකට (consonant) පසුව එන ලකුණු.
    • හල් කිරීම / අල්-ලකුණ (al-lakuna / virama), U+0DCA ්: ව්‍යඤ්ජනයක ස්වරය ඉවත් කරයි.
    • ශුන්‍ය-පළල සම්බන්ධකය (zero width joiner, ZWJ), U+200D: නොපෙනෙන අක්ෂරයකි. අකුරු බැඳීමට ඉල්ලයි.

    3. UTF-8 අතින්: සිංහල අකුරකට bytes 3 යි#

    RFC 3629 (§3) අනුව U+0800 සිට U+FFFF දක්වා code point එකක් 1110xxxx 10xxxxxx 10xxxxxx ලෙස bytes 3 කට කේතනය වේ.

    අ = U+0D85:

    • binary: 0000 1101 1000 0101
    • පළමු bits 4 (0000) → 11100000 = E0
    • ඊළඟ bits 6 (110110) → 10110110 = B6
    • අවසාන bits 6 (000101) → 10000101 = 85
    • ප්‍රතිඵලය: E0 B6 85 (bytes 3)

    එබැවින් සිංහල block එකේ සෑම code point එකක්ම UTF-8 හි bytes 3 කි: U+0D80–0DBF → E0 B6 xx, U+0DC0–0DFF → E0 B7 xx. ZWJ (U+200D) → E2 80 8D.

    NIE p.107 හි “වැඩි මතකයක්” ප්‍රකාශය නිවැරදිව කියවීම:

    • UTF-8 හි ASCII අක්ෂර byte 1 ක් ලෙසම පවතී. ඉංග්‍රීසි පෙළට මතක දඬුවමක් නැත.
    • Unicode Standard ch.2 (§2.5) මෙසේ කියයි: UTF-8 ASCII සඳහා UTF-16 ට වඩා බොහෝ කුඩාය, නමුත් හින්දි, තායි වැනි ආසියානු ලේඛන ක්‍රම සඳහා “significantly larger” (සැලකිය යුතු ලෙස විශාලය).
    • සිංහල code point එකක් UTF-8 හි bytes 3 ක් වන අතර UTF-16 හි bytes 2 කි.
    • UCSC 2003 (PDF p.4) Unicode “16-bit” ලෙස විස්තර කළේ Unicode 3.0 යුගයේ දෘෂ්ටියෙනි. UTF-8 variable-length කේතනයක් ලෙස ද එහි සඳහන් වේ.

    3. Font ආදේශනය (font substitution): ලබන්නාගේ පරිගණකයේ එම font එක නැත්නම් browser එක වෙනත් font එකක් ආදේශ කරයි. එවිට Latin අකුරු පෙනේ.
    4. වර්ග කිරීම (sorting): Byte පිළිවෙලට sorted(['@g','@k','@k`','k']) → @g, @k, @k`, k. එනම් ගෙ, කෙ, කො, ක. ක අන්තිමට ද, ගෙ පළමුවට ද යයි. Unicode පිළිවෙල: ක, කෙ, කො, ගෙ (7 කොටස).

    පරිවර්තක (converters) ක්‍රියා කළ ආකාරය (සාමාන්‍ය යාන්ත්‍රණය, ආදර්ශ): පැරණි-font පෙළ Unicode බවට හැරවීමට,

    1. එක් එක් font එක සඳහා byte → Unicode වගුවක් අවශ්‍ය වේ (k → U+0D9A).
    2. දිගම ගැළපීම (longest match) පළමුව: @ + ව්‍යඤ්ජනය + backtick → ව්‍යඤ්ජනය + U+0DDC.
    3. නැවත පෙළගැස්වීම (reordering): @ + ව්‍යඤ්ජනය → ව්‍යඤ්ජනය + U+0DD9 (කොම්බුව පසුපසට).
    4. බැඳි අකුරු glyphs → ව්‍යඤ්ජන + ් + ZWJ + ව්‍යඤ්ජන.
