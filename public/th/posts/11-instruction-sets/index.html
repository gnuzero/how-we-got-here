    ชุดคำสั่ง

    มกราคม 1, 2026

    Instruction Set Architecture (ISA) คือสัญญาระหว่างซอฟต์แวร์กับฮาร์ดแวร์: การดำเนินการใดที่มี การเข้ารหัสเป็นบิตอย่างไร และบิตเหล่านั้นหมายความว่าอะไร มันคือ สเปก ไม่ใช่ชิป x86, ARM และ RISC-V เป็น ISA — ชิปต่างกันหลายตัวสามารถ implement ตัวเดียวกันแล้วยังรันไบนารีชุดเดียวกันได้

    คำศัพท์ก่อนเริ่ม (ศัพท์บัญญัติราชบัณฑิตยสภา สาขาคอมพิวเตอร์และเทคโนโลยีสารสนเทศ): ชุดของคำสั่งเครื่อง (instruction set) และ สถาปัตยกรรมคอมพิวเตอร์ (computer architecture); รหัสเครื่อง (machine code — บิตที่ CPU อ่านจริง); คำ (word — หน่วยข้อมูลที่เครื่องหยิบทีละชิ้น); รหัสดำเนินการ (operation code หรือ opcode — ส่วนของคำสั่งที่บอกว่าให้ทำอะไร); ตัวถูกดำเนินการ (operand — ข้อมูลหรือที่อยู่ที่คำสั่งทำงานด้วย); รอบคำสั่งเครื่อง (instruction cycle — วงจรไปนำมา ถอดรหัส ทำงาน); เข้ารหัส และ ถอดรหัส (encode, decode); ไปนำมา (fetch — ขั้นดึงคำสั่งจากหน่วยความจำ); ตัวนับระบุตำแหน่งคำสั่ง (program counter, PC); เรจิสเตอร์ (register) และ ตัวสะสม (accumulator — เรจิสเตอร์หลักที่ผลคำนวณสะสมอยู่ เช่น A ใน mini-CPU); ตัวบ่งชี้ (flag); ตัวทด (carry); การล้น (overflow); หยุด (halt); ไมโครโปรแกรม (microprogram); การทำงานแบบสายท่อ (pipeline); ตัวแปลโปรแกรม (compiler); แอสเซมเบลอร์ (assembler); เติมหน้า (prefix); และ ความเข้ากันได้ (compatibility) คำต่อไปนี้ยังไม่พบศัพท์บัญญัติ จึงใช้คำอธิบายหรือทับศัพท์: microarchitecture (ไมโครสถาปัตยกรรม), immediate (ค่าคงที่ที่ฝังในตัวคำสั่ง), sign extension (การขยายบิตเครื่องหมาย), addressing mode (โหมดระบุที่อยู่), control store (หน่วยความจำเก็บไมโครโปรแกรม) และ wraparound (การวนกลับ)

    การแยกนั้น — สถาปัตยกรรม (สิ่งที่ซอฟต์แวร์เห็น) กับไมโครสถาปัตยกรรม (ซิลิคอนสร้างอย่างไร) — คือกระดูกสันหลังของเฟสนี้ ไปป์ไลน์ แคช และคอร์นอกลำดับทั้งหมดอยู่ ใต้ ISA ซอฟต์แวร์ไม่จำเป็นต้องรู้

    สองปรัชญา: CISC กับ RISC#

    CISC (Complex Instruction Set Computing) — สายเลือดหลัง x86 — อัดมากเข้าไปในแต่ละคำสั่ง: ความยาวแปรได้ โหมดระบุที่อยู่หลากหลาย เลขคณิตที่แตะหน่วยความจำโดยตรงได้ คำสั่งน้อยลงต่อโปรแกรม; ดีโค้ดเดอร์ยากขึ้น

    RISC (Reduced Instruction Set Computing) ไปอีกทาง: คำสั่งความยาวคงที่ แบบจำลอง load/store เข้มงวด (การดำเนินการ ALU บนรีจิสเตอร์เท่านั้น) ฟิลด์สม่ำเสมอ คำสั่งมากขึ้นต่อโปรแกรม; แต่ละคำสั่งเรียบง่ายพอที่จะดึงและดีโค้ดแบบคาดเดาได้ ทีละขั้น ความสม่ำเสมอนั้นคือเหตุผลที่ไปป์ไลน์ (บทที่ 13) จัดการได้บน RISC ก่อน — คำสั่งความกว้างคงที่ง่ายกว่ามากที่จะแบ่งขั้นกว่าคำสั่ง CISC ที่ความยาวยังไม่รู้จนกว่าจะเริ่มดีโค้ดไปแล้ว

    เชิงรูปธรรม: คำสั่ง RISC โดยทั่วไปยาว 32 บิตพร้อมฟิลด์ในตำแหน่งคงที่ คำสั่ง x86 ยาวได้ตั้งแต่ 1 ไบต์ถึง 15 ไบต์ พร้อมพรีฟิกซ์ที่เป็นทางเลือก — หนาแน่นและทรงพลัง แพงที่จะดีโค้ดที่ปริมาณงานสูง

    RISC-V ทีละบิต: ฟิลด์คงที่และกับดักของค่าคงที่#

    คู่มือชุดคำสั่ง RISC-V (Volume I, ฉบับ 20240411) ระบุว่าชุดคำสั่งพื้นฐานมีคำสั่งยาว 32 บิตคงที่ ต้องวางตรงขอบ 4 ไบต์ มีรูปแบบหลักสี่แบบ (R/I/S/U) และ “เก็บเรจิสเตอร์ต้นทาง (rs1, rs2) และปลายทาง (rd) ไว้ในตำแหน่งเดียวกันในทุกรูปแบบเพื่อให้ถอดรหัสง่าย” บิตเครื่องหมายของค่าคงที่ทุกแบบอยู่ที่บิต 31 เสมอ เพื่อให้ขยายบิตเครื่องหมายไปพร้อมกับการถอดรหัสได้ ผู้เขียนเข้ารหัสคำสั่ง add x3, x1, x2 (x3 ← x1 + x2) ด้วยมือจากตารางในคู่มือ:

    ฟิลด์ funct7 (บิต 31–25) rs2 (24–20) rs1 (19–15) funct3 (14–12) rd (11–7) opcode (6–0)
    ค่า 0000000 00010 (x2) 00001 (x1) 000 00011 (x3) 0110011

    ต่อกันได้ 0x002081B3 ส่วน sub x3, x1, x2 ต่างเพียงบิต 30 (funct7 = 0100000) ได้ 0x402081B3 — ฮาร์ดแวร์แยก add กับ sub ด้วยบิตเดียว addi x3, x1, 5 เป็นรูปแบบ I (ค่าคงที่ 12 บิตแทนที่ funct7 และ rs2) ได้ 0x00508193 คู่มือยังกำหนดว่าเรจิสเตอร์ x0 มีค่าศูนย์ตายตัว และคำสั่ง NOP เข้ารหัสเป็น addi x0, x0, 0 = 0x00000013 — เขียนลง x0 แล้วผลหายไป ไม่ต้องมี opcode พิเศษสำหรับ “ไม่ทำอะไร”

    กรณีขอบ: ค่าคงที่ 12 บิต ค่าคงที่ของ addi เป็นเลขมีเครื่องหมาย 12 บิต ใส่ได้ตั้งแต่ −2048 ถึง 2047 addi x5, x0, 2047 เข้ารหัสได้ (0x7FF00293) แต่ 2048 ใส่ไม่ได้ ต้องใช้สองคำสั่ง: lui วางค่า 20 บิตบนแล้วเติมศูนย์ 12 บิตล่าง ตามด้วย addi เติมส่วนล่าง กับดักคือ addi ขยายบิตเครื่องหมาย ของค่าคงที่: ถ้าบิต 11 ของส่วนล่างเป็น 1 (ส่วนล่าง ≥ 0x800) addi จะบวกเลขติดลบ จึงต้องบวก 1 ให้ส่วนบนชดเชย ผู้เขียนเขียนโปรแกรมแยกค่าทั้งแบบถูกและแบบซื่อ ๆ (lui ด้วย 20 บิตบนตรง ๆ) แล้วจำลองเลขคณิต 32 บิต (RV32):

    ค่าที่ต้องการ ลำดับที่ถูก ผลของวิธีซื่อ ๆ
    0x000007FF (2047) addi 2047 ถูก
    0x00000800 (2048) lui 0x1; addi −2048 0xFFFFF800 ผิด
    0x00000FFF lui 0x1; addi −1 0xFFFFFFFF ผิด
    0x12345678 lui 0x12345; addi 1656 ถูก (บิต 11 เป็น 0)
    0x12345FFF lui 0x12346; addi −1 0x12344FFF ผิด
    0x7FFFFFFF lui 0x80000; addi −1 0x7FFFEFFF ผิด
    0xFFFFFFFF (−1) addi −1 (คำสั่งเดียว) 0xFFFFEFFF ผิด

    ค่าทุกแถวในคอลัมน์กลางผ่านการจำลองกลับเป็นค่าที่ต้องการ แถว 0x7FFFFFFF น่าสนใจ: ส่วนบนกลายเป็น 0x80000 แล้ว addi −1 วนกลับมาเป็นค่าบวกที่ใหญ่ที่สุดพอดี — ถูกต้องเพราะคู่มือระบุว่า addi “ไม่สนใจการล้น” เก็บเพียงบิตล่าง แอสเซมเบลอร์จัดการเรื่องนี้ให้ (pseudo-instruction li) แต่ใครเขียนตัวแปลโปรแกรมหรือ JIT ต้องทำเอง

    RISC-V ไม่มีตัวบ่งชี้ ADD ของ RISC-V ไม่สนใจการล้นเช่นกัน และไม่มีตัวทดหรือตัวบ่งชี้ใด ๆ คู่มืออธิบายว่าเลือกคำสั่งเปรียบเทียบแล้วกระโดดในคำสั่งเดียว แทน condition codes แบบ x86 และ ARM เพราะเข้ากับไปป์ไลน์ได้ดีกว่าและไม่ต้องมีสถานะเพิ่ม การตรวจการล้นแบบไม่มีเครื่องหมายใช้คำสั่งเดียวหลังการบวก: add t0, t1, t2; bltu t0, t1, overflow (ถ้าผลรวมน้อยกว่าตัวตั้ง แปลว่าวนกลับ) ผู้เขียนตรวจกฎนี้แบบครบทุกคู่ในเลข 8 บิต (256 × 256 คู่): “ผลรวมที่ตัดเหลือ 8 บิตน้อยกว่าตัวตั้ง” ตรงกับ “ผลรวมจริงเกิน 255” ทุกคู่ รวมกรณีขอบ t2 = 0 (ผลรวมเท่าตัวตั้ง ไม่น้อยกว่า จึงไม่ล้น) และ 0xFF + 1 (ได้ 0 น้อยกว่า 0xFF จึงล้น)

    x86 ทีละไบต์: หลายทางสู่ความหมายเดียว#

    ผู้เขียนประกอบคำสั่งด้วย GNU as แล้วถอดกลับด้วย objdump (ความหมายของแต่ละ opcode ตรวจกับหน้า ADD ที่ถอดจากคู่มือ Intel):

    คำสั่ง ไบต์ ความยาว
    add eax, ebx 01 D8 2
    add eax, ebx (อีกรูปแบบ) 03 C3 2
    add eax, 5 83 C0 05 3
    add eax, 127 83 C0 7F 3
    add eax, 128 05 80 00 00 00 5
    add eax, −128 83 C0 80 3
    add eax, [rbx+rcx*4+16] 03 44 8B 10 4
    add dword [rbx+rcx*4+0x12345678], 0x12345678 81 84 8B 78 56 34 12 78 56 34 12 11
    lock add dword fs:[…เดิม…], 0x12345678 64 F0 81 84 8B … 13
    lock add qword fs:[r9+r10*4+0x12345678], 0x12345678 64 F0 4B 81 84 91 … 14

    สองรหัส ความหมายเดียว: opcode 01 แปลว่า “บวกเรจิสเตอร์เข้า r/m” ส่วน 03 แปลว่า “บวก r/m เข้าเรจิสเตอร์” ไบต์ถัดมา (ModRM) แบ่งเป็น mod 2 บิต, reg 3 บิต, r/m 3 บิต สำหรับ 01 D8: D8 = 11 011 000 คือ mod = 11 (ทั้งคู่เป็นเรจิสเตอร์), reg = 011 (ebx), r/m = 000 (eax) สำหรับ 03 C3: C3 = 11 000 011 สลับบทบาท ผลลัพธ์เหมือนกันทุกบิต — ความซ้ำซ้อนที่ RISC-V ไม่มี

    กรณีขอบ 127/128: opcode 83 ใช้ค่าคงที่ 8 บิตที่ “ขยายบิตเครื่องหมาย” (หน้า ADD ระบุไว้) ไบต์ 7F คือ 127 แต่ไบต์ 80 คือ −128 ไม่ใช่ 128 ดังนั้น add eax, 128 ต้องกระโดดไปใช้รูปยาว 5 ไบต์ ขณะที่ add eax, −128 ยังใช้รูปสั้น 3 ไบต์ได้ — ขอบแบบเดียวกับ 2047/2048 ของ RISC-V แต่เลื่อนมาที่ 127/128 และผลคือ ความยาวคำสั่งเปลี่ยน ไม่ใช่จำนวนคำสั่ง

    กรณีขอบ 15 ไบต์: คู่มือ Intel (Volume 2, ฉบับกันยายน 2026) ระบุว่า “ความยาวสูงสุดของคำสั่ง Intel 64 และ IA-32 ยังคงเป็น 15 ไบต์” ผู้เขียนลองเติมพรีฟิกซ์ ds ที่ซ้ำซ้อนหน้าคำสั่ง 14 ไบต์ในตาราง: เติมหนึ่งตัว (15 ไบต์) objdump ยังถอดได้ เติมสองตัว (16 ไบต์) objdump รายงาน “(bad)” — ขอบอยู่ตรง 15 พอดี

    ผลต่อดีโค้ดเดอร์: ใน RISC-V พื้นฐาน คำสั่งที่ k เริ่มที่ไบต์ 4k เสมอ ดีโค้ดเดอร์หลายตัวเริ่มพร้อมกันได้ทันที ใน x86 จะรู้ว่าคำสั่งถัดไปเริ่มตรงไหน ต้องอ่านพรีฟิกซ์ opcode ModRM และรู้ว่ามีไบต์ที่อยู่และค่าคงที่ตามมากี่ไบต์ก่อน — ความยาวของคำสั่งที่ 2 ขึ้นกับการถอดรหัสคำสั่งที่ 1 นี่คือราคาของ “หนาแน่นและทรงพลัง” ในย่อหน้าข้างบนเป็นตัวเลข

    งานเดียว สามสัญญา: “A ← A + ค่าในหน่วยความจำ” ใน mini-CPU คือ ADD 14 ไบต์เดียว (0x2E) ใน x86 คือ add eax, [rbx+rcx*4+16] คำสั่งเดียว 4 ไบต์ ใน RISC-V ต้องสองคำสั่งตามแบบ load/store: lw x6, 16(x5) (0x0102A303) แล้ว add x10, x10, x6 (0x00650533) รวม 8 ไบต์ ข้อสังเกต: mini-CPU มีความยาวคงที่แบบ RISC แต่ให้ ALU แตะหน่วยความจำได้แบบ CISC — ตัวอย่างเล็ก ๆ ว่าป้ายกำกับสองขั้วไม่ได้แบ่งโลกสะอาด

    ลองตอนนี้. mini-CPU ด้านล่างคือ ISA เล็ก ๆ: opcode 4 บิต ตัวถูกดำเนินการ 4 บิต หน่วยความจำสิบหกคำ ก้าวโปรแกรมนำทาง 8 คำสั่งแล้วดู fetch / decode / execute เคลื่อน A และหน่วยความจำ — สัญญาเดียวกับที่บทนี้เพิ่งตั้งชื่อ เล็กพอถือในหนึ่งจอ

    เปิดแล็บในแท็บใหม่ ↗

    อ่านสัญญาของ mini-CPU จากซอร์สจริง#

    สัญญาที่แท้จริงของ mini-CPU ไม่ได้อยู่ในคำอธิบาย แต่อยู่ในซอร์ส JavaScript ของแล็บข้างบน ผู้เขียนอ่านซอร์สนั้นและรันสคริปต์ของแล็บ ตัวจริง ใน Node.js (แทนหน้าจอด้วยออบเจ็กต์จำลอง) เพื่อตรวจทุกข้อด้านล่าง

    การเข้ารหัส: แต่ละคำยาว 8 บิต = opcode × 16 + ตัวถูกดำเนินการ (ในซอร์ส: (op << 4) | (arg & 0xF)) โปรแกรมนำทางแปดคำสั่งจึงเป็นรหัสเครื่องแปดไบต์:

    ที่อยู่ คำสั่ง รหัสเครื่อง ความหมาย
    0 LDI 5 0x55 A ← 5
    1 STA 14 0x4E mem[14] ← A
    2 LDI 8 0x58 A ← 8
    3 ADD 14 0x2E A ← A + mem[14] = 13
    4 STA 15 0x4F mem[15] ← A
    5 LDA 15 0x1F A ← mem[15]
    6 OUT 0xE0 เอาต์พุต ← A
    7 HLT 0xF0 หยุด

    รันจริงได้เอาต์พุต 13 ใน 8 ก้าว opcode 4 บิตมีได้ 16 รหัส แล็บใช้ 11 รหัส (0–8, E, F) เหลือ 0x9–0xD ว่างห้ารหัส

    กรณีขอบ 1 — รหัสที่ไม่ได้นิยาม: แอสเซมเบลอร์ไม่ยอมสร้างรหัส 0x9–0xD แต่โปรแกรมสร้างเองได้ขณะรัน: โปรแกรม LDA 6, SUB 7, STA 5, JMP 5, HLT, NOP, HLT, ADD 0 อ่านคำ HLT ที่ที่อยู่ 6 (0xF0) มาเป็นข้อมูล ลบด้วยคำ ADD 0 ที่ที่อยู่ 7 (0x20) ได้ 0xD0 เขียนทับ NOP ที่ที่อยู่ 5 แล้วกระโดดไปรัน — แล็บรายงาน “Unknown opcode 0xd at PC 5” แล้วหยุดที่ก้าวที่ 5 ISA จริงต้องตัดสินใจเรื่องนี้เช่นกัน: คู่มือ RISC-V ระบุว่าพฤติกรรมเมื่อถอดรหัสคำสั่งที่สงวนไว้ “ไม่ได้กำหนด” (UNSPECIFIED) บางแพลตฟอร์มบังคับให้เกิด exception บางแพลตฟอร์มปล่อยให้ใช้เป็นส่วนขยาย

    กรณีขอบ 2 — ตัวสะสม 8 บิตวนกลับ: ADD คำนวณ r = A + mem[x] แล้วตั้งตัวทดเมื่อ r > 255 และเก็บ A = r & 0xFF; SUB ตั้งตัวทด (ทำหน้าที่ตัวยืม) เมื่อ r < 0 ผู้เขียนรันในแล็บ:

    การคำนวณ A ที่ได้ ตัวทด zero
    240 + 240 = 480 224 1 0
    128 + 128 = 256 (ขอบพอดี) 0 1 1
    0 − 1 255 1 0

    LDI รับได้แค่ 0–15 และแอสเซมเบลอร์ไม่มีคำสั่งประกาศข้อมูล จะได้ 240 หรือ 128 มาบวกก็ต้อง ใช้รหัสคำสั่งเป็นข้อมูล: คำ HLT คือ 0xF0 = 240 และคำ JZ 0 คือ 0x80 = 128 เพราะคำสั่งและข้อมูลอยู่ในหน่วยความจำสิบหกคำเดียวกัน

    กรณีขอบ 3 — ลูปนับถอยหลังเมื่อ n = 0: โปรแกรม LDI 1, STA 15, LDI n, SUB 15, JZ 6, JMP 3, HLT ลบ 1 จนกว่าจะเป็นศูนย์ รันจริงได้จำนวนก้าว 6, 9, 18, 48 สำหรับ n = 1, 2, 5, 15 ตรงกับสูตร 3n + 3 แต่เมื่อ n = 0 การลบครั้งแรกให้ 0 − 1 = 255 ไม่ใช่ศูนย์ ลูปจึงวนต่ออีก 255 รอบ ได้ 771 ก้าว = 3 × 256 + 3 — n = 0 ทำตัวเหมือน n = 256 ถ้าผู้เขียนโปรแกรมทดสอบแค่ n = 1 ถึง 15 จะไม่เห็นเลย

    กรณีขอบ 4 — คำสั่งไหนตั้งตัวบ่งชี้ zero เป็นส่วนหนึ่งของสัญญา: ในซอร์ส ADD, SUB, LDI และ LDA ปรับ zero เมื่อ A เป็น 0 ส่วน STA, OUT และคำสั่งกระโดดไม่แตะธง โปรแกรม LDI 0, STA 15, LDI 7, LDA 15, JZ 6, HLT, OUT, HLT โหลดศูนย์เข้า A ด้วย LDA แล้ว zero ติดตามเป็น 1 JZ จึงกระโดดไป OUT — รวม 7 ก้าว (ไม่ใช่ 6 ที่จะได้ถ้า LDA ไม่แตะธง) และเอาต์พุตเป็น 0 อีกข้อ: Reset เคลียร์ zero เป็น 0 ดังนั้น JZ เป็นคำสั่งแรกจะไม่กระโดด (รัน JZ 3, LDI 9, OUT, HLT แล้วได้เอาต์พุต 9) ตัวแปลโปรแกรมที่สร้างรหัสให้ mini-CPU ต้องรู้รายละเอียดระดับนี้ — นี่คือความหมายของ “บิตเหล่านั้นหมายความว่าอะไร” ในนิยาม ISA ย่อหน้าแรก

    กรณีขอบ 5 — PC วนกลับและขอบของขนาดโปรแกรม: ในซอร์ส PC = (PC + 1) & 0xF ที่อยู่ 15 จึงตามด้วย 0 โปรแกรมที่ลืม HLT (เช่น LDI 1, OUT แล้วที่เหลือเป็นศูนย์ = NOP) วนไม่รู้จบ หลัง 17 ก้าว PC กลับมาอยู่ที่ 1 และปุ่ม Run จะวิ่งไปเรื่อย ๆ เพราะหยุดเฉพาะเมื่อเจอ HLT ที่แนบเนียนกว่า: ถ้าขยายโปรแกรมนำทางด้วย NOP จนเต็ม 16 คำโดยให้ HLT อยู่ที่ 15 คำสั่ง STA 15 จะเขียนผลรวม 13 (0x0D = NOP 13) ทับ HLT ของตัวเอง ผู้เขียนรัน 200 ก้าวแล้วยังไม่หยุด เอาต์พุต 13 ถูกต้องแต่โปรแกรมไม่จบ — ข้อมูลกับคำสั่งชนกันเพราะใช้หน่วยความจำเดียวกัน

    กรณีขอบ 6 — แอสเซมเบลอร์ไม่ใช่ ISA: แอสเซมเบลอร์ของแล็บรับตัวถูกดำเนินการเป็นทศนิยม (13) หรือเลขฐานสิบหก (0xD) และปฏิเสธสิ่งอื่น — LDI 16, LDI -1, LDI 0xZZ และ LDI 5abc ล้วนรายงานข้อผิดพลาดที่บอกเลขบรรทัดในตัวแก้ไข (นับบรรทัดว่างและบรรทัดหมายเหตุด้วย) LDI 0x5 ประกอบถูกต้องเป็น LDI 5 (0x55) ส่วน HLT 3 ยังประกอบได้เป็น 0xF3 เพราะ NOP/OUT/HLT เก็บตัวถูกดำเนินการไว้ในบิตล่างแม้ตอนรันจะเมินมัน (NOP n คือวิธีปลูกคำข้อมูล n ตอนประกอบ) โปรแกรมเกิน 16 คำถูกปฏิเสธ ทั้งหมดนี้เป็นพฤติกรรมของ เครื่องมือ ไม่ใช่ของสัญญา — แยกให้ออกเหมือนแยกสถาปัตยกรรมออกจากไมโครสถาปัตยกรรม

    ข้อสังเกตสุดท้าย: หน้าจอแสดงเรจิสเตอร์ B แต่ในซอร์ส B ถูกตั้งเป็นศูนย์ตอนเริ่มและตอน Reset เท่านั้น ไม่มีคำสั่งใดอ่านหรือเขียนมัน สถานะที่ไม่มีคำสั่งใดแตะต้องไม่ได้เป็นส่วนของ ISA จริง ๆ แม้จะมองเห็นได้

    ลองเอง: พิมพ์ LDA 4, ADD 4, OUT, HLT, JZ 0 ลงในแล็บ กด Assemble แล้ว Step: บรรทัดสุดท้ายไม่เคยถูกรันแต่เป็นข้อมูล 128 ดูว่า A กลายเป็น 00 และไฟ CARRY กับ ZERO ติดพร้อมกัน จากนั้นลองโปรแกรมนับถอยหลังข้างบนกับ n = 0 แล้วกด Run

    ข้อโต้แย้งของ Patterson และ Ditzel (1980) เป็นตัวเลข#

    บทความที่ประตูออกของบทนี้ชี้ไว้ให้ตัวเลขที่ยังคำนวณตามได้:

    • ความซับซ้อนวัดจากขนาดหน่วยความจำเก็บไมโครโปรแกรม: PDP-11/40 มี 256 × 56 บิต VAX 11/780 มี 5120 × 96 บิต ผู้เขียนคูณได้ 14,336 กับ 491,520 บิต โตราว 34 เท่า
    • คำสั่งส่วนน้อยทำงานส่วนใหญ่: ตัวแปลโปรแกรมของ IBM 360 ตัวหนึ่ง: 10 คำสั่งคิดเป็น 80% ของคำสั่งที่รัน 16 คำสั่ง 90% 21 คำสั่ง 95% 30 คำสั่ง 99% โปรแกรม COBOL บน IBM 370 ใช้ 84 จาก 183 คำสั่ง แต่ 26 คำสั่งคิดเป็น 90.28% และ 48 คำสั่งคิดเป็น 99.08%
    • คำสั่ง “ระดับสูง” ไม่ได้เร็วกว่าเสมอ: บน VAX 11/780 การแทนคำสั่ง INDEX ด้วยคำสั่งง่าย ๆ หลายคำสั่ง (COMPARE, JUMP LESS UNSIGNED, ADD, MULTIPLY) เร็วขึ้น 45% และ 60% เมื่อตัวแปลโปรแกรมใช้ประโยชน์จากกรณีขอบล่างเป็นศูนย์ บน IBM 370 การ load ทีละตัวเร็วกว่า load multiple เมื่อน้อยกว่า 4 เรจิสเตอร์ ซึ่งคิดเป็น 40% ของการใช้งานจริง และบน VAX PUSHL R0 ช้ากว่า MOVL R0,-(SP) ที่ทำงานเดียวกัน
    • กฎ 10%: ถ้าการตัดคำสั่งหรือโหมดระบุที่อยู่หนึ่งอย่างทำให้รอบสัญญาณเร็วขึ้น 10% การเพิ่มมันกลับเข้าไปต้องทำให้เครื่องเร็วขึ้นเกิน 10% จึงจะคุ้ม
    • ราคาของการแก้บั๊ก: VAX 11/780 มีหน่วยความจำไมโครโปรแกรมที่เขียนได้ 1024 คำไว้แก้ข้อผิดพลาด บทความระบุว่ามีการแก้แล้วกว่า 50 ครั้ง ใช้ 252 ไมโครคำสั่ง — ผู้เขียนคำนวณได้ราวหนึ่งในสี่ (24.6%) ของพื้นที่นั้น

    บทความยังชี้ว่าความเข้ากันได้แบบขึ้นไปข้างบน (upward compatibility) ทำให้ “แทบไม่เคยมีการตัดคำสั่งหรือโหมดระบุที่อยู่ออก” ชุดคำสั่งจึงโตขึ้นทางเดียว — เหตุผลเดียวกับที่หัวข้อถัดไปใช้อธิบายว่าทำไม x86 ยังอยู่

    เหตุใด x86 จึงยังอยู่ต่อไป#

    หาก RISC ไปป์ไลน์ง่ายกว่า เหตุใด x86 ยังครองเดสก์ท็อปและเซิร์ฟเวอร์? ความเข้ากันได้และการลงทุนทางวิศวกรรมหลายทศวรรษ — ไม่ใช่ความสง่างามดิบ ชิป x86 สมัยใหม่ แปล คำสั่ง CISC เป็นไมโคร-ออปภายในที่เรียบง่ายแบบ RISC แล้วรันพวกนั้นบนคอร์แบบ RISC หลังฟรอนต์เอนด์ CISC (บทที่ 19) การถกเถียงไม่ใช่ทวิภาคที่สะอาดเท่าป้ายกำกับบอก

    ต่อไป: สร้าง datapath จริง — โครงสร้างทางกายภาพที่ ISA ทำงานอยู่บน
