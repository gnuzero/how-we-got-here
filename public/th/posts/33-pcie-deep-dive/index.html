    เจาะลึก PCIe

    มกราคม 1, 2026

    บทที่ 32 ครอบคลุม เหตุใด PCIe จึงไปอนุกรมและจุดต่อจุด บทนี้คือ ว่า การถ่ายโอนถูกจัดโครงสร้างบนลิงก์เหล่านั้นอย่างไร — ชั้นที่สำคัญหากคุณสร้างฮาร์ดแวร์ที่ต้องพูด fabric รวมถึงงาน GPU memory บน Nitefury ที่ชุดบทความนี้กลับมาหา

    แหล่งภาษาไทยส่วนใหญ่พูดถึง PCIe ในระดับ “สล็อตไหนเร็วกว่า” บทนี้จะลงไปถึงว่าข้อมูลหนึ่งก้อนถูกห่อ ส่ง ตรวจ และตอบรับอย่างไร และคำนวณให้ดูว่าตัวเลข “GB/s” บนสเปกมาจากไหน

    ศัพท์ที่ใช้: ลิงก์ (link, ศัพท์บัญญัติ เชื่อมโยง) คือการเชื่อมต่อจุดต่อจุดระหว่างอุปกรณ์สองตัว เลน (lane) คือสายคู่ดิฟเฟอเรนเชียลหนึ่งคู่ต่อทิศทาง ลิงก์หนึ่งประกอบด้วย 1 ถึง 16 เลน root complex คือฝั่ง CPU ที่เป็นรากของต้นไม้ PCIe endpoint คืออุปกรณ์ปลายทาง เช่น การ์ดจอ SSD หรือการ์ด FPGA กลุ่มข้อมูล (packet, ศัพท์บัญญัติ; ในบทนี้ใช้ว่า แพ็กเก็ต) คือหน่วยข้อมูลที่ส่งเป็นก้อน

    เจตนา ความเชื่อถือได้ อิเล็กตรอน#

    สามชั้น สามงาน Transaction Layer คือที่ที่การอ่าน การเขียน หรือ completion เกิดและจบ — ชั้นที่ซอฟต์แวร์คิด Data Link Layer ทำให้การส่งมอบเชื่อถือได้: หมายเลขลำดับ CRC การส่งซ้ำหากแพ็กเก็ตเสีย Physical Layer คือสาย: คู่ดิฟเฟอเรนเชียล การเข้ารหัสให้กระแสกู้คืนได้ การ serialize ลงทองแดง แยกแบบนั้นเพื่อให้ออกแบบกำหนดเองแสดง เจตนา โดยไม่ต้องประดิษฐ์อิเล็กตรอนใหม่

    ถ้าเคยเรียนแบบจำลองเครือข่ายเป็นชั้น (บทที่ 41) จะเห็นว่าหลักเดียวกัน ชั้นบนไม่ต้องรู้ว่าชั้นล่างทำงานอย่างไร แต่ละชั้นเติมหัวหรือท้ายของตัวเองเข้าไปเวลาส่ง และแกะออกเวลารับ

    แพ็กเก็ตคือสัญญา#

    หน่วยคือ Transaction Layer Packet TLP ตั้งชื่อประเภท (อ่าน/เขียนหน่วยความจำ I/O การตั้งค่า) ที่อยู่ ความยาว และ — ในการเขียน — payload Link layer ห่อด้วยลำดับและ CRC; ฝั่งไกลตรวจและ retry หากจำเป็น จากข้างบน มันดูเหมือนการอ่านหรือเขียนที่เชื่อถือได้ ความเชื่อถือได้ไม่ใช่เวทมนตร์ มันคือการห่อนั้น

    กายวิภาคของ TLP#

    หน่วยนับในสเปกคือ DW (double word) = 4 ไบต์

    • ส่วนหัว (header) ยาว 3 DW (12 ไบต์) สำหรับแอดเดรส 32 บิต หรือ 4 DW (16 ไบต์) สำหรับแอดเดรส 64 บิต บอกประเภทของธุรกรรม ความยาว แอดเดรส และหมายเลขผู้ร้องขอ
    • ข้อมูล (payload) มีได้ตั้งแต่ 0 ถึงสูงสุด 1,024 DW (4 KiB) แต่ในทางปฏิบัติถูกจำกัดด้วย Max Payload Size (MPS) ที่ทั้งสองฝั่งตกลงกันตอนเริ่มระบบ ค่าที่พบบ่อยคือ 128 หรือ 256 ไบต์
    • ชั้น Data Link เติม หมายเลขลำดับ (sequence number) 2 ไบต์ข้างหน้า และ LCRC (link CRC) 4 ไบต์ข้างหลัง
    • ชั้น Physical เติมสัญลักษณ์บอกจุดเริ่มและจุดจบของเฟรมอีกเล็กน้อย รูปแบบต่างกันไปตามรุ่น

    ประสิทธิภาพของการห่อ: คำนวณเอง#

    สมมติเขียนหน่วยความจำด้วยแอดเดรส 64 บิต ส่วนหัว 16 ไบต์ บวกลำดับ 2 ไบต์ บวก LCRC 4 ไบต์ = 22 ไบต์ต่อ TLP (ตัวเลขนี้ไม่นับสัญลักษณ์เฟรมของชั้น Physical และ ECRC ที่เป็นตัวเลือก จึงเป็นค่าประมาณที่มองโลกแง่ดีเล็กน้อย)

    • payload 256 ไบต์: 256 ÷ (256 + 22) = 92.1% ของแบนด์วิดท์เป็นข้อมูลจริง
    • payload 64 ไบต์: 64 ÷ (64 + 22) = 74.4%

    เขียนข้อมูล 4 KiB ด้วย MPS = 256 ไบต์ ต้องแบ่งเป็น 4,096 ÷ 256 = 16 TLP ส่วนหัวรวม 16 × 22 = 352 ไบต์ ส่งจริงทั้งหมด 4,448 ไบต์ ข้อสรุปเชิงปฏิบัติ: การส่งทีละก้อนเล็ก ๆ เปลืองแบนด์วิดท์ไปกับหัวแพ็กเก็ต ไดรเวอร์และ DMA engine ที่ดีจึงพยายามรวมการถ่ายโอนเป็นก้อนใหญ่

    เขียนแบบส่งแล้วจบ อ่านแบบต้องรอคำตอบ#

    TLP ของการเขียนหน่วยความจำ (Memory Write, MWr) เป็นแบบ posted คือผู้ส่งยิงไปแล้วถือว่าจบ ไม่ต้องรอคำตอบจากปลายทาง ส่วนการอ่าน (Memory Read, MRd) เป็นแบบ non-posted ผู้อ่านส่ง MRd ที่มีแต่ส่วนหัว บอกแอดเดรสและความยาว แล้วต้องรอ ปลายทางตอบกลับด้วย Completion with Data (CplD) หนึ่งหรือหลายแพ็กเก็ตที่มีข้อมูลอยู่ข้างใน

    ผลที่ตามมาคือการอ่านข้ามลิงก์มีเวลาแฝง (latency) ของการเดินทางไปกลับเสมอ ส่วนการเขียนไม่มี นี่คือเหตุผลที่การออกแบบประสิทธิภาพสูงมักให้อุปกรณ์ เขียน ผลลงหน่วยความจำของโฮสต์ (เช่น NIC เขียนแพ็กเก็ตที่รับมาลง RAM ด้วย DMA) แทนที่จะให้ CPU ไป อ่าน จากอุปกรณ์ และเป็นเหตุผลที่อุปกรณ์ที่อยากอ่านเร็วต้องปล่อย MRd ออกไปหลายตัวพร้อมกันโดยไม่รอกัน

    ความเชื่อถือได้: ACK, NAK และบัฟเฟอร์ส่งซ้ำ#

    ชั้น Data Link ทำงานคล้าย TCP ขนาดจิ๋ว (บทที่ 41) แต่เป็นฮาร์ดแวร์ล้วนและทำงานเฉพาะบนลิงก์เดียว

    1. ผู้ส่งแปะหมายเลขลำดับให้ทุก TLP แล้วเก็บสำเนาไว้ใน บัฟเฟอร์ส่งซ้ำ (replay buffer)
    2. ผู้รับตรวจ LCRC ถ้าถูกต้องและลำดับถูก ส่ง ACK (การตอบรับ) กลับไปในแพ็กเก็ตควบคุมเล็ก ๆ ชื่อ DLLP ACK หนึ่งครั้งยืนยันได้ทุกแพ็กเก็ตจนถึงหมายเลขนั้น
    3. ผู้ส่งได้ ACK แล้วจึงลบสำเนาออกจากบัฟเฟอร์
    4. ถ้า LCRC ผิด ผู้รับส่ง NAK ผู้ส่งจะส่ง TLP ทั้งหมดตั้งแต่ตัวที่เสียเป็นต้นไปใหม่จากบัฟเฟอร์ ถ้าไม่ได้รับ ACK หรือ NAK ภายในเวลาที่กำหนด ก็ส่งซ้ำเช่นกัน

    ซอฟต์แวร์ด้านบนไม่เคยเห็นกระบวนการนี้ เห็นแค่ว่าการเขียนถึงปลายทางเสมอ ความผิดพลาดของบิตบนทองแดงที่วิ่งหลายสิบกิกะทรานสเฟอร์ต่อวินาทีเกิดได้เป็นปกติ แต่ถูกซ่อนไว้ในชั้นนี้

    การควบคุมการไหลด้วยเครดิต#

    ผู้ส่งต้องไม่ส่งเร็วเกินกว่าที่ผู้รับมีที่พักข้อมูล (บัฟเฟอร์) รองรับ ถ้าส่งเกินแล้วผู้รับต้องทิ้ง ก็ต้องส่งซ้ำ เสียเวลาเปล่า PCIe จึงใช้ การควบคุมสายงาน (flow control, ศัพท์บัญญัติ) แบบ เครดิต (credit) ตอนเริ่มลิงก์ ผู้รับประกาศว่าตัวเองมีเครดิตเท่าไรในแต่ละประเภท (posted, non-posted, completion แยกเครดิตส่วนหัวกับเครดิตข้อมูล) ผู้ส่งหักเครดิตทุกครั้งที่ส่ง ถ้าเครดิตหมดต้องหยุดรอ เมื่อผู้รับประมวลผลแพ็กเก็ตและเคลียร์บัฟเฟอร์แล้ว ก็คืนเครดิตกลับไปด้วย DLLP

    เครดิตข้อมูลหนึ่งหน่วย = 4 DW = 16 ไบต์ ตัวอย่าง: ผู้รับประกาศเครดิตข้อมูลแบบ posted 64 หน่วย = 1,024 ไบต์ ด้วย payload 256 ไบต์ ผู้ส่งยิง TLP ได้ 4 ตัว ก่อนต้องรอเครดิตคืน ถ้าเวลาไปกลับของลิงก์นานกว่าเวลาที่ใช้ส่ง 4 ตัวนั้น ลิงก์จะว่างเป็นช่วง ๆ ขนาดบัฟเฟอร์ของผู้รับจึงเป็นตัวกำหนดความเร็วจริงได้พอ ๆ กับจำนวนเลน

    Lane สเกลความกว้าง; รุ่นสเกลอัตรา#

    Lane คือคู่ดิฟเฟอเรนเชียลหนึ่งคู่ต่อทาง — ลิงก์ขั้นต่ำ รวม lane (x1…x16) เพื่อคูณแบนด์วิดท์ แต่ละรุ่นประมาณสองเท่าอัตราต่อ lane (ส่งสัญญาณสูงขึ้น การเข้ารหัสแน่นขึ้น) สล็อต x16 เดียวกัน Gen 5 เทียบ Gen 3: แบนด์วิดท์ทิศทางเดียวประมาณ 4× (~64 GB/s เทียบ ~16 GB/s) โดยไม่เพิ่มสาย การเดิมพันอนุกรมจากบทที่ 32 คือสิ่งที่ทำให้การปีนนั้นเป็นไปได้

    ตัวเลข GB/s มาจากไหน#

    อัตราของเลนระบุเป็น GT/s (gigatransfers ต่อวินาที) คือจำนวนบิตดิบบนสายต่อวินาที ไม่ใช่บิตข้อมูล เพราะชั้น Physical ต้องใช้ การเข้ารหัส (encoding, ศัพท์บัญญัติ) เพื่อให้ผู้รับกู้สัญญาณนาฬิกาจากกระแสบิตได้ และให้สัญญาณมีจำนวน 0 กับ 1 สมดุล

    • Gen1 และ Gen2 ใช้ 8b/10b ข้อมูล 8 บิตกลายเป็น 10 บิตบนสาย เสียไป 20%
    • Gen3 ถึง Gen5 ใช้ 128b/130b ข้อมูล 128 บิตบวกหัวบล็อก 2 บิต เสียไปแค่ 2 ÷ 130 ≈ 1.54%

    แบนด์วิดท์ต่อเลนต่อทิศทาง = อัตรา GT/s × ประสิทธิภาพการเข้ารหัส ÷ 8 บิตต่อไบต์

    รุ่น อัตรา การเข้ารหัส ต่อเลน x16
    Gen1 2.5 GT/s 8b/10b 2.5 × 0.8 ÷ 8 = 0.25 GB/s 4.0 GB/s
    Gen2 5 GT/s 8b/10b 0.5 GB/s 8.0 GB/s
    Gen3 8 GT/s 128b/130b 8 × 128/130 ÷ 8 ≈ 0.985 GB/s ≈ 15.75 GB/s
    Gen4 16 GT/s 128b/130b ≈ 1.97 GB/s ≈ 31.5 GB/s
    Gen5 32 GT/s 128b/130b ≈ 3.94 GB/s ≈ 63.0 GB/s

    สังเกต Gen2 → Gen3: อัตราบนสายเพิ่มแค่ 1.6 เท่า (5 → 8 GT/s) แต่แบนด์วิดท์ข้อมูลเพิ่มเกือบ 2 เท่า (0.5 → 0.985 GB/s) ส่วนต่างมาจากการเปลี่ยนการเข้ารหัสล้วน ๆ นี่คือความหมายของ “การเข้ารหัสแน่นขึ้น” ในย่อหน้าข้างบน และอย่าลืมว่าตัวเลขในตารางเป็นแบนด์วิดท์ ก่อน หักหัวแพ็กเก็ต ถ้า payload 256 ไบต์ ลิงก์ Gen4 x16 จะส่งข้อมูลจริงได้ราว 31.5 × 0.921 ≈ 29 GB/s ต่อทิศทาง (และน้อยกว่านี้อีกเมื่อนับ DLLP และสัญลักษณ์เฟรม)

    PCIe 6.0 เปลี่ยนวิธีการส่งสัญญาณเป็น PAM4 (สัญญาณสี่ระดับ ส่งได้ 2 บิตต่อสัญลักษณ์) ที่ 64 GT/s และเปลี่ยนการห่อข้อมูลเป็นหน่วยขนาดคงที่ที่เรียกว่า FLIT พร้อมการแก้ความผิดพลาดล่วงหน้า (FEC) หลักการสามชั้นยังเหมือนเดิม แต่รายละเอียดของการเข้ารหัสและการห่อในตารางข้างบนใช้ไม่ได้กับรุ่นนั้นตรง ๆ

    เหตุใด fabric กำหนดเองจึงสนใจ#

    การ์ด memory fabric บน FPGA ต้องอยู่บนสแต็กนี้: สร้าง TLP ที่ root complex และ endpoint อื่นยอมรับ และให้ IP ที่เป็นที่ยอมรับจัดการความเชื่อถือได้ของลิงก์กับ physical layer Peer-to-peer แบบ GPUDirect (บทที่ 37) คือไอเดียเดียวกันที่พาไปต่อ — TLP ที่ระบุที่อยู่ระหว่างสอง endpoint โดย CPU อยู่นอกเส้นทางข้อมูล

    ในทางปฏิบัติ ผู้ออกแบบการ์ด FPGA แทบไม่ต้องเขียนชั้น Data Link และ Physical เอง ผู้ผลิต FPGA ให้ hard IP ที่จัดการ ACK/NAK เครดิต และการเข้ารหัสมาให้ งานของผู้ออกแบบอยู่ที่ชั้น Transaction คือสร้างและแกะ TLP ให้ถูก ซึ่งต้องเข้าใจเรื่อง posted กับ non-posted, MPS และเครดิตในบทนี้ ถึงจะได้แบนด์วิดท์ใกล้ตัวเลขในตาราง

    ประตูออก: The PCI Express Base Specification (PCI-SIG) — เอกสารปฐมภูมิที่มีชีวิตสำหรับ lane, TLP และสแต็กชั้นที่บทนี้ตั้งชื่อ; มีรุ่น (Base Spec ไม่ใช่เปเปอร์แช่แข็ง)
