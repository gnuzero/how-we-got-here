    GNU இயக்கம் மற்றும் Linux

    ஜனவரி 1, 2026

    1980களின் ஆரம்பத்தில், Unix (பதிவு 22) தொழில்நுட்பரீதியாகச் சிறந்ததாகவும் அதிகரித்து proprietary-ஆகவும் இருந்தது — AT&T வணிகக் கட்டுப்பாட்டை உறுதிப்படுத்தி, கல்வி மற்றும் பொழுதுபோக்கு அணுகல் இறுக்கமடைந்தது. Richard Stallman-இன் பதில், 1983-இல் தொடங்கி, முதன்மையாகத் தொழில்நுட்பத் தீர்வு அல்ல. அது கருத்தியல் மற்றும் சட்டம்: முழுமையாக இலவச (சுதந்திரம் என்ற அர்த்தத்தில், விலை மட்டும் அல்ல) Unix மாற்றீட்டை புதிதாகக் கட்டுங்கள், மற்றும் அதை அவ்வாறே வைத்திருக்க வடிவமைக்கப்பட்ட license-ஆல் ஆதரியுங்கள்.

    தமிழ் இடைவெளிக் குறிப்பு: GNU, Linux, GPL/copyleft மூன்றுக்கும் தமிழ் எழுத்து விளக்கம் மெலிதானது; காணொளிச் சான்று YouTube தேடல் முடிவுகள் மட்டும் — காணொளிகள் பார்க்கப்படவில்லை. இந்தப் பக்கத்தில் GPL பற்றிய விதிகள் GPL பதிப்பு 2-இன் மூல உரையிலிருந்து (Version 2, June 1991; Free Software Foundation) நேரடியாகப் படித்துச் சுருக்கப்பட்டவை; Linux kernel-இன் license அதன் COPYING கோப்பிலிருந்து சரிபார்க்கப்பட்டது; VM பயிற்சியின் வெளியீடுகள் உண்மையில் ஓட்டிப் பெற்றவை. இது சட்ட ஆலோசனை அல்ல — கருத்தைப் புரிந்துகொள்ளும் கணக்கு மட்டும். “எடுத்துக்காட்டு மதிப்பு” என்று குறிக்கப்பட்டவை கணக்குக்காகத் தேர்ந்தெடுத்தவை.

    முதலில் சொற்கள்#

    • Kernel (கருநிரல்): வன்பொருளை நேரடியாகக் கட்டுப்படுத்தி, நினைவகம், செயல்முறைகள், கோப்புகள், சாதனங்களை நிர்வகிக்கும் இயக்க அமைப்பின் மையப் பகுதி.
    • Userland (பயனர் வெளி): kernel-க்கு மேல் ஓடும் எல்லா நிரல்களும் — shell, ls, cp, compiler, editor.
    • கட்டற்ற மென்பொருள் (free software): “free” என்றால் விலை இல்லை என்பதல்ல, சுதந்திரம் — பயன்படுத்த, மாற்ற, மறுவிநியோகிக்க, உங்கள் மாற்றங்களையும் விநியோகிக்க.
    • Copyleft: copyright-ஐப் பயன்படுத்தியே, வழிவந்த படைப்புகளும் அதே சுதந்திர விதிகளின் கீழ் இருக்க வேண்டும் என்று கட்டாயப்படுத்தும் license முறை.
    • மூலக் குறியீடு (source code): மனிதர் படித்து மாற்றக்கூடிய நிரல் உரை; இயந்திரக் குறியீடு (object code / binary) அதிலிருந்து compile செய்யப்படுவது.
    • வழிவந்த படைப்பு (derivative work, “work based on the Program”): GPL நிரலின் ஒரு பகுதியை — மாற்றியோ மாற்றாமலோ — உள்ளடக்கிய படைப்பு.
    • Distribution (விநியோகம்): நகல்களை மற்றவர்களுக்குக் கொடுப்பது; GPL-2-இன் கடமைகள் இதில்தான் தொடங்குகின்றன.

    GNU: Kernel இல்லாத Userland#

    GNU — “GNU’s Not Unix” — ஒவ்வொரு கூறும் இலவச மென்பொருளாக இருக்கும் முழுமையான, Unix-இணக்க operating system கட்ட அமைந்தது: பயன்படுத்தக்கூடியது, மாற்றக்கூடியது, மறுவிநியோகம் செய்யக்கூடியது, உங்கள் சொந்த மாற்றங்களின் மறுவிநியோகம் உட்பட. அடுத்த தசாப்தத்தில் திட்டம் அத்தியாவசிய உள்கட்டமைப்பை உருவாக்கியது: GCC (இன்னும் மிகப் பரவலாகப் பயன்படுத்தப்படும் compilers ஒன்று — பதிவு 28), Bash, GNU coreutils, Emacs, மற்றும் மேலும் பல.

    GNU ஆண்டுகளாக இல்லாதது: வேலை செய்யும் kernel. அதன் திட்டமிட்ட kernel, GNU Hurd, கடுமையான தொழில்நுட்பச் சிக்கல்களில் சிக்கி பரந்த நடைமுறைப் பயன்பாட்டை எட்டாதது. முழுமையான userland; உண்மையான வன்பொருளுக்குக் கீழே kernel இல்லை.

    GPL: Copyright வெளிநோக்கித் திருப்பப்பட்டது#

    Stallman-இன் மற்றொரு முக்கிய பங்களிப்பு GNU General Public License (GPL) — வேண்டுமென்றே ஒரு பண்பு கொண்ட “copyleft” license: GPL-licensed குறியீட்டை உள்ளடக்கிய மென்பொருளை நீங்கள் விநியோகித்தால், உங்கள் மாற்றப்பட்ட மூலத்தை அதே நிபந்தனைகளின் கீழ் கிடைக்கச் செய்ய வேண்டும். பொதுவாக மறுவிநியோகத்தை கட்டுப்படுத்தும் கருவியான copyright, ஒவ்வொரு derivative வழியாகவும் சுதந்திரம் பரவுவதை உறுதிப்படுத்தப் பயன்படுத்தப்பட்டது — கீழ்நிலை வணிக fork அமைதியாக மூடுவதற்குப் பதிலாக.

    GPL-2 விதிகள், ஒரு கணக்காக#

    GPL பதிப்பு 2-இன் உரை (June 1991) மூன்று முக்கியக் கோடுகளை வரைகிறது. பிரிவு 0: நகலெடுத்தல், விநியோகம், மாற்றம் தவிர மற்ற செயல்கள் இந்த license-இன் எல்லைக்கு வெளியே; நிரலை ஓட்டுவது கட்டுப்படுத்தப்படவில்லை. பிரிவு 2(b): நீங்கள் விநியோகிக்கும் வழிவந்த படைப்பு முழுவதும் எல்லா மூன்றாம் தரப்பினருக்கும் கட்டணமின்றி இதே license-இன் கீழ் license செய்யப்பட வேண்டும். பிரிவு 3: binary வடிவில் விநியோகித்தால் (a) முழு மூலக் குறியீட்டையும் உடன் கொடுக்க வேண்டும், அல்லது (b) குறைந்தது மூன்று ஆண்டுகள் செல்லுபடியாகும், மூலத்தை விநியோகிக்கும் உண்மைச் செலவுக்கு மேல் கட்டணம் வாங்காத எழுத்துமூல வாக்குறுதியைக் கொடுக்க வேண்டும். அதே பிரிவு 2-இன் இறுதியில்: GPL-க்குச் சம்பந்தமில்லாத வேறு படைப்பு ஒரே சேமிப்பு ஊடகத்தில் “வெறும் சேர்த்து வைத்தல்” (mere aggregation) ஆக இருந்தால், அது GPL எல்லைக்குள் வராது.

    ஒரு நிறுவனம் GPL-2 நிரல் ஒன்றை மாற்றுகிறது என்று வைத்துக்கொள்வோம் (சூழ்நிலைகள் எடுத்துக்காட்டு மதிப்புகள்):

    சூழ்நிலை விநியோகம் உண்டா? GPL-2 கடமை
    மாற்றிய நிரலை உள் சேவையகங்களில் மட்டும் ஓட்டுகிறது இல்லை கடமை தொடங்கவில்லை (பிரிவு 0)
    மாற்றிய binary-ஐ 1,000 வாடிக்கையாளர் சாதனங்களில் அனுப்புகிறது ஆம் மூலம் உடன் (3a) அல்லது ≥3 ஆண்டு வாக்குறுதி (3b); முழுப் படைப்பும் GPL-2 (2b)
    அதே சாதனத்தில், GPL குறியீடு இல்லாத தன் சொந்தத் தனி நிரலையும் வைக்கிறது ஆம் வெறும் சேர்த்து வைத்தல் — அந்தத் தனி நிரல் GPL-க்குள் வராது
    GPL குறியீட்டைத் தன் நிரலுக்குள்ளேயே இணைத்து விநியோகிக்கிறது ஆம் இணைந்த படைப்பு முழுவதும் GPL-2 விதிகளின் கீழ் (2b)

    வாக்குறுதியின் கணக்கு (எடுத்துக்காட்டு மதிப்புகள்): சாதனங்கள் 2026 மார்ச்சில் அனுப்பப்பட்டால், வாக்குறுதி குறைந்தது 2026 + 3 = 2029 மார்ச் வரை செல்லுபடி. ஒரு வாடிக்கையாளர் மூலத்தைக் கேட்டால், அதை வட்டில் எழுதி அனுப்ப உண்மைச் செலவு ₹150 (ஊடகம்) + ₹250 (அஞ்சல்) = ₹400 என்றால், அதிகபட்சக் கட்டணம் ₹400; “₹5,000 license கட்டணம்” என்பது பிரிவு 3(b)-க்கு முரண்.

    பரவலின் கணக்கு: A என்ற GPL நிரலை B மாற்றி விநியோகிக்கிறார்; B-இன் பதிப்பை C மாற்றுகிறார்; C-இன் பதிப்பை D. ஒவ்வொரு படியிலும் 2(b) மீண்டும் பொருந்துவதால், மூன்று படிகளுக்குப் பின்னும் D-இன் பயனருக்கு A-இன் பயனருக்கு இருந்த அதே உரிமைகள் — சுதந்திரம் “கீழ்நோக்கி” நழுவி மூடப்படுவதில்லை. ஆங்கிலப் பதிவு சொல்லும் “copyright turned outward” என்பது இதுதான்.

    Linux இடைவெளியை நிரப்புகிறது#

    1991-இல், பின்லாந்து மாணவர் Linus Torvalds தன் சொந்த PC-க்கான தனிப்பட்ட திட்டமாக ஒரு kernel தொடங்கினார். அந்த ஆண்டு தன் சொந்த கட்டுப்படுத்தும் non-commercial license-இன் கீழ் வெளியிட்டார், பிறகு — முக்கியமாக — 1992 ஆரம்பத்தில் GPL-இன் கீழ் மறுlicense செய்தார். அந்தச் சேர்க்கை காணாமல் போன துண்டு: GNU-க்கு முதிர்ந்த userland இருந்தது, நடைமுறை kernel இல்லை; Linux செயல்படும் kernel, அடிப்படையில் userland இல்லை. சேர்ந்து, Linux kernel மீது GNU utilities முழுமையான, இலவசமாக license செய்யப்பட்ட, Unix-இணக்க அமைப்பை உருவாக்கின — பொதுவாக “Linux” என்று அழைக்கப்படுகிறது, இருப்பினும் “GNU/Linux” சேர்க்கைக்கு வரலாற்றுரீதியாகத் துல்லியமான பெயர் (Stallman-இன் அவ்வப்போதைய பொது விரக்திக்கு).

    காலவரிசை, ஆண்டுக் கணக்குடன்#

    ஆண்டு நிகழ்வு ஆதாரம்
    1983 Stallman GNU திட்டத்தைத் தொடங்குகிறார் ஆங்கிலப் பதிவு
    1985 GNU Manifesto ஆங்கிலப் பதிவு
    1991 (June) GPL பதிப்பு 2 வெளியீடு GPL-2 உரையின் தலைப்பு
    1991 Torvalds kernel-ஐத் தொடங்கி, தன் சொந்த non-commercial license-இல் வெளியிடுகிறார் ஆங்கிலப் பதிவு
    1992 ஆரம்பம் Linux GPL-க்கு மறுlicense ஆங்கிலப் பதிவு
    2007 (29 June) GPL பதிப்பு 3 வெளியீடு GPL-3 உரையின் தலைப்பு

    கணக்கு: GNU தொடக்கம் (1983) முதல் Linux GPL-க்கு வந்தது (1992) வரை 1992 − 1983 = சுமார் 9 ஆண்டுகள் — GNU userland நடைமுறை kernel இல்லாமல் காத்திருந்த இடைவெளி. இன்றைய Linux kernel-இன் COPYING கோப்பு: “GPL-2.0 WITH Linux-syscall-note” — GPL பதிப்பு 2 மட்டும், system call-கள் வழியாக kernel-ஐப் பயன்படுத்தும் நிரல்களுக்கு வெளிப்படையான விதிவிலக்குடன். அதாவது 2007-இல் GPL-3 வந்தபின்னும் kernel GPL-2-இலேயே இருக்கிறது.

    இப்போது முயல்க. கீழே உள்ள VM-ஐ boot செய்து, திரையைக் கிளிக் செய்து, பிறகு uname, whoami, மற்றும் ls முயல்க — உங்கள் உலாவியில் அந்தச் சேர்க்கையின் GNU/Linux பக்கத்தில் இருக்கிறீர்கள்.

    இப்போது முயல்க: kernel எது, userland எது? அதே VM-இல் (எல்லாக் கட்டளைகளும் ஓட்டிச் சரிபார்த்தவை; வெளியீடுகள் எங்கள் ஓட்டத்திலிருந்து):

    1. uname -sr → Linux 4.16.13. இது kernel — Linux.
    2. cat /proc/version → … (gcc version 7.3.0 (Buildroot 2018.08-git-…)) …. அந்த kernel-ஐ compile செய்தது GNU-வின் GCC.
    3. ls -l /bin/ls /bin/sh /bin/cat → மூன்றும் -> busybox என்ற symlink-கள். இங்கே ls GNU coreutils அல்ல!
    4. busybox | head -4 → BusyBox v1.28.4 … multi-call binary. … Licensed under GPLv2.
    5. ls /bin | wc -l → 73; ls -l /bin | grep -c busybox → 73 — /bin-இல் உள்ள ஒவ்வொரு பெயரும் busybox அல்லது அதற்கான link. bash --version → bash: not found.

    முடிவு: இந்த VM-இல் kernel Linux, அதைக் கட்டிய compiler GNU, ஆனால் userland GNU அல்ல — ஒரே BusyBox binary (அதுவும் GPL-2). ஆங்கிலப் பதிவு சொல்வதுபோல் பொதுவான desktop/server அமைப்புகளில் userland GNU கருவிகள் (Bash, coreutils); ஆனால் kernel-உம் userland-உம் தனித்தனியாக மாற்றக்கூடிய அடுக்குகள் என்பதை இந்தச் சிறிய VM காட்டுகிறது — “GNU/Linux” என்ற பெயர் விவாதம் ஏன் எழுகிறது என்பதும் இதுதான்.

    இந்தச் சேர்க்கை ஏன் வென்றது#

    GPL-இன் கட்டமைப்பு நிறுவனங்கள் அடிப்படை தளத்தை அமைதியாக மூடாமல் Linux சுற்றி வணிகத் தயாரிப்புகளைக் கட்ட அனுமதித்தது — kernel மாற்றங்கள் அதே நிபந்தனைகளின் கீழ் மூலமாகக் கிடைக்க வேண்டும். அது நீடித்த நம்பிக்கையையும், இறுதியில் நீடித்த நிறுவன பங்களிப்பையும் கட்டியது: ஒரு போட்டியாளரால் பிடிக்கப்படுவதற்குப் பதிலாகத் தளம் திறந்தே இருக்கும் என்று நிறுவனங்கள் நம்பலாம். இலவசம், வணிகப் பயன்பாட்டிற்குத் திறந்தது, அவ்வாறே இருக்க சட்டரீதியாகக் கட்டமைக்கப்பட்டது — Linux சேவையகங்கள், cloud உள்கட்டமைப்பு, Android, மற்றும் நவீன இணையத்தின் முதுகெலும்பின் பெரும்பகுதிக்குக் கீழே ஆதிக்க kernel ஆனதின் பெரும் பகுதி, ஒரு மாணவரின் தனிப்பட்ட திட்டத்தைத் தாண்டி.

    Door out: The GNU General Public License (Free Software Foundation) — copyleft-ஐ அமல்படுத்திய முதன்மை சட்ட உரை; திட்டத்தின் கூறப்பட்ட இலக்குக்கு Stallman-இன் GNU Manifesto (1985) உடன் படியுங்கள்.
