    Interconnects at Scale

    ஜனவரி 1, 2026

    இந்த phase இதுவரை ஒரு இயந்திரத்திற்குள் பாகங்களை இணைத்தது — CPU-க்கு நினைவகம், CPU-க்கு சாதனங்கள். ஒரு workload பல GPU-களை, அல்லது பல இயந்திரங்களைத் தேவைப்பட்டால், கேள்வி மாறுகிறது: அந்த அலகுகள் ஒன்றையொன்று கூடுதல் தொடர்பு கூடுதல் compute-ஐத் தின்னாத அளவுக்கு வேகமாகப் பேச முடியுமா?

    தமிழ் இடைவெளிக் குறிப்பு: NVLink, CXL, InfiniBand மூன்றுக்கும் தமிழில் எழுத்தும் காணொளியும் கிடைக்கவில்லை (காணொளித் தேடல்: YouTube தேடல் முடிவுகள் மட்டும் — காணொளிகள் பார்க்கப்படவில்லை). ஆங்கிலப் பதிவு InfiniBand-ஐப் பெயரிடவில்லை; இங்கே அது GPUDirect RDMA பாதையின் network பகுதியாக மட்டும், NVIDIA ஆவணம் சொல்லும் அளவுக்கு வருகிறது. சரிபார்த்த மூலங்கள்: NVIDIA nccl-tests PERFORMANCE.md (all-reduce நேரச் சூத்திரம்), NVIDIA-வின் NVLink / NVLink Switch பக்கம் (தலைமுறை வாரியான bandwidth அட்டவணை), NVIDIA CUDA “GPUDirect RDMA” ஆவணம், Compute Express Link Consortium-இன் “About CXL” பக்கம்; PCIe Gen 5 x16 ≈ 64 GB/s ஆங்கிலப் பதிவு 33-இலிருந்து. Model அளவு, நினைவகத் தேவைகள் போன்றவை “எடுத்துக்காட்டு மதிப்புகள்”. இந்தப் பதிவுக்கு lab இல்லை; காகிதப் பயிற்சிகள் கீழே.

    முதலில் சொற்கள்#

    • Interconnect (இணைப்பு வலை): சிப்கள், GPU-கள், இயந்திரங்களுக்கு இடையே தரவு நகரும் கம்பி / இணைப்பு அமைப்பு.
    • Peer-to-peer, P2P (சமநிலை இணைப்பு): CPU / system memory வழியாகச் செல்லாமல் இரு சாதனங்கள் நேரடியாகத் தரவு பரிமாறுவது.
    • DMA (நேரடி நினைவக அணுகல்): CPU ஒவ்வொரு byte-ஐயும் நகர்த்தாமல், சாதனமே நினைவகத்தில் படித்து எழுதுவது.
    • NVLink / NVSwitch: NVIDIA-வின் GPU-to-GPU இணைப்பு / பல NVLink-களை இணைத்து எல்லா GPU-க்கும் எல்லா GPU-வையும் அடையச் செய்யும் switch சிப்.
    • Cache-coherent (cache ஒத்திசைவுள்ள): ஒரு முகவரியின் எல்லா cache நகல்களும் ஒரே மதிப்பைக் காட்டும்படி வன்பொருளே பார்த்துக்கொள்வது.
    • CXL (Compute Express Link): processor, நினைவக விரிவாக்கம், accelerator-களுக்கான cache-coherent திறந்த இணைப்புத் தரநிலை.
    • RDMA / GPUDirect RDMA: தொலை இயந்திரத்தின் நினைவகத்தில் CPU தலையீடின்றி நேரடியாக எழுதுதல் / NIC GPU நினைவகத்தையே நேரடியாக அணுகுதல்.
    • InfiniBand / HCA: உயர்-வேக, குறைந்த-latency datacenter network / அதற்கான network அட்டை (Host Channel Adapter).

    இயல்புநிலை பாதை வரி#

    Peer பாதை இல்லாமல், GPU A system memory வழியாக எழுதுகிறது மற்றும் GPU B அதை மீண்டும் படிக்கிறது — கூடுதல் hops, கூடுதல் latency, நகல்களில் செலவழிக்கப்பட்ட PCIe bandwidth. PCIe மட்டும் இருந்தாலும், GPUDirect P2P host staging இல்லாமல் GPU↔GPU DMA செய்ய முடியும் (இன்னும் PCIe வீதங்களில்). மீதமுள்ள கட்டுப்பாடு bandwidth மற்றும் topology: பகிரப்பட்ட விரிவாக்க fabric பல-GPU mesh-ஆக ஒருபோதும் வடிவமைக்கப்படவில்லை.

    “வரி"யை எண்ணுதல் — நகல்கள் எத்தனை?#

    ஒரு GPU-விலிருந்து இன்னொரு இயந்திரத்தின் GPU-க்கு 1 GB அனுப்புவதாக வைப்போம் (எடுத்துக்காட்டு மதிப்பு; எளிய மாதிரி — ஒவ்வொரு படியும் ஒரு முழு நகல்):

    பாதை படிகள் system memory வழியாகச் செல்லும் தரவு
    Host வழியாக (staged) GPU → system memory → NIC → … → NIC → தொலை system memory → தொலை GPU அனுப்புபக்கம்: எழுது 1 GB + படி 1 GB; பெறுபக்கம்: எழுது 1 GB + படி 1 GB = 4 GB
    GPUDirect RDMA GPU → NIC → … → NIC → தொலை GPU 0 GB

    ஒவ்வொரு GB-க்கும் இரு பக்க system memory-யிலும் மொத்தம் 4 GB போக்குவரத்து — மற்ற வேலைகளுக்கான நினைவக bandwidth-இலிருந்து பறிக்கப்படுகிறது, CPU நகல்களை மேற்பார்வையிடுகிறது.

    PCIe மட்டும் இருந்தாலும். NVIDIA-வின் GPUDirect RDMA ஆவணம்: இது Kepler-வகை GPU-களிலும் CUDA 5.0-இலும் அறிமுகமானது; “standard features of PCI Express” மட்டுமே பயன்படுத்துகிறது; ஆனால் இரு சாதனங்களும் ஒரே upstream PCIe root complex-ஐப் பகிர வேண்டும். பாதையில் PCIe switch-கள் மட்டும் இருந்தால் சிறந்த செயல்திறன்; ஒரு CPU/IOH இருந்தால் வேலை செய்யும் ஆனால் மெதுவாக; இரண்டு CPU-களுக்கு இடையேயான QPI/HT இணைப்பைக் கடந்தால் “extremely performance-limited or even not work reliably”. அதாவது topology-யே கட்டுப்பாடு — பதிவு சொல்வது போல.

    அர்ப்பணிக்கப்பட்ட இணைப்புகள், Coherent நினைவகம், குறைந்த நகல்கள்#

    NVIDIA-இன் NVLink நோக்கத்திற்காகக் கட்டப்பட்ட GPU-to-GPU interconnect — பரிமாற்றத்திலிருந்து CPU மற்றும் system memory வெளியே. ஒரு NVSwitch ஒரு node-இல் ஒவ்வொரு GPU-ஐயும் மற்ற ஒவ்வொன்றிலிருந்தும் அடையக்கூடியதாக்கலாம், PCIe-மற்றும்-CPU பாதையை விட மிக அதிக bandwidth-இல். அடிக்கடி, பெரிய பரிமாற்றங்கள் — பெரிய அளவிலான training Phases 7 மற்றும் 10-இல் திரும்பும் முறை — அந்த நேரடிப் பாதை முதல்-வரிசை, சிறு சரிசெய்தல் அல்ல.

    NVLink, எண்களில்#

    NVIDIA-வின் NVLink பக்க அட்டவணை (GPU ஒன்றுக்கு NVLink bandwidth):

    தலைமுறை GPU ஒன்றுக்கு Architecture Switch domain மொத்தம் (எங்கள் சரிபார்ப்பு)
    4 900 GB/s Hopper 8 GPU 8 × 900 = 7,200 GB/s = 7.2 TB/s (அட்டவணை: 7.2 TB/s)
    5 1,800 GB/s Blackwell 72 GPU (NVL72) 72 × 1,800 = 129,600 GB/s ≈ 130 TB/s (அட்டவணை: 130 TB/s)
    6 3,000 GB/s Vera Rubin 72 GPU (NVL72) 72 × 3,000 = 216 TB/s (அட்டவணை: 216 TB/s)

    அதே பக்கம் 6-ஆம் தலைமுறையை “3 TB/s bidirectional” என்றும் “PCIe Gen6-இன் 12 மடங்கு” என்றும் சொல்கிறது: 3,000 ÷ 12 = 250 GB/s — ஒரு PCIe Gen6 x16 இணைப்பின் இருதிசை மொத்தத்துக்கு அருகில்.

    PCIe-உடன் ஒப்பீடு. 4-ஆம் தலைமுறையின் 900 GB/s இருதிசை மொத்தம் என்று எடுத்தால், ஒரு திசைக்கு 450 GB/s (பாதி — எங்கள் கணிப்பு). ஆங்கிலப் பதிவு 33-இன்படி PCIe Gen 5 x16 ஒரு திசைக்கு ≈ 64 GB/s. 450 ÷ 64 ≈ 7 மடங்கு.

    ஏன் switch? ஒவ்வொரு GPU-வையும் மற்ற ஒவ்வொன்றுடனும் நேரடிக் கம்பியால் இணைத்தால் n(n − 1)/2 இணைப்புகள்:

    GPU-கள் n நேரடி இணைப்புகள் n(n − 1)/2
    8 8 × 7 ÷ 2 = 28
    72 72 × 71 ÷ 2 = 2,556

    Switch இருந்தால் ஒவ்வொரு GPU-வும் தன் link-களை switch-களுக்கு மட்டும் இணைக்கிறது; எந்த ஜோடியும் முழு வேகத்தில் பேசலாம் — NVIDIA அதை “all-to-all”, “non-blocking” என்கிறது.

    Training-இல் அதன் பொருள் (எடுத்துக்காட்டு மதிப்புகள்). 8 GPU-கள், bf16 gradients S = 14 GB (7 B parameters × 2 bytes), NVIDIA nccl-tests ஆவணத்தின் (PERFORMANCE.md) all-reduce சூத்திரம் t = (S ÷ B) × 2(n − 1)/n, 2 × 7/8 = 1.75:

    இணைப்பு (ஒரு திசைக்கு B) t
    NVLink 4, 450 GB/s 14 ÷ 450 × 1.75 ≈ 0.054 s
    PCIe Gen 5 x16, 64 GB/s 14 ÷ 64 × 1.75 ≈ 0.383 s

    ஒவ்வொரு training படியிலும் இந்த வேறுபாடு — அதனால்தான் பதிவு நேரடிப் பாதையை “முதல்-வரிசை” என்கிறது.

    CXL (Compute Express Link) அண்டை கட்டுப்பாட்டிற்குப் பதிலளிக்கிறது: ஒரு die-க்கு அப்பால் cache-coherent அணுகல், மற்றும், மேலும் வெளியே, ஒரு socket-க்கு soldering செய்யப்படாத pooled நினைவகம். கொள்ளளவு compute nodes இடையே நகரலாம் எந்த DIMM slot-இல் இறங்கியதோ அதற்கு உறைந்திருக்காமல் — DDR (பதிவு 34) அல்லது மூல PCIe கொடுக்காத நெகிழ்வுத்தன்மை.

    CXL — ஒத்திசைவும், பகிரப்பட்ட நினைவகமும்#

    CXL Consortium-இன் விளக்கம்: CXL என்பது processor-கள், நினைவக விரிவாக்கம், accelerator-களுக்கான “cache-coherent interconnect”; CPU நினைவக இடத்துக்கும் இணைக்கப்பட்ட சாதனங்களின் நினைவகத்துக்கும் இடையே coherency-ஐப் பராமரிக்கிறது. CXL 4.0 bandwidth-ஐ 64 GT/s-இலிருந்து 128 GT/s-க்கு இருமடங்காக்குகிறது; CXL 3.x, 2.0, 1.1, 1.0-உடன் பின்னோக்கு இணக்கம்.

    Pooling ஏன் உதவுகிறது (எடுத்துக்காட்டு மதிப்புகள்). நான்கு server-கள்; ஒவ்வொன்றின் உச்ச நினைவகத் தேவை 512 GB, ஆனால் உச்சங்கள் வெவ்வேறு நேரங்களில்:

    நேரம் S1 S2 S3 S4 மொத்தம்
    காலை 512 128 128 256 1,024
    மதியம் 128 512 256 128 1,024
    மாலை 256 128 512 128 1,024
    இரவு 128 256 128 512 1,024

    ஒவ்வொரு socket-இலும் நினைவகம் பற்றவைக்கப்பட்டால், ஒவ்வொருவரின் உச்சத்துக்கும் 512 × 4 = 2,048 GB வாங்க வேண்டும். ஒரு பொதுக் குளத்திலிருந்து பகிர்ந்தால், எந்த நேரத்திலும் மொத்தத் தேவை 1,024 GB — பாதி போதும் (latency, தோல்வி-பகுதி வடிவமைப்பைப் புறக்கணித்த எளிய கணக்கு).

    GPUDirect RDMA ஒரு NIC-ஐ GPU நினைவகத்தை நேரடியாகப் படிக்க அல்லது எழுத அனுமதிக்கிறது. அது இல்லாமல், network குறுக்கே GPU-to-GPU பரிமாற்றம் GPU → system memory → NIC → தொலை system memory → தொலை GPU — latency மற்றும் நினைவக bandwidth செலவாகும் நகல்கள். அதை GPU → network → GPU ஆகச் சுருக்குங்கள், RDMA (பதிவு 42) storage மற்றும் messaging-இல் வெல்வதற்கான அதே காரணத்திற்கு: குறைந்த நகல்கள், நகர்வை babysit செய்யும் குறைந்த CPU.

    GPUDirect RDMA, InfiniBand, மற்றும் BAR சாளரம்#

    NVIDIA ஆவணப்படி, nvidia-peermem kernel module NVIDIA InfiniBand HCA-களுக்கு GPU நினைவகத்தில் நேரடி peer-to-peer படிக்கும் / எழுதும் அணுகலைத் தருகிறது — host நினைவகத்துக்கு நகலெடுக்காமல்; இது InfiniBand, RoCE (RDMA over Converged Ethernet) இரண்டுடனும் வேலை செய்கிறது. பதிவு 42-இன் RDMA இங்கே GPU நினைவகம் வரை நீள்கிறது.

    NIC GPU நினைவகத்தை PCIe BAR எனும் முகவரிச் சாளரம் வழியாகப் பார்க்கிறது. அதே ஆவணம் ஒரு உதாரணம் தருகிறது: Kepler-வகை GPU-களில் மிகச் சிறிய BAR 256 MB, அதில் 32 MB உள் பயன்பாட்டுக்கு ஒதுக்கப்பட்டது; GPU BAR 64 KB பக்கங்களாக map செய்யப்படுகிறது.

    • பயன்படுத்தக்கூடியது: 256 − 32 = 224 MB
    • 64 KB பக்கங்களில்: 224 × 1,024 ÷ 64 = 3,584 பக்கங்கள் ஒரே நேரத்தில் pin செய்யக்கூடியவை.

    அதனால்தான் ஆவணம் “lazy unpinning”, “registration cache” பரிந்துரைக்கிறது: pinning “milliseconds வரை” எடுக்கும் விலையுயர்ந்த செயல், சாளரமும் சிறியது.

    அதே பிரச்சனை, திறந்த வன்பொருள்#

    இது தொடர் சுட்டிக்காட்டும் தனிப்பயன் GPU நினைவக fabric கீழ் உள்ள கருத்து அடித்தளம்: பொது நோக்க CPU பாதையில் இல்லாமல் தொலை GPU நினைவகத்தை முகவரியிடக்கூடியதாக்குங்கள். NVLink மற்றும் GPUDirect அதை ஒரு vendor-இன் stack-க்குள் தீர்க்கின்றன. ஒரு திறந்த, PCIe-அடிப்படையிலான மாற்று அதே திறமையின்மையை அகற்ற வேண்டும் — அதனால்தான் பதிவுகள் 32–33-இன் TLP-நிலை peer பாதையும், இந்தப் பதிவின் “அர்ப்பணிக்கப்பட்ட இணைப்பு ஏன் உள்ளது” என்பதும் அதே கதை.

    காகிதப் பயிற்சிகள் (விடைகளுடன்)#

    1. 16 GPU-களை நேரடிக் கம்பிகளால் முழுமையாக இணைக்க எத்தனை இணைப்புகள்? விடை: 16 × 15 ÷ 2 = 120.

    2. NVLink 5-ஆம் தலைமுறை, 8-GPU domain. மொத்த bandwidth (அட்டவணை முறையில்)? விடை: 8 × 1,800 = 14,400 GB/s = 14.4 TB/s.

    3. 16 GPU-கள், S = 2 GB (எடுத்துக்காட்டு மதிப்புகள்). ஒரு திசைக்கு 450 GB/s எதிர் 64 GB/s இணைப்பில் all-reduce நேரங்கள்? விடை: 2(16 − 1)/16 = 1.875. 2 ÷ 450 × 1.875 ≈ 8.3 ms; 2 ÷ 64 × 1.875 ≈ 58.6 ms.

    4. Host வழிப் பாதையில் 5 GB (எடுத்துக்காட்டு மதிப்பு) அனுப்பினால் இரு பக்க system memory-யிலும் மொத்தம் எவ்வளவு போக்குவரத்து (மேலே உள்ள எளிய மாதிரி)? விடை: 4 × 5 = 20 GB; GPUDirect RDMA-வில் 0.

    5. BAR 16 GB, அதில் 32 MB ஒதுக்கப்பட்டது (எடுத்துக்காட்டு மதிப்புகள்). 64 KB பக்கங்களில் எத்தனை? விடை: 16 GB = 16,384 MB; 16,384 − 32 = 16,352 MB; 16,352 × 1,024 ÷ 64 = 261,632 பக்கங்கள்.

    6. மூன்று server-கள், உச்சம் தலா 400 GB, ஆனால் ஒரே நேரத்தில் மொத்தத் தேவை அதிகபட்சம் 700 GB (எடுத்துக்காட்டு மதிப்புகள்). தனித்தனியாக எதிர் pool? விடை: 3 × 400 = 1,200 GB எதிர் 700 GB; 500 GB சேமிப்பு.
