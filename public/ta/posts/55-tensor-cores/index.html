    Tensor Cores

    ஜனவரி 1, 2026

    பதிவு 53 CUDA cores-ஐ உள்ளடக்கியது — பரந்த வரம்பு parallel வேலைக்குப் பொது-நோக்கு SIMT lanes. Tensor cores குறுகியவை: ஒரு செயல்பாட்டிற்கான அர்ப்பணிக்கப்பட்ட வன்பொருள் — matrix multiply-accumulate — நவீன neural-network compute-ஐ ஆதிக்கம் செலுத்துவது. அந்த op-க்குச் சிறப்புப்படுத்துங்கள், பொது CUDA cores மட்டும் அதே வேலையைச் செய்வதை விட வெல்லுங்கள்.

    தமிழ் இடைவெளிக் குறிப்பு: Tensor core பற்றித் தமிழில் எழுத்து விளக்கமோ காணொளியோ இல்லை. இங்கே ஒரு 4 × 4 matrix பெருக்கல்-கூட்டலைக் கையால் செய்து, NVIDIA Tesla V100-இன் tensor core எண்களை (Volta whitepaper-இலிருந்து சரிபார்த்தவை) வைத்து அதன் வேகத்தைக் கணக்கிடுகிறோம். எடுத்துக்காட்டு மதிப்புகள் அப்படியே குறிக்கப்பட்டுள்ளன.

    முதலில் சொற்கள்#

    • Matrix (அணி): எண்களின் செவ்வக அட்டவணை. 4 × 4 matrix = 4 வரிசைகள், 4 நெடுவரிசைகள்.
    • Matrix பெருக்கல்: A (M × K) மற்றும் B (K × N) → C (M × N); C-இன் ஒவ்வொரு உறுப்பும் A-இன் ஒரு வரிசைக்கும் B-இன் ஒரு நெடுவரிசைக்கும் இடையிலான dot product (ஒத்த உறுப்புகளைப் பெருக்கிக் கூட்டுவது).
    • MAC / FMA (பெருக்கல்-கூட்டல்): a × b + c என்ற ஒரு செயல். Matrix பெருக்கலின் அடிப்படை அலகு.
    • Accumulator (திரட்டி): பகுதிக் கூட்டுத்தொகைகளைச் சேர்த்து வைத்திருக்கும் இடம்/எண்.
    • Precision (துல்லியம்): ஒரு எண்ணைச் சேமிக்க எத்தனை பிட்கள் — FP32 = 32 பிட், FP16 = 16 பிட். குறைந்த பிட் = குறைந்த துல்லியம், ஆனால் சிறிய, மலிவான வன்பொருள்.
    • Tile (துண்டு): ஒரு பெரிய matrix-இன் சிறிய சதுரப் பகுதி.

    ஏன் Matrix Multiply#

    Fully connected layers, convolutions (matmul-ஆக மறுவடிவமைக்கப்பட்டவை), மற்றும் transformers-இல் attention அனைத்தும், அவற்றின் மையத்தில், matrices-இன் multiply-accumulate-க்குக் குறைகின்றன — அதன் திறன் அமைப்பு செயல்திறனை ஆதிக்கம் செய்யும் அளவில். அந்த செறிவு நோக்கத்துடன் கட்டப்பட்ட சிலிகானை மதிப்புள்ளதாக்குகிறது.

    ஒரு Tensor Core என்ன செய்கிறது#

    ஒரு tensor core சிறிய நிலையான-அளவு matrix multiply-accumulate-ஐ — எடுத்துக்காட்டாக இரு 4×4 matrices-ஐ மூன்றாவதாக — பொது CUDA cores வழியாகத் தனி multiply மற்றும் add அறிவுறுத்தல்களின் நீண்ட வரிசைக்குப் பதிலாக ஒரு வன்பொருள் செயல்பாடாக இணைக்கிறது. Fusion பயனுள்ள arithmetic-க்கு ஒப்பீட்டில் per-op overhead (fetch, decode, operand routing) வெட்டும். பெரிய products tiled: துணை-தொகுதிகளை வரிசையாக உணவளித்து, partials குவிக்க — திறமையான deep-learning kernels-ஐத் தன் சொந்த கலையாக்கும் ஒருங்கிணைப்பு வேலை.

    Precision சிலிகானுடன் இணைக்கப்பட்டுள்ளது#

    Tensor cores அடிக்கடி குறைந்த precisions-இல் (FP16, BF16, INT8, அதிகரித்து FP8) மிகத் திறமையாக ஓடும். குறுகிய arithmetic ஒரு op-க்குக் குறைந்த பரப்பு மற்றும் ஆற்றல் தேவை, எனவே கொடுக்கப்பட்ட பட்ஜெட் அதிக MAC throughput அடுக்கும். பதிவு 59 இதை முழுமையாகத் திரும்பும்: precision குறைப்பு தூய மென்பொருள் தேர்வு அல்ல — ஒவ்வொரு வடிவத்திலும் அடிப்படை MAC வன்பொருள் எவ்வளவு திறமையாக ஓடுகிறது என்பதோடு இணைக்கப்பட்டுள்ளது.

    ஒரே பதில் அல்ல#

    Tensor cores இல்லையெனில் பொதுவான GPU-க்குள் NVIDIA-வின் பதில். Phase 10 systolic arrays-ஐ உள்ளடக்கும் — Google-இன் TPU மிகத் தெளிவானது — அதே matmul இலக்கிற்காகக் கட்டப்பட்டவை, வன்பொருள் மட்டத்தில் வேறுபட்ட அமைப்பு. அதே கட்டுப்பாடு; வேறு கட்டமைப்பு.

    V100 tensor core: whitepaper என்ன சொல்கிறது#

    Volta whitepaper-இன்படி ஒவ்வொரு tensor core-உம் 4 × 4 matrix-களின் மேல் இந்த ஒரு செயலைச் செய்கிறது:

    D = A × B + C

    A, B ஆகியவை FP16 matrix-கள்; C, D ஆகியவை FP16 அல்லது FP32. FP16 பெருக்கலின் முழுத் துல்லிய விளைவு FP32 கூட்டலால் திரட்டப்படுகிறது. ஒரு 4 × 4 × 4 பெருக்கலுக்கு 4 × 4 × 4 = 64 FMA-கள் — ஒவ்வொரு tensor core-உம் ஒரு clock-க்கு அவ்வளவு. V100-இன் ஒவ்வொரு SM-இலும் 8 tensor core-கள், மொத்தம் 640.

    கையால் ஒரு உறுப்பு#

    D-இன் ஒவ்வொரு உறுப்பும் 4 பெருக்கல்கள் + 4 கூட்டல்கள் (C-இன் உறுப்பையும் சேர்த்து). எடுத்துக்காட்டு மதிப்புகள்: A-இன் வரிசை 0 = [1, 2, 0, −1], B-இன் நெடுவரிசை 0 = [3, 1, 4, 2], C[0][0] = 0.5.

    1. 1 × 3 = 3
    2. 2 × 1 = 2
    3. 0 × 4 = 0
    4. (−1) × 2 = −2
    5. கூட்டுத்தொகை = 3 + 2 + 0 − 2 = 3
    6. D[0][0] = 3 + 0.5 = 3.5

    இதே வேலை 16 உறுப்புகளுக்கும் = 16 × 4 = 64 பெருக்கல்கள். Tensor core இந்த 64-ஐயும் ஒரே வன்பொருள் செயலாக, ஒரு clock-இல் செய்கிறது.

    CUDA core-களில் செய்தால் என்ன வேறுபாடு?#

    அதே 64 FMA-களை பதிவு 53-இன் FP32 CUDA core-களில் செய்ய, ஒவ்வொரு FMA-வும் ஒரு thread-இன் ஒரு அறிவுறுத்தல். 64 FMA = இரண்டு முழு warp அறிவுறுத்தல்கள் — மேலும் ஒவ்வொரு operand-ஐயும் register-களுக்கு இடையே நகர்த்தும் கூடுதல் அறிவுறுத்தல்கள். ஒவ்வொரு அறிவுறுத்தலுக்கும் fetch, decode, register file படிப்பு/எழுத்து. Tensor core-இல் ஒரு அறிவுறுத்தல் பல டஜன் FMA-களைத் தூண்டுகிறது; operand-கள் அலகுக்குள்ளேயே பல பெருக்கிகளுக்குப் பகிரப்படுகின்றன (A-இன் ஒவ்வொரு உறுப்பும் 4 முறை, B-இன் ஒவ்வொன்றும் 4 முறை பயன்படுகிறது).

    ஒரு SM, ஒரு clock:

    • FP32 CUDA core-கள்: 64 core × 1 FMA = 64 FMA
    • Tensor core-கள்: 8 × 64 = 512 FMA
    • விகிதம்: 8 மடங்கு

    முழு GPU உச்சம்:

    1. 640 tensor core × 64 FMA × 2 FLOP × 1.53 × 10⁹ Hz ≈ 125.3 × 10¹² → 125 TFLOPS (whitepaper சொல்லும் “125 Tensor TFLOPS”)
    2. FP32 CUDA core-களின் 15.7 TFLOPS-உடன் ஒப்பிட: 125 ÷ 15.7 ≈ 8 மடங்கு — மேலே உள்ள SM கணக்குடன் பொருந்துகிறது.

    பெரிய matrix-கள்: tiling#

    64 × 64 matrix-களைப் பெருக்குவோம் (M = N = K = 64):

    1. மொத்த FMA = 64 × 64 × 64 = 262,144
    2. 4 × 4 × 4 tensor-core செயல்கள் = 262,144 ÷ 64 = 4,096
    3. ஒரு SM-இன் 8 tensor core-களில், இலட்சியமாக: 4,096 ÷ 8 = 512 clock-கள் → 1.53 GHz-இல் சுமார் 0.33 µs
    4. ஒவ்வொரு 4 × 4 வெளியீட்டுத் துண்டும் K திசையில் 64 ÷ 4 = 16 படிகள் திரட்டப்படுகிறது: D₁ = A₁B₁ + C, D₂ = A₂B₂ + D₁, … — முந்தைய D அடுத்த படியின் C ஆகிறது.

    தரவு பக்கம்: A, B ஒவ்வொன்றும் 64 × 64 × 2 byte (FP16) = 8 KB → மொத்தம் 16 KB. கணக்கு 2 × 262,144 = 524,288 FLOP. 524,288 ÷ 16,384 = 32 FLOP/byte shared memory-இலிருந்து. 512 clock-களில் அந்த 16 KB தயாராக இருக்க வேண்டும் — அதனால்தான் பதிவு 54-இன் tiling மற்றும் bandwidth கணக்கு tensor core-க்கு இன்னும் கடுமையாகிறது: கணக்கு 8 மடங்கு வேகமானால், தரவும் 8 மடங்கு வேகமாக வர வேண்டும்.

    ஏன் FP32-இல் திரட்ட வேண்டும்: ஒரு சோதனை#

    FP16-இல் 1 sign பிட், 5 exponent பிட், 10 fraction பிட். 2048 = 2¹¹ அருகில், அடுத்தடுத்த FP16 எண்களுக்கு இடையிலான இடைவெளி 2^(11 − 10) = 2. அதனால் 2048 + 1 = 2049 என்பதை FP16-இல் எழுதவே முடியாது; அது 2048-க்கு round ஆகிறது.

    சோதனை: 1-ஐ 4,096 முறை கூட்டுவோம்.

    • FP16 திரட்டி: 2048 வரை சரியாக ஏறுகிறது; பிறகு ஒவ்வொரு “+1”-உம் 2048-க்கே திரும்புகிறது. இறுதி விடை 2048 — பாதி வேலை காணாமல் போனது.
    • FP32 திரட்டி (FP16 உள்ளீடுகளுடன்): இறுதி விடை 4096.

    (இந்த இரண்டு முடிவுகளையும் numpy float16/float32 கொண்டு ஓட்டிச் சரிபார்த்தோம்.) நீண்ட dot product-களில் — ஆயிரக்கணக்கான பெருக்கல்களின் கூட்டு — இதுவே நடக்கும். அதனால்தான் “குறைந்த துல்லியத்தில் பெருக்கு, அதிக துல்லியத்தில் திரட்டு” என்ற mixed-precision வடிவமைப்பு: பெருக்கிகள் சிறியவை (FP16), திரட்டி அகலமானது (FP32). பதிவு 59 இதை விரிவாகப் பார்க்கிறது.

    காகிதப் பயிற்சிகள் (விடைகளுடன்)#

    (பயிற்சிகளில் புதிதாக வரும் உள்ளீட்டு எண்கள், மூலத்துடன் குறிக்கப்பட்டவை தவிர, எடுத்துக்காட்டு மதிப்புகள்.)

    1. A-இன் வரிசை = [2, −1, 3, 0], B-இன் நெடுவரிசை = [1, 4, 2, 5], C = −1. D உறுப்பு? விடை: 2 − 4 + 6 + 0 = 4; 4 + (−1) = 3.
    2. 128 × 128 × 128 matmul-க்கு எத்தனை 4 × 4 × 4 tensor-core செயல்கள்? 640 tensor core-களிலும் இலட்சியமாகப் பகிர்ந்தால் எத்தனை clock? விடை: 128³ = 2,097,152 FMA ÷ 64 = 32,768 செயல்கள்; ÷ 640 = 51.2 → சுமார் 52 clock-கள் (நடைமுறையில் தரவு நகர்வு இதைவிடப் பல மடங்கு நேரம் எடுக்கும்).
    3. FP16-இல் 4096 = 2¹² அருகில் இடைவெளி என்ன? 4096 + 3 என்ன ஆகும்? விடை: 2^(12 − 10) = 4. 4099 என்பது 4096-க்கும் 4100-க்கும் இடையே, 4100-க்கு அருகில் → 4100.
