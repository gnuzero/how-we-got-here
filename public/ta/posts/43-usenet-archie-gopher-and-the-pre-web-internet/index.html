    Usenet, Archie, Gopher மற்றும் Pre-Web இணையம்

    ஜனவரி 1, 2026

    TCP/IP (பதிவு 41) இணையத்திற்கு உலகளாவிய முகவரி மற்றும் transport அடித்தளம் கொடுத்தது. அதன் மீது ஓடியது, World Wide Web ஆதிக்க இடைமுகமாக மாறுவதற்கு முன் ஏறக்குறைய இரண்டு பத்தாண்டுகளுக்கு, இரண்டு முகங்களுடன் ஒரு வளைவு: ஏதோ ஒன்றை கண்டுபிடி, பிறகு யாரோ ஒருவரிடம் பேசு. விநியோகிக்கப்பட்ட விவாதம், ஆரம்ப தேடல், மெனு-இயக்க உலாவல், real-time அரட்டை, மற்றும் இறுதியில் consumer portals ஒவ்வொன்றும் அந்த வளைவின் ஒரு துண்டை அந்த நேரத்தில் கிடைத்த தொழில்நுட்பத்தால் தீர்த்தன.

    தமிழ் இடைவெளிக் குறிப்பு: Usenet பற்றித் தமிழ் எழுத்து விளக்கம் கிடைக்கவில்லை; Archie, Gopher இரண்டுக்கும் தமிழில் எழுத்தும் காணொளியும் இல்லை; காணொளிச் சான்று YouTube தேடல் முடிவுகள் மட்டும் — காணொளிகள் பார்க்கப்படவில்லை. இங்குள்ள நெறிமுறை விவரங்கள் மூல RFC உரைகளிலிருந்து நேரடியாகச் சரிபார்க்கப்பட்டவை: Gopher — RFC 1436 (March 1993), NNTP — RFC 977 (February 1986), IRC — RFC 1459 (May 1993). Server எண்ணிக்கைகள், கோப்பு எண்ணிக்கைகள் “எடுத்துக்காட்டு மதிப்புகள்”. VM-இல் உள்ள சிறிய Gopher server பயிற்சி உண்மையில் ஓட்டிச் சரிபார்த்தது.

    முதலில் சொற்கள்#

    • Newsgroup (செய்திக் குழு): Usenet-இல் ஒரு தலைப்புக்கான விவாத இடம் — comp.lang.c போல புள்ளிகளால் பிரிந்த படிநிலைப் பெயர்.
    • NNTP (Network News Transfer Protocol): TCP/IP மீது Usenet செய்திகளை server-களுக்கிடையே பரிமாறும் நெறிமுறை.
    • Message-ID (செய்தி அடையாளம்): ஒவ்வொரு Usenet செய்திக்கும் உலகளவில் தனித்த அடையாளம் — <4105@ucbvax.ARPA> போல; மறுநகல்களைத் தவிர்க்க உதவுகிறது.
    • அட்டவணை (index): பல இடங்களில் உள்ளவற்றின் பெயர்களை ஒரே இடத்தில் தேடக்கூடியதாகச் சேகரித்த பட்டியல்.
    • Selector (தேர்வுச் சரம்): Gopher client server-க்கு அனுப்பும் ஒரு வரி உரை — “இதைக் கொடு” என்பதன் பெயர்.
    • மெனு (menu): எண்ணிட்ட அல்லது வகையிட்ட தேர்வுகளின் பட்டியல்; Gopher-இன் முதன்மை வழிசெலுத்தல்.
    • Channel / nickname (அலைவரிசை / புனைபெயர்): IRC-இல் பேச்சு அறை (# முதலில்) / பயனரின் பெயர்.
    • Federated (கூட்டமைப்பு): ஒரே நிறுவனம் அல்லாமல், பலரால் நடத்தப்படும் server-கள் இணைந்து ஒரு சேவையாக இயங்குவது.

    Usenet: விநியோகிக்கப்பட்ட விவாதம், மைய Server இல்லை#

    Usenet (Duke-இல் Tom Truscott மற்றும் Jim Ellis, 1979-இல் கருத்தரிக்கப்பட்டது, 1980-இல் பொது) நவீன web-ஐ ஒரு பத்தாண்டுக்கு மேல் முந்தியது. அனைத்து விவாதத்தையும் மைய server host செய்யாது. பங்கேற்கும் servers செய்திகளை store-and-forward பரிமாறும் — முதலில் UUCP dial-up மீது, பின்னர் NNTP (1986) வழியாக TCP/IP மீது — எனவே ஒரு server தன் peers-இலிருந்து posts ஏற்று, சேமித்து, முன்னனுப்பும். ஒரு post ஒற்றை மைய கட்டுப்பாட்டுப் புள்ளி இல்லாமல் பரவுகிறது.

    Hierarchical newsgroups (comp.lang.c, rec.arts.movies, …) மைய moderator மரம் திணிக்காமல் விவாதம் தலைப்பால் தானே ஒழுங்கமைக்க அனுமதிக்கின்றன. அந்த வடிவமைப்பு அதை மாற்றிய பெரும்பாலானவற்றின் வேறு தத்துவம் — பதிவு 44 உள்ளடக்கும் distributed-systems கருத்துகளுக்கு ஆவியில் நெருக்கமானது, தரவுச் செயலாக்கத்திற்குப் பதிலாக மனிதப் பேச்சுக்குப் பயன்படுத்தப்பட்டது.

    ஒரு செய்தி எப்படிப் பரவுகிறது: IHAVE கணக்கு#

    RFC 977 (NNTP) வரையறுக்கும் IHAVE <messageid> கட்டளை: ஒரு server தன் அண்டை server-இடம் “இந்த Message-ID கொண்ட செய்தி என்னிடம் உண்டு” என்று சொல்கிறது. பதில்கள்: 335 — அனுப்பு; 435 — வேண்டாம் (ஏற்கனவே உண்டு); அனுப்பிய பின் 235 — பெற்றோம். RFC-இன் சொந்த எடுத்துக்காட்டு உரையாடல்:

    C:  IHAVE <4105@ucbvax.ARPA>
S:  435 Already seen that one, where you been?
C:  IHAVE <4106@ucbvax.ARPA>
S:  335 News to me!  <CRLF.CRLF> to end.

    கணக்கு (எடுத்துக்காட்டு மதிப்புகள்): A, B, C, D என்ற நான்கு server-கள், ஒவ்வொன்றும் மற்ற மூன்றுடனும் இணைந்தவை. A-இல் ஒரு புதிய செய்தி இடப்படுகிறது; ஒவ்வொரு server-உம் புதிதாகப் பெற்றதைத் தான் பெற்ற இடம் தவிர மற்ற அண்டைகளுக்கு முன்மொழிகிறது; A-இன் மூன்று அனுப்புதல்களும் முதலில் முடிகின்றன என்று வைத்துக்கொள்வோம்.

    படி IHAVE முன்மொழிவுகள் பதில் செய்தி உடல் அனுப்பப்பட்டது
    A → B, C, D 3 335 ×3 3 முறை
    B → C, D; C → B, D; D → B, C 6 435 ×6 0
    மொத்தம் 9 3

    9 முன்மொழிவுகள் ஆனால் செய்தியின் உடல் 3 முறை மட்டுமே — ஒவ்வொரு server-க்கும் சரியாக ஒருமுறை. மையக் கட்டுப்பாடு இல்லாமல் மறுநகலைத் தடுப்பது Message-ID-இன் வேலை.

    Archie: முதல் தேடல் கருவி#

    நவீன search engine போன்ற எதற்கும் முன், குறிப்பிட்ட கோப்பைக் கண்டுபிடிப்பது எந்த host அதை வைத்திருக்கிறது என அறிவதைக் குறித்தது. Archie (1990, McGill; Alan Emtage, Bill Heelan மற்றும் Peter Deutsch உடன்) குறுகிய வெட்டை எடுத்தது: அறியப்பட்ட FTP servers-ஐ அவ்வப்போது poll செய்து, பொது filename-களை index செய்து, பயனர்கள் index-ஐத் தேட அனுமதிக்க. உள்ளடக்கங்கள் வரம்புக்கு வெளியே — பெயர்கள் மட்டும் — ஆனால் server ஊகிப்பதைத் தாண்டிய பெரிய படி அது.

    அட்டவணையின் பலன், ஒரு கணக்கில் (எடுத்துக்காட்டு மதிப்புகள்): 1,000 FTP server-கள், ஒவ்வொன்றிலும் 5,000 பொதுக் கோப்புகள் → Archie அட்டவணையில் 1,000 × 5,000 = 5,000,000 பெயர்கள். அட்டவணை இல்லாமல் ஒரு கோப்பைத் தேட, மோசமான நிலையில் 1,000 server-களுடனும் இணைந்து பட்டியல் கேட்க வேண்டும்; அட்டவணையுடன் ஒரே ஒரு கேள்வி. விலை: அட்டவணை கடைசியாக server-களைச் சுற்றி வந்த நேரத்தின் நிலையை மட்டுமே காட்டும் — அதற்குப் பின் சேர்ந்த கோப்புகள் அடுத்த சுற்று வரை தெரியாது.

    Gopher: Web-க்கு முன் மெனு-இயக்க உலாவல்#

    Gopher (1991, University of Minnesota; Mark McCahill மற்றும் சக ஊழியர்கள்) hierarchical, மெனு-இயக்க வழிசெலுத்தல் வழங்கியது: ஆவணங்கள், துணைமெனுக்கள், பிற Gopher servers-க்கான இணைப்புகள், free-form hyperlinks-க்குப் பதிலாக எண்ணால் தேர்ந்தெடுக்கப்பட்டவை. Web-ஐ விட அதிகக் கட்டுப்படுத்தப்பட்டது — மற்றும் 1990களின் ஆரம்பத்தில் சுருக்கமான காலத்திற்கு, இணையத்தின் தகவல் இடம் எப்படி ஒழுங்கமைக்கப்படும் என்பதற்குத் தீவிர போட்டியாளர்.

    ஒரு Gopher மெனு வரியைப் பிரித்துப் படித்தல்#

    RFC 1436-இன்படி: client, server-இன் port 70-இல் TCP இணைப்பைத் திறந்து, ஒரு selector வரியை அனுப்புகிறது (வெற்று வரி = “உன்னிடம் என்ன உண்டு?”). Server உரை வரிகளை அனுப்பி, தனியாக ஒரு புள்ளி (.) உள்ள வரியுடன் முடித்து, இணைப்பை மூடுகிறது; server எந்த நிலையையும் நினைவில் வைப்பதில்லை. மெனுவின் ஒவ்வொரு வரியும் TAB-களால் பிரிக்கப்பட்ட நான்கு புலங்கள். RFC-இன் எடுத்துக்காட்டிலிருந்து ஒரு வரி (→ = TAB):

    1Microcomputer News & Prices→Prices/→pserver.bookstore.umn.edu→70

    புலம் மதிப்பு பொருள்
    முதல் எழுத்து 1 வகை: அடைவு (menu); 0 = கோப்பு, 7 = தேடல் server
    காட்சிச் சரம் Microcomputer News & Prices பயனருக்குக் காட்டப்படுவது
    Selector Prices/ இதைத் தேர்ந்தால் அனுப்ப வேண்டிய சரம்
    Host pserver.bookstore.umn.edu இணைய வேண்டிய server — வேறொரு server ஆகவும் இருக்கலாம்
    Port 70 அந்த server-இன் port

    கடைசி இரண்டு புலங்கள்தான் முக்கியம்: ஒரு மெனு வேறொரு server-இல் உள்ள மெனுவைச் சுட்டலாம். ஆனால் சுட்டுவது மெனுவிலிருந்து மட்டுமே — ஆவணத்தின் உரைக்குள் எங்கும் இணைப்பு வைக்க முடியாது; Web-இன் hyperlink அந்தக் கட்டுப்பாட்டை நீக்கியது.

    IRC: Peer Talk in Real Time#

    Usenet பரவிய பேச்சு. IRC இப்போது நடந்த பேச்சு. ஆகஸ்ட் 1988-இல், University of Oulu-வில் Jarkko Oikarinen OuluBox BBS-இல் பல-பயனர் உரையாடலை மேம்படுத்த Internet Relay Chat கட்டினார் — பகுதியாக Bitnet Relay மற்றும் Jyrki Kuoppala, Jukka Pihl ஆகியோரின் உள்ளூர் கருவிகளால் ஈர்க்கப்பட்டு — பிறகு நண்பர்கள் வேறு இடங்களில் ircd ஓட்டியபோது servers Finland-ஐ North America-வுடன் இணைப்பதைப் பார்த்தார். Channels, nicknames, மற்றும் servers-இன் federated mesh ஒற்றை corporate host இல்லாமல் இணையத்திற்கு நேரடி அறை கொடுத்தன. நெறிமுறை பின்னர் RFC 1459-இல் இறங்கியது (Oikarinen மற்றும் Darren Reed, 1993).

    IRC-இன் வரம்புகள், RFC 1459-இலிருந்து: ஒரு செய்தி CR-LF உட்பட 512 எழுத்துகளுக்கு மேல் போகக்கூடாது — எனவே கட்டளைக்கும் அளவுருக்களுக்கும் 512 − 2 = 510; தொடர் வரிகள் கிடையாது. புனைபெயர் அதிகபட்சம் 9 எழுத்துகள்; channel பெயர் 200 வரை. கணக்கு: PRIVMSG #tamil : = 7 + 1 + 6 + 1 + 1 = 16 எழுத்துகள் → செய்தி உரைக்கு 510 − 16 = 494 எழுத்துகள் (ASCII-இல் 494 byte). (Server பயனருக்கு அனுப்பும்போது அனுப்புநரின் முன்னொட்டும் வரியில் சேர்வதால், நடைமுறையில் இன்னும் சற்றுக் குறைவு.) தமிழ் உரையை UTF-8-இல் அனுப்பினால் ஒவ்வொரு தமிழ் எழுத்துக் குறியும் (code point) 3 byte; வரம்பு byte-களில் எண்ணப்பட்டால் 494 ÷ 3 ≈ 164 குறிகள் மட்டுமே.

    Door out: RFC 1459 — முதன்மை IRC நெறிமுறை விவரக்குறிப்பு.

    Consumer Portals: கண்டுபிடித்தலையும் பேச்சையும் தொகுத்தல்#

    1990களின் நடுவில், மேலே உள்ள திறந்த கருவிகள் இன்னும் நீங்கள் client-ஐ எங்கு சுட்டிக்காட்ட வேண்டும் என அறிவீர்கள் எனக் கருதின. Consumer portals வேறு பந்தயம் விற்றன: directory கண்டுபிடித்தல், செய்திகள், mail, மற்றும் chat-ஐ தொகுக்கும் ஒரு homepage, புதியவர் வளைவைத் தானே அமைக்கத் தேவையில்லை.

    Yahoo அந்த வகையின் விதை. 1994-இல், Stanford பட்டதாரி மாணவர்கள் Jerry Yang மற்றும் David Filo “Jerry and David’s Guide to the World Wide Web”-ஐத் தொடங்கினர் — மனித-வரையறுக்கப்பட்ட hierarchical directory — அதை Yahoo! என மறுபெயரிட்டு, directory மீது search, mail, மற்றும் பிற sticky சேவைகளை அடுக்கிய portal-ஆக வளர்த்தனர். உறவினர்களைத் தருவித்து நிறுத்துங்கள்: AOL-இன் walled garden, Excite, Lycos, மற்றும் ஒத்த முன் கதவுகள் அதே வகை — வெகுஜன பார்வையாளருக்கு find-then-talk தொகுத்த கவன மையங்கள் — இரண்டாவது நிறுவனக் கலைக்களஞ்சியம் அல்ல. Door out: portal காலத்தை மேலே உள்ள நெறிமுறைகள் மீது அமர்ந்த தயாரிப்பு வரலாறாகக் கருதுங்கள், அவற்றுக்கு மாற்றாக அல்ல.

    திறந்த Web ஏன் மெனுக்களையும் Hubs-ஐயும் முந்தியது#

    Web-இன் மைய நகர்வு — நிலையான மெனு படிநிலை அல்லது ஒரு portal-இன் taxonomy-க்குப் பூட்டப்படாமல், எந்த பிற ஆவணத்தையும், எங்கும் சுட்டிக்காட்டக்கூடிய hyperlinks உடன் HTML — Gopher மெனுக்கள் அல்லது curated directory-ஐ விட நெகிழ்வான find மாதிரி. Netscape Navigator (1994), முன்னாள் NCSA Mosaic developers நிறுவிய நிறுவனத்திலிருந்து வணிக ஆதரவு மற்றும் விரைவு iteration உடன், அந்த மாதிரியை ஆராய்ச்சிக் கருவியிலிருந்து mainstream பயன்பாட்டுக்குத் தள்ளியது. Portals வளைவைத் தொகுத்துக் கொண்டே இருந்தன; திறந்த hyperlink graph (மற்றும் பின்னர், அடுத்த பதிவில் crawler-அளவு தேடல்) கண்டுபிடி பாதியை வென்று கொண்டே இருந்தது.

    Gopher mainstream பயன்பாட்டிலிருந்து மறைந்தது. Usenet மற்றும் IRC முழுவதும் மறையவில்லை — பெரும்பாலான மக்களின் முதல் கதவாக இருப்பதை நிறுத்தின. Archie-இன் filename index ஒரு வகையின் விதை, பதிவு 44 முழு decentralized web-ஐ index செய்வதாக அளவிடும்.

    இது ஏன் இந்தத் தொடரில் சேர்கிறது#

    கண்டுபிடித்தலும் பேச்சும் பக்க trivia அல்ல. Usenet-இன் decentralized பரவல், Archie-இன் index-over-distributed-hosts பிரச்சனை, IRC-இன் federated நேரடி அறைகள், மற்றும் அனைத்தையும் productize செய்யும் portal பந்தயம் அடுத்த பதிவுகள் பெரிய அளவில் கேட்கும் அதே வகை கேள்விகளாக மீண்டும் தோன்றும்: மைய catalog இல்லாத இடத்தை எப்படித் தேடுவீர்கள், மற்றும் கம்பி பகிரப்பட்ட பிறகு மக்கள் எப்படி உரையாடலில் இருப்பார்கள்?

    இப்போது முயல்க: சில வரிகளில் ஒரு Gopher server. கீழே உள்ள VM-இல் RFC 1436 நெறிமுறையைப் பேசும் ஒரு சிறிய server-ஐ உருவாக்குங்கள் (எல்லாம் ஓட்டிச் சரிபார்த்தவை):

    1. ifconfig lo 127.0.0.1 up
    2. மெனு: printf '0About this server\t/about\t127.0.0.1\t70\r\n1Tamil notes\t/ta\t127.0.0.1\t70\r\n.\r\n' > /tmp/menu
    3. Server நிரல் — இந்த வரிகளைத் தட்டுங்கள் (> தூண்டல் வரும்; கடைசியில் END):
    cat > /tmp/g.sh << 'END'
#!/bin/sh
read sel
sel=$(echo "$sel" | tr -d '\r')
if [ "$sel" = "/about" ]; then printf 'A tiny Gopher server in BusyBox.\r\n.\r\n'; else cat /tmp/menu; fi
END
    1. chmod +x /tmp/g.sh; echo '70 stream tcp nowait root /tmp/g.sh g.sh' > /tmp/inetd.conf; inetd /tmp/inetd.conf — port 70-இல் வரும் ஒவ்வொரு இணைப்புக்கும் inetd நம் நிரலை ஓட்டும்.
    2. telnet 127.0.0.1 70, பிறகு /about அல்லாத எதையாவது தட்டி Enter (எங்கள் ஓட்டத்தில் x) → இரண்டு மெனு வரிகள் (TAB-களுடன்), தனிப் புள்ளி, Connection closed by foreign host.
    3. மீண்டும் telnet 127.0.0.1 70, இம்முறை /about → A tiny Gopher server in BusyBox., புள்ளி, இணைப்பு மூடல்.

    ஒவ்வொரு கேள்வியும் ஒரு புதிய இணைப்பு, ஒரு selector, ஒரு பதில், மூடல் — server எதையும் நினைவில் வைப்பதில்லை; RFC 1436 சொல்வதுபோலவே.
