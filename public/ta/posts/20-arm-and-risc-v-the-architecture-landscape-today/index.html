    ARM மற்றும் RISC-V: இன்றைய கட்டமைப்பு நிலப்பரப்பு

    ஜனவரி 1, 2026

    x86-எதிர்-RISC போர் (பதிவு 19) 1990களின் பிற்பகுதியில் desktop மற்றும் சேவையகத்தை பெரும்பாலும் தீர்த்தது. போட்டி முடியவில்லை — அது நகர்ந்தது. Mobile, embedded, மற்றும் edge single-thread உச்சத்தை விட watts-ஐ அதிகம் கவனிக்கின்றன, மற்றும் ஒரு ISA-வைச் சுற்றிய வணிக மாதிரி குறியாக்கத்தைப் போலவே முக்கியம் என்று மாறியது.

    தமிழ் இடைவெளிக் குறிப்பு: RISC-V பற்றி தமிழில் எழுத்து விளக்கமோ காணொளியோ இல்லை; ARM பற்றிய தமிழ் விளக்கமும் மிகக் குறைவு. எனவே இந்தப் பதிவில் RISC-V அறிவுறுத்தல்கள் பிட் அளவில் எப்படி அமைக்கப்படுகின்றன என்பதைக் கையால் கணக்கிட்டுக் காட்டுகிறோம், மேலும் இந்தப் பக்கத்தின் mini-CPU lab-உடன் ஒப்பிடுகிறோம்.

    முதலில் சொற்கள்#

    • ISA (Instruction Set Architecture, அறிவுறுத்தல் தொகுப்புக் கட்டமைப்பு): மென்பொருளுக்கும் வன்பொருளுக்கும் இடையிலான ஒப்பந்தம் — எந்த அறிவுறுத்தல்கள் உள்ளன, அவை எந்த register-களைப் பயன்படுத்துகின்றன, ஒவ்வொன்றும் எந்த பிட் வடிவில் குறியாக்கப்படுகிறது (encoding). ஒரே ISA-வுக்குப் பல வேறுபட்ட chip வடிவமைப்புகள் இருக்கலாம்.
    • Register (பதிவேடு): CPU-க்குள் உள்ள மிக வேகமான, சிறிய சேமிப்பிடம். அறிவுறுத்தல்கள் பெரும்பாலும் இவற்றின் மேல் வேலை செய்கின்றன.
    • Opcode (செயல் குறியீடு): ஒரு அறிவுறுத்தலின் எந்தப் பகுதி “என்ன செய்ய வேண்டும்” (கூட்டு, ஏற்று, தாவு…) என்று சொல்கிறது.
    • Immediate (உடனடி மதிப்பு): அறிவுறுத்தலுக்குள்ளேயே எழுதப்பட்ட ஒரு நிலையான எண் (எ.கா. “5-ஐக் கூட்டு” என்பதில் 5).
    • Load/store கட்டமைப்பு: நினைவகத்தைத் தொடும் அறிவுறுத்தல்கள் load (ஏற்று) மற்றும் store (சேமி) மட்டுமே; கணக்குகள் register-களுக்குள் மட்டும் நடக்கும். RISC வழித்தோன்றல்களின் (பதிவு 19) அடையாளம்.
    • License (உரிமம்) / royalty (உரிமைத் தொகை): ஒரு ISA-வைப் பயன்படுத்த அதன் உரிமையாளரிடம் பெறும் சட்ட அனுமதி, மற்றும் விற்கப்படும் ஒவ்வொரு chip-க்கும் செலுத்தும் கட்டணம்.
    • Extension (நீட்டிப்பு): அடிப்படை ISA-வின் மேல் சேர்க்கக்கூடிய விருப்ப அறிவுறுத்தல் குழு.

    ARM: ISA-ஐ License செய்யுங்கள், Fab கட்டாதீர்கள்#

    ARM Holdings ISA-ஐ வடிவமைத்து license செய்கிறது — fabricate செய்யத் தயாரான cores, அல்லது ஒரு நிறுவனம் தன் சொந்த ARM-இணக்க core-ஐ வடிவமைக்க அனுமதிக்கும் architecture licenses (Apple-இன் சிலிகான் பிந்தையதின் முதன்மை எடுத்துக்காட்டு). மாதிரி ARM ஒரு fab ஓட்டாமல் பல உற்பத்தியாளர்களிடம் ISA-ஐப் பரப்பியது.

    தொழில்நுட்பரீதியாக, ARM மொபைல் காலத்திற்குள் ஏற்கனவே மின்சாரத் திறனுக்குச் சரிசெய்யப்பட்டு நுழைந்தது — RISC-வம்சாவளி எளிய decode முதன்முறையாகப் பெருமளவில் performance-per-watt-ஐக் கவனித்த சந்தையைச் சந்தித்தது. அது அதிர்ஷ்டம் அல்ல; பேட்டரி இயக்கப்படும் சாதனங்களைச் சந்தித்த அந்த வடிவமைப்பு ஒழுக்கத்தின் பல தசாப்தங்கள்.

    RISC-V: License-க்குப் பதிலாக திறந்தது#

    RISC-V (சுமார் 2010-இல் UC Berkeley-இல் தொடங்கிய வேலை, Krste Asanović, David Patterson, மற்றும் சக பணியாளர்கள் பெயரிடப்பட்ட இயக்கிகளில்) மேலும் செல்கிறது: ISA திறந்ததும் royalty-இல்லாததும். கட்டுப்படுத்தும் vendor-உடன் பேச்சுவார்த்தை இல்லாமல் ஒரு core-ஐச் செயல்படுத்துங்கள். ஆழமான தனிப்பயனாக்கம் அல்லது பூஜ்ய ISA licensing செலவு முக்கியமாகும் இடத்தில் அது மிகவும் முக்கியம் — embedded அமைப்புகள், மற்றும் அனுமதி கேட்காமல் RISC-V அடிப்படையில் தனிப்பயன் அறிவுறுத்தல்களை விரும்பும் accelerators.

    அதே பாடம், ஒரு அடுக்கு ஆழமாக#

    தோராய வரைபடம்: x86 இன்னும் இணக்கத்தன்மை inertia-வில் desktop மற்றும் சேவையகத்தின் பெரும்பகுதியை வைத்திருக்கிறது. ARM மொபைலை வைத்திருக்கிறது, உண்மையான சேவையக மற்றும் laptop நுழைவுகளுடன் (தனிப்பயன் cloud ARM; Apple Silicon). RISC-V வணிகரீதியாக முந்தையது, royalty-இல்லாத நெகிழ்வுத்தன்மை முதிர்ந்த மென்பொருள் stack-ஐ வெல்லும் இடத்தில் வேகமாக வளர்கிறது.

    பதிவு 19-இன் முறை மீண்டும்: ஒரு பிரிவில் வெற்றியாளர் தனியாக “சிறந்த” ISA அல்ல — அந்தப் பிரிவு வாங்குவதற்குப் பொருந்தும் பொருளாதாரம் கொண்டது. ARM மொபைலை watts-மற்றும் தொலைபேசி தயாரிப்பாளர்கள் கீழ் தனிப்பயனாக்கக்கூடிய licensing மாதிரியில் வென்றது. RISC-V “இலவசமும் திறந்ததும்” வளரும் வழக்குகளுக்கு அதையும் வெல்லும் என்று பந்தயம் கட்டுகிறது. அது x86 அல்லது ARM அளவை அடைகிறதா என்பது இன்னும் திறந்தது.

    மூன்று ISA-கள் அருகருகே#

    முதலில் ஒரு பருந்துப் பார்வை. கீழே உள்ளவை ஒவ்வொரு ISA-வின் 64-bit பதிப்பின் பொதுவான பண்புகள்:

    பண்பு x86-64 ARM (AArch64 / A64) RISC-V (RV64I)
    அறிவுறுத்தல் நீளம் மாறும் நீளம், 1 முதல் 15 byte வரை நிலையான 32 bit 32 bit (C நீட்டிப்புடன் 16-bit சுருக்க வடிவங்களும்)
    பொது நோக்க register-கள் 16 31 (X0–X30) + பூஜ்ஜிய register/stack pointer 31 + எப்போதும் பூஜ்ஜியமான x0
    Condition flags (நிலைக் கொடிகள்) உண்டு உண்டு (N, Z, C, V) இல்லை — branch இரண்டு register-களை நேரடியாக ஒப்பிடுகிறது
    நினைவக அணுகல் கணக்கு அறிவுறுத்தல்களே நினைவகத்தைத் தொடலாம் load/store load/store
    யாருடையது Intel / AMD Arm நிறுவனம் — license தேவை RISC-V International — திறந்தது, royalty இல்லை

    முதல் மூன்று வரிகள் தொழில்நுட்பம்; கடைசி வரி வணிகம். இந்தப் பதிவின் வாதம் என்னவென்றால், பிரிவுகளைத் தீர்மானித்தது அந்தக் கடைசி வரிதான்.

    RISC-V உள்ளே: ஒரு சிறிய அடிப்படை, பல நீட்டிப்புகள்#

    “RISC-V” என்ற பெயர் UC Berkeley-இன் ஐந்தாவது பெரிய RISC ISA வடிவமைப்பைக் குறிக்கிறது (RISC-I, RISC-II, SOAR, SPUR முதல் நான்கு என்று RISC-V கையேடே சொல்கிறது). அமைப்பு ரீதியாக: 2015-இல் RISC-V Foundation உருவானது; மார்ச் 2020-இல் அது சுவிட்சர்லாந்தின் Zurich-இல் RISC-V International என்ற அமைப்பாகப் பதிவு செய்யப்பட்டது. அடிப்படை integer ISA-வின் unprivileged விவரக்குறிப்பு 20191213 பதிப்பில் அங்கீகரிக்கப்பட்டது (ratified).

    RISC-V-இன் வடிவமைப்புத் தத்துவம்: மிகச் சிறிய, ஒருபோதும் மாறாத அடிப்படை + தேவைக்கேற்ப சேர்க்கும் நீட்டிப்புகள். பெயரிலேயே எழுத்துகளாக அவை குறிக்கப்படுகின்றன:

    எழுத்து பொருள்
    RV32I / RV64I அடிப்படை integer அறிவுறுத்தல்கள் — 32-bit அல்லது 64-bit register-கள்
    M பெருக்கல் மற்றும் வகுத்தல்
    A atomic அறிவுறுத்தல்கள் (பல core-கள் ஒரே நினைவகத்தைப் பாதுகாப்பாகப் பகிர)
    F / D single / double precision floating-point
    C அடிக்கடி வரும் அறிவுறுத்தல்களுக்கு 16-bit சுருக்க வடிவம்
    V vector அறிவுறுத்தல்கள்
    G IMAFD மற்றும் சில அடிப்படை system நீட்டிப்புகளின் சுருக்கம் — “பொது நோக்கம்”

    எனவே “RV64GC” என்பது: 64-bit integer அடிப்படை + M + A + F + D + C. Linux ஓட்டும் பல பொது நோக்க RISC-V chip-கள் இதைக் குறிப்பிடுகின்றன. ஒரு சிறிய microcontroller RV32I அல்லது RV32IMC மட்டும் செயல்படுத்தலாம் — தேவையில்லாததற்கு silicon செலவழிக்க வேண்டாம். இந்த “தேர்ந்தெடுத்துச் சேர்” அமைப்புதான் மேலே சொன்ன “தனிப்பயன் அறிவுறுத்தல்களுடன் accelerators” என்ற பயன்பாட்டைச் சாத்தியமாக்குகிறது: அடிப்படையும் நிலையான நீட்டிப்புகளும் அப்படியே இருக்க, custom அறிவுறுத்தல்களுக்கென ஒதுக்கப்பட்ட opcode இடத்தில் சொந்த அறிவுறுத்தல்களைச் சேர்க்கலாம்.

    Register-கள்: x0 முதல் x31 வரை 32 integer register-கள். x0 எப்போதும் 0; அதில் எழுதினாலும் மதிப்பு மாறாது. இது ஒரு சிறிய தந்திரம் ஆனால் பல அறிவுறுத்தல்களை மிச்சப்படுத்துகிறது: “x5 ← 5” என்பதற்குத் தனி அறிவுறுத்தல் தேவையில்லை; “x5 ← x0 + 5” (addi) போதும். மென்பொருள் மரபில் இந்த register-களுக்கு ABI பெயர்களும் உண்டு (எ.கா. x5, x6, x7 = t0, t1, t2 — “temporary”); disassembler-கள் பெரும்பாலும் அந்தப் பெயர்களைக் காட்டும்.

    ஒரு அறிவுறுத்தலைக் கையால் குறியாக்குவோம்#

    RV32I-இன் அடிப்படை அறிவுறுத்தல்கள் அனைத்தும் 32 bit. ஆறு வடிவங்கள் (formats) உள்ளன: R (register–register), I (immediate / load), S (store), B (branch), U (மேல் immediate), J (jump). முக்கியமான விஷயம்: opcode எப்போதும் bit 6–0; இலக்கு register rd எப்போதும் bit 11–7; மூல register-கள் rs1, rs2 எப்போதும் bit 19–15, 24–20. Decoder ஒவ்வொரு வடிவத்துக்கும் புதிதாகத் தேட வேண்டியதில்லை — பதிவு 19-இன் “எளிய decode” இதுதான்.

    R-வடிவம்: funct7 (7) | rs2 (5) | rs1 (5) | funct3 (3) | rd (5) | opcode (7)

    எடுத்துக்காட்டு: add x7, x5, x6 (x7 ← x5 + x6). RISC-V விவரக்குறிப்பின்படி add-க்கு opcode = 0110011 (0x33), funct3 = 000, funct7 = 0000000.

    புலம் மதிப்பு பிட்கள்
    funct7 0 0000000
    rs2 x6 = 6 00110
    rs1 x5 = 5 00101
    funct3 0 000
    rd x7 = 7 00111
    opcode 0x33 0110011

    சேர்த்து எழுதினால்: 0000000 00110 00101 000 00111 0110011. நான்கு நான்கு பிட்டுகளாகப் பிரித்தால் 0000 0000 0110 0010 1000 0011 1011 0011 = 0x006283B3.

    sub x7, x5, x6 க்கு ஒரே ஒரு வேறுபாடு: funct7 = 0100000. அதனால் முதல் hex இலக்கம் 0 → 4: 0x406283B3. ஒரே opcode, funct7 மட்டும் கூட்டலையும் கழித்தலையும் பிரிக்கிறது.

    I-வடிவம்: imm[11:0] (12) | rs1 (5) | funct3 (3) | rd (5) | opcode (7)

    எடுத்துக்காட்டு: addi x5, x0, 5 (x5 ← 0 + 5; opcode 0x13, funct3 000): 000000000101 00000 000 00101 0010011 = 0x00500293. 12-bit immediate இரண்டின் நிரப்பு (two’s complement) எண் என்பதால் அதன் வீச்சு −2048 முதல் +2047 வரை. addi x5, x5, -1 இல் −1 = 111111111111, அதனால் குறியீடு 0xFFF28293. (வேடிக்கையான உண்மை: addi x0, x0, 0 = 0x00000013 தான் RISC-V-இன் அதிகாரப்பூர்வ NOP — x0-இல் எழுதுவது எதையும் மாற்றாது.)

    S-வடிவம் (store): immediate இரண்டாகப் பிளக்கப்படுகிறது — imm[11:5] | rs2 | rs1 | funct3 | imm[4:0] | opcode. ஏன்? rs1, rs2 எப்போதும் அதே இடத்தில் இருக்க வேண்டும் என்பதற்காக; store-க்கு rd இல்லை, எனவே அந்த 5 பிட் இடத்தை immediate-இன் கீழ்ப் பகுதி எடுத்துக்கொள்கிறது. sw x7, 60(x0) (mem[0 + 60] ← x7; opcode 0x23, funct3 010): 60 = 0000001 11100 → 0x02702E23.

    B-வடிவம் (branch) — குறியீட்டைப் பின்னோக்கிப் படிப்போம். bne x5, x0, -4 (x5 ≠ 0 என்றால் 4 byte பின்னே தாவு) = 0xFE029EE3. இதை decode செய்ய:

    1. பைனரியில்: 1111111 00000 00101 001 11101 1100011
    2. opcode 1100011 = 0x63 → branch. funct3 001 → bne.
    3. rs1 = 00101 = x5, rs2 = 00000 = x0.
    4. Immediate பிட்கள் சிதறியுள்ளன: bit 31 = imm[12] = 1; bit 30–25 = imm[10:5] = 111111; bit 11–8 = imm[4:1] = 1110; bit 7 = imm[11] = 1. imm[0] எப்போதும் 0 (அறிவுறுத்தல்கள் இரட்டை byte எல்லையில்).
    5. சேர்த்தால் 1 1 111111 1110 0 = 13-bit எண் 1111111111100 = இரண்டின் நிரப்பில் −4.

    (இந்த ஐந்து குறியீடுகளையும் ஒரு Python encoder மூலம் கணக்கிட்டு, capstone disassembler கொண்டு பின்னோக்கிச் சரிபார்த்தோம்.)

    Mini-CPU எதிர் RISC-V: அதே 5 + 8#

    இந்தப் பக்கத்தின் lab-இல் உள்ள mini-CPU ஒவ்வொரு அறிவுறுத்தலையும் 8 bit ஆகக் குறியாக்குகிறது: மேல் 4 bit opcode, கீழ் 4 bit operand. எ.கா. LDI 5 → opcode 5 (0101), operand 5 (0101) → 0101 0101 = 0x55. அதன் விளைவுகள்:

    Mini-CPU (lab) RV32I
    அறிவுறுத்தல் அகலம் 8 bit 32 bit
    Opcode இடம் 4 bit → அதிகபட்சம் 16 அறிவுறுத்தல்கள் 7-bit opcode + funct3 + funct7
    Immediate / முகவரி வீச்சு 0–15 மட்டும் 12-bit immediate: −2048 முதல் 2047
    Register-கள் ஒரு accumulator A (+ B) 31 பொது + x0
    கூட்டல் ADD n: A ← A + mem[n] (நினைவகத்திலிருந்து) add rd, rs1, rs2: register-களுக்குள் மட்டும்
    நிபந்தனைத் தாவல் JZ/JC — zero/carry கொடிகளைப் பார்க்கும் beq/bne/blt… — இரண்டு register-களை ஒப்பிடும்

    Lab-இன் இயல்புநிலை program 5 + 8-ஐக் கணக்கிட 8 அறிவுறுத்தல்கள் எடுக்கிறது, ஏனெனில் ADD-க்கு இரண்டாவது எண் நினைவகத்தில் இருக்க வேண்டும் — அதனால் முதலில் 5-ஐ mem[14]-இல் சேமிக்க வேண்டியுள்ளது. RISC-V-இல் அதே கணக்கு:

    addi x5, x0, 5     # 0x00500293   x5 ← 5
addi x6, x0, 8     # 0x00800313   x6 ← 8
add  x7, x5, x6    # 0x006283B3   x7 ← 13
sw   x7, 60(x0)    # 0x02702E23   (விருப்பம்) mem[60] ← 13

    மூன்று அறிவுறுத்தல்களில் பதில் register x7-இல். ஆனால் ஒவ்வொரு அறிவுறுத்தலும் 4 மடங்கு அகலம்: mini-CPU program 8 byte; RISC-V program (sw உடன்) 16 byte. குறைவான அறிவுறுத்தல்கள், அதிக byte-கள் — இதுதான் RISC-V-க்கு C நீட்டிப்பு (16-bit வடிவங்கள்) ஏன் வந்தது என்பதற்கான காரணம், மற்றும் பதிவு 19-இன் “குறியாக்க அடர்த்தி” விவாதத்தின் சிறிய வடிவம்.

    Flags இல்லாமல் ஒரு loop. x5-இல் 3 வைத்து மூன்று முறை ஓடும் loop:

          addi x5, x0, 3     # x5 ← 3
loop: addi x5, x5, -1    # x5 ← x5 − 1
      bne  x5, x0, loop  # x5 ≠ 0 என்றால் loop-க்குத் திரும்பு (offset −4)
    சுற்று addi-க்குப் பின் x5 bne முடிவு
    1 2 2 ≠ 0 → தாவு
    2 1 1 ≠ 0 → தாவு
    3 0 0 = 0 → கீழே தொடர்

    Mini-CPU-இல் இதே வேலைக்கு SUB ஒரு zero கொடியை அமைக்க, JZ அதைப் படிக்க வேண்டும் — அறிவுறுத்தல்களுக்கு இடையே மறைமுகத் தொடர்பு. RISC-V-இல் ஒப்பீடு branch-க்குள்ளேயே உள்ளது; out-of-order core-களில் (பதிவு 16) கொடிகளின் சார்புநிலையைக் கண்காணிக்கும் சிக்கல் குறைகிறது.

    இப்போது முயல்க.

    1. கீழே உள்ள lab-இல் இயல்புநிலை program ஏற்கனவே ஏற்றப்பட்டுள்ளது (LDI 5, STA 14, LDI 8, ADD 14, STA 15, LDA 15, OUT, HLT). Step பொத்தானை ஒவ்வொரு முறை அழுத்திய பின்னும் IR பெட்டியில் உள்ள இரண்டு hex இலக்கங்களைக் குறித்துக்கொள்ளுங்கள். எட்டு Step-களில் நீங்கள் பார்க்க வேண்டியது: 55, 4E, 58, 2E, 4F, 1F, E0, F0.
    2. ஒவ்வொன்றையும் கையால் பிரியுங்கள்: முதல் இலக்கம் = opcode, இரண்டாவது = operand. எ.கா. 4E → opcode 4 = STA, operand 0xE = 14 → “STA 14”. 2E → ADD 14. E0 → opcode 0xE = OUT. Lab-இன் விளக்கப் பலகத்தில் வரும் “DECODE: … (opcode 0x…, operand …)” வரியுடன் உங்கள் விடையை ஒப்பிடுங்கள்.
    3. A register-உம் hex-இல் காட்டப்படுகிறது: ADD 14-க்குப் பின் அது 0D (= 13).
    4. இப்போது 4-bit operand வரம்பைச் சோதியுங்கள்: Assembly பெட்டியில் LDI 5 என்பதை LDI 16 என மாற்றி Assemble அழுத்துங்கள். விளக்கப் பலகம் “Assemble error” என்றும் “Line 1: operand out of range (0-15)” என்றும் காட்டும் (comment வரிகளை assembler எண்ணுவதில்லை, அதனால் இது “Line 1”). RISC-V-இன் addi இதே இடத்தில் 2047 வரை ஏற்கும் — 16 bit அதிகமாக அகலம் கொடுத்ததன் பலன் இதுதான்.
    5. காகிதத்தில்: மேலே உள்ள RISC-V 5 + 8 program-ஐ LDI 5 → 0x55 போலவே பிட் புலங்களாகப் பிரித்து, addi x6, x0, 8 = 0x00800313 என்பதைச் சரிபாருங்கள். (குறிப்பு: immediate 8 = 000000001000, rd = x6 = 00110.)

    (இந்தப் படிகளில் உள்ள பொத்தான் பெயர்கள், IR மதிப்புகள் மற்றும் பிழைச் செய்தி lab-இன் மூலக் குறியீட்டிலிருந்து (static/labs/mini-cpu) நேரடியாக ஓட்டிச் சரிபார்க்கப்பட்டன.)
