    Machine Code-இலிருந்து Assembly வரை

    ஜனவரி 1, 2026

    Phase 3-இன் ஒவ்வொரு அறிவுறுத்தலும் — datapath, pipeline, ISA — இறுதியில் raw binary ஆக உள்ளது: வன்பொருள் நேரடியாக decode செய்யும் பிட் வடிவங்கள். யாரும் அளவில் அவ்வாறு நிரல்களை எழுதுவதில்லை. Assembly அந்த binary மேல் முதல் abstraction. அது வாங்குவது — மற்றும் மாற்றாதது — மென்பொருள் வரலாற்றில் கீழ்நிலை எல்லாவற்றிற்கும் முக்கியம்.

    தமிழ் இடைவெளிக் குறிப்பு: எந்திரமொழி (machine code), சில்லுமொழி (assembly) பற்றித் தமிழில் அறிமுக அளவிலான எழுத்து உண்டு (கீழே மேலும் படிக்க); காணொளிச் சான்று YouTube தேடல் முடிவுகள் மட்டும் — காணொளிகள் பார்க்கப்படவில்லை. ஒரு நிரலைக் கையால் assemble செய்வது, label-களை assembler எப்படித் தீர்க்கிறது, label இல்லாமல் ஒரு வரியைச் சேர்த்தால் என்ன உடையும் — இவை படிப்படியாக விளக்கப்பட்டதாகத் தெரியவில்லை. இங்கே உள்ள எல்லா mini-CPU நிரல்களும் lab-இன் மூலக் குறியீட்டுக்கு எதிராகவும் அதன் simulator-இல் ஓட்டியும் சரிபார்க்கப்பட்டவை; x86 குறியாக்கம் capstone disassembler மூலம்.

    முதலில் சொற்கள்#

    • எந்திரமொழி (machine code): CPU நேரடியாக decode செய்யும் பிட் வடிவங்கள் — எ.கா. 0101 0011.
    • சில்லுமொழி (assembly language): அதே instruction-களுக்கு மனிதர் படிக்கக்கூடிய பெயர்கள் — எ.கா. LDI 3. ஒரு வரி = ஒரு machine instruction.
    • Mnemonic (நினைவுக்குறி): opcode-க்கான சுருக்கப் பெயர் (LDI, ADD, JMP).
    • Assembler (சில்லுமொழி பெயர்ப்பி): assembly உரையை machine code ஆக மாற்றும் நிரல்.
    • Label (குறிப்பெயர்): ஒரு முகவரிக்கு வைக்கும் பெயர் (loop, end); assembler அதை எண்ணாக மாற்றும்.
    • Symbol table (குறியீட்டு அட்டவணை): ஒவ்வொரு label-க்கும் அதன் முகவரி — assembler-இன் முதல் சுற்று கட்டும் அட்டவணை.
    • Two-pass assembler (இரு-சுற்று): முதல் சுற்றில் label முகவரிகளைக் கண்டுபிடித்து, இரண்டாம் சுற்றில் குறியாக்கும் assembler.
    • Disassembler: எதிர்த்திசை — machine code-ஐ மீண்டும் assembly ஆகப் படிக்கும் கருவி.

    Assembly உண்மையில் என்ன#

    Assembly ஒவ்வொரு அறிவுறுத்தலுக்கும் மனிதர் வாசிக்கக்கூடிய mnemonic கொடுக்கிறது — ADD, LDA, JMP — machine-code பிட் வடிவத்துடன் ஒன்றுக்கு ஒன்று பொருந்தும். பதிவு 27-இன் மொழிகள் போல் அது “உயர்நிலை” அல்ல; அடிப்படை வன்பொருள் ops மேல் abstraction இல்லை. ஒவ்வொரு assembly அறிவுறுத்தலும் சரியாக ஒரே machine அறிவுறுத்தலுக்கு வரைபடமாகிறது. நீங்கள் பெறுவது வாசிப்புத்திறன் மற்றும் குறியீட்டு குறிப்பு: opcode 0101-ஐ நினைவில் வைப்பதற்குப் பதிலாக LDI எழுதுங்கள்; முழு assembler-இல், label எழுதி அதுவே jump இலக்கைக் கணக்கிடட்டும் — byte முகவரிகளைக் கையால் மீண்டும் கணக்கிடாமல். (Mini-CPU lab-இன் சிறிய assembler-இல் label-கள் இல்லை; அங்கே முகவரிகளை நீங்களே எழுத வேண்டும்.)

    ஒன்றுக்கு ஒன்று: ஒரு அட்டவணையில்#

    Mini-CPU-இன் வழிகாட்டும் நிரல், மூன்று வடிவங்களில் (lab மூலக் குறியீட்டின் குறியாக்க விதி: opcode × 16 + operand):

    முகவரி Assembly இருமம் Hex
    0 LDI 5 0101 0101 55
    1 STA 14 0100 1110 4E
    2 LDI 8 0101 1000 58
    3 ADD 14 0010 1110 2E
    4 STA 15 0100 1111 4F
    5 LDA 15 0001 1111 1F
    6 OUT 1110 0000 E0
    7 HLT 1111 0000 F0

    எட்டு வரிகள் → எட்டு byte-கள். எதுவும் சேர்க்கப்படவில்லை, எதுவும் மறுசீரமைக்கப்படவில்லை. Assembly-க்கு முன் நிரலாளர் நடு நெடுவரிசையை (அல்லது hex-ஐ) நேரடியாக உள்ளிட்டார்.

    உண்மையான ISA-விலும் அதே உறவு. x86-64-இல் add eax, ebx ↔ byte-கள் 01 D8; disassembler 01 D8-ஐப் படித்து மீண்டும் add eax, ebx என்று தருகிறது (capstone சரிபார்த்தது). பதிவு 11-இல் பார்த்ததுபோல் x86 instruction-களின் நீளம் மாறும், ஆனால் ஒவ்வொரு assembly வரியும் இன்னும் சரியாக ஒரு machine instruction.

    Assembler-இன் வேலை#

    Assembler assembly உரையை machine code-ஆக மொழிபெயர்க்கிறது — labels-ஐ முகவரிகளாகத் தீர்த்தல், mnemonics-ஐ opcode பிட்களாக, operands-ஐ ISA-இன் encoding புலங்களில் பொதித்தல் (பதிவு 11). இயந்திரவியல், பெரும்பாலும் ஒன்றுக்கு ஒன்று. ஆழமான அர்த்தத்தில் எதுவும் மேம்படுத்தப்படவோ மறுகட்டமைக்கப்படவோ இல்லை — முழு compiler (பதிவு 28) உயர்நிலை மொழியுடன் செய்வதைப் போல் அல்ல.

    கையால் assemble செய்வோம்: label-களுடன் ஒரு loop#

    3-இலிருந்து 0 வரை எண்ணி ஒவ்வொரு எண்ணையும் Output-க்கு அனுப்பும் நிரல். loop, end label-கள், ONE என்ற மாறிலி முகவரி:

            LDI 1
        STA ONE      ; mem[ONE] = 1
        LDI 3        ; A = 3
loop:   OUT          ; Output ← A
        SUB ONE      ; A = A − 1
        JZ  end      ; A = 0 என்றால் முடி
        JMP loop
end:    OUT
        HLT

    சுற்று 1 — முகவரிகளை எண்ணுதல். ஒவ்வொரு instruction-உம் ஒரு word என்பதால் வரிசை எண்ணே முகவரி:

    Label முகவரி ஏன்
    loop 3 நான்காவது instruction (0, 1, 2, 3)
    end 7 எட்டாவது instruction
    ONE 15 தரவுக்காக நாம் தேர்ந்த கடைசி நினைவக word (நிரல் 0–8 மட்டும் பயன்படுத்துகிறது)

    சுற்று 2 — குறியாக்குதல். Label-களை எண்களால் மாற்றி, opcode × 16 + operand:

    முகவரி Assembly (label தீர்த்த பின்) Hex
    0 LDI 1 5 × 16 + 1 = 81 = 51
    1 STA 15 4F
    2 LDI 3 53
    3 OUT E0
    4 SUB 15 3F
    5 JZ 7 87
    6 JMP 3 63
    7 OUT E0
    8 HLT F0

    ஓட்டம் (simulator-இல் சரிபார்த்தது): 16 படிகள். Output 3 → 2 → 1 → 0 என மாறுகிறது; A = 0 ஆனதும் SUB zero கொடியை 1 ஆக்குகிறது, JZ 7-க்குத் தாவுகிறது, கடைசி OUT 0-ஐ அனுப்பி HLT.

    Label இல்லாமல் ஒரு வரி சேர்த்தால்#

    இப்போது நிரலின் தொடக்கத்தில் ஒரு NOP சேர்க்கிறோம் என்று வைத்துக்கொள்வோம். எல்லா instruction-களும் ஒரு முகவரி கீழே நகர்கின்றன: loop 3 → 4, end 7 → 8.

    • Label-களுடன்: assembler சுற்று 1-ஐ மீண்டும் ஓட்டி புதிய முகவரிகளைத் தானே கணிக்கிறது. நீங்கள் எதையும் மாற்ற வேண்டாம்.
    • கையால் எழுதிய எண்களுடன் (JZ 7, JMP 3 அப்படியே விட்டால்): simulator-இல் ஓட்டியபோது JMP 3 இப்போது LDI 3-இல் இறங்குகிறது → A மீண்டும் 3 → நிரல் முடிவில்லாமல் சுற்றுகிறது, Output 3-இலேயே நிற்கிறது (simulator 500 படி வரம்பில் நிறுத்தியது).
    • சரியான கைத்திருத்தம்: JZ 8, JMP 4 — இரண்டு வரிகளையும் தேடிக் கண்டுபிடித்துத் திருத்த வேண்டும். 9 வரி நிரலில் இரண்டு; ஆயிரம் வரி நிரலில் நூற்றுக்கணக்கான தாவல்கள்.

    ஆங்கிலப் பதிவு சொல்லும் “குறியீட்டு label-கள் மட்டுமே மாற்றம் தந்தன” என்பது இதுதான்.

    இது ஏன் நடக்க வேண்டியிருந்தது#

    Assembly-க்கு முன், நிரலாக்கம் binary அல்லது சிறந்த நிலையில் raw hex அல்லது octal opcodes உள்ளீடு செய்வதாக இருந்தது — அற்ப நிரல்களுக்கு அப்பால் கையாள முடியாதது, அளவில் debug அல்லது மாற்ற கிட்டத்தட்ட இயலாதது. குறியீட்டு labels மட்டும் மாற்றும் தன்மை கொண்டவை: ஒரு அறிவுறுத்தலைச் செருகுங்கள் அல்லது அகற்றுங்கள், ஒவ்வொரு jump-ஐயும் கையால் மீண்டும் கணக்கிட வேண்டாம் — assembler கணிதத்தைச் செய்கிறது.

    Assembly இன்னும் எங்கே முக்கியம்#

    நவீன மென்பொருள் மிகைப் பெரும்பாலும் உயர்நிலை மொழிகளில் எழுதப்பட்டு பதிவு 28-இன் pipeline வழியாகத் தொகுக்கப்படுகிறது. Assembly மறைந்துவிடவில்லை. பொறியாளர்கள் இன்னும் compiler சரியாக என்ன உருவாக்கியது என்பதைப் புரிந்துகொள்ள அதற்கு இறங்குகிறார்கள் (hot loops, பாதுகாப்பு ஆய்வு, reverse engineering), அல்லது மிகக் குறைந்த அடுக்குகளை எழுத — boot குறியீடு, interrupt handlers, kernel-இன் பாகங்கள் — அறிவுறுத்தல்-நிலை கட்டுப்பாடு தேவைப்படும் இடத்தில் உயர் abstractions மறைக்கும் அல்லது தடுக்கும்.

    இப்போது முயல்க. கீழே உள்ள mini-CPU lab தொடரில் மிக நேரடி hands-on இணைப்பு: வழிகாட்டும் நிரலை Assemble செய்து, பிறகு Step — ஒவ்வொரு mnemonic-உம் (LDI, ADD, STA, OUT) opcode பிட்களுக்கு ஒன்றுக்கு ஒன்று வரைபடமாகிறது, இந்தப் பதிவு விவரிப்பது போலவே. அதை விட abstraction இல்லை.

    இப்போது முயல்க: assembler-ஆக நீங்களே இருங்கள். இந்த lab-இன் assembler label-களை ஏற்காது — mnemonic, 0–15 எண் மட்டும் (lab மூலக் குறியீடு). அதனால் சுற்று 1, 2-ஐ நீங்கள் செய்ய வேண்டும்:

    1. மேலே “சுற்று 2” அட்டவணையின் ஒன்பது வரிகளை (label தீர்த்த வடிவம்: LDI 1, STA 15, LDI 3, OUT, SUB 15, JZ 7, JMP 3, OUT, HLT) மூல உரைப் பெட்டியில் எழுதி Assemble அழுத்துங்கள். நினைவக grid ஒவ்வொரு byte-ஐயும் மீண்டும் mnemonic ஆகக் காட்டும் (“0: LDI 1”, “5: JZ 7” …) — அது ஒரு சிறிய disassembler. Step செய்யும்போது IR பெட்டியில் hex வடிவம் தெரியும்: 51 4F 53 E0 3F 87 63 …
    2. Step-ஐ அழுத்திக்கொண்டே இருங்கள்: Output Register 3, 2, 1, 0 என மாறி, 16-ஆவது படியில் HALT.
    3. இப்போது முதல் வரியாக NOP சேர்த்து, மற்றதை மாற்றாமல் Assemble செய்து Run அழுத்துங்கள்: நிரல் நிற்காது, Output 3-இலேயே இருக்கும். Stop அழுத்துங்கள்.
    4. JZ 7 → JZ 8, JMP 3 → JMP 4 எனத் திருத்தி மீண்டும் Assemble, Run: இப்போது 17 படிகளில் HALT, Output 0. இந்தத் திருத்தத்தைத்தான் ஒரு assembler label-களிலிருந்து தானாகச் செய்கிறது.
