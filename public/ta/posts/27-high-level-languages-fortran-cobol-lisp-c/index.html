    உயர்நிலை மொழிகள்: FORTRAN, COBOL, Lisp, C

    ஜனவரி 1, 2026

    Assembly (பதிவு 26) machine code மேல் ஒன்றுக்கு-ஒன்று அடுக்கு — raw binary-ஐ விடச் சிறந்தது, இன்னும் நிரலாளரை அறிவுறுத்தல்கள், பதிவேடுகள், மற்றும் கையேடு layout-இல் சிந்திக்க வைக்கிறது. உயர்நிலை மொழிகள் வேறு ஒன்றை அறிமுகப்படுத்தின: வன்பொருளில் ஒன்றுக்கு ஒன்று வரைபடமாகாத abstractions. என்ன கணிக்க வேண்டும் என்பதை வெளிப்படுத்துங்கள்; compiler (பதிவு 28) எப்படி என்பதைக் கண்டுபிடிக்கும்.

    தமிழ் இடைவெளிக் குறிப்பு: FORTRAN, COBOL, Lisp மூன்றுக்கும் தமிழ் எழுத்து விளக்கம் மெலிதானது (Lisp-க்கு ஒரு குறுங்கட்டுரை மட்டும்); காணொளிச் சான்று YouTube தேடல் முடிவுகள் மட்டும் — காணொளிகள் பார்க்கப்படவில்லை. கீழே உள்ள நான்கு மொழி எடுத்துக்காட்டுகளும் எங்கள் பணிக் கணினியில் (Linux, x86-64) இன்றைய compiler-களில் உண்மையில் ஓட்டிச் சரிபார்த்தவை: GNU Fortran 14.2, GnuCOBOL 3.2, SBCL 2.5.2 (Common Lisp), GCC 14.2. இவை நவீனச் செயலாக்கங்கள் — 1950-60களின் அசல் compiler-கள் அல்ல; தொடரியல் அடிப்படையில் ஒத்தது. எண்ணிக்கைகள் (வரிகள், இயந்திரங்கள்) “எடுத்துக்காட்டு மதிப்புகள்”. இந்தப் பதிவுக்கு lab இல்லை; காகிதப் பயிற்சிகள் கீழே.

    முதலில் சொற்கள்#

    • உயர்நிலை மொழி (high-level language): வன்பொருள் அறிவுறுத்தல்களுக்கு ஒன்றுக்கு-ஒன்று பொருந்தாத abstraction-களில் நிரல் எழுதும் மொழி.
    • Compiler (தொகுப்பி): உயர்நிலை மூல உரையை இயந்திரக் குறியீடாக மாற்றும் நிரல் (பதிவு 28).
    • Imperative (கட்டளை பாணி): “இதைச் செய், பிறகு அதைச் செய்” என்று நிலையை மாற்றும் படிகளாக எழுதுவது — FORTRAN, COBOL, C.
    • Functional (செயல்கூறு பாணி): செயல்கூறுகளை (functions) மதிப்புகளாகக் கையாண்டு, அவற்றை இணைத்துக் கணிப்பது — Lisp-இன் வழி.
    • First-class value (முதல்-வகுப்பு மதிப்பு): மாறியில் வைக்க, அனுப்ப, திருப்பித் தர முடிந்த எதுவும்.
    • S-expression (குறியீட்டு வெளிப்பாடு): Lisp-இன் அடைப்புக்குறிப் பட்டியல் வடிவம்; குறியீடும் தரவும் ஒரே வடிவம்.
    • Pointer (சுட்டி): நினைவக முகவரியைக் கொண்ட மதிப்பு; C-இன் வன்பொருள் அருகாமையின் மையம்.
    • Portability (பெயர்வுத்திறன்): மென்பொருளை வேறு இயந்திரத்துக்கு மாற்றி ஓட்டக்கூடிய தன்மை.

    FORTRAN: Formula Translation#

    FORTRAN (1957, IBM) அறிவியல் மற்றும் பொறியியல் கணிப்புக்காகக் கட்டப்பட்டது — பெயர் “Formula Translation” என்று பொருள். வெளிப்படையான பதிவேடு ஒதுக்கீட்டுடன் எண்கணித அறிவுறுத்தல்களின் வரிசைக்குப் பதிலாக X = A * B + C எழுதுங்கள். அதற்கு உண்மையான compiler புத்திசாலித்தனம் தேவைப்பட்டது. தொடக்க சந்தேகம் தொகுக்கப்பட்ட குறியீடு கையால் எழுதப்பட்ட assembly-உடன் போட்டியிட முடியாது என்றது; FORTRAN-இன் compiler ஆக்ரோஷமான optimization மூலம் அது தவறு என்று நிரூபிக்க வேண்டியிருந்தது, மற்றும் பெரும்பாலும் நிரூபித்தது.

    ஒரு வரி, மூன்று அறிவுறுத்தல்கள்: C-இல் return a * b + c; என்ற function-ஐ gcc -O2 x86-64-க்குத் தொகுத்தபோது கிடைத்தது —

    imul  edi, esi          ; a × b
lea   eax, [rdi+rdx]    ; + c, முடிவு eax-இல்
ret

    எந்தப் பதிவேட்டில் எது வாழ்கிறது, எந்த instruction கூட்டலைச் செய்கிறது (இங்கே add அல்ல, முகவரிக் கணக்கீட்டு instruction lea!) — இவற்றை compiler தேர்ந்தெடுத்தது. FORTRAN-இன் X = A * B + C வாக்குறுதி இதுதான்: நிரலாளர் சூத்திரத்தை எழுதுகிறார், பதிவேடு ஒதுக்கீட்டை அல்ல.

    COBOL: அறிவியல் அல்ல, வணிகம்#

    COBOL (1959–60, CODASYL) வேறு துறையை இலக்கு வைத்தது: ஊதியம், கணக்கியல், சரக்கு — வணிகத் தரவு செயலாக்கம், அறிவியல் அல்ல. Grace Hopper COBOL-ஐத் தானே எழுதவில்லை, ஆனால் அவரது முந்தைய FLOW-MATIC முதன்மை செல்வாக்கு, மற்றும் அந்தச் செல்வாக்கு மற்றும் அவரது வாதத்திற்காக அவர் அடிக்கடி “COBOL-இன் தாய்” என வரவு வைக்கப்படுகிறார். வடிவமைப்புத் தேர்வு: விரிவான, ஆங்கிலம்-போன்ற தொடரியல் (ADD SALARY TO TOTAL-PAY), நிரலாளர் அல்லாத ஆய்வாளர்கள் மற்றும் தணிக்கையாளர்களால் வாசிக்கக்கூடியதாக. Legacy மிகப் பெரியது மற்றும் இன்னும் குறைவாகப் பாராட்டப்படுகிறது: மைய வங்கி, காப்பீடு, மற்றும் அரசு அமைப்புகளின் கணிசமான பகுதி இன்னும் தசாப்தங்களுக்கு முன் எழுதப்பட்ட COBOL ஓட்டுகிறது — mission-critical நிதி அமைப்புகளை மீண்டும் எழுதுவது போதுமான அளவு விலையுயர்ந்ததும் ஆபத்தானதும், பல நிறுவனங்கள் அசலைப் பராமரிப்பதைத் தேர்வு செய்கின்றன.

    ஒரே கணக்கு, நான்கு மொழிகள் (ஓட்டிச் சரிபார்த்தவை)#

    A = 6, B = 7, C = 8 என்றால் X = A × B + C = 42 + 8 = 50. ஒவ்வொரு மொழியிலும் மையவரி:

    மொழி மையவரி வெளியீடு (எங்கள் ஓட்டம்)
    FORTRAN X = A * B + C 50.0000000 (REAL மாறி)
    COBOL ADD SALARY TO TOTAL-PAY. (SALARY = 42, பிறகு BONUS = 8 சேர்த்து) TOTAL-PAY = 00050
    Lisp (+ (* *a* *b*) *c*) 50
    C int x = a * b + c; 50

    கவனிக்க வேண்டியவை:

    • COBOL-இல் TOTAL-PAY PIC 9(5) என்று அறிவித்தது — ஐந்து தசம இலக்கங்கள். அதனால்தான் 00050: வணிகத் தரவு நிலைத்த அகலத் தசம எண்கள், அச்சிட்ட அறிக்கையின் நெடுவரிசை போல.
    • அதே நிரலில் SALARY = 99990, BONUS = 20 என்று மாற்றினால்: 99,990 + 20 = 100,010, ஆனால் ஐந்து இலக்கங்களில் இடமில்லை — GnuCOBOL 3.2 அச்சிட்டது TOTAL-PAY = 00010. மேல் இலக்கம் அமைதியாக வெட்டப்பட்டது. (COBOL-இல் இதைப் பிடிக்க ON SIZE ERROR பிரிவு உண்டு.) ஊதிய நிரலில் இது ஏன் முக்கியம் என்று ஊகிக்கலாம்.
    • FORTRAN REAL மிதவைப் புள்ளி எண் (50.0000000); அறிவியலுக்கு ஏற்றது, பணத்துக்கு அல்ல — COBOL-இன் தசம வடிவம் அதனால்தான்.

    Lisp: வேறு paradigm#

    Lisp (1958, John McCarthy) FORTRAN மற்றும் COBOL-இன் imperative பாணியை முழுவதுமாக விட்டுவிட்டது — functions முதல்-வகுப்பு மதிப்புகளாக, மற்றும் குறியீடும் தரவும் அதே பட்டியல் கட்டமைப்பைப் பகிரும் குறைந்தபட்ச ஒரேமாதிரி தொடரியல். பாணி மட்டும் அல்ல: runtime-இல் மற்ற நிரல்களைக் கட்டி இயக்கும் நிரல்கள் AI மற்றும் குறியீட்டு கணிப்பின் தசாப்தங்களுக்கு அடிப்படையானவை, மற்றும் இன்றும் முதன்மை மொழிகளில் functional அம்சங்களைச் செல்வாக்கு செலுத்துகின்றன.

    குறியீடே தரவு: Lisp-இல் ஒரு சோதனை (ஓட்டிச் சரிபார்த்தது)#

    SBCL-இல்:

    (defvar *expr* (list '+ (list '* 6 7) 8))
(print *expr*)                      ; → (+ (* 6 7) 8)
(print (length *expr*))             ; → 3
(print (eval *expr*))               ; → 50
(print (eval (list '* 2 *expr*)))   ; → 100

    *expr* ஒரு சாதாரணப் பட்டியல் — மூன்று உறுப்புகள்: +, (* 6 7), 8. அதை length-ஆல் எண்ணலாம், தரவைப் போல. அதையே eval-க்குக் கொடுத்தால் நிரலாக ஓடி 50 தருகிறது. கடைசி வரி: ஓடும்போதே ஒரு புதிய நிரலைக் கட்டி — “2 × (பழைய நிரல்)” — ஓட்டுகிறது: 2 × 50 = 100. ஆங்கிலப் பதிவு சொல்லும் “runtime-இல் மற்ற நிரல்களைக் கட்டி இயக்கும் நிரல்கள்” இதுதான்.

    C: Systems நிரலாக்கம், இயந்திரத்திற்கு அருகில்#

    C (1972, Dennis Ritchie, Unix உடன் உருவாக்கப்பட்டது — பதிவு 22) இன்னொரு வர்த்தகத்தை எடுத்தது: assembly மேல் உண்மையான உற்பத்தித்திறனுக்கு போதுமான உயர்நிலை, முழு OS kernel-ஐ அதில் எழுதக்கூடிய அளவுக்கு வன்பொருளுக்கு அருகில் — அப்போது அசாதாரணம். Pointer எண்கணிதம், குறைந்தபட்ச runtime, machine ops-க்கு கணிக்கக்கூடிய வரைபடம் Unix-ஐ portable ஆக்கியது: ஒவ்வொரு இலக்கின் assembly-இல் OS-ஐ மீண்டும் எழுதாமல், C compiler-ஐப் புதிய இயந்திரத்திற்கு port செய்யுங்கள்.

    பெயர்வுத்திறனின் கணக்கு (எடுத்துக்காட்டு மதிப்புகள்): ஒரு OS 20,000 வரிகள். முழுவதும் assembly-இல் இருந்தால், 4 புதிய இயந்திரங்களுக்கு 4 × 20,000 = 80,000 வரிகளை மீண்டும் எழுத வேண்டும். 95% C, 5% assembly என்றால், ஒவ்வொரு இயந்திரத்துக்கும் C compiler-ஐ port செய்து, 20,000 × 0.05 = 1,000 assembly வரிகளை மட்டும் மீண்டும் எழுதினால் போதும்: 4 × 1,000 = 4,000 வரிகள் — 20 மடங்கு குறைவு.

    பொது இழை#

    ஒவ்வொரு மொழியும் வேறு முன்னுரிமைக்கு optimize செய்தது — FORTRAN எண் வெளிப்பாட்டிற்கு, COBOL வணிக வாசிப்புத்திறனுக்கு, Lisp குறியீட்டு abstraction-க்கு, C systems-நிலை கட்டுப்பாட்டிற்கு — மற்றும் ஒவ்வொன்றும் இன்னும் இன்றைய வடிவமைப்பை வடிவமைக்கிறது. அவை பகிர்வது, மற்றும் அவற்றில் ஏதேனும் பயன்படுத்தக்கூடியதாக ஆக்குவது, abstraction-ஐ நிரலாளர் கையால் மொழிபெயர்க்காமல் திறமையான machine code-ஆக மாற்றும் compiler. அந்தச் செயல்முறை — மற்றும் “optimization” உறுதியாக என்ன பொருள் — அடுத்த பதிவு.

    காகிதப் பயிற்சிகள் (விடைகளுடன்)#

    1. A = 3, B = 9, C = −2. FORTRAN-இன் X = A * B + C என்ன தரும்? C-இன் a * b + c என்ன? விடை: 3 × 9 = 27; 27 + (−2) = 25 இரண்டிலும் — பெருக்கல் கூட்டலுக்கு முன் (இரண்டு மொழிகளிலும் அதே முன்னுரிமை).

    2. Lisp-இல் (+ (* 2 3) (* 4 5)) என்ன மதிப்பு? அந்தப் பட்டியலில் எத்தனை மேல்நிலை உறுப்புகள்? விடை: 6 + 20 = 26; உறுப்புகள் +, (* 2 3), (* 4 5) → 3.

    3. COBOL-இல் PIC 9(4) புலத்தில் 9,995 இருக்கிறது. அதனுடன் 7 சேர்த்தால், size error பிடிக்காமல், மேலே கண்ட வெட்டுதல் நடத்தையில் என்ன தெரியும்? விடை: 9,995 + 7 = 10,002; நான்கு இலக்கங்களில் மேல் இலக்கம் வெட்டப்பட்டு 0002.

    4. எடுத்துக்காட்டு மதிப்புகள்: 50,000 வரி OS, 3% assembly, 6 இயந்திரங்கள். C-உடன் எத்தனை வரிகள் மீண்டும் எழுத வேண்டும்? முழு assembly என்றால்? விடை: 50,000 × 0.03 = 1,500; × 6 = 9,000. முழு assembly: 50,000 × 6 = 300,000 — 33⅓ மடங்கு அதிகம்.

    5. ஒரு வங்கி 40 ஆண்டுப் பழைய COBOL அமைப்பை ஏன் மீண்டும் எழுதாமல் பராமரிக்கிறது? விடை: ஆங்கிலப் பதிவு சொல்வதுபடி, mission-critical நிதி அமைப்பை மீண்டும் எழுதுவது விலையுயர்ந்ததும் ஆபத்தானதும்; பல தசாப்தங்களாகச் சோதிக்கப்பட்ட நடத்தையை — மேலே கண்ட தசம, வெட்டுதல் விதிகள் உட்பட — புதிய மொழியில் பிழையின்றி மீண்டும் உருவாக்குவது கடினம்.

    Door out: Dennis M. Ritchie, “The Development of the C Language” (HOPL-II / ACM) — Unix அருகே C வடிவமைப்பின் முதன்மைக் கணக்கு; Lisp-இன் நிறுவனக் கூற்றுக்கு, குறியீட்டு வெளிப்பாடுகளின் recursive functions பற்றிய John McCarthy-இன் தொடக்க CACM கட்டுரைகளைப் பாருங்கள்.
