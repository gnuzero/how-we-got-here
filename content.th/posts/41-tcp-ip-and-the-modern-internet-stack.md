ARPANET (บทที่ 39) พิสูจน์ว่า packet switching ใช้ได้ Ethernet (บทที่ 40) ทำให้การเชื่อมต่อท้องถิ่นเป็นมาตรฐาน ไม่มีอย่างใดอย่างหนึ่งเพียงอย่างเดียวที่กำหนดวิธีเชื่อมเครือข่าย *ต่างกัน* — เทคโนโลยีกายภาพต่างกัน แบบแผน addressing ต่างกัน — เข้าเป็นอินเตอร์เน็ตเวิร์กที่สอดคล้องเดียวที่เครื่องสองเครื่องใด ๆ ใช้ถึงกันได้ TCP/IP คือชุดโปรโตคอลที่แก้ปัญหานั้น และยังเป็นรากฐานที่อินเทอร์เน็ตสมัยใหม่รันอยู่

## แบบจำลองแบบชั้น

TCP/IP จัดเป็นชั้น แต่ละชั้นจัดการข้อกังวลต่างกันและพึ่งเพียงชั้นที่อยู่ใต้โดยตรง — หลักการจัดโครงสร้างเดียวกับสแต็กแบบชั้นของ PCIe ในบทที่ 33 นำไปใช้ที่นี่ในระดับอินเตอร์เน็ตเวิร์ก **Link layer** จัดการเทคโนโลยีเครือข่ายกายภาพสำหรับฮอปที่กำหนด — Ethernet, Wi-Fi หรือสิ่งที่มีในท้องถิ่น **Internet layer** (IP) ให้ addressing และ routing สากล *ข้าม* เทคโนโลยีลิงก์ต่างกัน — แพ็กเก็ต IP ไม่สนใจว่ากำลังเดินทางบน Ethernet, Wi-Fi หรือ backbone ไฟเบอร์; นั่นเป็นเรื่องของ Link layer **Transport layer** (TCP หรือ UDP) ให้การส่งมอบที่เชื่อถือได้มีลำดับ (TCP) หรือการส่งมอบ best-effort ไม่ว่างานลำดับ overhead ต่ำ (UDP) ทับบริการส่งต่อแพ็กเก็ตของ IP **Application layer** คือที่โปรโตคอลที่แอปใช้ — HTTP, DNS, SMTP — ทำงาน บน transport ที่เหมาะกับความต้องการ

## Encapsulation: Header ตลอดทางลง

ข้อมูลที่เคลื่อน *ลง* ผ่านชั้นเหล่านี้ได้ header ในแต่ละขั้น — ข้อมูลแอปได้ TCP (หรือ UDP) header กลายเป็น segment; segment นั้นได้ IP header กลายเป็นแพ็กเก็ต; แพ็กเก็ตนั้นได้ Link-layer header (และมัก trailer) กลายเป็นเฟรมพร้อมส่ง ที่ฝั่งรับ กระบวนการวิ่งย้อนกลับ: แต่ละชั้นลอก header ของตัวเองและส่งส่วนที่เหลือขึ้น โดยใช้ข้อมูลใน header ที่เพิ่งบริโภค (หมายเลขพอร์ตสำหรับ TCP ที่อยู่สำหรับ IP) เพื่อตัดสินว่า payload ไปที่ใดต่อไป จนถึงแอปที่ถูกต้อง

## การรับประกันความเชื่อถือได้ของ TCP และวิธีที่ Handshake ทำงาน

IP เองเป็น best-effort อย่างชัด — ไม่มีสัญญาการส่งมอบ การจัดลำดับ หรือว่าแพ็กเก็ตจะไม่ถูกทิ้งระหว่างทาง TCP สร้างกระแสไบต์ที่เชื่อถือได้มีลำดับทับพื้นผิวที่ไม่เชื่อถือได้นั้น โดยใช้หมายเลขลำดับ (เพื่อให้แพ็กเก็ตนอกลำดับหรือซ้ำตรวจและแก้ได้) และการยืนยัน (acknowledgment เพื่อให้ผู้ส่งรู้ว่าอะไรได้รับแล้ว และส่งซ้ำสิ่งที่ดูเหมือนหาย) — คล้ายกลไกความเชื่อถือได้ที่ Data Link Layer ของ PCIe ใช้ในบทที่ 33 ทำงานข้ามอินเตอร์เน็ตเวิร์กที่ไม่เชื่อถือได้ทั้งก้อนแทนลิงก์เฉพาะเส้นเดียว

การตั้งการเชื่อมต่อ TCP ใช้ three-way handshake: ไคลเอนต์ส่ง SYN เสนอหมายเลขลำดับเริ่มต้น; เซิร์ฟเวอร์ตอบด้วย SYN-ACK ยืนยันหมายเลขลำดับของไคลเอนต์และเสนอของตัวเอง; ไคลเอนต์ตอบด้วย ACK สุดท้าย หลังการแลกเปลี่ยนนี้เสร็จเท่านั้น ทั้งสองฝั่งจึงถือว่าการเชื่อมต่อตั้งแล้วและเริ่มแลกข้อมูลแอป — ต้นทุนเล็กน้อยโดยเจตนาเพื่อให้ทั้งสองฝั่งมีสถานะซิงค์ก่อนข้อมูลจริงไหล

## เหตุใดการออกแบบนี้ชนะ

การตัดสินใจออกแบบที่เป็นเสาหลักของ TCP/IP คือการถือว่าเครือข่ายพื้นฐานไม่เชื่อถือได้และต่างชนิดโดยธรรมชาติ และสร้างการรับประกัน (เมื่อต้องการ) ที่ชั้นสูงกว่า แทนการสมมติว่าทุกลิงก์กายภาพจะให้พวกมันมาแต่กำเนิด การสมมตินั้นถูกสำหรับอินเตอร์เน็ตเวิร์กโลกที่เย็บจากเทคโนโลยีกายภาพต่างกัน เพิ่มทีละทศวรรษ โดยองค์กรที่ไม่เคยประสานบนมาตรฐานกายภาพเดียว — ซึ่งคือเหตุผลที่ TCP/IP ยังเป็นรากฐาน addressing และ transport ใต้เกือบทั้งอินเทอร์เน็ตสมัยใหม่ รวมเครือข่ายระดับศูนย์ข้อมูลในบทถัดไป
