บทที่ 10 วางลำดับชั้นหน่วยความจำไว้แล้ว: รีจิสเตอร์, แคช SRAM, หน่วยความจำหลัก DRAM, ดิสก์ — แต่ละระดับแลกความจุกับความเร็ว แคชคือจุดที่การแลกเปลี่ยนนั้นกลายเป็นสิ่งแบกรับน้ำหนักสำหรับประสิทธิภาพของ CPU ทุกตัว สมมติฐานของมันวางบนข้อสังเกตเชิงประจักษ์เกี่ยวกับโปรแกรมจริงข้อเดียว: locality

## Locality สองชนิด

**Temporal locality:** หากโปรแกรมเข้าถึงตำแหน่งหน่วยความจำตำแหน่งหนึ่ง มีแนวโน้มว่าจะเข้าถึงตำแหน่ง *เดิม* อีกในไม่ช้า (ตัวแปรลูป โค้ดฟังก์ชันที่ถูกเรียกบ่อย) **Spatial locality:** หากโปรแกรมเข้าถึงตำแหน่งหนึ่ง มีแนวโน้มว่าจะเข้าถึงตำแหน่ง *ใกล้เคียง* ในไม่ช้าเช่นกัน (การไล่ผ่านอาร์เรย์ การดึงคำสั่งตามลำดับ) แคชใช้ประโยชน์ทั้งสอง — temporal ด้วยการเก็บข้อมูลที่ใช้ล่าสุดไว้ spatial ด้วยการดึง cache *line* ทั้งก้อน (โดยทั่วไป 64 ไบต์) ทีเดียวแทนคำเดียว เดิมพันว่าไบต์ข้างเคียงจะถูกต้องการในไม่ช้า

## การแยกที่อยู่: Tag, Index, Offset

ที่อยู่หน่วยความจำถูกแยกเป็นสามฟิลด์สำหรับการค้นแคช บิต **offset** เลือกไบต์เฉพาะภายใน cache line บิต **index** เลือก "set" ของแคชที่ที่อยู่นี้แมปไป บิตสูงที่เหลือคือ **tag** เก็บคู่กับข้อมูลในแคช — ใช้ยืนยันว่า line ที่มีอยู่ที่ index นั้นตรงกับที่อยู่ที่กำลังค้นจริง ๆ ไม่ใช่ที่อยู่อื่นที่แมปไป index เดียวกัน

## Direct-Mapped, Set-Associative, Fully-Associative

แคช **direct-mapped** ให้ทุกที่อยู่มีตำแหน่งที่เป็นไปได้พอดีหนึ่งตำแหน่ง ถูกกำหนดโดยบิต index อย่างเดียว ง่ายและตรวจเร็ว แต่เสี่ยง conflict miss: ที่อยู่ที่ใช้บ่อยสองตำแหน่งที่แชร์ index เดียวกันไล่กันออกตลอด แม้แคชส่วนที่เหลือจะว่าง

แคช **fully-associative** อนุญาตให้ที่อยู่ใดอยู่ที่ line ใดก็ได้ — ไม่มีข้อจำกัดตาม index — ซึ่งกำจัด conflict miss โดยสิ้นเชิง แต่ต้องตรวจ tag ของทุก line ทุกครั้งที่เข้าถึง แพงและไม่ขยายขนาดได้ดีสำหรับแคชใหญ่

**Set-associative** คือจุดกลางเชิงปฏิบัติที่แคชจริงเกือบทุกตัวใช้: index เลือก *set* เล็กของตำแหน่งที่เป็นไปได้ (เช่น 8-way associative หมายถึง 8 line ต่อ set) และ tag ถูกตรวจเทียบเฉพาะผู้สมัครเหล่านั้น จับความยืดหยุ่นของ fully-associative ส่วนใหญ่ได้ในต้นทุนฮาร์ดแวร์ต่ำกว่ามากเมื่อเทียบกับการสแกนแคชทั้งก้อนทุกครั้ง

## Coherence: ภาวะแทรกซ้อนของ Multicore

เมื่อมีมากกว่าหนึ่งคอร์ แต่ละคอร์อาจมีแคชส่วนตัวของตัวเอง ปัญหาใหม่ปรากฏ: จะเกิดอะไรขึ้นเมื่อคอร์ A แก้ค่าที่คอร์ B ก็มีในแคชด้วย? หากไม่มีโปรโตคอล coherence คอร์ B อาจอ่านค่าเก่าต่อไปไม่มีกำหนด MESI (Modified, Exclusive, Shared, Invalid) คือคำตอบคลาสสิก — ทุก cache line ถูกแท็กด้วยหนึ่งในสี่สถานะนี้ และคอร์สื่อสารการเปลี่ยนสถานะ (โดยทั่วไปด้วยการ snoop บนบัสร่วม หรือผ่าน directory ในระบบใหญ่กว่า) เพื่อให้การเขียนของคอร์หนึ่งทำให้ line เดียวกันที่แคชอยู่ที่อื่นถูก invalidate หรืออัปเดตอย่างถูกต้อง

Coherence เป็นหนึ่งในปัญหาที่ยากในการออกแบบ multicore มันไม่ฟรี และต้นทุนโตตามจำนวนคอร์ — เหตุผลจริงว่าเหตุใด "แค่เพิ่มคอร์" (บทที่ 17) จึงมีผลตอบแทนลดลงของตัวเอง แยกจากขีดจำกัด ILP ที่บทนั้นโฟกัส
