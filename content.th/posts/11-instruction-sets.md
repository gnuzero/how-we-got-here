Instruction Set Architecture (ISA) คือสัญญาระหว่างซอฟต์แวร์กับฮาร์ดแวร์: การดำเนินการที่โพรเซสเซอร์รองรับ และการเข้ารหัสบิตที่แน่นอนที่เรียกใช้พวกมัน มันคือสเปก ไม่ใช่ชิปทางกายภาพ x86, ARM และ RISC-V เป็น ISA; ชิปต่างกันหลายตัวสามารถ implement ตัวเดียวกันได้

## สิ่งที่มีอยู่ใน ISA จริง ๆ

ISA กำหนดชุดรีจิสเตอร์ (มีกี่ตัว กว้างแค่ไหน) การเข้ารหัสคำสั่ง (รูปแบบ opcode ฟิลด์ตัวถูกดำเนินการ) โหมดการระบุที่อยู่หน่วยความจำ (คำสั่งอ้างอิงหน่วยความจำอย่างไร) และความหมายของการดำเนินการทุกอย่าง — ADD ทำอะไรกับแฟล็ก การหารจัดการกรณีขอบอย่างไร เป็นต้น ชิปสองตัวที่ทั้งคู่ implement เช่น RISC-V สามารถรันไบนารีที่คอมไพล์แล้วชุดเดียวกันและให้ผลเหมือนกัน แม้ไมโครสถาปัตยกรรมภายใน (ไปป์ไลน์ แคช การประมวลผลนอกลำดับ — ทั้งหมดกล่าวถึงภายหลังในเฟสนี้) จะต่างกันโดยสิ้นเชิง การแยกระหว่างสถาปัตยกรรม (สิ่งที่ซอฟต์แวร์เห็น) กับไมโครสถาปัตยกรรม (ฮาร์ดแวร์สร้างอย่างไร) คือหนึ่งในแนวคิดสำคัญที่สุดในชุดนี้

## CISC กับ RISC: สองปรัชญา

CISC (Complex Instruction Set Computing) — สายเลือดของ x86 — ชอบคำสั่งที่ทำมากต่อคำสั่ง: การเข้ารหัสความยาวแปรได้ โหมดระบุที่อยู่ซับซ้อน และคำสั่งเดียวที่รวมการเข้าถึงหน่วยความจำกับเลขคณิต ปรัชญา: คำสั่งน้อยลง แต่เข้มข้นกว่าต่อโปรแกรม ประหยัดหน่วยความจำคำสั่งและลดจำนวนครั้งที่ดึง แลกกับดีโค้ดเดอร์ที่ซับซ้อนกว่ามาก

RISC (Reduced Instruction Set Computing) ชอบตรงกันข้าม: คำสั่งความยาวคงที่ แบบจำลอง load/store เข้มงวด (เลขคณิตทำงานเฉพาะบนรีจิสเตอร์ ไม่เคยบนหน่วยความจำโดยตรง) และการระบุที่อยู่ที่เรียบง่าย สม่ำเสมอ ปรัชญา: ให้ทุกคำสั่งเรียบง่ายและดีโค้ดเร็ว และให้คอมไพเลอร์ปล่อยคำสั่งมากขึ้นถ้าจำเป็น ความสม่ำเสมอนั้นคือสิ่งที่ทำให้ไปป์ไลน์ (บทที่ 13) จัดการได้ — คำสั่งความยาวคงที่ โครงสร้างสม่ำเสมอ ดึงและดีโค้ดแบบคาดเดาได้ง่ายกว่ามาก ทีละขั้น มากกว่าคำสั่ง CISC ที่ความยาวยังไม่รู้จนกว่าจะดีโค้ดไปบางส่วนแล้ว

## การเข้ารหัส แบบจับต้องได้

คำสั่ง RISC โดยทั่วไปยาว 32 บิต แบ่งเป็นฟิลด์คงที่: opcode รีจิสเตอร์ต้นทาง รีจิสเตอร์ปลายทาง และ (สำหรับคำสั่ง immediate) ค่าคงที่ — ทุกคำสั่งกว้างเท่ากัน ทุกฟิลด์อยู่ในตำแหน่งที่คาดเดาได้ คำสั่ง x86 ในทางตรงกันข้าม ยาวตั้งแต่ 1 ไบต์ถึง 15 ไบต์ มีพรีฟิกซ์ ไบต์ opcode และการเข้ารหัสตัวถูกดำเนินการที่เป็นทางเลือกทั้งหมดแปรได้ — หนาแน่นและทรงพลัง แต่ดีโค้ดที่ปริมาณงานสูงได้ยากกว่า

## เหตุใด x86 จึงยังอยู่ต่อไป

หาก RISC สร้างไปป์ไลน์เร็วรอบตัวได้ง่ายกว่า เหตุใด x86 ยังครองการคำนวณเดสก์ท็อปและเซิร์ฟเวอร์? ส่วนใหญ่คือความเข้ากันได้ของซอฟต์แวร์และการลงทุนปรับแต่งที่สะสมมานานหลายทศวรรษ — ไม่ใช่ความเหนือกว่าเชิงสถาปัตยกรรมดิบ บทที่ 19 กล่าวถึงความตึงเครียดนี้ลึก: ชิป x86 สมัยใหม่ *แปล* คำสั่ง CISC เป็นไมโคร-ออปภายในที่เรียบง่ายแบบ RISC แล้วรันพวกนั้นบนคอร์แบบ RISC หลังฟรอนต์เอนด์ที่เข้ากันได้กับ CISC การประนีประนอมนั้นเป็นส่วนใหญ่ของเหตุผลที่การถกเถียง CISC/RISC วันนี้ไม่ใช่ทวิภาคที่สะอาดเท่าที่บทนี้อาจบอก บทถัดไปเริ่มสร้าง datapath จริง — โครงสร้างทางกายภาพที่ ISA ทำงานอยู่บน
