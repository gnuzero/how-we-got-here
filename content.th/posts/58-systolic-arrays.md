บทที่ 55 ครอบคลุม tensor core — ฮาร์ดแวร์คูณเมทริกซ์เฉพาะทางที่ฝังใน GPU ที่ยังอเนกประสงค์อยู่ Systolic array เอาไอเดียการเฉพาะทางไปไกลกว่า: สถาปัตยกรรมชิปทั้งก้อน จากพื้น จัดรอบการสตรีมข้อมูลผ่านกริดของ processing element ง่าย ๆ เพื่อการคูณเมทริกซ์ — TPU (Tensor Processing Unit) ของ Google เป็นตัวอย่างโลกจริงที่เด่นที่สุด

## ไอเดียแก่น: ข้อมูลไหล การคำนวณเกิดระหว่างทาง

Systolic array คือกริด 2 มิติของ processing element ง่าย ๆ แต่ละตัวทำปฏิบัติการ multiply-accumulate พื้นฐาน จัดให้ข้อมูลเคลื่อนผ่านกริดในแบบแผนประสานเป็นจังหวะ แต่ละ PE ทำ MAC เมื่อข้อมูลมาถึง ในออกแบบ weight-stationary (อย่างใน MXU ของ TPU ของ Google) น้ำหนักถูกโหลดล่วงหน้าและถือไว้ใน PE ขณะที่ activation สตรีมข้ามอาร์เรย์ และผลย่อยแพร่ไปเพื่อนบ้าน — "heartbeat" แบบ systolic ไม่ใช่ทั้งสอง operand ไหลอิสระ ชื่อ "systolic" อ้างจงใจถึงการสูบเป็นจังหวะของหัวใจ — ข้อมูลเต้นผ่านอาร์เรย์เป็นคลื่นประสาน แทนการถูกดึงและประมวลโดยเส้นทางควบคุมกลางที่แชร์แบบที่สถาปัตยกรรมทั่วไปมักทำงาน

## Dataflow แบบ Weight-Stationary

การออกแบบ systolic array ที่พบบ่อยถือค่าน้ำหนักให้ *นิ่ง* — โหลดเข้าแต่ละ processing element ครั้งเดียวแล้วถือไว้ — ขณะที่ข้อมูล activation อินพุตสตรีมผ่านอาร์เรย์ ถูกคูณกับน้ำหนักนิ่งของแต่ละองค์ประกอบเมื่อผ่าน โดยผลย่อยสะสมและแพร่ผ่านกริด ผลตอบแทนตรง: เมื่อโหลดแล้ว น้ำหนักไม่ต้องถูกดึงจากหน่วยความจำใหม่ทุก multiply-accumulate — พวกมันนั่งที่เดิม ท้องถิ่น ขณะที่ข้อมูล activation สตรีมผ่าน เนื่องจากความกังวลแบนด์วิดท์หน่วยความจำจากบทที่ 35 และบทที่ 54 เป็นแกนตลอดชุดนี้ สิ่งนั้นสำคัญมหาศาล การลดว่าข้อมูลต้องเคลื่อนไปและจากหน่วยความจำบ่อยเพียงใด — โดยถือค่าที่ถูกใช้ซ้ำบ่อย (น้ำหนัก) ให้อยู่ที่ไซต์คำนวณทางกายภาพ — คือการลดการเคลื่อนข้อมูลแบบที่ระบบถูกจำกัดด้วยแบนด์วิดท์หน่วยความจำได้ประโยชน์มากที่สุด

## เหตุใดสิ่งนี้ต่างจาก Tensor Core ของ GPU

Tensor core ของ GPU ฝังในสถาปัตยกรรม SIMT ที่ยังอเนกประสงค์โดยพื้นฐาน (บทที่ 52–53) — รัน workload ขนานกว้างเกินการคูณเมทริกซ์ได้ โดยมี tensor core เป็นตัวเร่งเฉพาะทาง *ภายใน* สถาปัตยกรรมที่ยืดหยุ่นนั้น ชิป systolic array อย่าง TPU เดิมพันแคบกว่า รุนแรงกว่า: ชิป *ทั้งก้อน* ถูกจัดรอบการคูณเมทริกซ์ที่มีประสิทธิภาพ โดยความยืดหยุ่นน้อยกว่าตามสัดส่วนสำหรับ workload ขนานหลากที่ GPU อเนกประสงค์ก็จัดการได้ดี

นี่คือ tradeoff สถาปัตยกรรมจริง ไม่ใช่เพียง "TPU ดีกว่าเด็ดขาด" หรือ "GPU ดีกว่าเด็ดขาด" Systolic array สามารถได้ประสิทธิภาพยอดเยี่ยมสำหรับ workload ที่การคูณเมทริกซ์ครอง ซึ่งมันถูกสร้างรอบ โดยมีต้นทุนความยืดหยุ่นสำหรับ workload ที่ไม่พอดีรูปทรงนั้นสะอาดเท่า GPU ที่คงความยืดหยุ่นอเนกประสงค์มากกว่า จัดการ workload ขนานหลากชนิดได้กว้างกว่า — รวม compute ที่ไม่ใช่การคูณเมทริกซ์จำนวนมาก — โดยมีต้นทุนเทียบกับประสิทธิภาพของ systolic array บนกรณีคูณเมทริกซ์แคบที่มันถูก optimize รุนแรงที่สุด

## MXU: Systolic Array ในฐานะองค์ประกอบหนึ่ง

ในสถาปัตยกรรม TPU ของ Google โดยเฉพาะ Matrix Multiply Unit (MXU) คือองค์ประกอบ systolic array ที่รับปริมาณงานคูณเมทริกซ์ส่วนใหญ่ รวมกับ logic สนับสนุน (ควบคุม อินเทอร์เฟซหน่วยความจำ หน่วยเวกเตอร์สำหรับส่วนที่ไม่ใช่การคูณเมทริกซ์ของ workload) เป็นชิปที่ deploy ได้ครบ — systolic array คือหัวใจเฉพาะทางของการออกแบบ ไม่ใช่ logic ทั้งก้อนของชิป การจับคู่โครงสร้าง compute แก่นที่เฉพาะทางสูงกับ logic สนับสนุนที่อเนกประสงค์พอที่รายล้อม คือแบบแผนที่เกิดซ้ำข้ามตัวเร่งเฉพาะทางเกือบทุกตัวที่เฟสสุดท้ายนี้ครอบคลุม
