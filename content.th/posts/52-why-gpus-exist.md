ทุก CPU ที่ครอบคลุมในเฟส 3 พักบนสมมติฐานหลัก: คำสั่งเป็นอิสระและคาดเดายากพอที่เครื่องจักรต้องเป็นอเนกประสงค์ — การทำนายสาขา การรันนอกลำดับ แคชลึก ทั้งหมดเพื่อรับใช้การรันโค้ดลำดับ *ใดก็ได้* ให้เร็วที่สุด GPU เริ่มจากสมมติฐานต่าง ที่รากใน workload ดั้งเดิม: การเรนเดอร์กราฟิก ที่ปฏิบัติการ *เดียวกัน* ต้องถูกนำไปใช้กับจุดข้อมูลจำนวนมหาศาลพร้อมกันอย่างอิสระ

## ความขนานธรรมชาติของท่อกราฟิก

การเรนเดอร์ฉาก 3D หมายถึงการแปลงจุดยอดนับล้านและการ shade พิกเซลนับล้าน — และปฏิบัติการทางคณิตศาสตร์เดียวกัน (การแปลงจุดยอด การคำนวณแสง) ถูกนำไปใช้กับแต่ละจุดอย่างอิสระ ไม่มีการพึ่งพาข้อมูลที่มีความหมายระหว่างการ shade ของพิกเซล (100, 200) กับการ shade ของพิกเซล (100, 201) — หากมีฮาร์ดแวร์ขนานพอ พวกมันทั้งหมดคำนวณพร้อมกันได้

นั่นคือรูปร่างปัญหาต่างจากสิ่งที่ microarchitecture ของ CPU (เฟส 3) ถูกสร้างมาจัดการ การรันนอกลำดับและการทำนายสาขาของ CPU มีอยู่เพื่อสกัดความขนานจากโค้ดที่ *ไม่มี* โครงสร้างขนานชัดแบบ embarrassingly parallel นี้ — โปรแกรมลำดับทั่วไปที่มีสาขาคาดเดายากและการพึ่งพาข้อมูลจริงระหว่างคำสั่งใกล้เคียง การเรนเดอร์กราฟิกไม่ต้องการเครื่องจักรนั้นเพื่อสกัดความขนานซ่อน เพราะความขนานไม่ได้ซ่อน — มันชัดและมหาศาลตั้งแต่ต้น

## SIMD และ SIMT: คำสั่งเดียว ข้อมูลหลายชิ้น

SIMD (Single Instruction, Multiple Data) คือแนวคิดทั่วไป: คำสั่งเดียวถูกนำไปใช้พร้อมกันข้ามองค์ประกอบข้อมูลหลายชิ้น แทนคำสั่งเดียวที่ทำงานบนข้อมูลชิ้นเดียวต่อครั้ง GPU implement โมเดลที่เกี่ยวข้องใกล้เรียกว่า SIMT (Single Instruction, Multiple Thread) — "เธรด" ขนานหลายเส้น แต่ละเส้นโดยนามรันสตรีมคำสั่งเดียวกัน แต่ละเส้นทำงานบนข้อมูลต่างของตัวเอง (พิกเซลของตัวเอง จุดยอดของตัวเอง) โดยฮาร์ดแวร์รันกลุ่มเธรดเหล่านี้แบบ lockstep ข้ามเลนการรันขนานง่าย ๆ หลายเลน

ผลตอบแทนทางสถาปัตยกรรมตรง: เนื่องจากทุกเลนในกลุ่มรันคำสั่ง *เดียวกัน* ในชั่วขณะเดียวกัน คุณไม่ต้องการ logic ดึงคำสั่ง decode และควบคุมแยก duplicate ต่อเลนแบบที่ CPU ต้องการเครื่องจักรท่อเต็มต่อคอร์ — หน่วยควบคุมที่แชร์หนึ่งหน่วยขับเลนการรันขนานหลายเลนพร้อมกันได้ นั่นคือชัยชนะด้านพื้นที่และประสิทธิภาพพลังงานมหึมาโดยเฉพาะ *สำหรับ* workload ประเภท embarrassingly parallel ปฏิบัติการเดียว-ข้อมูลหลายชิ้นนี้ — และในทางกลับกันพอดีแย่กับโค้ดลำดับทั่วไปที่มีสาขาคาดเดายาก ซึ่งคือเหตุผลพอดีที่ CPU กับ GPU ใช้แทนกันไม่ได้ และเหตุผลที่ระบบจริงมักมีทั้งสอง

## จากกราฟิกสู่การคำนวณอเนกประสงค์

การตระหนักที่เปลี่ยนอุตสาหกรรม: โมเดลการรัน SIMT เดียวกันนี้ — เลนขนานง่าย ๆ หลายเลน คำสั่งเดียวกัน ข้อมูลต่างกัน — พอดียอดเยี่ยมกับปัญหาประเภทกว้างกว่ากราฟิกเพียงอย่างเดียว ตราบที่คณิตศาสตร์พื้นฐานมีโครงสร้าง embarrassingly parallel แบบเดียวกัน การฝึกและ inference โครงข่ายประสาท ตามที่ปรากฏ สร้างเกือบทั้งหมดจากคณิตศาสตร์เมทริกซ์และเวกเตอร์ขนานมหาศาล ปกติแบบนี้ — ซึ่งคือเหตุผลที่ GPU ที่เดิมสร้างมาเพื่อเรนเดอร์สามเหลี่ยม กลายเป็นฮาร์ดแวร์ที่ครองสำหรับการคำนวณ AI และเหตุผลที่ส่วนที่เหลือของเฟสนี้เกี่ยวกับการโปรแกรมและ optimize สถาปัตยกรรมขนานเดียวกันนั้น ไม่ใช่การเรนเดอร์กราฟิกโดยเฉพาะ
