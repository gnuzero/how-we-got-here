ทุกเฟสก่อนหน้าสร้างอะไรสักอย่าง — ตรรกะ CPU ระบบปฏิบัติการ เฟสนี้คือวิธีที่ชิ้นส่วนเหล่านั้น *คุยกัน* บัสคือเส้นทางร่วมระหว่าง CPU หน่วยความจำ และ I/O และการออกแบบของมันตัดสินว่าระบบเคลื่อนข้อมูลระหว่างส่วนที่เฟส 3 และเฟส 4 ถือว่าแค่ "เชื่อมต่อ" ได้เร็วแค่ไหน

คำศัพท์ก่อนเริ่ม (ศัพท์บัญญัติราชบัณฑิตยสภา สาขาคอมพิวเตอร์และเทคโนโลยีสารสนเทศ): **บัส** (bus); **บัสข้อมูล** (data bus); **บัสควบคุม** (control bus); **เลขที่อยู่** (address); **ตัวคุมบัส** (bus master); **อุปกรณ์รอบข้าง** (peripheral); **ช่องทางเข้า/ออก** (port หรือ input/output port); **ธุรกรรม** (transaction); **ตัวควบคุม** (controller); **สัญญาณขัดจังหวะ** (interrupt); **นาฬิกา** (clock); **แบนด์วิดท์** (bandwidth); **หน่วยความจำ** (memory); และ **บริดจ์** (bridge — อุปกรณ์เชื่อมบัสสองชนิด) คำต่อไปนี้ยังไม่พบศัพท์บัญญัติในความหมายนี้ จึงใช้คำอธิบายพร้อมคำอังกฤษ: address bus (บัสเลขที่อยู่), address space (พื้นที่เลขที่อยู่), arbitration (การตัดสินสิทธิ์ใช้บัส — คำว่า arbitration มีศัพท์บัญญัติในสาขานิติศาสตร์และเศรษฐศาสตร์ว่า "การอนุญาโตตุลาการ" ซึ่งไม่ตรงความหมายนี้), direct memory access หรือ DMA (การเข้าถึงหน่วยความจำโดยตรงโดยไม่ผ่านซีพียู) และ memory-mapped I/O (การให้อุปกรณ์อยู่ในพื้นที่เลขที่อยู่เดียวกับหน่วยความจำ)

## สัญญาณสามชนิด สายชุดเดียว

บัสระบบคลาสสิกพกสัญญาณสามชนิดบนสายกายภาพร่วม **Address bus** ตั้งชื่อเป้าหมาย — ความกว้างของมันคือเพดานพื้นที่แอดเดรส (32 บิต → 4 GB กำแพงที่ระบบ 32 บิตชนเมื่อหน่วยความจำโต) **Data bus** พกค่า — ความกว้างคือแบนด์วิดท์ต่อทรานแซกชัน **Control bus** ประสานงาน: ทิศทาง ความถูกต้อง คล็อก interrupt

## ความกว้างของบัสเลขที่อยู่เป็นตัวเลข

บัสเลขที่อยู่กว้าง n เส้น แต่ละเส้นเป็น 0 หรือ 1 จึงระบุตำแหน่งได้ 2ⁿ ตำแหน่ง ตั้งแต่ 0 ถึง 2ⁿ − 1:

| n (เส้น) | จำนวนตำแหน่ง | เลขที่อยู่สูงสุด |
| --- | --- | --- |
| 0 | 1 | 0 (กรณีขอบ: มีที่เดียว ไม่ต้องระบุเลย) |
| 1 | 2 | 0x1 |
| 16 | 65,536 (64 KiB) | 0xFFFF |
| 20 | 1,048,576 (1 MiB) | 0xFFFFF |
| 32 | 4,294,967,296 (4 GiB) | 0xFFFFFFFF |

**กรณีขอบ — การวนกลับ:** ถ้าเครื่องคำนวณเลขที่อยู่ 0xFFFF + 1 บนบัส 16 เส้น ผลคือ 0x0000 ไม่ใช่ 0x10000 เพราะไม่มีเส้นที่ 17 ให้บิตนั้นไปอยู่ ในทำนองเดียวกัน 0xFFFFFFFF + 1 บนบัส 32 เส้นกลับไปที่ 0 (ผู้เขียนคำนวณแบบมอดุโล 2ⁿ) การอ่านต่อเนื่องที่ข้ามขอบบนจึงวนกลับมาที่ต้นพื้นที่ ไม่ใช่ล้นออกไปข้างนอก

**4 GB ไม่ใช่ RAM 4 GB:** "32 บิต → 4 GB" ในย่อหน้าข้างบนคือจำนวน *เลขที่อยู่* ไม่ใช่จำนวน RAM ที่ใช้ได้ เพราะอุปกรณ์ก็ต้องการเลขที่อยู่ในพื้นที่เดียวกัน ดูได้จากเครื่องจำลองของแล็บเทอร์มินัล VM (ในบทที่ 28 และบทที่ 40) ผู้เขียนบูตแล้วอ่าน `dmesg` กับ `/proc/iomem`:

- เคอร์เนล 32 บิตของแล็บรายงาน `max_arch_pfn = 0x100000` คือ 2²⁰ หน้า × 4,096 ไบต์ = 4 GiB พอดี — เพดานของบัสเลขที่อยู่ 32 เส้น
- RAM จริงมี 128 MiB (`last_pfn = 0x8000` = 32,768 หน้า × 4 KiB) แต่ไม่ต่อเนื่อง: `0x00001000–0x0009FBFF` (ต่ำกว่า 640 KiB) แล้วเว้นช่วง `0x000A0000–0x000BFFFF` ให้ Video RAM และช่วงถัดไปให้ Video ROM กับ System ROM จากนั้น RAM ต่อที่ `0x00100000–0x07FFFFFF` (127 MiB)
- เคอร์เนลประกาศว่า `[mem 0x08000000-0xfffbffff] available for PCI devices` — ราว 3,968 MiB ของพื้นที่เลขที่อยู่ที่ไม่มี RAM ถูกใช้เป็นหน้าต่างให้อุปกรณ์ เช่น หน่วยความจำของการ์ดจอที่ `0xE0000000–0xE07FFFFF` (8 MiB) และ BIOS ที่ `0xFFFC0000–0xFFFFFFFF` (256 KiB บนสุดของ 4 GiB)

ผู้เขียนอนุมานจากแผนที่นี้ว่า ถ้าเครื่อง 32 บิตแบบนี้ใส่ RAM ครบ 4 GiB ส่วนที่ทับกับหน้าต่างของอุปกรณ์จะเข้าถึงไม่ได้ — นั่นคือกำแพง 4 GB ที่ระบบ 32 บิตชนจริง

**บัสข้อมูล — ต้นทุนของธุรกรรม:** ธุรกรรมหนึ่งครั้งบนบัสขนานร่วมไม่ได้มีแค่ข้อมูล ต้องมีรอบส่งเลขที่อยู่ และมักมีรอบเว้นให้ตัวขับสายสลับกัน สมมุติบัสข้อมูลกว้าง 32 บิต นาฬิกา 33 MHz โอนหนึ่งคำต่อรอบ (ตัวเลขสมมุติเพื่ออธิบาย) เพดานคือ 4 ไบต์ × 33 × 10⁶ = 132 MB/s ถ้าธุรกรรมหนึ่งครั้ง = 1 รอบเลขที่อยู่ + b รอบข้อมูล + 1 รอบเว้น จะได้ 4b / (b + 2) ไบต์ต่อรอบ:

| b (คำต่อธุรกรรม) | ได้จริง (MB/s) |
| --- | --- |
| 0 (กรณีขอบ: ธุรกรรมไม่มีข้อมูล) | 0 — แต่ยังกินบัส 2 รอบ |
| 1 | 44 |
| 4 | 88 |
| 8 | 105.6 |
| 64 | 128 |
| มากไม่จำกัด | เข้าใกล้ 132 |

การโอนทีละคำได้แค่หนึ่งในสามของเพดาน บัสจริงจึงนิยมโอนเป็นชุดยาว (burst) และนี่คือเหตุผลเดียวกับ burst ของ DDR ในบทที่ 34

## เหตุใดการแชร์ต้องการ master

บัสร่วมโดยนิยาม CPU, DMA controller, อุปกรณ์ I/O อาจต้องการเริ่มถ่ายโอนพร้อมกัน; มีเพียงตัวเดียวที่ขับสายได้ มิฉะนั้นแรงดันจะชนกัน Arbitration เลือก bus master สำหรับทรานแซกชันถัดไป — request และ grant บางครั้งมีลำดับความสำคัญเพื่อไม่ให้ DMA ที่อ่อนไหวต่อ latency อดโดยคนอื่น ปัญหาความยุติธรรมเดียวกับ scheduler ในเฟส 4 ชั้นหนึ่งลงมา ในฮาร์ดแวร์

**จำลองการตัดสินสิทธิ์สองแบบ:** ให้มีตัวคุมบัส A, B, C (A สำคัญสุด) ผู้เขียนจำลอง 12 รอบ แต่ละรอบให้สิทธิ์หนึ่งตัว:

| สถานการณ์ | ลำดับความสำคัญคงที่ | วนรอบ (round-robin) |
| --- | --- | --- |
| ทั้งสามขอตลอด | AAAAAAAAAAAA — A ได้ 12, B และ C ได้ 0 | ABCABCABCABC — ได้ตัวละ 4 |
| C ขอตัวเดียว | CCCCCCCCCCCC — C ได้ทั้งหมด | CCCCCCCCCCCC |
| ไม่มีใครขอ | บัสว่างทั้ง 12 รอบ | บัสว่างทั้ง 12 รอบ |

แถวแรกคือ "การอด" (starvation) ในรูปบริสุทธิ์: ลำดับความสำคัญคงที่ยุติธรรมเฉพาะเมื่อตัวที่สำคัญกว่าไม่ขอตลอด แถวที่สองเป็นกรณีขอบที่ทั้งสองแบบเหมือนกัน — การตัดสินสิทธิ์มีผลเฉพาะเมื่อมีการแย่ง ระบบจริงจึงมักผสม: ให้ความสำคัญกับงานที่ทนรอไม่ได้ (เช่น DMA ของอุปกรณ์ที่บัฟเฟอร์เล็ก) แต่จำกัดไม่ให้ใครยึดบัสได้ตลอด

## ข้อจำกัด: ทีละหนึ่งทรานแซกชัน

แบนด์วิดท์รวมเป็นเพดานแข็งที่ทั้งเครื่องแชร์ อุปกรณ์มากขึ้นหมายถึงการรอมากขึ้น และแบนด์วิดท์ที่มีผลที่ใครก็ตามเห็นภายใต้การแย่งยิ่งน้อย นั่นไม่ใช่รายละเอียดการอิมพลีเมนต์ มันคือข้อจำกัดที่ส่วนที่เหลือของเฟสนี้ทำงานรอบ — ก่อนด้วยการทำให้บัสขนานร่วมเร็วขึ้น แล้วด้วยการทิ้งสายร่วมทั้งหมด บทที่ 32 คือทางหนีนั้น: จากบัสขนานหนึ่งอันไปสู่ลิงก์อนุกรมจุดต่อจุดที่ไม่บังคับทุกอุปกรณ์แข่งเพื่อทองแดงเส้นเดียวกัน

**กรณีขอบของการแบ่ง:** ถ้าอุปกรณ์ N ตัวต่างต้องการแบนด์วิดท์ b บนบัสที่มีเพดาน B และการตัดสินสิทธิ์ยุติธรรม แต่ละตัวได้ราว min(b, B/N) เมื่อ N = 1 ได้ min(b, B) เมื่อ N โตขึ้น B/N เล็กลงเรื่อย ๆ ส่วน N = 0 คือบัสว่าง (สูตรไม่นิยามเพราะหารด้วยศูนย์) ตัวอย่าง (สมมุติ): B = 132 MB/s กับอุปกรณ์ 4 ตัวที่ต่างต้องการ 50 MB/s จะได้ตัวละ 33 MB/s — ไม่มีตัวไหนได้ตามต้องการ แม้แต่ละตัวต้องการไม่ถึงครึ่งของเพดาน

## ดูบัสจริงในเครื่องจำลอง

บทนี้ไม่มีแล็บของตัวเอง แต่เครื่องในแล็บเทอร์มินัล VM (บทที่ 28 และบทที่ 40) มีบัสให้ดูครบทั้งสามชนิดของพื้นที่เลขที่อยู่ ผู้เขียนบูตอิมเมจแล้วสั่งตามนี้ (ผลด้านล่างมาจากการรันจริง):

**1. พื้นที่ช่องทางเข้า/ออกแยกจากหน่วยความจำ:** `cat /proc/ioports` แสดงอุปกรณ์ที่ตอบเลขที่อยู่ในพื้นที่ I/O ขนาด 16 บิต (0x0000–0xFFFF) เช่น `0060` และ `0064` คีย์บอร์ด, `0070-0071` นาฬิกา, `01f0-01f7` ตัวควบคุมดิสก์, `03f8-03ff` พอร์ตอนุกรม, `0cf8-0cff : PCI conf1` และ `c000-c01f : ne2k-pci` (การ์ดเครือข่าย 32 ช่อง) ซีพียู x86 ใช้คำสั่ง `in`/`out` สำหรับพื้นที่นี้ ต่างจาก `/proc/iomem` ที่เป็นพื้นที่หน่วยความจำ (ข้างบน)

**2. PCI configuration ผ่านสองช่องทาง:** ไฟล์ `arch/x86/pci/direct.c` ของ Linux แสดงวิธี "conf1": เขียนเลขที่อยู่ 32 บิต `0x80000000 | ((reg & 0xF00) << 16) | (bus << 16) | (devfn << 8) | (reg & 0xFC)` ลงช่อง `0xCF8` (พจน์ `(reg & 0xF00) << 16` ใช้กับ register 256–4095 ของพื้นที่ขยาย สำหรับ register ต่ำกว่า 256 พจน์นี้เป็น 0) แล้วอ่านข้อมูลจากช่อง `0xCFC` ผู้เขียนคำนวณสำหรับการ์ดเครือข่ายของแล็บ (บัส 0 อุปกรณ์ 5 ฟังก์ชัน 0 จึง devfn = 5 × 8 = 0x28): อ่าน register 0x00 ต้องเขียน `0x80002800` กรณีขอบในโค้ดเดียวกัน:
- register ถูก `& 0xFC` เสมอ การอ่านไบต์เดียวที่ register 0x3D จึงเขียนเลขที่อยู่ของ 0x3C แล้วเลือกไบต์ด้วยการอ่านช่อง `0xCFC + (0x3D & 3)` = `0xCFD`
- ถ้า seg ไม่ใช่ 0 หรือ bus > 255 หรือ devfn > 255 หรือ register > 4095 ฟังก์ชันอ่านคืนข้อผิดพลาดและให้ค่า −1 (บิตเป็น 1 ทั้งหมด) โดยไม่แตะบัส
- การเขียนเลขที่อยู่แล้วอ่านข้อมูลเป็นสองขั้น โค้ดจึงล็อก (`raw_spin_lock_irqsave`) ครอบทั้งคู่ ไม่เช่นนั้นผู้ใช้อีกรายอาจเขียน 0xCF8 แทรกกลาง — ปัญหาการแย่งทรัพยากรร่วมแบบเดียวกับบัส ในระดับซอฟต์แวร์

**3. อ่าน configuration space ของจริง:** `od -A x -t x1 /sys/bus/pci/devices/0000:00:05.0/config` ขึ้นต้นด้วย `ec 10 29 80 03 01 00 00 00 00 00 02` เมื่ออ่านตามตำแหน่งใน `pci_regs.h` ของ Linux: vendor ID ที่ 0x00 = 0x10EC และ device ID ที่ 0x02 = 0x8029 (ไบต์ต่ำมาก่อน — ต้องกลับลำดับเอง) class ที่ 0x09–0x0B = 0x020000 (ตัวควบคุมเครือข่าย) BAR0 ที่ 0x10 คือ `01 c0 00 00` = 0x0000C001 บิตต่ำสุดเป็น 1 แปลว่าอยู่ในพื้นที่ I/O และเมื่อตัดสองบิตล่างทิ้งได้ฐาน 0xC000 ตรงกับ `c000-c01f` ใน `/proc/ioports` ข้างบน ส่วน command register ที่ 0x04 = 0x0103: บิต I/O (0x1) และบิตหน่วยความจำ (0x2) เปิด แต่บิตตัวคุมบัส (0x4) *ปิด* ในขณะที่อ่าน — ขณะนั้นการ์ดนี้ไม่ได้รับอนุญาตให้เป็นตัวคุมบัส (ผู้เขียนอนุมานว่าไดรเวอร์ย้ายข้อมูลผ่านช่องทางเข้า/ออกทีละคำแทน DMA) `ls /sys/bus/pci/devices/` แสดงอุปกรณ์ห้าตัวบนบัส PCI เดียว: 00:00.0 host bridge (class 0x060000), 00:01.0 ISA bridge, 00:05.0 การ์ดเครือข่าย, 00:12.0 การ์ดจอ และ 00:1e.0 ตัวควบคุม IDE — ทั้งหมดอยู่บนบัส PCI หมายเลข 0 เดียวกัน ใช้เลขที่อยู่และสายร่วมชุดเดียวตามแบบที่บทนี้อธิบาย (ในเครื่องจำลอง บัสนี้เป็นซอฟต์แวร์ที่เลียนแบบพฤติกรรม ไม่ใช่ทองแดงจริง)
