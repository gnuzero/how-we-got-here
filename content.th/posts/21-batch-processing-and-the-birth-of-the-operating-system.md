เมนเฟรมในบทที่ 18 เดิมไม่ได้รันระบบปฏิบัติการในความหมายที่เราจะจำได้วันนี้ มีคนโหลดโปรแกรม รัน รอให้เสร็จ แล้วโหลดตัวถัดไป โมเดลนั้นใช้ได้สำหรับผู้ใช้หนึ่งคนที่เข้าถึงเครื่องแพงแบบเฉพาะตัว มันพังทันทีเมื่อผู้ใช้หลายคน — หรืองานหลายงาน — ต้องแชร์เครื่องนั้น ซึ่ง เมื่อพิจารณาว่าเมนเฟรมแพงแค่ไหน เกิดขึ้นเกือบทันที

## การจัดตารางด้วยมือ แล้วเป็นการจัดตารางอัตโนมัติ

การดำเนินงานเมนเฟรมยุคแรกเกี่ยวข้องกับผู้ปฏิบัติงานมนุษย์ที่โหลดชุดบัตรเจาะของงานทางกายภาพ รัน เก็บผลลัพธ์ และโหลดชุดถัดไป — กระบวนการช้าที่ CPU แพงนั่งว่างระหว่างทุกการตั้งค่าและรื้อระหว่างงาน Batch processing ทำให้ *ลำดับ* เป็นอัตโนมัติ: ส่งงานเป็นกอง และโปรแกรมที่อยู่ในเครื่องตลอด (early "monitor") โหลดและรันทีละงาน โดยไม่มีมนุษย์แทรกแซงระหว่างงาน

Resident monitor นี้คือบรรพบุรุษตรงของระบบปฏิบัติการ งานของมันแคบ — โหลดงานถัดไป เริ่ม ตรวจจับเมื่อเสร็จ โหลดถัดไป — แต่นั่นคือชิ้นส่วนแรกของซอฟต์แวร์ *ระบบ* ที่แยกจากโปรแกรมของผู้ใช้รายใดรายหนึ่ง รันต่อเนื่องเพื่อจัดการเครื่องในนามของงานที่กำลังประมวลผล

## Job Control และการจัดคิว

เมื่อระบบ batch สุกขึ้น พวกมันได้ภาษาควบคุมงาน — วิธีให้งานที่ส่งระบุทรัพยากรที่ต้องการ จะทำอะไรหากล้มเหลว และควรจัดการผลลัพธ์อย่างไร — บวกการจัดคิว เพื่อให้งานถูกจัดลำดับความสำคัญและจัดตารางแทนที่จะรันตามลำดับส่งแบบเข้มงวดเท่านั้น นี่คือจุดที่แนวคิดอย่างลำดับความสำคัญ การจัดสรรทรัพยากร และนโยบายการจัดตารางปรากฏเป็นข้อกังวลระบบปฏิบัติการจริงครั้งแรก ไม่ใช่แค่การตัดสินใจไม่เป็นทางการของผู้ปฏิบัติงาน

## สิ่งที่ Batch Processing ทำไม่ได้

ข้อจำกัดพื้นฐาน: ไม่มีการโต้ตอบ งานรันตั้งแต่ต้นจนจบโดยไม่มีโอกาสให้ผู้ใช้แทรกแซง ตรวจสถานะกลางทาง หรือเปลี่ยนทิศทางการประมวลผลตามสิ่งที่กำลังเห็น หากโปรแกรมมีบั๊ก คุณรู้หลังจากรันทั้งก้อนเสร็จ (หรือพัง) เท่านั้น — บางครั้งหลายชั่วโมงถัดมา หลังเผาโควตาเวลาเครื่องแพงทั้งก้อน สำหรับงานสำรวจหรือทำซ้ำ รอบการตอบสนองนั้นเป็นคอขวดผลิตภาพร้ายแรง

การแก้สิ่งนั้นต้องการสิ่งที่สถาปัตยกรรมของ batch processing ให้ไม่ได้: ผู้ใช้หลายคนโต้ตอบกับเครื่อง *พร้อมกัน* แต่ละคนมีภาพลวงตาของเซสชันเฉพาะตัว นั่นคือ time-sharing และมันเป็นปัญหาต่างกัน — ไม่ใช่แค่การทำให้ลำดับงานเป็นอัตโนมัติ แต่การสลับโปรแกรมที่แอคทีฟพร้อมกันหลายตัว และทำให้การสลับมองไม่เห็นพอที่ผู้ใช้แต่ละคนรู้สึกว่ามีเครื่องทั้งเครื่อง บทถัดไปรับตรงจุดนั้นพอดี
