ทุกอย่างในเฟสนี้จนถึงตอนนี้กล่าวถึงการเชื่อมส่วนประกอบ *ภายใน* เครื่องเดียว — CPU กับหน่วยความจำ CPU กับอุปกรณ์ขยาย เมื่อ workload ต้องการหลาย GPU หรือหลายเครื่องทำงานด้วยกัน คำถามใหม่เกิดขึ้น: หน่วยคำนวณอิสระเหล่านั้นคุยกัน *เอง* เร็วพอที่ overhead การสื่อสารจะไม่ลบประโยชน์ของการมีมากขึ้นได้อย่างไร?

## เส้นฐาน: วนผ่าน CPU บน PCIe

หากไม่มีเส้นทาง peer คำตอบแบบตรง ๆ คือให้ทุกอย่างคุยผ่าน fabric PCIe เดียวกันที่กล่าวในบทที่ 32–33: GPU A ส่งผ่านหน่วยความจำระบบ และ GPU B อ่านกลับ — ฮอปเพิ่ม latency และแบนด์วิดท์ PCIe ที่เผาไปกับการคัดลอก แม้บน PCIe อย่างเดียว GPUDirect P2P ก็สามารถ DMA GPU↔GPU โดยไม่ต้อง stage ผ่านโฮสต์ได้ (ยังที่แบนด์วิดท์ PCIe) NVLink คือสิ่งที่เพิ่มแบนด์วิดท์เฉพาะทางสูงกว่ามากและทอโพโลยีมัลติ-GPU ที่ดีกว่าทับบนนั้น

## NVLink: เส้นทางตรง GPU-ถึง-GPU

NVLink ของ NVIDIA เป็นอินเตอร์คอนเนกต์ที่สร้างเพื่อการสื่อสาร GPU-ถึง-GPU ตรงที่มีแบนด์วิดท์สูงโดยเฉพาะ — ข้าม CPU และหน่วยความจำระบบทั้งหมดสำหรับการถ่ายโอนระหว่าง GPU ที่รองรับทั้งคู่ หลาย GPU เชื่อมผ่าน NVSwitch ได้ ให้ทอโพโลยี all-to-all ที่ทุก GPU ในโหนดถึงทุก GPU อื่นได้โดยตรง ที่แบนด์วิดท์สูงกว่าการวนการถ่ายโอนเดียวกันผ่าน PCIe และ CPU มาก สำหรับ workload ที่ต้องการแลกเปลี่ยนข้อมูลขนาดใหญ่บ่อยระหว่าง GPU — พอดีกับสิ่งที่การฝึก ML ระดับใหญ่ต้องการ (หัวข้อที่ชุดบทความกลับมาในเฟส 7 และเฟส 10) — เส้นทางตรงนี้เป็นปัจจัยสมรรถนะอันดับหนึ่ง ไม่ใช่การปรับแต่งเล็กน้อย

## CXL: ขยายหน่วยความจำที่สอดคล้องแคชออกนอกไดย์เดียว

CXL (Compute Express Link) จัดการปัญหาข้างเคียงแต่ต่าง: แทนการเพิ่มประสิทธิภาพการถ่ายโอนข้อมูลอุปกรณ์-ถึง-อุปกรณ์โดยเฉพาะ CXL ขยายการเข้าถึงหน่วยความจำที่สอดคล้องแคชข้ามอุปกรณ์หลายตัว และในการติดตั้งขั้นสูงกว่า ข้ามหน่วยความจำแบบพูลที่ไม่ได้ติดกายภาพกับ CPU ใดตัวเดียว นี่เปิดสถาปัตยกรรมที่ความจุหน่วยความจำแชร์และจัดสรรแบบไดนามิกข้ามโหนดคำนวณหลายตัวได้ แทนการผูกแน่นกับซ็อกเก็ต CPU ที่มันบังเอิญเสียบอยู่ — ความยืดหยุ่นต่างจากทั้ง DDR แบบดั้งเดิม (บทที่ 34) หรือ PCIe อย่างเดียว

## GPUDirect RDMA: เหตุใดจึงมีอยู่

GPUDirect RDMA ให้การ์ดเครือข่ายอ่านตรงจาก หรือเขียนตรงเข้า หน่วยความจำ GPU — โดยไม่ต้อง stage ข้อมูลผ่านหน่วยความจำ CPU/ระบบเป็นฮอปกลางก่อน หากไม่มี ถ่ายโอน GPU-ถึง-GPU ข้ามเครือข่ายจะต้อง: หน่วยความจำ GPU → หน่วยความจำระบบ (คัดลอกหนึ่งครั้ง) → การ์ดเครือข่าย → หน่วยความจำระบบปลายทาง → หน่วยความจำ GPU ปลายทาง (คัดลอกอีกครั้ง) — การคัดลอกที่ไม่จำเป็นหลายครั้ง แต่ละครั้งเพิ่มทั้ง latency และแบนด์วิดท์หน่วยความจำที่ใช้ไปที่มิฉะนั้นจะทำงานที่มีประโยชน์ GPUDirect RDMA ยุบเส้นทางนั้นลงเหลือโดยพื้นฐาน หน่วยความจำ GPU → เครือข่าย → หน่วยความจำ GPU โดยตรง ซึ่งเป็นชัยชนะใหญ่ด้วยเหตุผลเดียวกับที่ RDMA โดยทั่วไป (บทที่ 42) เป็นชัยชนะสำหรับที่เก็บและข้อความบนเครือข่าย: คัดลอกน้อยลง latency ต่ำลง และรอบ CPU ว่างสำหรับคำนวณจริงแทนการเฝ้าการถ่ายโอนข้อมูล

## เส้นตรงสู่งานฮาร์ดแวร์ของชุดบทความนี้เอง

บททั้งหมดนี้คือรากฐานแนวคิดใต้โครงการ GPU memory fabric แบบกำหนดเองที่ชุดบทความนี้กล่าวถึงเป็นระยะ: ทำให้หน่วยความจำ GPU ระยะไกลปรากฏว่า address ได้โดยตรง โดยไม่ต้องวนทุกการถ่ายโอนผ่านเส้นทางที่ CPU อเนกประสงค์เป็นตัวกลาง คือปัญหาเดียวกับที่ NVLink และ GPUDirect RDMA แก้ภายในระบบนิเวศของ NVIDIA เอง — เพียงที่นี่ไล่ตามเป็นทางเลือกแบบเปิดบน PCIe แทนอินเตอร์คอนเนกต์เฉพาะของ NVIDIA การเข้าใจ *เหตุใด* NVLink และ GPUDirect จึงมีอยู่ และ inefficiency เฉพาะใดที่พวกมันลบ คือวิธีชัดที่สุดในการเข้าใจว่าทางเลือกฮาร์ดแวร์กำหนดเองแบบเปิดจะต้องทำอะไรให้สำเร็จ
