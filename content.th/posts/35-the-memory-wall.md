บทที่ 34 จบด้วยข้อสังเกตเฉพาะ: แบนด์วิดท์ DDR ขยายอย่างมากข้ามรุ่น แต่ *latency* ของ DRAM ไม่ตามทันใกล้เคียงกัน บทนี้เกี่ยวกับผลของความแยกนั้นในระดับระบบ — ช่องว่างระหว่างความเร็ว CPU กับความเร็วหน่วยความจำที่กว้างขึ้นมานานหลายทศวรรษ โดยทั่วไปเรียกว่า memory wall

## ความแยก ที่วาดกราฟแล้ว

วาดสมรรถนะ CPU และ latency การเข้าถึง DRAM เทียบกันตั้งแต่ราวปี 1980 ถึงวันนี้ และเส้นทั้งสองไม่เคลื่อนไปด้วยกันเลย สมรรถนะ CPU (ขับด้วยความเร็วคล็อกและกำไรสถาปัตยกรรมที่กล่าวตลอดเฟส 3) ดีขึ้นหลายลำดับขนาดในช่วงนี้ Latency ของ DRAM ก็ดีขึ้นเช่นกัน แต่ด้วยตัวคูณที่เล็กกว่ามาก — ช่องว่างระหว่างสองอย่าง เมื่อวาดบนสเกลลอการิทึม ไม่เพียงคงอยู่; มันกว้างขึ้นอย่างเห็นได้ชัดทีละทศวรรษ ความแยกนี้มีชื่อในวรรณกรรมสถาปัตยกรรม — memory wall — ตั้งชื่ออย่างชัดเพราะมันทำตัวเหมือนขีดจำกัดโครงสร้างแข็ง ไม่ใช่ความไม่สะดวกเล็ก ๆ ที่วิศวกรรมดีกว่าจะดูดซับเงียบ ๆ

## เหตุใดแบนด์วิดท์ดีขึ้นแต่ Latency ไม่

ความไม่สมมาตรนี้ไม่ใช่ความประมาททางวิศวกรรม — มันย้อนไปถึงฟิสิกส์จริง Latency การเข้าถึงพื้นฐานของ DRAM ถูกครอบงำด้วยเวลาที่ต้องใช้เพื่อ sense ประจุเล็กน้อยบนตัวเก็บประจุ (เซลล์ 1T1C ในบทที่ 10) ให้เชื่อถือได้พอที่จะแยก 1 จาก 0 — และกระบวนการ sense นั้นมีขีดจำกัดทางฟิสิกส์จริงที่หดตัวไม่เร็วใกล้เคียงความเร็วสวิตช์ทรานซิสเตอร์ แบนด์วิดท์ในทางกลับกัน ปรับปรุงได้ผ่านกลเม็ดสถาปัตยกรรมที่ไม่ต้องชนเพดาน sensing-latency พื้นฐานนั้นเลย: prefetch กว้างขึ้น bank มากขึ้นทำงานขนาน channel มากขึ้น การถ่ายโอน double-data-rate — ทั้งหมดนี้เพิ่ม *throughput* โดยไม่ต้องทำให้ latency ของการเข้าถึงเดี่ยวใดสั้นลง นั่นคือเหตุผลที่การปรับปรุงรุ่นต่อรุ่นของ DDR (บทที่ 34) เน้นแบนด์วิดท์อย่างสม่ำเสมอ เพราะนั่นคือมิติที่ความพยายามทางวิศวกรรมจ่ายจริง; latency พิสูจน์แล้วว่าดื้อกว่ามาก

## ช่องว่างนั้นมีราคาเท่าไรจริง ๆ

คอร์ CPU ที่ค้างรอการเข้าถึงหน่วยความจำที่ใช้เวลาประมาณหลายร้อยรอบคล็อกกว่าจะเสร็จ สำหรับช่วง stall ทั้งนั้น ไม่ได้ทำงานที่มีประโยชน์ — ของเสียมหาศาลเทียบกับว่าคอร์เดียวกันนั้นจะคำนวณได้มากเพียงใดในเวลาเดียวกัน นี่คือเหตุผลที่ลำดับชั้นแคชจากบทที่ 15 ไม่ใช่แค่สิ่งสวยงามด้านสมรรถนะ — มันคือกลไก *หลัก* ที่อุตสาหกรรมพึ่งเพื่อปิดทับ memory wall เลย: เก็บ working set ใน SRAM เร็วให้มากที่สุดเท่าที่จะทำได้ และ CPU แทบไม่ต้องจ่ายต้นทุน latency เต็มของ DRAM Out-of-order execution (บทที่ 16) ก็ช่วยเช่นกัน ให้คำสั่งอิสระเดินหน้าขณะที่ตัวหนึ่งรอหน่วยความจำช้า — แต่ทั้งแคชและการออกนอกลำดับไม่ได้ *ปิด* ช่องว่างจริง ๆ; ทั้งสองเพียงซ่อนผลกระทบสำหรับ workload ที่รูปแบบการเข้าถึงหน่วยความจำเป็นมิตรกับแคช หรือมีงานอิสระพอที่จะทับซ้อน

## สิ่งนี้ทิ้งระบบสมัยใหม่ไว้ที่ใด

Workload ที่ locality ของแคชแย่ — โครงสร้างข้อมูลเข้าถึงแบบสุ่มขนาดใหญ่ อัลกอริทึมกราฟบางชนิด workload ฐานข้อมูลบางอย่าง — ยังรู้สึกถึง memory wall โดยตรงและรุนแรง เพราะไม่มีกลไกซ่อนที่ใช้ได้เมื่อเกือบทุก access พลาดแคช นี่เป็นส่วนใหญ่ของ *เหตุผล* ที่แบนด์วิดท์หน่วยความจำ (ไม่ใช่แค่ความจุ) กลายเป็นข้อพิจารณาออกแบบศูนย์กลางในระบบสมรรถนะสูงสมัยใหม่ — ลำดับชั้นหน่วยความจำของ GPU (เฟส 9) และ HBM โดยเฉพาะ มีอยู่พอสมควรเพราะแรงกดดันนี้พอดี เลือกเพิ่ม *แบนด์วิดท์* สูงสุดแม้จะมีต้นทุนและความซับซ้อนจริง เพราะ latency เองพิสูจน์แล้วว่าต้านการปรับปรุงได้ดี บทถัดไปกล่าวถึงกำแพงที่เกี่ยวข้องใกล้ชิด และเกิดราวช่วงเวลาเดียวกัน — ฝั่ง compute แทนฝั่งหน่วยความจำ
