GPU เดียว ไม่ว่าจะมีความสามารถเพียงใด มีปริมาณงาน compute จำกัดและความจุ HBM จำกัด (บทที่ 54) การฝึกหรือเสิร์ฟโมเดลใหญ่ที่สุดในปัจจุบันต้องการการประสานงานข้ามหลาย GPU เป็นประจำ — บางครั้งในเซิร์ฟเวอร์เดียว บางครั้งข้ามคลัสเตอร์เซิร์ฟเวอร์ทั้งก้อน — และวิธีที่ GPU เหล่านั้นสื่อสารกันกลายเป็นอย่างน้อยสำคัญเท่าสเปกของ GPU ตัวใดตัวหนึ่งต่อประสิทธิภาพที่ได้จริง

## เหตุใดการสเกลแบบตรง ๆ จึงใช้ไม่ได้เฉย ๆ

การแบ่งงานข้ามหลาย GPU ไม่ฟรี — การสนทนาการฝึกแบบ data-parallel และ model-parallel ของบทที่ 46 ครอบคลุมว่า *เหตุใด* การแบ่งนี้จึงมักจำเป็น แต่การทำให้มัน *มีประสิทธิภาพ* ขึ้นหนักกับว่า GPU เหล่านั้นแลกข้อมูลกันเร็วเพียงใด หากการสื่อสารระหว่าง GPU ช้าเทียบกับปริมาณงาน compute ของแต่ละ GPU GPU จะใช้สัดส่วนที่มีความหมายของเวลาไปกับการรอข้อมูลจากเพื่อน แทนการคำนวณที่มีประโยชน์ — เทียบตรงกับการที่คอร์ CPU ค้างรอการเข้าถึงหน่วยความจำช้า (memory wall ของบทที่ 35 อีกครั้ง) เพียงนำไปใช้ที่สเกลการสื่อสาร GPU-ถึง-GPU แทน CPU-ถึง-DRAM

## NVLink และ NVSwitch: เส้นทางตรง

บทที่ 37 แนะนำ NVLink ในฐานะอินเตอร์คอนเนกต์ GPU-ถึง-GPU แบนด์วิดท์สูงตรง ที่จงใจข้ามเส้นทาง PCIe ผ่าน CPU ซึ่งมิฉะนั้นจะเป็นค่าเริ่มต้น ภายในเซิร์ฟเวอร์เดียว NVSwitch ขยายสิ่งนี้เป็นทอโพโลยี all-to-all จริง — ทุก GPU เข้าถึงทุก GPU อื่นในเซิร์ฟเวอร์นั้นได้ตรง ที่แบนด์วิดท์ของ NVLink สูงกว่าการส่งเทียบเท่าผ่าน PCIe และ CPU อย่างมาก สำหรับ workload ที่ต้องการการแลกข้อมูลใหญ่บ่อยระหว่าง GPU — พอดีกับที่ขั้นซิงค์ gradient ของการฝึกขนาดใหญ่ต้องการ — เส้นทางตรงแบนด์วิดท์สูงนี้มักเป็นตัวกำหนดจริงของปริมาณงานฝึกที่ได้ ไม่ใช่ตัวเลข compute ทฤษฎีสูงสุดของ GPU ใดตัวเดียวแยกเดี่ยว

## การสเกลเกินเซิร์ฟเวอร์เดียว

NVLink และ NVSwitch จัดการการสื่อสาร GPU-ถึง-GPU ภายในเซิร์ฟเวอร์หนึ่งได้ดีมาก แต่การฝึกขนาดใหญ่จริงมักครอบหลายเซิร์ฟเวอร์ นั่นคือที่แนวคิดเครือข่ายศูนย์ข้อมูลและ RDMA จากบทที่ 42 กลับมาเกี่ยวข้องตรง: GPUDirect RDMA ให้ตัวปรับเครือข่ายอ่านจากหรือเขียนตรงเข้าหน่วยความจำ GPU ข้ามขอบเซิร์ฟเวอร์ โดยไม่ต้องคัดลอกผ่านหน่วยความจำระบบโฮสต์โดยไม่จำเป็น — ขยายปรัชญา "ลดฮอป ทำให้แบนด์วิดท์ตรงสูงสุด" เดียวกันที่กระตุ้น NVLink ภายในเซิร์ฟเวอร์เดียว ออกไปถึงสเกลคลัสเตอร์หลายเซิร์ฟเวอร์ทั้งก้อน

## สิ่งนี้นำไปที่ไหน

การสนทนาทั้งหมดนี้ — เส้นทาง GPU-ถึง-GPU ตรง การลดฮอปที่ไม่จำเป็น การถือแบนด์วิดท์อินเตอร์คอนเนกต์เป็นข้อจำกัดการออกแบบชั้นหนึ่งแทนสิ่งคิดทีหลัง — คือปรัชญาพื้นฐานเดียวกันเบื้องหลังโครงการ fabric หน่วยความจำ GPU เฉพาะที่ชุดนี้กล่าวถึงเป็นระยะ: แนวทางเปิดบน PCIe เพื่อบรรลุสิ่งที่ NVLink บรรลุภายในระบบนิเวศกรรมสิทธิ์ของ NVIDIA ทำให้หน่วยความจำ GPU ระยะไกลปรากฏเป็นที่อยู่ได้ตรง แทนที่การส่งข้าม GPU ทุกครั้งต้องวนผ่านเส้นทางซอฟต์แวร์อเนกประสงค์ที่ผ่าน CPU เฟส 10 รับเส้นด้ายนี้ที่สเกลศูนย์ข้อมูลจริง — ไม่ใช่เพียงว่า GPU กำมือในเซิร์ฟเวอร์หนึ่งคุยกันอย่างไร แต่ GPU นับพันข้ามคลัสเตอร์ฝึกทั้งก้อนถูกเดินสายและถูกป้อนข้อมูลมีประสิทธิภาพพอที่จะเข้าใกล้ศักยภาพ compute รวมทางทฤษฎีได้อย่างไร
