ตรรกะเชิงผสม (บทที่ 8) เป็นฟังก์ชันบริสุทธิ์ของอินพุตปัจจุบัน — ไม่มีความจำของอดีต คอมพิวเตอร์ต้องการ *สถานะ*: รีจิสเตอร์ โปรแกรมเคาน์เตอร์ เนื้อหาหน่วยความจำที่คงอยู่ข้ามรอบ นั่นต้องการฟีดแบ็ก

## ความจำจากฟีดแบ็ก

ต่อเกต NOR (หรือ NAND) สองตัวไขว้ — เอาต์พุตแต่ละตัวป้อนอินพุตของอีกตัว — แล้วได้สถานะเสถียรสองสถานะ วงจรนั่งที่ไหนก็ตามที่คุณผลักไว้ล่าสุด ตราบเท่าที่มีไฟ นั่นคือความจำในความหมายทางกายภาพ: bistability ไม่ใช่ "store" นามธรรม

ลองไล่ด้วยมือให้เห็นว่าทำไมมันจำได้ เรียกเกต NOR สองตัวว่า G1 และ G2 ให้ G1 รับอินพุต R (reset) กับเอาต์พุตของ G2 และ G2 รับอินพุต S (set) กับเอาต์พุตของ G1 เอาต์พุตของ G1 คือ Q และของ G2 คือ Q̄ กฎของ NOR มีข้อเดียว: เอาต์พุตเป็น 1 ก็ต่อเมื่ออินพุตทั้งสองเป็น 0

1. ให้ S = 1, R = 0: G2 มีอินพุตหนึ่งเป็น 1 จึงได้ Q̄ = 0 แล้ว G1 เห็น R = 0 และ Q̄ = 0 จึงได้ Q = 1 วงจรถูก "ตั้ง" (set)
2. ปล่อย S กลับเป็น 0 (ตอนนี้ S = R = 0): G2 เห็น S = 0 และ Q = 1 จึงยังให้ Q̄ = 0 ส่วน G1 ยังเห็น 0 กับ 0 จึงยังให้ Q = 1 **สถานะค้างอยู่ได้เองทั้งที่อินพุตหายไปแล้ว**
3. ให้ R = 1: G1 ได้ Q = 0 แล้ว G2 เห็น 0 กับ 0 จึงได้ Q̄ = 1 วงจรถูก "ล้าง" (reset) และเมื่อปล่อย R กลับเป็น 0 ก็จะค้างที่ Q = 0 ด้วยเหตุผลเดียวกัน

ที่ S = R = 0 วงจรจึงมีคำตอบที่สอดคล้องในตัวเองได้สองแบบ คือ (Q, Q̄) = (1, 0) หรือ (0, 1) และมันจะอยู่ในแบบที่ถูกผลักไว้ล่าสุด นี่คือความหมายของ bistable (เสถียรสองสถานะ) ชุดต้องห้ามคือ S = R = 1 ซึ่งบังคับให้ Q = Q̄ = 0 พร้อมกัน และถ้าปล่อยทั้งคู่กลับเป็น 0 ในเวลาเดียวกัน วงจรไม่มีเหตุผลที่จะเลือกข้างใด ปมนี้จะกลับมาอีกครั้งในหัวข้อ metastability ด้านล่าง

**แลตช์** (latch, ศัพท์บัญญัติ) คือชื่อเรียกวงจรความจำหนึ่งบิตที่สร้างจากฟีดแบ็กแบบนี้

SR latch ที่ไม่มีเกตเปิดเสมอต่ออินพุต และมีชุดอินพุตต้องห้าม การออกแบบ synchronous ต้องการ latch แบบ gated (ไวต่อระดับ): ขณะ enable สูงมัน *โปร่งใส* (เอาต์พุตติดตามข้อมูล); เมื่อ enable ต่ำลงมันค้าง ความโปร่งใสยุ่งเมื่อองค์ประกอบหลายตัวต้องอัปเดตพร้อมกัน

คำว่า synchronous ใช้ศัพท์บัญญัติว่า **ประสานเวลา** หมายถึงวงจรที่องค์ประกอบความจำทุกตัวเปลี่ยนสถานะตามจังหวะของสัญญาณ **นาฬิกา** (clock, ศัพท์บัญญัติ; ในบทนี้เรียกทับศัพท์ว่า "คล็อก" ด้วย) ร่วมกันหนึ่งสัญญาณ คล็อกคือคลื่นสี่เหลี่ยมที่สลับ 0/1 ด้วยคาบคงที่ T และความถี่ f = 1/T เช่น คาบ 500 ps คือความถี่ 2 GHz

ทำไมความโปร่งใสถึงยุ่ง? สมมติรีจิสเตอร์ A ส่งค่าผ่านวงจรบวก 1 แล้ววนกลับเข้า A เอง (ตัวนับ) ถ้า A เป็นแลตช์ที่โปร่งใสตลอดช่วง enable สูง ค่าใหม่จะไหลออกไป ผ่านวงจรบวก แล้ววนกลับเข้ามาอีก ภายในช่วง enable ครั้งเดียว ค่าจึงอาจเพิ่มขึ้น 1, 2 หรือ 5 ขึ้นกับว่าช่วง enable ยาวกี่เท่าของความหน่วงของวงจรบวก ผลลัพธ์ขึ้นกับความเร็วของสายไฟ ไม่ใช่ตรรกะ

**ลองตอนนี้.** แล็บด้านล่างยังเป็นเกตสด — สลับอินพุตแล้วดูเอาต์พุตเปลี่ยน *ทันที* การตอบสนองฉับพลันนั้นคือเชิงผสม บทนี้คือสิ่งที่เกิดขึ้นเมื่อคุณต่อเกตวนกลับเข้าตัวเอง เพื่อให้เอาต์พุต *ค้าง* ได้หลังจากอินพุตจากไป

แล็บนี้เป็นเครื่องจำลองวงจรที่แก้ไขได้ ถ้าอยากลองต่อ SR latch เอง: เพิ่มเกต NOR สองตัว (หาได้ในเมนูสำหรับเพิ่มชิ้นส่วนของเครื่องจำลอง ชื่อเมนูอาจต่างกันเล็กน้อย) ต่อเอาต์พุตของแต่ละตัวไขว้เข้าอินพุตหนึ่งขาของอีกตัว ใส่สวิตช์อินพุตเป็น S และ R แล้วไล่ทำขั้นที่ 1–3 ข้างบน ข้อควรรู้คือเครื่องจำลองลักษณะนี้ใช้แบบจำลองเกตแบบอุดมคติ จึงจะไม่แสดงสภาวะ metastable ให้เห็น

## D Flip-Flop: ขอบ ไม่ใช่ระดับ

D flip-flop ซ้อน latch สองตัวแบบ master–slave ภายใต้คล็อก เอาต์พุตเปลี่ยนเฉพาะที่ *ขอบ* คล็อก ไม่ใช่ตลอดเฟสสูง (หรือต่ำ) ระหว่างขอบ flop เพิกเฉยต่อ D และค้าง การกระตุ้นด้วยขอบคือสิ่งที่ทำให้การออกแบบ synchronous จัดการได้: flop ทุกตัวอัปเดตที่ขอบเดียวกัน ดังนั้นคุณให้เหตุผลทีละขั้นไม่ต่อเนื่อง แทนที่จะแข่งสัญญาณต่อเนื่อง

**ฟลิปฟล็อป** (flip-flop, ศัพท์บัญญัติ) แบบ D ทำงานแบบนี้: แลตช์ตัวแรก (master) โปร่งใสขณะคล็อกเป็น 0 และติดตาม D ตัวที่สอง (slave) โปร่งใสขณะคล็อกเป็น 1 เมื่อคล็อกขึ้นจาก 0 เป็น 1 master ปิดและค้างค่า D ที่เห็นในขณะนั้น พร้อมกับที่ slave เปิดและส่งค่านั้นออกไปที่ Q ไม่มีช่วงเวลาไหนที่ทั้งสองตัวโปร่งใสพร้อมกัน เส้นทางจาก D ถึง Q จึงไม่เคยเปิดทะลุ ปัญหาตัวนับวิ่งเกินในหัวข้อก่อนหน้าหายไป: ต่อคล็อกหนึ่งขอบ ตัวนับเพิ่มหนึ่งครั้งพอดี

## Setup, Hold และเพดานคล็อก

อินพุต D ต้องเสถียรเป็นหน้าต่างขั้นต่ำ *ก่อน* ขอบ (setup) และ *หลัง* ขอบ (hold) ละเมิดอย่างใดอย่างหนึ่งแล้ว flop อาจเข้าสู่ metastable — สถานะไม่กำหนดที่ตกลงช้าหรือไม่สอดคล้องกันปลายทาง นั่นไม่ใช่การสอนในตำรา: มันคือเหตุผลที่ความถี่คล็อกสูงสุดมีเพดานแข็ง คาบต้องครอบคลุมการแพร่เชิงผสม *บวก* setup ของ flop ถัดไป พร้อมมาร์จิน บทที่ 36 (The Clock Speed Wall) รับข้อจำกัดนี้กลับเมื่อการเร่งความถี่เพียงอย่างเดียวหยุดใช้ได้

### นิยามตัวเลขทั้งห้า

ยังไม่พบศัพท์บัญญัติสำหรับ setup time และ hold time บทนี้จึงใช้คำอธิบายภาษาไทยคู่กับคำอังกฤษ

- **เวลาตั้งก่อน** (setup time, t_su) — D ต้องนิ่งอย่างน้อยเท่านี้ *ก่อน* ขอบคล็อก เพราะ master ต้องมีเวลาให้ฟีดแบ็กภายในของมันรับค่าใหม่ให้มั่นคงก่อนจะปิด
- **เวลาคงค้าง** (hold time, t_h) — D ต้องนิ่งต่ออีกอย่างน้อยเท่านี้ *หลัง* ขอบคล็อก เพราะการปิดของ master ไม่ได้เกิดทันทีที่ขอบ ถ้า D เปลี่ยนเร็วเกินไป ค่าใหม่อาจเล็ดลอดเข้าไปได้
- **ความหน่วงคล็อกถึงเอาต์พุต** (clock-to-Q delay, t_cq) — หลังขอบคล็อกนานเท่าไร Q ของ flop ต้นทางจึงเป็นค่าใหม่
- **เวลาประวิงการแพร่กระจาย** (propagation delay, ศัพท์บัญญัติ; t_pd) ของตรรกะเชิงผสมระหว่างสอง flop — เวลากรณี *ช้าสุด* ที่เอาต์พุตของตรรกะจะนิ่งหลังอินพุตเปลี่ยน
- **ความหน่วงกรณีเร็วสุด** (contamination delay, t_cd) — เวลาที่ *เร็วที่สุด* ที่เอาต์พุตของตรรกะจะเริ่มเปลี่ยน

ข้อสังเกตสำคัญ: ตรรกะหนึ่งก้อนมีทั้งความหน่วงช้าสุดและเร็วสุด เพราะสัญญาณเดินได้หลายเส้นทาง บางเส้นผ่านเกตสิบชั้น บางเส้นผ่านชั้นเดียว setup สนใจเส้นทางที่ช้าที่สุด hold สนใจเส้นทางที่เร็วที่สุด

### เงื่อนไข setup: ทำไมคล็อกเร่งได้ไม่สุด

ลองตามข้อมูลหนึ่งบิตจาก flop ต้นทาง (FF1) ไปยัง flop ปลายทาง (FF2) ภายในหนึ่งคาบ

1. ขอบคล็อกที่เวลา 0: FF1 จับค่าใหม่ ค่าออกมาที่ Q หลัง t_cq
2. ค่านั้นวิ่งผ่านตรรกะ ใช้เวลาถึง t_pd ในกรณีช้าสุด
3. ต้องมาถึง D ของ FF2 ก่อนขอบถัดไป (ที่เวลา T) อย่างน้อย t_su

จึงได้เงื่อนไข **T ≥ t_cq + t_pd + t_su**

ตัวอย่างตัวเลข (สมมติเพื่อประกอบคำอธิบาย ไม่ใช่ค่าของกระบวนการผลิตใดโดยเฉพาะ): t_cq = 50 ps, t_pd = 400 ps, t_su = 30 ps

T ≥ 50 + 400 + 30 = 480 ps → f ≤ 1/480 ps ≈ **2.08 GHz**

สังเกตว่า 400 จาก 480 ps เป็นของตรรกะ นี่คือเหตุผลที่ไปป์ไลน์ (บทที่ 13) เพิ่มความถี่ได้: ผ่าตรรกะ 400 ps ออกเป็นสองท่อนละ 200 ps แล้ววาง flop คั่นกลาง คาบต่ำสุดจะเหลือ 50 + 200 + 30 = 280 ps (≈ 3.57 GHz) แต่ได้ไม่ถึงสองเท่า เพราะ t_cq + t_su = 80 ps เป็นค่าใช้จ่ายคงที่ที่จ่ายซ้ำทุกท่อน ยิ่งผ่าละเอียด ค่าใช้จ่ายนี้ยิ่งกินสัดส่วนของคาบมากขึ้น

### เงื่อนไข hold: ปัญหาของเส้นทางที่ *เร็วเกินไป*

ที่ขอบคล็อกเดียวกัน FF2 กำลังจับค่า *เก่า* อยู่ และต้องการให้ D ของมันนิ่งต่ออีก t_h แต่ FF1 ก็เพิ่งปล่อยค่าใหม่ออกมาที่ขอบเดียวกันนี้ ค่าใหม่จะมาถึง D ของ FF2 เร็วที่สุดหลัง t_cq,min + t_cd จึงต้องมี

**t_cq,min + t_cd ≥ t_h**

ตัวอย่าง (ตัวเลขสมมติเช่นกัน): t_cq,min = 40 ps, t_cd = 10 ps (เส้นทางตรงผ่านเกตเดียว), t_h = 60 ps → 40 + 10 = 50 ps ซึ่งน้อยกว่า 60 ps ขาดไป **10 ps** ค่าใหม่วิ่งมาทับค่าเก่าก่อนที่ FF2 จะจับเสร็จ

สิ่งที่ต้องเข้าใจให้ชัด: **T ไม่อยู่ในสมการ hold เลย** การลดความถี่คล็อกแก้ setup ได้เสมอ แต่แก้ hold ไม่ได้แม้แต่นิดเดียว ชิปที่ละเมิด hold จะผิดพลาดที่ทุกความถี่ วิธีแก้คือทำให้เส้นทางเร็วสุดช้าลง เช่น แทรกบัฟเฟอร์ (เกตที่ส่งค่าผ่านเฉย ๆ) ลงในเส้นทางนั้น ถ้าบัฟเฟอร์หนึ่งตัวหน่วง 15 ps เส้นทางเร็วสุดจะเป็น 50 + 15 = 65 ps ≥ 60 ps ผ่าน และถ้าบัฟเฟอร์นั้นบังเอิญอยู่บนเส้นทางช้าสุดด้วย คาบต่ำสุดจะกลายเป็น 495 ps ซึ่งยังผ่านที่ 2 GHz (500 ps)

### ความเบ้ของคล็อก: ช่วยข้างหนึ่ง ทำร้ายอีกข้าง

ในชิปจริงคล็อกไม่ได้มาถึงทุก flop พร้อมกัน เพราะเดินทางผ่านสายยาวไม่เท่ากัน ความต่างของเวลามาถึงเรียกว่า **ความเบ้ของคล็อก** (clock skew, ยังไม่พบศัพท์บัญญัติ) ให้ δ คือเวลาที่คล็อกมาถึง FF2 *ช้ากว่า* FF1

- setup: FF2 จับข้อมูลช้าลง δ ข้อมูลจึงมีเวลาเพิ่ม → T ≥ t_cq + t_pd + t_su − δ
- hold: FF2 ต้องการให้ค่าเก่านิ่งนานขึ้น δ → t_cq,min + t_cd ≥ t_h + δ

ด้วยตัวเลขเดิม δ = +20 ps ทำให้คาบต่ำสุดเหลือ 460 ps (≈ 2.17 GHz) แต่ hold ขาดจาก 10 ps กลายเป็น 30 ps ส่วน δ = −20 ps ทำให้คาบต่ำสุดเป็น 500 ps (2.00 GHz) แต่ผ่อน hold ลง ความเบ้จึงเป็นเครื่องมือที่ตัดสองคม ไม่ใช่ของฟรี นี่คือเหตุผลที่นักออกแบบชิปลงแรงมากกับการกระจายคล็อกให้มาถึงทุกจุดพร้อมกันที่สุด

## Metastability: เมื่อฟีดแบ็กลังเล

**อุปเสถียร** (metastable, ศัพท์บัญญัติสาขาวิทยาศาสตร์) คือสภาวะสมดุลที่ไม่มั่นคง เปรียบกับลูกบอลที่วางอยู่บนยอดเนินพอดี ในทางทฤษฎีมันอยู่ได้ แต่แรงรบกวนนิดเดียวก็ทำให้กลิ้งลงข้างใดข้างหนึ่ง แลตช์ไขว้สองเกตก็มีจุดแบบนั้น: จุดที่แรงดันทั้งสองข้างอยู่กลาง ๆ ระหว่าง 0 และ 1 พอดี ถ้า D เปลี่ยนในช่วงแคบ ๆ รอบขอบคล็อก แลตช์อาจถูกทิ้งไว้ใกล้ยอดเนินนั้น

สิ่งที่ทำให้ปัญหานี้วิเคราะห์ได้คือ ฟีดแบ็กขยายความต่างเล็ก ๆ แบบ *ทวีคูณ* ถ้าความต่างแรงดันเริ่มต้นเป็น V₀ มันจะโตประมาณ V₀·e^(t/τ) โดย τ เป็นค่าคงตัวเวลาของแลตช์ ความน่าจะเป็นที่ผ่านไปแล้ว S วินาทียังตัดสินใจไม่ได้จึงลดลงเป็น e^(−S/τ) Ginosar (2011) รวมเป็นสูตรเวลาเฉลี่ยระหว่างความล้มเหลว (mean time between failures, MTBF)

MTBF = e^(S/τ) / (T_W · F_C · F_D)

- S — เวลาที่เรายอมให้แลตช์ตัดสินใจก่อนจะมีใครอ่านค่ามัน
- τ — ค่าคงตัวเวลาของการตัดสินใจ
- T_W — ความกว้างของหน้าต่างอันตรายรอบขอบคล็อก
- F_C — ความถี่คล็อก
- F_D — อัตราที่ข้อมูลอินพุตเปลี่ยน

ตัวส่วน T_W·F_C·F_D คืออัตราการ *เข้า* สภาวะอุปเสถียร ในตัวอย่างของ Ginosar สำหรับ ASIC บนกระบวนการผลิต 28 nm: τ = 10 ps, T_W = 20 ps (เขาระบุว่าทั้งสองค่าใกล้กับความหน่วงของเกตทั่วไปในกระบวนการนั้น), F_C = 1 GHz และข้อมูลเปลี่ยนทุก 10 รอบคล็อก คือ F_D = 100 MHz ได้อัตราเข้า 20×10⁻¹² × 10⁹ × 10⁸ = **2×10⁶ ครั้งต่อวินาที** แลตช์เข้าสภาวะอุปเสถียรบ่อยมาก แต่เกือบทุกครั้งมันหลุดออกมาเองอย่างรวดเร็ว คำถามคือจะรอได้นานแค่ไหน

| เวลาที่ให้ตัดสินใจ S | e^(S/τ) | MTBF |
| --- | --- | --- |
| 200 ps | 4.85×10⁸ | ≈ 243 วินาที (ราว 4 นาที) |
| 300 ps | 1.07×10¹³ | ≈ 5.3×10⁶ วินาที (ราว 62 วัน) |
| 500 ps | 5.18×10²¹ | ≈ 8.2×10⁷ ปี |
| 1 ns | 2.69×10⁴³ | ≈ 4.3×10²⁹ ปี |

(ตัวเลขในตารางคำนวณเองจากสูตรข้างบน แถว 1 ns ตรงกับค่า "4×10²⁹ ปี" ที่ Ginosar ให้ไว้) เพิ่ม S เพียง 100 ps เปลี่ยนจากพังทุกไม่กี่นาทีเป็นพังทุกสองเดือน เพราะเวลาที่เพิ่มขึ้นทุก τ·ln10 ≈ 23 ps คูณ MTBF ขึ้นสิบเท่า

### ซิงโครไนเซอร์แบบฟลิปฟล็อปสองตัว

สัญญาณที่มาจากนอกโดเมนคล็อก (ปุ่มกด สายสื่อสาร หรือส่วนของชิปที่ใช้คล็อกอีกตัว) เปลี่ยนเมื่อไรก็ได้เมื่อเทียบกับขอบคล็อกของเรา setup และ hold จึงถูกละเมิดแน่นอนเป็นครั้งคราว หลีกเลี่ยงไม่ได้ วิธีมาตรฐานคือให้สัญญาณเข้าฟลิปฟล็อปตัวแรก (FF1) ซึ่งอาจเข้าสภาวะอุปเสถียร แล้วให้ FF2 อ่านเอาต์พุตของ FF1 อีกหนึ่งรอบคล็อกถัดมา FF1 จึงมีเวลาตัดสินใจเกือบหนึ่งคาบเต็ม: S = T_C − t_cq(FF1) − t_su(FF2) ที่ 1 GHz ด้วย t_cq = 50 ps และ t_su = 30 ps จะได้ S = 920 ps และ MTBF ≈ 1.4×10²⁶ ปี ราคาที่จ่ายคือความหน่วงเพิ่มหนึ่งรอบคล็อก Ginosar เตือนไว้ด้วยว่า ถ้าส่งข้อมูลหลายบิตโดยซิงโครไนซ์ทีละบิตแยกกัน แต่ละบิตอาจตัดสินใจไม่ตรงกัน วิธีที่ถูกคือซิงโครไนซ์เฉพาะสัญญาณควบคุม (เช่น req/ack) แล้วค่อยอ่านข้อมูลเมื่อมันนิ่งแล้ว

## สิ่งที่สิ่งนี้ปลดล็อก

Flop ที่กระตุ้นด้วยขอบกลายเป็นรีจิสเตอร์ เคาน์เตอร์ เครื่องสถานะ — และ ในเฟส 3 โปรแกรมเคาน์เตอร์กับรีจิสเตอร์ไปป์ไลน์ที่ทำให้ CPU เป็นเครื่อง *เชิงลำดับ* ต่อไป: นำการเก็บแบบ bistable ไปเฉพาะทางเพื่อความหนาแน่น — จุดที่ SRAM กับ DRAM แยกทาง
