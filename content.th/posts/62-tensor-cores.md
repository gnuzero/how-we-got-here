บทที่ 53 ครอบคลุม CUDA core — เลน SIMT อเนกประสงค์สำหรับงานขนานกว้าง Tensor core แคบกว่า: ฮาร์ดแวร์เฉพาะสำหรับปฏิบัติการเดียว — matrix multiply-accumulate — ที่ครอง compute ของโครงข่ายประสาทสมัยใหม่ เฉพาะทางสำหรับ op นั้นแล้วเอาชนะการทำงานเดียวกันบน CUDA core อเนกประสงค์เพียงอย่างเดียว

## นิยามก่อนเริ่ม

- **เมทริกซ์** (matrix) คือตารางตัวเลขเป็นแถวและหลัก เมทริกซ์ขนาด M×K มี M แถว K หลัก **เทนเซอร์** (tensor, ศัพท์บัญญัติ) คือการขยายแนวคิดนี้ไปหลายมิติ ในวงการ deep learning คำนี้ใช้เรียกอาร์เรย์หลายมิติของตัวเลขทั่วไป ชื่อ tensor core มาจากตรงนี้
- **การคูณสะสม** (multiply-accumulate, MAC) คือขั้นตอน c ← c + a×b คูณสองตัวแล้วบวกเข้าตัวสะสม
- **FMA** (fused multiply-add) คือ MAC ที่ฮาร์ดแวร์ทำในคำสั่งเดียวและปัดเศษเพียงครั้งเดียวตอนจบ นับเป็นสองการดำเนินการจุดลอยตัว (FLOP) คือคูณหนึ่งและบวกหนึ่ง

การคูณเมทริกซ์ A (M×K) กับ B (K×N) ได้ C (M×N) โดยแต่ละช่อง C[i][j] คือผลรวมของ A[i][k]×B[k][j] สำหรับ k ทั้ง K ค่า จึงต้องใช้ FMA ทั้งหมด **M×N×K ครั้ง**

## เหตุใดการคูณเมทริกซ์

ชั้น fully connected, convolution (ที่ reformulate เป็น matmul) และ attention ใน transformer ทั้งหมดลดลงที่แก่น เป็นการคูณสะสมของเมทริกซ์ — ที่สเกลที่ประสิทธิภาพของมันครองสมรรถนะระบบ ความเข้มข้นนั้นทำให้ซิลิคอนเฉพาะทางคุ้ม

"ความเข้มข้น" นี้มีตัวเลขรองรับ สำหรับเมทริกซ์จัตุรัส n×n การคูณใช้ FMA n³ ครั้ง แต่ข้อมูลที่ต้องอ่านและเขียนมีแค่ราว 3n² ตัว งานต่อข้อมูลหนึ่งตัวจึงโตตาม n: ที่ n = 4 คือ 64 FMA ต่อข้อมูล 48 ตัว ที่ n = 4096 คือ FMA ราว 6.9×10¹⁰ ครั้งต่อข้อมูลราว 5×10⁷ ตัว ข้อมูลแต่ละตัวถูกใช้ซ้ำหลายพันครั้ง นี่คือคุณสมบัติที่ทำให้การคูณเมทริกซ์ต่างจากงานส่วนใหญ่: ถ้าจัดการข้อมูลดี มันจะติดที่ความเร็วการคำนวณ ไม่ใช่ความเร็วหน่วยความจำ ฮาร์ดแวร์ที่คำนวณได้เร็วขึ้นจึงแปลงเป็นความเร็วจริงได้

## Tensor Core ทำอะไร

Tensor core fuse การคูณสะสมเมทริกซ์ขนาดคงที่เล็ก — เช่น เมทริกซ์ 4×4 สองตัวเข้าตัวที่สาม — เป็นปฏิบัติการฮาร์ดแวร์เดียว แทนลำดับคำสั่งคูณและบวกแยกยาวผ่าน CUDA core อเนกประสงค์ การ fuse ตัด overhead ต่อ op (ดึง decode เดิน operand) เทียบกับเลขคณิตที่มีประโยชน์ ผลคูณใหญ่กว่าถูกไทล์: ป้อนบล็อกย่อยตามลำดับ สะสมผลย่อย — งานประสานที่ทำให้เคอร์เนล deep learning ที่มีประสิทธิภาพเป็นฝีมือของตัวเอง

### ตัวอย่างที่คำนวณด้วยมือ: D = A×B + C

Whitepaper ของ Tesla V100 (Volta, 2017) ซึ่งเป็น GPU รุ่นแรกที่มี tensor core บรรยายว่า tensor core แต่ละตัวทำ D = A×B + C โดย A, B, C, D เป็นเมทริกซ์ 4×4 ลองทำหนึ่งครั้งด้วยมือ

```
A = | 1 2 0 1 |    B = | 1 0 2 0 |    C = ทุกช่องเป็น 1
    | 0 1 1 0 |        | 0 1 0 1 |
    | 2 0 1 1 |        | 1 1 0 0 |
    | 1 1 1 1 |        | 0 2 1 1 |
```

ช่อง D[0][1] (แถว 0 ของ A คูณหลัก 1 ของ B แล้วบวก C):

1×0 + 2×1 + 0×1 + 1×2 + 1 = 0 + 2 + 0 + 2 + 1 = **5**

ช่อง D[2][2]: 2×2 + 0×0 + 1×0 + 1×1 + 1 = **6**

ทำครบทั้ง 16 ช่องจะได้

```
D = | 2 5 4 4 |
    | 2 3 1 2 |
    | 4 4 6 2 |
    | 3 5 4 3 |
```

(ตรวจด้วยโปรแกรมแล้ว) แต่ละช่องใช้ FMA 4 ครั้ง 16 ช่องจึงเป็น **64 FMA** ตรงกับที่ whitepaper ระบุว่า tensor core หนึ่งตัวทำ FMA 64 ครั้งต่อคล็อก สิ่งที่ควรสังเกตคือการใช้ข้อมูลซ้ำ: ค่าจาก A และ B รวม 32 ตัว (บวก C อีก 16 เป็น 48 ตัว) ป้อนการคูณ 64 ครั้ง ค่า A แต่ละตัวถูกใช้ 4 ครั้ง (ครั้งละหนึ่งหลักของ B) และค่า B แต่ละตัวก็ถูกใช้ 4 ครั้ง

### ทำไมถึงถูกกว่าการทำบน CUDA core

บน CUDA core FMA หนึ่งครั้งคือหนึ่งคำสั่ง ต้องดึงคำสั่ง ถอดรหัส อ่านตัวถูกดำเนินการ 3 ตัวจากรีจิสเตอร์ และเขียนผลกลับ 1 ตัว การคำนวณ 4×4×4 เดียวกันจึงเป็น 64 คำสั่ง อ่านรีจิสเตอร์ 192 ครั้ง บน tensor core คือการดำเนินการเดียวที่อ่านค่าเข้า 48 ตัว เฉลี่ย 0.75 ตัวต่อ FMA แทน 3 ตัว ค่าใช้จ่ายส่วนที่ "ไม่ใช่เลขคณิต" ถูกแบ่งเฉลี่ยไปบนงานที่มากกว่าเดิมหลายสิบเท่า (whitepaper กล่าวแค่ว่าเส้นทางข้อมูลของ tensor core ออกแบบเฉพาะเพื่อประสิทธิภาพด้านพลังงานสูง แต่ไม่ได้ให้ตัวเลขพลังงานต่อการดำเนินการ ตัวเลขการนับข้างบนจึงเป็นการนับเชิงหลักการ ไม่ใช่การวัด)

### นับปริมาณงานของ V100

ตัวเลขจาก whitepaper: V100 มี tensor core 640 ตัว (8 ตัวต่อ SM) แต่ละตัวทำ 64 FMA ต่อคล็อก และความถี่บูสต์ 1530 MHz

640 × 64 FMA × 2 FLOP × 1.53×10⁹ ต่อวินาที ≈ **125.3 TFLOPS**

ตรงกับ "125 Tensor TFLOPS" ที่ NVIDIA ประกาศ เทียบกับ CUDA core แบบ FP32 5120 ตัว ตัวละ 1 FMA ต่อคล็อก:

5120 × 2 × 1.53×10⁹ ≈ **15.7 TFLOPS**

ต่างกัน 8 เท่าบนชิปตัวเดียวกัน นี่คือเหตุผลที่ซอฟต์แวร์ deep learning ทุกชั้นพยายามแปลงงานให้เป็นการคูณเมทริกซ์ที่ลง tensor core ได้

### การไทล์: จากก้อน 4×4 สู่เมทริกซ์ขนาดจริง

เมทริกซ์จริงใหญ่กว่า 4×4 มาก whitepaper ระบุว่าระดับ CUDA โปรแกรมเมอร์เห็นอินเทอร์เฟซระดับ warp ที่ทำงานกับเมทริกซ์ 16×16 โดยใช้ 32 เธรดของ warp ร่วมกัน ไทล์ 16×16×16 หนึ่งไทล์คือ 16³ = 4096 FMA = 64 ก้อนขนาด 4×4×4 ที่ฮาร์ดแวร์ต้องเรียงป้อนเข้า tensor core

ลองดูว่าการไทล์เปลี่ยนสมดุลระหว่างการคำนวณกับหน่วยความจำอย่างไร ใช้ตัวเลข V100 (125.3 TFLOPS และแบนด์วิดท์ HBM2 900 GB/s จาก whitepaper) โดยสมมติ A และ B เป็น FP16 (2 ไบต์) และผลลัพธ์เป็น FP32 (4 ไบต์) แต่ละตัวถูกอ่านหรือเขียนจากหน่วยความจำหลักเพียงครั้งเดียว (กรณีอุดมคติที่การไทล์ทำได้ดีที่สุด)

| ขนาด n | FLOP (2n³) | ไบต์ขั้นต่ำ | FLOP/ไบต์ | เวลาคำนวณที่ peak | เวลาย้ายข้อมูล |
| --- | --- | --- | --- | --- | --- |
| 4096 | 1.37×10¹¹ | 134 MB | 1024 | ≈ 1.10 ms | ≈ 0.15 ms |
| 64 | 5.2×10⁵ | 32 KB | 16 | ≈ 4.2 ns | ≈ 36 ns |

อัตราส่วน peak ของเครื่องคือ 125.3×10¹² / 900×10⁹ ≈ 139 FLOP ต่อไบต์ งานที่มี FLOP/ไบต์สูงกว่านี้ (n = 4096) ติดที่การคำนวณ tensor core ได้ทำงานเต็มที่ งานที่ต่ำกว่า (n = 64) ติดที่หน่วยความจำ tensor core นั่งรอข้อมูลเกือบ 90% ของเวลา ความเร็วของ tensor core จึงมีค่าเฉพาะเมื่อเคอร์เนลใช้ข้อมูลซ้ำได้มากพอ ผ่านการเก็บไทล์ไว้ในหน่วยความจำบนชิป (บทที่ 54) นั่นคือ "ฝีมือ" ที่ย่อหน้าข้างบนพูดถึง

## ความละเอียดผูกลึกกับซิลิคอน

Tensor core มักรันมีประสิทธิภาพที่สุดที่ความละเอียดต่ำกว่า (FP16, BF16, INT8 และ FP8 ที่เพิ่มขึ้น) เลขคณิตแคบกว่าต้องการพื้นที่และพลังงานต่อ op น้อยกว่า จึงบรรจุปริมาณงาน MAC ได้มากกว่าที่งบเดียวกัน บทที่ 59 กลับมาเต็ม: การลดความละเอียดไม่ใช่ทางเลือกซอฟต์แวร์ล้วน — มันผูกลึกกับว่าฮาร์ดแวร์ MAC ข้างใต้รันที่แต่ละฟอร์แมตได้มีประสิทธิภาพเพียงใด

### คูณด้วย FP16 แต่สะสมด้วย FP32: ทำไม

Whitepaper ของ V100 ระบุว่า tensor core รับ A และ B เป็น FP16 ผลคูณ FP16 ถูกเก็บแบบความละเอียดเต็ม แล้วสะสมด้วยการบวก FP32 (C และ D เป็น FP16 หรือ FP32 ก็ได้) ทำไมไม่สะสมด้วย FP16 ให้จบ?

FP16 มีบิตเศษส่วน 10 บิต (รายละเอียดของรูปแบบอยู่ในบทที่ 59) ระหว่าง 2048 ถึง 4096 ตัวเลขที่ FP16 แทนได้จึงห่างกันทีละ 2 ถ้าตัวสะสมอยู่ที่ 2048 แล้วบวก 1 ผลลัพธ์ที่แท้จริง 2049 อยู่กึ่งกลางระหว่าง 2048 กับ 2050 พอดี กฎการปัดเศษมาตรฐาน (ปัดไปหาเลขคู่) ปัดกลับเป็น 2048 ตัวสะสม **ติดตาย**

- บวกเลข 1 จำนวน 4096 ครั้งด้วยตัวสะสม FP16 ได้ **2048** แทน 4096
- บวก 0.01 (ในรูป FP16) จำนวน 10,000 ครั้งด้วยตัวสะสม FP16 ได้ **32.0** แทนราว 100 ขณะที่ตัวสะสม FP32 ได้ 100.02 (ส่วนที่เกิน 100 มาจากการที่ 0.01 ในรูป FP16 จริง ๆ คือ 0.010002)

(ทั้งสองผลได้จากการจำลองด้วย NumPy) ผลรวมตาม K ในการคูณเมทริกซ์ใหญ่คือการบวกหลายพันพจน์ต่อช่อง ตรงกับสถานการณ์นี้ทุกประการ การคูณ FP16 ประหยัดวงจรตัวคูณซึ่งเป็นส่วนที่แพงที่สุด ส่วนตัวสะสม FP32 ป้องกันการติดตาย เป็นการแบ่งงานที่เลือกมาอย่างจงใจ

## ไม่ใช่คำตอบเดียว

Tensor core คือคำตอบของ NVIDIA ภายใน GPU ที่ยังอเนกประสงค์ เฟส 10 ครอบคลุม systolic array — TPU ของ Google ที่เด่นที่สุด — สร้างเพื่อเป้าหมาย matmul เดียวกัน จัดที่ระดับฮาร์ดแวร์ต่าง ข้อจำกัดเดียวกัน; สถาปัตยกรรมต่าง
