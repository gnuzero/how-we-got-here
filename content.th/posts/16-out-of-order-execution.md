บทที่ 13 อธิบาย load-use hazard: คำสั่งต้องการค่าที่ load ก่อนหน้ายังดึงไม่เสร็จ บังคับให้ไปป์ไลน์ stall ไปป์ไลน์แบบ in-order ต้อง stall ไปป์ไลน์ *ทั้งก้อน* หลังคำสั่งนั้น แม้คำสั่งถัดไปจะเป็นอิสระและรันได้ทันที การประมวลผลนอกลำดับตอบสิ่งนั้น: ให้คำสั่งอิสระรันเมื่อตัวถูกดำเนินการพร้อม โดยไม่สนใจลำดับโปรแกรมเดิม และบังคับลำดับเฉพาะที่สำคัญ

## Register Renaming: กำจัดการพึ่งพาเทียม

รายละเอียดที่ทำให้คนสะดุด: ไม่ใช่ทุกการพึ่งพาที่เห็นระหว่างคำสั่งจะเป็นของ *จริง* หากคำสั่ง A เขียนรีจิสเตอร์ R1 และอีกหลายคำสั่งถัดมา คำสั่ง B *ก็* เขียน R1 (สำหรับการคำนวณที่ไม่เกี่ยวข้อง) ไม่มีข้อมูลไหลระหว่างพวกมัน — ISA แค่มีรีจิสเตอร์สถาปัตยกรรมจำนวนจำกัด และคอมไพเลอร์นำชื่อ R1 กลับมาใช้ นั่นคือการพึ่งพา "เทียม" (หรือ "name") ต่างจากการพึ่งพา "จริง" (ข้อมูล) ที่ค่าไหลจากคำสั่งหนึ่งไปอีกคำสั่งจริง ๆ

Register renaming แก้สิ่งนี้ด้วยการให้ CPU มีรีจิสเตอร์ *กายภาพ* มากกว่าที่ ISA เปิดเผย และแมปการอ้างอิงรีจิสเตอร์สถาปัตยกรรมของแต่ละคำสั่งไปยังรีจิสเตอร์กายภาพใหม่แบบไดนามิกตอนดีโค้ด การเขียน "R1" ของคำสั่ง A กลายเป็นการเขียนรีจิสเตอร์กายภาพ P17; การเขียน "R1" ภายหลังของคำสั่ง B กลายเป็นการเขียน P42 — ไม่มีความขัดแย้งเทียม และทั้งคู่เดินหน้าได้อิสระจากกัน

## Reservation Stations และการ Issue นอกลำดับ

เมื่อ rename แล้ว คำสั่งรอใน reservation stations — บัฟเฟอร์เล็กที่ถือคำสั่งไว้จนกว่าตัวถูกดำเนินการ *ทั้งหมด* จะพร้อม (มีอยู่แล้ว หรือกำลังถูกผลิตโดยคำสั่งที่บินอยู่ ติดตามผ่านแท็ก) ทันทีที่ตัวถูกดำเนินการของคำสั่งพร้อม มันสามารถ issue ไปยังหน่วยประมวลผลได้ โดยไม่สนใจลำดับโปรแกรมเดิมเทียบกับคำสั่งอื่นที่รอ นั่นคือส่วนนอกลำดับ: คำสั่งประมวลผลตามลำดับที่การพึ่งพาอนุญาต ไม่ใช่ลำดับที่ปรากฏในโปรแกรม

## Reorder Buffer: คืนลำดับที่สำคัญ

การประมวลผลนอกลำดับภายในใช้ได้ แต่ผล *สถาปัตยกรรม* — สิ่งที่ commit ไปยังรีจิสเตอร์และหน่วยความจำที่มองเห็นได้ และลำดับที่ exception หรือ interrupt ปรากฏ — ต้องดูเหมือนทุกอย่างประมวลผลตามลำดับโปรแกรมเดิมพอดี นั่นคืองานของ reorder buffer (ROB): มันติดตามทุกคำสั่งที่บินอยู่ตามลำดับโปรแกรมเดิม และ *retire* (commit ผลไปยังสถานะสถาปัตยกรรม) คำสั่งตามลำดับเดิมนั้นเท่านั้น แม้พวกมันอาจประมวลผลเสร็จภายในเวลาต่างกันมาก

รูปแบบ "ประมวลผลเมื่อพร้อม commit ตามลำดับอย่างเคร่งครัด" นี้ — มักให้เครดิตกับอัลกอริทึมของ Tomasulo ซึ่งพัฒนาเดิมสำหรับหน่วย floating-point ของ IBM System/360 Model 91 (เผยแพร่ปี 1967) — คือแก่นเชิงแนวคิดของ CPU นอกลำดับประสิทธิภาพสูงเกือบทุกตัวที่สร้างตั้งแต่นั้น มันก็แพงเช่นกัน: reservation stations, reorder buffer และ register renaming ล้วนเสียพื้นที่ซิลิคอนและพลังงาน ซึ่งเป็นส่วนหนึ่งของเหตุผลที่การเพิ่มเครื่องจักรนอกลำดับอย่างเดียวมีผลตอบแทนลดลง — หัวข้อที่บทถัดไปรับตรง
