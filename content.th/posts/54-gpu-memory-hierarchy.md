บทที่ 35 วาง memory wall: latency ของ DRAM ไม่ตามทันความเร็ว compute และอุตสาหกรรมส่วนใหญ่ตอบโดยไล่ตาม *แบนด์วิดท์* ในที่ที่ latency เองดื้อ ไม่มีที่ไหนที่การตอบแบบไล่แบนด์วิดท์นั้นเห็นได้ชัด — หรือมีผลต่อสถาปัตยกรรมมากกว่า — เท่าการออกแบบหน่วยความจำ GPU เพราะปริมาณงานคำนวณขนานของ GPU (บทที่ 52–53) สร้างความอยากแบนด์วิดท์หน่วยความจำมหาศาลที่ DDR ทั่วไป (บทที่ 34) ตอบไม่ได้

## เหตุใด GPU จึงต้องการแบนด์วิดท์มากกว่า CPU มาก

CPU แม้หลายคอร์ กำลังรันสตรีมคำสั่งอิสระจำนวนค่อนข้างน้อยในชั่วขณะหนึ่ง แต่ละสตรีมมี working set ที่การแคช (บทที่ 15) มักดูดซับได้พอสมควร GPU ในทางกลับกัน อาจมีเธรดนับพันข้ามหลาย SM ที่ต้องการอ่านเขียนหน่วยความจำพร้อมกัน — และแม้แคชบนชิปช่วยที่นี่ด้วย ขนาดความต้องการขนานรวมหมายความว่าแบนด์วิดท์หน่วยความจำรวมสูงกว่าที่ระบบหน่วยความจำของ CPU ต้องให้ แม้ที่งบพลังงานชิปรวมใกล้เคียงกัน

## HBM: ซ้อนหน่วยความจำแทนการกระจายออก

High Bandwidth Memory (HBM) ใช้แนวทางกายภาพต่างจาก DDR แบบ DIMM ทั่วไป (บทที่ 34) แทนที่ชิป DRAM นั่งบนโมดูลแยกต่อกับโพรเซสเซอร์ผ่านรอย PCB ค่อนข้างยาว HBM ซ้อนได DRAM หลายชั้นในแนวตั้ง เชื่อมกัน — และสุดท้ายกับไดคำนวณของ GPU — ผ่าน through-silicon via (TSV): การเชื่อมไฟฟ้าแนวตั้งที่ถูก fabricate/etch ผ่านตัวไดซิลิคอนเอง แทนการเดินรอบขอบ

โครงสร้างซ้อนนี้ รวมกับอินเทอร์เฟซกว้างมาก (เส้นข้อมูลขนานมากกว่าความกว้างอินเทอร์เฟซของ DIMM ทั่วไปมาก) ให้แบนด์วิดท์สูงกว่าหน่วยความจำ DDR เทียบเท่าอย่างมาก — ที่ต้นทุนตรงของความซับซ้อนการบรรจุขั้นสูงที่บทที่ 51 ครอบคลุม ได HBM กับไดคำนวณ GPU โดยปกติอยู่ด้วยกันบน silicon interposer ที่แชร์ เทคโนโลยีบรรจุพื้นฐานเดียวกับที่บทนั้นอธิบายสำหรับการออกแบบ chiplet โดยทั่วไป นำไปใช้ที่นี่เพื่อซ้อนไดหน่วยความจำใกล้ compute มาก แทนการแยก chiplet เชิงหน้าที่ออกจากกัน

## ลำดับชั้นหน่วยความจำภายในของ GPU เอง

นอกจากความต่าง HBM กับ DDR GPU มีลำดับชั้นภายในของตัวเอง สะท้อนพีระมิด register–cache–main-memory จากบทที่ 10 โดยมีโครงสร้างเฉพาะ GPU ซ้อนเข้าไป แต่ละ SM มี register file (บทที่ 53) ให้ที่เก็บเร็วที่สุด ท้องถิ่นที่สุด เทียบตรงกับ register file ของ CPU Shared memory — scratchpad เร็วที่โปรแกรมเมอร์จัดการได้ ท้องถิ่นต่อ SM — นั่งต่ำกว่านั้น ให้เธรดใน thread block เดียวกัน (กลุ่มเธรดที่ถูก schedule ด้วยกันบน SM เดียว) แชร์ข้อมูลอย่างชัดเจนโดยไม่ต้องวนไปหน่วยความจำที่ช้าและไกลกว่า L2 cache ที่แชร์ข้าม GPU ทั้งก้อน แทนที่จะเป็นของส่วนตัวต่อ SM นั่งต่ำกว่านั้น และ HBM เองคือชั้น "หน่วยความจำหลัก" — แบนด์วิดท์สูงกว่าชั้น DRAM เทียบของ CPU อย่างมาก แต่ยังมี latency สูงกว่าชั้นบนชิปใด ๆ อย่างมีความหมาย ในแบบแผน tradeoff ระหว่าง latency กับความจุที่บทที่ 10 วางสำหรับลำดับชั้นหน่วยความจำ CPU โดยทั่วไป

## เหตุใดสิ่งนี้จัดฉาก Tensor Core โดยตรง

สถาปัตยกรรมหน่วยความจำทั้งหมดนี้มีอยู่เพื่อป้อนความอยาก compute มหาศาล — และกรอบ memory wall ของบทที่ 35 ควรพูดซ้ำให้คมขึ้น: ปริมาณงาน compute ดิบไร้ประโยชน์หากระบบหน่วยความจำส่ง operand และรับผลเร็วไม่พอที่จะให้หน่วยคำนวณเหล่านั้นไม่ว่าง บทถัดไปครอบคลุมโครงสร้าง compute เฉพาะ — tensor core — ที่แบนด์วิดท์ของ HBM มีอยู่เพื่อป้อน และควรพากรอบแบนด์วิดท์หน่วยความจำนี้เข้าการสนทนานั้น: ตัวเลขปริมาณงานสูงสุดของ tensor core มีความหมายเฉพาะในบริบทของระบบหน่วยความจำที่ค้ำจุนมันได้
