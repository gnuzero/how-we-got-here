บทที่ 53 ครอบคลุม CUDA core — เลนการรันขนานอเนกประสงค์ที่รองรับโมเดลคำนวณ SIMT กว้างของ GPU เหมาะกับ workload ขนานหลากชนิด Tensor core เฉพาะทางกว่า: ฮาร์ดแวร์ที่สร้างมาเพื่อปฏิบัติการเดียวพอดี — matrix multiply-accumulate — ซึ่งบังเอิญเป็นปฏิบัติการที่พบบ่อยที่สุดและวิกฤตต่อประสิทธิภาพที่สุดในการคำนวณโครงข่ายประสาทสมัยใหม่ ฮาร์ดแวร์เฉพาะทางสำหรับมันให้ชัยชนะด้านประสิทธิภาพมากเมื่อเทียบกับการทำงานเดียวกันด้วย CUDA core อเนกประสงค์เพียงอย่างเดียว

## เหตุใดการคูณเมทริกซ์โดยเฉพาะ

เกือบทุกชั้นในโครงข่ายประสาทสมัยใหม่ — ชั้น fully connected, convolution (ซึ่ง reformulate เป็นการคูณเมทริกซ์ได้), กลไก attention ในสถาปัตยกรรม transformer — ลดลงที่แก่นการคำนวณ เป็นการคูณเมทริกซ์และการสะสม: รับเมทริกซ์สองตัว คูณเข้าด้วยกัน และสะสมผลเข้าผลรวมวิ่ง ปฏิบัติการนี้ถูกทำจำนวนมหาศาลทั้งตอนฝึกและ inference ที่สเกลใหญ่พอที่ประสิทธิภาพของมันมีผลเกินสัดส่วนต่อประสิทธิภาพระบบรวม — ซึ่งทำให้มันเป็นเป้าที่คุ้มสำหรับฮาร์ดแวร์เฉพาะทางที่สร้างมาเพื่อสิ่งนี้ แทนการพึ่ง compute อเนกประสงค์ล้วน

## Tensor Core ทำอะไรจริง ๆ

Tensor core ทำการคูณเมทริกซ์สะสมขนาดคงที่เล็ก — เช่น คูณเมทริกซ์ 4×4 สองตัวแล้วสะสมผลเข้าตัวที่สาม — ในรอบคล็อกเดียวสำหรับ MMA 4×4×4 เนทีฟ (ไทล์ CUDA WMMA ที่ใหญ่กว่าใช้หลายรอบ) รันเป็นการปฏิบัติการฮาร์ดแวร์แบบ fuse เดียว แทนลำดับคำสั่งคูณและบวกแยกจำนวนมากที่ถูก issue ทีละคำสั่งผ่าน CUDA core อเนกประสงค์ การ fuse นั้นสำคัญต่อประสิทธิภาพ: implementation อเนกประสงค์ของการคูณเมทริกซ์เดียวกันจะต้อง issue คำสั่งแยกหลายครั้ง แต่ละครั้งมี overhead ของตัวเอง — การดึงคำสั่ง decode การเดิน operand — ในขณะที่ฮาร์ดแวร์เฉพาะของ tensor core ทำปฏิบัติการ fuse เล็กทั้งก้อนเป็นหน่วยเดียว โดย overhead ต่อปฏิบัติการน้อยกว่าเลขคณิตที่มีประโยชน์ที่กำลังทำอย่างมาก

## การไหลของข้อมูลอย่างรูปธรรม

เมทริกซ์อินพุต (activation จากชั้นก่อน และน้ำหนักที่เรียนรู้ของชั้น) ถูกโหลดเข้า tensor core ถูกคูณและสะสมตามปฏิบัติการคงที่ที่ฮาร์ดแวร์ถูกสร้างมาทำ และผล — ชิ้นหนึ่งของผลคูณเมทริกซ์ที่ใหญ่กว่า — ถูกเขียนออก โดยปกติสะสมเข้าผลใหญ่ที่ครอบคลุมหลายปฏิบัติการ tensor core ต่อกันเพื่อคำนวณการคูณเมทริกซ์เต็มที่ใหญ่กว่าขนาดปฏิบัติการคงที่ของ tensor core ใดตัวเดียว การประสานสิ่งนี้ — ป้อนบล็อกย่อยที่ถูกของเมทริกซ์ใหญ่เข้า tensor core ในลำดับที่ถูก สะสมผลย่อยให้ถูก — คือส่วนจริงที่ทำให้การออกแบบเคอร์เนล GPU ที่มีประสิทธิภาพสำหรับ deep learning เป็นพื้นที่ความเชี่ยวชาญของตัวเอง ต่างจากการโปรแกรมขนานทั่วไป

## การเชื่อมกับ Quantization

Tensor core ถูกออกแบบบ่อยให้ทำงานมีประสิทธิภาพที่สุดที่ความละเอียดเชิงตัวเลขเฉพาะ มักต่ำกว่า — หัวข้อที่บทที่ 59 ครอบคลุมตรง — เพราะเลขคณิตความละเอียดต่ำกว่า (FP16, BF16, INT8 และ FP8 ที่เพิ่มขึ้น) ต้องการพื้นที่ฮาร์ดแวร์และพลังงานต่อปฏิบัติการน้อยกว่าตามสัดส่วนเมื่อเทียบกับความละเอียด FP32 เต็ม ให้ชิปบรรจุปริมาณงานคูณสะสมขนานได้มากกว่าที่งบพื้นที่และพลังงานเดียวกัน นี่คือการเชื่อมที่รับน้ำหนัก ควรชูไว้ตอนนี้: ส่วนใหญ่ของ *เหตุผล* ที่อุตสาหกรรมผลัก numerics ความละเอียดต่ำสำหรับการเรียนรู้เชิงลึก ย้อนไปที่ประสิทธิภาพฮาร์ดแวร์ของ tensor core ที่ไวต่อความละเอียดเชิงตัวเลขที่ถูกขอให้ทำงาน — การลดความละเอียดไม่ใช่ทางเลือกซอฟต์แวร์หรืออัลกอริทึมที่เป็นอิสระจากฮาร์ดแวร์; มันผูกลึกกับว่าฮาร์ดแวร์ tensor core ข้างใต้รันที่แต่ละระดับความละเอียดได้มีประสิทธิภาพเพียงใด

## สถาปัตยกรรมทางเลือกที่ควรรู้

Tensor core คือคำตอบเฉพาะของ NVIDIA ต่อการเร่งการคูณเมทริกซ์ภายในสถาปัตยกรรม GPU ที่ยังอเนกประสงค์อยู่ ไม่ใช่แนวทางเดียวที่ใช้ได้ — เฟส 10 ครอบคลุม systolic array ตรง เป็นโครงสร้างฮาร์ดแวร์ต่าง (ใช้เด่นที่สุดใน TPU ของ Google) สร้างรอบเป้าหมายพื้นฐานเดียวกันคือการคูณเมทริกซ์ที่มีประสิทธิภาพ แต่จัดที่ระดับฮาร์ดแวร์ต่างกันพอควร และคุ้มที่จะเข้าใจในฐานะทางเลือกสถาปัตยกรรมจริง ไม่ใช่เพียง "ไอเดียเดียวกันคนละชื่อ"
