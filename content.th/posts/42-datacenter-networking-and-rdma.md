TCP/IP (บทที่ 41) คือกระดูกสันหลัง addressing และความเชื่อถือได้ของอินเทอร์เน็ตทั่วไป — ยอดเยี่ยมที่การสื่อสารแข็งแรงข้ามเครือข่ายต่างชนิด ไม่เชื่อถือได้ กระจายทั่วโลก ภายในศูนย์ข้อมูลเดียว อย่างไรก็ตาม ที่ทุกเครื่องอยู่ภายใต้การควบคุมขององค์กรเดียวและอยู่ใกล้กันทางกายภาพ เส้นทางแบบผ่านเคอร์เนลแบบดั้งเดิมของ TCP/IP เริ่มดูเหมือน overhead ที่ไม่จำเป็นสำหรับ workload ที่ต้องการทุกไมโครวินาทีของ latency และทุกบิตของแบนด์วิดท์ที่เป็นไปได้

## Overhead มาจากไหนจริง ๆ

การส่ง TCP/IP แบบดั้งเดิมเกี่ยวข้องกับแอปคัดลอกข้อมูลเข้าบัฟเฟอร์เคอร์เนล สแต็กเครือข่ายของเคอร์เนลประมวลผล header และตรรกะ TCP/IP และ NIC ท้ายที่สุดส่งผล — พร้อมกระบวนการประมาณสมมาตรที่ฝั่งรับ แต่ละขั้นใช้อรอบ CPU และ สำคัญกว่าสำหรับ workload ที่ไวต่อ latency คือการ *คัดลอก* จริงของข้อมูลระหว่างตำแหน่งหน่วยความจำ — บัฟเฟอร์แอปไปบัฟเฟอร์เคอร์เนล บัฟเฟอร์เคอร์เนลไป NIC และภาพกระจกที่ฝั่งรับ สำหรับคำขอเว็บอเนกประสงค์ overhead นี้เล็กน้อย สำหรับ high-performance computing หรือการฝึก ML แบบกระจายที่แลก gradient หลายครั้งต่อวินาที มันสะสมเป็นภาษีสมรรถนะที่วัดได้

## RDMA: เอาเคอร์เนลและ CPU ออกจากเส้นทางข้อมูล

RDMA — Remote Direct Memory Access — ให้เครื่องหนึ่งอ่านจาก หรือเขียนตรงเข้า หน่วยความจำของอีกเครื่อง โดยไม่ต้องให้ CPU หรือเคอร์เนลของเครื่องรับมีส่วนร่วมในการถ่ายโอนนั้น การ์ดเครือข่ายที่รองรับ RDMA เคลื่อนข้อมูลตรงระหว่างหน่วยความจำของสองเครื่อง ข้ามเส้นทางคัดลอกผ่านเคอร์เนลแบบดั้งเดิม นี่คือแนวคิดเดียวกับ GPUDirect RDMA จากบทที่ 37 — การถ่ายโอนหน่วยความจำ-ถึง-หน่วยความจำตรง ไม่มีการคัดลอกกลางที่ไม่จำเป็น รอบ CPU ว่างสำหรับคำนวณแทนการเฝ้าการถ่ายโอน — นำไปใช้กับการสื่อสาร *เครือข่าย* ระหว่างเครื่องแยก แทนระหว่าง GPU ภายในหรือติดกับเครื่องเดียว

## ทอโพโลยี Fat-Tree: การเดินสายเครื่องนับพันเข้าด้วยกัน

ที่สเกลศูนย์ข้อมูล — เครื่องนับพัน ไม่ใช่แค่หยิบมือ — วิธีที่เครื่องเหล่านั้นถูกเดินสายด้วยกันสำคัญต่อแบนด์วิดท์ที่ทำได้ และ สำคัญเท่า ๆ กัน ต่อว่าแบนด์วิดท์นั้นกระจาย *สม่ำเสมอ* เพียงใด ทอโพโลยี fat-tree เป็นวิธีที่มีโครงสร้างโดยเจตนาในการเชื่อมสวิตช์และเครื่อง เพื่อให้แบนด์วิดท์สเกลได้คาดการณ์เมื่อคุณขึ้นลำดับชั้น แทนการสร้างลิงก์คอขวดซ่อนที่โผล่เฉพาะใต้โหลดหนัก นั่นคือเหตุผลที่คลัสเตอร์ฝึกขนาดใหญ่ (หัวข้อที่เฟส 10 กลับมาสำหรับอินเตอร์คอนเนกต์คลัสเตอร์ฝึก AI) ถูกออกแบบด้วยระดับความตั้งใจเชิงทอโพโลยีนี้ แทนการเดินสายเครื่องด้วยวิธีเฉพาะกิจที่สะดวกทางกายภาพ

## เส้นตรงกลับสู่โครงการฮาร์ดแวร์ของชุดบทความนี้เอง

แนวคิดหลักของ RDMA — ลบการคัดลอกที่ไม่จำเป็น ข้ามเคอร์เนลเมื่อไม่จำเป็น ให้ฮาร์ดแวร์เคลื่อนข้อมูลตรงเท่าที่ทอโพโลยีอนุญาต — คือปรัชญาเดียวกับหลังโครงการ GPU memory fabric แบบกำหนดเองที่อ้างตลอดชุดบทความนี้: ให้ *ฮาร์ดแวร์เอง* รับผิดชอบการเคลื่อนข้อมูลอย่างมีประสิทธิภาพ แทนการวนทุกอย่างผ่านเส้นทางซอฟต์แวร์ที่ CPU อเนกประสงค์เป็นตัวกลางโดยปริยาย บทที่ 37 กล่าวสิ่งนี้ที่สเกล GPU-ถึง-GPU ภายในและข้ามเครื่อง; บทนี้นำหลักการเดียวกันไปใช้กับการสื่อสารบนเครือข่ายระหว่างเครื่องทั้งเครื่อง รวมกันแล้วพวกมันเป็นสะพานเข้าสู่บท distributed systems ในเฟส 7 ที่หลักการเคลื่อนข้อมูลเหล่านี้พบการคำนวณกระจายขนาดใหญ่ — เริ่มจากระบบกระจายยุคแรกของอินเทอร์เน็ตก่อนเว็บเอง
