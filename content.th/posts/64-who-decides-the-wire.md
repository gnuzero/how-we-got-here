ARPANET (บทที่ 39) และ TCP/IP (บทที่ 41) แก้ปัญหาว่าแพ็กเก็ตเคลื่อนที่อย่างไร แต่เพียงลำพังไม่ได้ตอบคำถามเงียบกว่า: *ใครมีสิทธิ์บอกว่าบิตเหล่านั้นหมายความว่าอะไร?* พอร์ต 80, คำนำหน้า IPv4, `.com`, code point ของ ก — ไม่มีอันใดใช้ได้ เว้นแต่ผู้ปฏิบัติการที่อยู่ห่างกันจะปฏิบัติต่อตัวระบุเดียวกันในทางเดียวกัน เรื่องการกำกับดูแลอินเทอร์เน็ตคือเรื่องของข้อตกลงนั้น: ไม่ใช่รัฐสภาเหนือเครือข่าย แต่เป็นชุดบัญชีแชร์สำหรับ **หมายเลข**, **ชื่อ**, และ **การเข้ารหัส**

## เอกสารก่อนสถาบัน

เครื่องมือประสานงานชิ้นแรกคือชุดเอกสาร ในเมษายน 1969 Steve Crocker ตีพิมพ์ [RFC 1](https://www.rfc-editor.org/rfc/rfc1) — *Host Software* — เป็นบันทึกทำงานสำหรับชุมชนวิจัย ARPANET น้ำเสียงสำคัญ: "Request for Comments" ไม่ใช่ "คำสั่ง" Jon Postel บรรณาธิการชุดนี้เกือบสามทศวรรษ เปลี่ยนบันทึกไม่เป็นทางการให้เป็นบันทึกสาธารณะที่ยั่งยืนว่าอินเทอร์เน็ตทำงานจริงอย่างไร ประตูออก: [ประวัติ RFC Editor](https://www.rfc-editor.org/history/)

เมื่อชุมชนวิจัยโตเกินการประชุมในทางเดิน มันเติบโตเป็น Internet Engineering Task Force (IETF) วลีที่รับน้ำหนักคือของ Dave Clark: *rough consensus and running code* — มาตรฐานพิสูจน์ตัวด้วยการส่งมอบ ไม่ใช่ด้วยการลงคะแนน IETF ไม่ได้เป็นเจ้าของอินเทอร์เน็ต; มันเป็นเจ้าของกระบวนการถกโปรโตคอลให้กลายเป็นสิ่งที่ผู้ปฏิบัติการจะนำไปใช้ ประตูออก: [ietf.org](https://www.ietf.org/)

## หมายเลข: ต้องมีใครแจกตัวระบุ

แพ็กเก็ตพกหมายเลขโปรโตคอล หมายเลขพอร์ต บล็อกที่อยู่ ค่า ASN ประเภทสื่อ — ตัวระบุที่ไร้ค่าหากสองกลุ่มสร้างตัวเดียวกันสำหรับความหมายต่างกัน เป็นปี ๆ บัญชีนั้นอยู่ที่เดียว: Internet Assigned Numbers Authority (IANA) บริหารเป็นบริการปฏิบัติโดย Jon Postel (พร้อม Joyce Reynolds เป็นจุดติดต่อยาวนาน) ภายใต้สัญญาวิจัยที่ UCLA และต่อมา USC/ISI IANA คือเมล็ดของ *ชนิด*: ทะเบียนกลางสำหรับพารามิเตอร์โปรโตคอล เพื่อให้การอิมพลีเมนต์ทำงานร่วมกันได้โดยไม่ต้องเจรจาคู่ต่อคู่

เมื่อเครือข่ายขยายเกินสมุดบันทึกของคนคนเดียว ทรัพยากรตัวเลขแยกตาม *ชนิด* พารามิเตอร์โปรโตคอลอยู่กับ IANA พื้นที่ที่อยู่ IP เคลื่อนไปสู่ Regional Internet Registries — ARIN (1997) สำหรับส่วนใหญ่ของอเมริกาเหนือคือชื่อเมล็ดที่ Nayana ให้; RIPE NCC, APNIC, LACNIC และ AFRINIC คือ *ชนิด* เดียวกันสำหรับภูมิภาคอื่น โดยมี national หรือ local Internet registries (NIRs) อยู่ใต้บางแห่งเมื่อภูมิภาคเลือกแบบนั้น รูปแบบคือจุดสำคัญ: ตัวระบุที่หายากและไม่ซ้ำต้องการผู้ดูแลที่ทุกคนชี้ได้ ประตูออก: [iana.org](https://www.iana.org/), [arin.net](https://www.arin.net/)

## ชื่อ: มนุษย์ต้องการคำ; เครื่องต้องการความไม่ซ้ำ

ข้อกำหนด DNS ของ Paul Mockapetris ([RFC 1034](https://www.rfc-editor.org/rfc/rfc1034), [RFC 1035](https://www.rfc-editor.org/rfc/rfc1035)) เปลี่ยนชื่อแบบลำดับชั้นให้เป็นระบบค้นหาแบบกระจายบนผ้าที่อยู่ ชื่อเป็นการเมืองในทางที่ตัวเลขดิบไม่ใช่: คนถกเถียงเรื่องคำ [RFC 1591](https://www.rfc-editor.org/rfc/rfc1591) ของ Jon Postel วางกรอบนโยบายโดเมนยุคแรกในฐานะการดูแล

ปลายทศวรรษ 1990 รัฐบาลสหรัฐต้องการย้ายฟังก์ชันประสานงานเหล่านั้นออกจากสัญญาวิจัยเดียว ICANN (Internet Corporation for Assigned Names and Numbers) ก่อตั้งปี 1998 — ประธานชั่วคราว Esther Dyson — เพื่อถือที่นั่งสถาบันสำหรับนโยบายชื่อและหมายเลข ในขณะที่ IANA ยังทำงานเป็นทะเบียนปฏิบัติภายใต้ร่มนั้น อ่าน ICANN เป็นเมล็ดอีกอันของ *ชนิด*: องค์กรหลายฝ่ายมีส่วนได้ส่วนเสียที่งานคือความเสถียรและความไม่ซ้ำของเนมสเปซแชร์ ไม่ใช่การเลือกผู้ชนะในแอปพลิเคชัน ประตูออก: [icann.org](https://www.icann.org/)

## การเข้ารหัส: เพย์โหลดต้องหมายถึงอักษรเดียวกัน

การทำงานร่วมกันพังเงียบเมื่อสองปลายไม่เห็นด้วยว่าลำดับไบต์ *คืออะไร* Unicode Consortium (ก่อตั้ง 1991; งานต้นจาก Joe Becker, Mark Davis และคนอื่นข้ามบริษัทที่ต้องการชุดอักขระเดียว) ดูแลการแมปแชร์จากอักขระนามธรรมสู่ code point — เหตุผลที่ไทย ละติน และอีโมจิแชร์สายเดียวกันได้โดยไม่ให้แต่ละแอปประดิษฐ์ตารางอักษรของตัวเอง UTF-8 จึงกลายเป็นการเข้ารหัส *บนสาย* ที่ครองสำหรับคลังนั้น ประตูออก: [unicode.org](https://www.unicode.org/), [Unicode Standard](https://www.unicode.org/standard/standard.html)

## ญาติของชนิดเดียวกัน

เพื่อนร่วมชนิดอีกไม่กี่รายได้หนึ่งประโยค — *ชนิด* ความหมายแชร์เดียวกัน ไม่ใช่ทัวร์องค์กรมาตรฐาน:

- **W3C และ WHATWG** — Tim Berners-Lee ก่อตั้ง World Wide Web Consortium (1994) เพื่อดูแลมาตรฐานแพลตฟอร์มเว็บ; WHATWG ภายหลังรับสเปก HTML/DOM แบบ living เมื่อผู้ผลิตเบราว์เซอร์ต้องการเส้นทางวนรอบเร็วขึ้น *ชนิด* เดียวกัน: ใครกำหนดได้ว่าเอกสารและ API หมายความว่าอะไรในเบราว์เซอร์
- **IEEE** — IEEE 802 คือเหตุผลที่ Ethernet (บทที่ 40) และ Wi-Fi ไม่ใช่ภาษาเกาะเฉพาะของผู้ผลิตที่ชั้นลิงก์
- **ISO และเพื่อน** — มาตรฐานสากลแบบทางการนั่งข้างโลก RFC เมื่อการจัดซื้อ ความปลอดภัย หรือหน่วยงานชาติเรียกร้อง; อินเทอร์เน็ตส่วนใหญ่ส่งมอบบน RFC ก่อน แล้วค่อย harmonize ทีหลัง

## เหตุใดบทนี้จึงอยู่ในเส้นทาง

บทที่ 39–41 คือการเดิมพันทางวิศวกรรม: แพ็กเก็ต ชั้น สื่อที่ไม่เชื่อถือได้ บทนี้คือการเดิมพันด้านพลเมืองที่อยู่ใต้พวกนั้น: **ความหมายแชร์คือโครงสร้างพื้นฐาน** หากไม่มีใคร (และกระบวนการ) ตัดสินหมายเลข ชื่อ และการเข้ารหัส เครือข่ายใหม่ทุกอันคือภาษาส่วนตัว ประตูด้านบนคือแหล่งปฐมภูมิ — RFC, ทะเบียน, หน้า consortium

เส้นทางข้างทางเลือกจากที่นี่: คน *หา* สิ่งต่าง ๆ และ *คุย* บนสายแชร์นั้นอย่างไร (บทที่ 43) หรือรหัสลับยามสงครามบังคับเครื่องที่เก็บความลับได้อย่างไร (บทที่ 66) แกนหลักยังเป็นแพ็กเก็ต → ระบบ → ซิลิคอน → attention; นี่คือจังหวะขยายเลนส์ที่คุณจะเข้าหรือข้ามก็ได้
