ஒரு ISA (பதிவு 11) ஒரு விவரக்குறிப்பு. ஒரு datapath அதைச் செயல்படுத்தும் இயற்பியல் வன்பொருள். மிக எளிய பதிப்பு — ஒரு single-cycle datapath — ஒரு முழு அறிவுறுத்தலை ஒரு clock சுழற்சிக்கு, தொடக்கம் முதல் முடிவு வரை, pipelining இல்லாமல் செயல்படுத்துகிறது. இன்றைய உண்மையான CPU-கள் இப்படிக் கட்டப்படுவதில்லை, ஆனால் முந்தைய கட்டங்களின் துண்டுகள் எப்படி இணைகின்றன என்பதைக் காண மிகத் தெளிவான வழி இது.

> **தமிழ் இடைவெளிக் குறிப்பு:** Datapath பற்றித் தமிழில் எழுத்து விளக்கம் கிடைக்கவில்லை; fetch-decode-execute, கட்டுப்பாட்டகம் பற்றி 11ஆம் வகுப்புப் பாடநூலில் சுருக்கமான அறிமுகம் மட்டும். காணொளிச் சான்று YouTube தேடல் முடிவுகள் மட்டும் — காணொளிகள் பார்க்கப்படவில்லை. இங்கே ஒரு instruction-ஐ datapath வழியாக எண்களுடன் பின்தொடர்கிறோம், கட்டுப்பாட்டு சமிக்ஞை அட்டவணையை எழுதுகிறோம், single-cycle clock காலத்தைக் கணக்கிடுகிறோம். Mini-CPU எண்கள் lab-இன் மூலக் குறியீடு மற்றும் அதன் simulator ஓட்டங்களிலிருந்து; தாமத (delay) எண்கள் "எடுத்துக்காட்டு மதிப்பு" — உண்மையான chip அளவீடுகள் அல்ல.

## முதலில் சொற்கள்

- **Datapath (தரவுப்பாதை):** தரவு பாயும் வன்பொருள் — பதிவேடுகள், ALU, நினைவகம், அவற்றை இணைக்கும் கம்பிகளும் multiplexer-களும்.
- **Control unit (கட்டுப்பாட்டகம்):** opcode-ஐப் படித்து, datapath-இன் ஒவ்வொரு தேர்வியையும் (mux) எழுதும்-அனுமதியையும் (enable) அமைக்கும் பகுதி.
- **கட்டுப்பாட்டு சமிக்ஞை (control signal):** ஒரு mux எந்த உள்ளீட்டைத் தேர்ந்தெடுக்க வேண்டும், ஒரு பதிவேடு இந்த clock-இல் எழுதப்பட வேண்டுமா போன்றவற்றைச் சொல்லும் ஒற்றைப் பிட் அல்லது சிறு பிட் தொகுதி.
- **IR (Instruction Register, அறிவுறுத்தல் பதிவேடு):** fetch செய்த instruction byte-ஐ வைத்திருக்கும் பதிவேடு.
- **கொடிகள் (flags):** கடைசி கணக்கின் பண்புகளைச் சொல்லும் பிட்கள் — carry (வரம்பு மீறல்), zero (முடிவு பூஜ்ஜியம்).
- **Critical path (மிக நீண்ட பாதை):** ஒரு clock சுழற்சிக்குள் சமிக்ஞை கடக்க வேண்டிய மிக நீண்ட தாமதச் சங்கிலி; clock காலம் இதைவிடக் குறைவாக இருக்க முடியாது.
- **Single-cycle:** ஒவ்வொரு instruction-உம் சரியாக ஒரு clock சுழற்சியில் முடியும் வடிவமைப்பு.

## மையக் கூறுகள்

**நிரல் கவுண்டர் (PC):** தற்போதைய அறிவுறுத்தலின் முகவரியை வைத்திருக்கும் ஒரு பதிவேடு (பதிவு 9-இன் flip-flop-கள்). **அறிவுறுத்தல் நினைவகம்:** datapath-இன் பார்வையில் படிக்க-மட்டும், PC-ஆல் அட்டவணைப்படுத்தப்பட்டது, மூல அறிவுறுத்தல் பிட்களைத் திருப்பும். **Register File:** பதிவேடுகளின் சிறிய, வேகமான அணி (பதிவு 10-இன் cache விவாதத்தின் அதே SRAM-குடும்பக் கலங்களிலிருந்து கட்டப்பட்டது, வேறுவிதமாக அமைக்கப்பட்டது) டிகோட் செய்யப்பட்ட அறிவுறுத்தல் தன் operands-ஐப் படித்து முடிவை எழுதும் இடம். **ALU:** பதிவு 8-இன் எண்கணித/தர்க்க அலகு, அறிவுறுத்தல் குறிப்பிடும் செயல்பாட்டைச் செய்கிறது. **தரவு நினைவகம்:** load/store அறிவுறுத்தல்களுக்கு, முதன்மை நினைவகத்திற்கான பாதை. **கட்டுப்பாட்டகம்:** opcode-ஐ டிகோட் செய்து ஒவ்வொரு கட்டுப்பாட்டு சமிக்ஞையையும் உருவாக்குகிறது — எந்த ALU செயல்பாட்டைச் செய்ய வேண்டும், register file-க்கு எழுத வேண்டுமா, இது நினைவக அணுகலா, மற்றும் பல.

## ஒரு அறிவுறுத்தலைத் தொடர்ந்து

ஒரு எளிய ADD-ஐ எடுங்கள். சுழற்சி தொடங்குகிறது: PC அறிவுறுத்தல் நினைவகத்தை அட்டவணைப்படுத்துகிறது, அறிவுறுத்தல் பிட்கள் வெளிவருகின்றன. கட்டுப்பாட்டகம் opcode-ஐ டிகோட் செய்து இது பதிவேடு-பதிவேடு வடிவத்தில் ஒரு ADD என்று தீர்மானிக்கிறது. Register file இரு மூல-பதிவேட்டுப் புலங்களைப் பயன்படுத்திப் படிக்கப்படுகிறது. அந்த மதிப்புகள் ALU-க்குள் நுழைகின்றன, கட்டுப்பாட்டகம் அதைக் கூட்டலுக்கு அமைத்துள்ளது. ALU முடிவு register file-இன் write-data உள்ளீட்டிற்குச் செல்கிறது, இலக்கு-பதிவேட்டுப் புலம் அது எங்கே எழுதப்படுகிறது என்பதைத் தேர்ந்தெடுக்கிறது. அதே நேரத்தில், PC அடுத்த அறிவுறுத்தலைச் சுட்ட அதிகரிக்கப்படுகிறது (அல்லது, ஒரு கிளைக்கு, வேறுவிதமாகக் கணிக்கப்படுகிறது). Fetch, decode, பதிவேட்டுப் படிப்பு, ALU செயல்பாடு, பதிவேட்டு எழுத்து, மற்றும் PC புதுப்பிப்பு அனைத்தும் *ஒரே* clock சுழற்சிக்குள் நடக்கின்றன.

## ஒரு instruction, எண்களுடன்: `ADD 14`

Mini-CPU-இன் வழிகாட்டும் நிரலில் நான்காவது instruction `ADD 14`. அதற்கு முன் நிலை (simulator ஓட்டம்): A = 8, mem[14] = 5, PC = 3.

| படி | என்ன நடக்கிறது | மதிப்புகள் |
|---|---|---|
| Fetch | IR ← mem[PC]; PC ← PC + 1 | IR ← mem[3] = 0x2E; PC ← 4 |
| Decode | IR-இன் மேல் 4 பிட் → opcode, கீழ் 4 பிட் → operand | 0010 → ADD; 1110 → 14 |
| Operand படிப்பு | operand-ஐ நினைவக முகவரியாகப் பயன்படுத்து | mem[14] = 5 |
| Execute | ALU: A + mem[14] | 8 + 5 = 13 |
| கொடிகள் | carry = (முடிவு > 255); zero = (முடிவு = 0) | 13 ≤ 255 → carry 0; 13 ≠ 0 → zero 0 |
| Write-back | A ← முடிவு (8 பிட்டுக்குக் குறைத்து) | A ← 13 = 0x0D |

**வரம்பு மீறல், ஒரு கணக்கில்** (காகிதத்தில்; எடுத்துக்காட்டு மதிப்புகள்): A = 200, mem[a] = 100 என்றால் 200 + 100 = 300. 8 பிட் அதிகபட்சம் 255. lab-இன் விதி: A ← 300 AND 0xFF = 300 − 256 = **44**, carry = **1**. அடுத்த `JC` instruction அந்த carry-ஐப் பார்த்துத் தாவும் — இப்படித்தான் 8-பிட் இயந்திரம் பெரிய எண்களைக் கையாள்கிறது.

## கட்டுப்பாட்டு சமிக்ஞை அட்டவணை

கட்டுப்பாட்டகம் உண்மையில் ஒரு பெரிய உண்மை அட்டவணை (truth table, பதிவு 8): உள்ளீடு opcode (மற்றும் கொடிகள்), வெளியீடு ஒவ்வொரு சமிக்ஞையும். Mini-CPU-இன் நடத்தையை (lab மூலக் குறியீட்டின் execute பகுதி) ஒரு வன்பொருள் கட்டுப்பாட்டகமாக எழுதினால் இப்படி ஒரு அட்டவணை வரும். சமிக்ஞைப் பெயர்கள் நம் விளக்கத்துக்காகத் தேர்ந்தவை; lab JavaScript-இல் இயங்குகிறது, கம்பிகளில் அல்ல.

| Instruction | A_எழுது | A_மூலம் | ALU_செயல் | Mem_எழுது | கொடிகள்_புதுப்பி | PC_மூலம் |
|---|---|---|---|---|---|---|
| NOP | 0 | — | — | 0 | 0 | PC+1 |
| LDA a | 1 | நினைவகம் | — | 0 | zero மட்டும் | PC+1 |
| ADD a | 1 | ALU | கூட்டல் | 0 | 1 | PC+1 |
| SUB a | 1 | ALU | கழித்தல் | 0 | 1 | PC+1 |
| STA a | 0 | — | — | 1 | 0 | PC+1 |
| LDI n | 1 | operand புலம் | — | 0 | zero மட்டும் | PC+1 |
| JMP a | 0 | — | — | 0 | 0 | operand |
| JC a | 0 | — | — | 0 | 0 | carry ? operand : PC+1 |
| JZ a | 0 | — | — | 0 | 0 | zero ? operand : PC+1 |
| OUT | 0 | — | — | 0 | 0 | PC+1 (Output ← A) |
| HLT | 0 | — | — | 0 | 0 | நிறுத்து |

"A_மூலம்" என்பது A-க்கு முன் உள்ள ஒரு 3-உள்ளீட்டு mux (நினைவகம் / ALU / operand புலம்). "PC_மூலம்" என்பது PC-க்கு முன் உள்ள 2-உள்ளீட்டு mux; அதன் தேர்வுப் பிட் = (JMP) OR (JC AND carry) OR (JZ AND zero) — மூன்று gate-களில் எழுதக்கூடிய தர்க்கம். ஒவ்வொரு வரிசையும் ஒரு instruction-இன் "பொருள்" (பதிவு 11-இன் ISA ஒப்பந்தம்) வன்பொருள் சமிக்ஞைகளாக மாறிய வடிவம்.

**இப்போது முயல்க.** கீழே உள்ள mini-CPU-வை அதன் வழிகாட்டும் நிரல் வழியாக **படி (Step)** அழுத்திச் செல்லுங்கள். ஒவ்வொரு **படி**-யும் அந்தத் துண்டுகளில் ஒன்று மெதுவான இயக்கத்தில் — IR-க்குள் fetch, opcode-ஐ decode, A மற்றும் நினைவகத்திற்குள் execute — இந்தப் பதிவு இப்போது பெயரிட்ட அதே பாதை, பார்க்கும் அளவுக்குச் சிறியது.

**இப்போது முயல்க: ஒரு trace அட்டவணையை நிரப்புங்கள்.** Lab-இல் **மீட்டமை (Reset)** அழுத்தி, ஒவ்வொரு **படி (Step)**-க்குப் பிறகும் PC (பதின்மம்), IR (hex), A (hex) ஆகியவற்றை எழுதுங்கள். lab-இன் வழிகாட்டிப் பலகம் ஒவ்வொரு படியிலும் "எடு: IR ← mem[…]", "குறிவிலக்கு: … (opcode 0x…, operand …)" என்று விவரிக்கும். உங்கள் அட்டவணை இதோடு பொருந்த வேண்டும் (simulator ஓட்டத்தால் சரிபார்த்தது):

| Step | PC | IR | A | குறிப்பு |
|---|---|---|---|---|
| 1 | 1 | 55 | 05 | LDI 5 |
| 2 | 2 | 4E | 05 | STA 14 — mem[14] = 5 |
| 3 | 3 | 58 | 08 | LDI 8 |
| 4 | 4 | 2E | 0D | ADD 14 — 8 + 5 = 13 |
| 5 | 5 | 4F | 0D | STA 15 — mem[15] = 13 |
| 6 | 6 | 1F | 0D | LDA 15 |
| 7 | 7 | E0 | 0D | OUT — Output 13 |
| 8 | 8 | F0 | 0D | HLT — HALT கொடி ஒளிரும் |

A எந்தப் படிகளில் மாறுகிறது (1, 3, 4), நினைவகம் எந்தப் படிகளில் மாறுகிறது (2, 5) என்பதைக் கவனியுங்கள் — மேலே உள்ள அட்டவணையின் A_எழுது, Mem_எழுது நெடுவரிசைகள் சரியாக அதைக் கணிக்கின்றன.

## "Single-Cycle" ஏன் கற்பித்தல் கருவி, உண்மையான வடிவமைப்பு அல்ல

கட்டுப்பாட்டைக் கவனியுங்கள்: clock காலம் *மிக மெதுவான* சாத்தியமான அறிவுறுத்தலின் ஒவ்வொரு நிலை வழியாகவும் முழுப் பாதைக்குப் போதுமான நீளமாக இருக்க வேண்டும் — ஒவ்வொரு நிலையும் தேவைப்படாத அறிவுறுத்தல்களுக்கும் கூட. ஒரு எளிய பதிவேடு-க்கு-பதிவேடு ADD தரவு நினைவகத்தை ஒருபோதும் தொடுவதில்லை, ஆயினும் clock காலம் தொடும் அறிவுறுத்தல்களையும் இன்னும் இடமளிக்க வேண்டும். எனவே ஒவ்வொரு அறிவுறுத்தலும் மோசமான நிலையின் வேகத்தில் ஓடுகிறது, அது சாத்தியமான throughput-ஐ வீணாக்குகிறது.

அதுவே pipelining தீர்க்கும் பிரச்சனை: மோசமான நிலைக்கு அளவிடப்பட்ட ஒரு நீண்ட clock காலத்திற்குப் பதிலாக, செயல்பாட்டை நிலைகளாக உடைத்து, ஒவ்வொன்றும் *தன் சொந்த* மோசமான நிலைக்கு அளவிடப்பட்டது, மற்றும் வெவ்வேறு அறிவுறுத்தல்கள் ஒரே நேரத்தில் வெவ்வேறு நிலைகளை ஆக்கிரமிக்க விடுங்கள். அது அடுத்த பதிவின் பொருள் — மேலும் செவ்வியல் CPU நுண்கட்டமைப்பில் ஒருவேளை மிக முக்கியமான ஒற்றை யோசனை.

## Single-cycle clock காலம், கணக்கில்

ஒவ்வொரு கூறுக்கும் ஒரு தாமதம் (எல்லாம் எடுத்துக்காட்டு மதிப்புகள்; picosecond, ps):

| கூறு | தாமதம் |
|---|---|
| Instruction நினைவகம் | 200 ps |
| Register file படிப்பு | 100 ps |
| ALU | 150 ps |
| தரவு நினைவகம் | 200 ps |
| Register file எழுத்து | 100 ps |

ஒவ்வொரு instruction வகையும் எந்தக் கூறுகளைக் கடக்கிறது:

| வகை | பாதை | மொத்தம் |
|---|---|---|
| பதிவேடு-பதிவேடு (ADD) | Inst + RegRd + ALU + RegWr | 200 + 100 + 150 + 100 = **550 ps** |
| Load | Inst + RegRd + ALU + DataMem + RegWr | 200 + 100 + 150 + 200 + 100 = **750 ps** |
| Store | Inst + RegRd + ALU + DataMem | 200 + 100 + 150 + 200 = **650 ps** |
| Branch | Inst + RegRd + ALU | 200 + 100 + 150 = **450 ps** |

**Single-cycle விதி:** clock காலம் ≥ மிக நீண்ட பாதை = 750 ps (load). அதிர்வெண் = 1 ÷ 750 ps ≈ **1.33 GHz**. ADD-க்கு 550 ps போதும், ஆனால் அதுவும் 750 ps காத்திருக்கிறது.

**எவ்வளவு வீணாகிறது?** Instruction கலவை (எடுத்துக்காட்டு மதிப்பு): 45% பதிவேடு-பதிவேடு, 25% load, 10% store, 20% branch. ஒவ்வொன்றும் தனக்குத் தேவையான நேரம் மட்டும் எடுத்தால் சராசரி:
- 0.45 × 550 + 0.25 × 750 + 0.10 × 650 + 0.20 × 450
- = 247.5 + 187.5 + 65 + 90 = **590 ps**
- Single-cycle எல்லாவற்றுக்கும் 750 ps → 750 ÷ 590 ≈ **1.27 மடங்கு** மெதுவு.

**Pipelining-இன் முன்னோட்டம்:** அதே பாதையை ஐந்து நிலைகளாக (Inst, RegRd, ALU, DataMem, RegWr) வெட்டினால், clock = மிக மெதுவான *நிலை* = 200 ps. ஒவ்வொரு நிலையிலும் ஒரு instruction இருந்தால், நிலையான நிலையில் ஒவ்வொரு 200 ps-க்கும் ஒரு instruction முடிகிறது: 750 ÷ 200 = **3.75 மடங்கு** அதிக throughput (hazard-கள், பதிவேட்டுச் செலவு இல்லாத இலட்சிய நிலை). ஆங்கிலப் பதிவின் "அதே ISA; வினாடிக்கு மிக அதிக வேலை" என்பதன் எண் வடிவம் இது. அந்த இலட்சியத்தை எது தடுக்கிறது என்பது அடுத்த பதிவு.
