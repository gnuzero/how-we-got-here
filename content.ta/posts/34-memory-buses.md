PCIe (பதிவுகள் 32–33) விரிவாக்கச் சாதனங்களுக்கான பாதை. Memory bus உண்மையில் CPU-க்கு உணவளிக்கும் பாதை — பதிவு 10-இன் DRAM — மற்றும் அதன் பரிணாமம் bandwidth, latency, மற்றும் மின்சாரம் இடையேயான தொடர் பேச்சுவார்த்தை. Generation பெயர்கள் கதை அல்ல. அந்த மூன்றிற்கும் இடையேயான பிரிவுதான்.

> **தமிழ் இடைவெளிக் குறிப்பு:** DDR SDRAM, நினைவகக் கட்டுப்படுத்தி / channel-கள் பற்றித் தமிழ் எழுத்து விளக்கம் இல்லை; காணொளிச் சான்று YouTube தேடல் முடிவுகள் மட்டும் — காணொளிகள் பார்க்கப்படவில்லை. கீழே உள்ள MT/s, CAS latency, அணுகல் நேரம் போன்ற எல்லா எண்களும் சூத்திரங்களைக் காட்டுவதற்கான "எடுத்துக்காட்டு மதிப்புகள்" — குறிப்பிட்ட தயாரிப்புகளின் அளவீடுகள் அல்ல. DDR5-இன் இரண்டு சுதந்திரமான 32-பிட் subchannel-கள் என்பது ஆங்கிலப் பதிவிலிருந்து. இந்தப் பதிவுக்கு lab இல்லை; காகிதப் பயிற்சிகள் கீழே.

## முதலில் சொற்கள்

- **DRAM (இயக்க நினைவகம்):** capacitor-களில் மின்னூட்டமாகத் தரவை வைக்கும், அவ்வப்போது புதுப்பிக்க (refresh) வேண்டிய முதன்மை நினைவகம்.
- **DDR (Double Data Rate, இரட்டைத் தரவு வீதம்):** clock-இன் உயரும், விழும் இரண்டு விளிம்புகளிலும் தரவு பரிமாற்றம்.
- **MT/s (வினாடிக்கு மில்லியன் பரிமாற்றங்கள்):** கம்பியில் ஒரு வினாடியில் நடக்கும் தரவுப் பரிமாற்றங்கள்; DDR-இல் clock அதிர்வெண்ணின் இருமடங்கு.
- **Bandwidth (அலைவரிசை):** தொடங்கிய ஓட்டம் எவ்வளவு வேகமாகத் தரவு நகர்த்துகிறது.
- **Latency (தாமதம்):** கோரிக்கையிலிருந்து முதல் bit வரும் வரை காத்திருப்பு.
- **CAS latency (CL):** column கட்டளைக்கும் தரவுக்கும் இடையிலான clock சுழற்சிகள்.
- **Channel / rank / bank:** சுதந்திரமான controller பாதை / ஒரு module-இல் சேர்ந்து இயங்கும் chip குழு / chip-க்குள் சுதந்திரமாக இயங்கக்கூடிய பகுதி.
- **DIMM:** நிலையான விளிம்பு இணைப்பியுடன் (edge connector) DRAM chip-கள் பொருத்திய பலகை.

## இரு Edges, வேகமான Clock அல்ல

DDR — Double Data Rate — உயரும் *மற்றும்* விழும் edge-இல் பரிமாற்றுகிறது. அதே clock-இல் single-data-rate வடிவமைப்பின் தோராயமாக இருமடங்கு throughput, அதிர்வெண்ணை இரட்டிப்பாக்காமல் (மற்றும் அதனுடன் வரும் signal-integrity பிரச்சனைகள் இல்லாமல்). முதலில் clock சுவருக்குச் செலுத்தாமல் bandwidth.

## இரு விளிம்புகளின் கணக்கு

எடுத்துக்காட்டு மதிப்புகள்: I/O clock 1,600 MHz, 64-பிட் (8 byte) channel.

| வடிவமைப்பு | ஒரு சுழற்சிக்குப் பரிமாற்றங்கள் | பரிமாற்றங்கள் / வினாடி | உச்ச bandwidth |
|---|---|---|---|
| ஒற்றைத் தரவு வீதம் (SDR) | 1 | 1,600 மில்லியன் | 1,600 M × 8 byte = 12.8 GB/s |
| DDR | 2 | 3,200 மில்லியன் (3,200 MT/s) | 3,200 M × 8 byte = 25.6 GB/s |

அதே clock, இருமடங்கு bandwidth. SDR-இல் அதைப் பெற clock-ஐ 3,200 MHz ஆக்க வேண்டும் — காலம் 0.625 ns-இலிருந்து 0.3125 ns ஆகச் சுருங்கி, பதிவு 32-இன் skew, சமிக்ஞை நேர்மைப் பிரச்சினைகள் அனைத்தும் இருமடங்கு கடினமாகும்.

## Bandwidth ஏறியது; First-Bit Latency ஏறவில்லை

ஒவ்வொரு DDR generation-ம் உச்ச bandwidth-ஐ உயர்த்தியது, பெரும்பாலும் வேகமான I/O மூலம். Prefetch மற்றும், DDR5-இல், இரண்டு சுதந்திரமான 32-bit subchannels-ஆகப் பிரிவு module-இல் அதிக parallelism வாங்குகிறது. தலைப்பு எண்கள் மறைப்பது: மூல அணுகல் *latency* — request-இலிருந்து முதல் bit வரை — bandwidth-ஐ விட மிக மெதுவாக நகர்ந்தது. DRAM தொடங்கியவுடன் ஒரு stream-இல் மிகச் சிறந்தது, தொடங்குவதற்கு முன் காத்திருப்பில் சற்று மட்டும் சிறந்தது. அது பதிவு 35-இன் அமைப்பு. வேறு அளவீடு, வேறு இயற்பியல் (charge sensing, capacitor கலங்கள்).

## Bandwidth ஏறியது, latency ஏன் அசையவில்லை: ஒரு கணக்கு

CAS latency சுழற்சிகளில் சொல்லப்படுகிறது; நானோவினாடியாக மாற்ற: CL × clock காலம். DDR-இல் clock = MT/s ÷ 2. இரண்டு கற்பனைத் தலைமுறைகள் (எடுத்துக்காட்டு மதிப்புகள்):

| | பழைய தலைமுறை | புதிய தலைமுறை |
|---|---|---|
| வீதம் | 3,200 MT/s | 6,400 MT/s |
| Clock | 1,600 MHz → காலம் 0.625 ns | 3,200 MHz → காலம் 0.3125 ns |
| CAS latency | 22 சுழற்சிகள் | 40 சுழற்சிகள் |
| CAS நேரம் | 22 × 0.625 = **13.75 ns** | 40 × 0.3125 = **12.5 ns** |
| 64-பிட் அகலத்துக்கு உச்ச bandwidth | 3,200 M × 8 = 25.6 GB/s | 6,400 M × 8 = 51.2 GB/s |

Bandwidth 2 மடங்கு; முதல்-bit காத்திருப்பு 13.75 → 12.5 ns, சுமார் 9% மட்டுமே குறைவு. சுழற்சி எண்ணிக்கை ஏறுவதால் clock வேகம் பெரும்பாலும் சமன்படுகிறது — capacitor-இன் மின்னூட்டத்தை உணரும் இயற்பியல் வேகமாகவில்லை. இதுவே பதிவு 35-இன் நினைவகச் சுவர்.

64 byte cache வரியை நகர்த்தும் மொத்த நேரம் (எடுத்துக்காட்டு, பழைய தலைமுறை): காத்திருப்பு 13.75 ns + பரிமாற்றம் 64 ÷ 25.6 GB/s = 2.5 ns → 16.25 ns; இதில் 85% காத்திருப்பு. புதிய தலைமுறையில் 12.5 + 1.25 = 13.75 ns — bandwidth இருமடங்கானாலும் ஒரு வரியின் நேரம் 15% மட்டுமே குறைகிறது.

## மெதுவான அணுகலை மறைக்க Parallelism

ஒரு *channel* சுதந்திரமான controller பாதை — இணை request-கள் ஒன்றையொன்று பின்னால் வரிசையில் நிற்கத் தேவையில்லை. ஒரு channel-க்குள், *ranks* மற்றும் *banks* ஒரு bank முடிக்க (அல்லது refresh — பதிவு 10) அனுமதிக்கின்றன மற்றொன்று புதிய request எடுக்கும்போது. போதுமான சுதந்திரமான அணுகல்களை மேற்பொருத்துங்கள், *aggregate* throughput உயர்ந்தே இருக்கும் எந்த ஒரு அணுகலும் வேகமாகாதபோதும். அதனால்தான் அமைப்பு உள்ளது: DIMM அம்சங்களின் பட்டியல் அல்ல, அடுத்த பதிவு சுவராகப் பெயரிடும் latency-ஐ மறைக்கும் வழி.

ஒரு DIMM இயற்பியல் தொகுப்பு — நிலையான edge connector-உடன் ஒரு பலகையில் chips — எனவே கொள்ளளவு "எத்தனை slots, என்ன அளவு," bus-இன் மறுவடிவமைப்பு அல்ல.

## இணைச் செயல்பாடு எப்படி latency-ஐ மறைக்கிறது

எடுத்துக்காட்டு மதிப்புகள்: ஒவ்வொரு நினைவக அணுகலும் (கோரிக்கை முதல் தரவு வரை) 50 ns, ஒவ்வொன்றும் 64 byte கொண்டுவருகிறது. ஒரே நேரத்தில் பறக்கும் சுதந்திரமான கோரிக்கைகள் N என்றால், பெறும் throughput ≈ N × 64 byte ÷ 50 ns (channel-இன் உச்சம் வரை):

| ஒரே நேரக் கோரிக்கைகள் N | Throughput |
|---|---|
| 1 | 64 ÷ 50 ns = 1.28 GB/s |
| 4 | 4 × 1.28 = 5.12 GB/s |
| 16 | 16 × 1.28 = 20.48 GB/s |
| 20 | 20 × 1.28 = 25.6 GB/s — மேலே உள்ள 25.6 GB/s channel உச்சம் |

ஒவ்வொரு அணுகலும் இன்னும் 50 ns — எதுவும் வேகமாகவில்லை. ஆனால் வெவ்வேறு bank-களும் channel-களும் ஒன்றோடொன்று ஒன்றிப் பணிபுரிவதால், மொத்த ஓட்டம் 20 மடங்கு. இரண்டு channel-கள் என்றால் உச்சம் 2 × 25.6 = 51.2 GB/s; அதை நிரப்ப சுமார் 40 ஒரே நேரக் கோரிக்கைகள் வேண்டும்.

அடுத்த இரண்டு பதிவுகள் இந்தப் பேச்சுவார்த்தை குறைந்தால் என்ன நடக்கிறது: memory wall, மற்றும் compute பக்கத்தில் அதன் உறவினர், clock-speed wall.

## காகிதப் பயிற்சிகள் (விடைகளுடன்)

1. **ஒரு DDR நினைவகம் 2,400 MT/s-இல் 64-பிட் channel-இல் ஓடுகிறது (எடுத்துக்காட்டு மதிப்பு). உச்ச bandwidth? அதன் I/O clock?**
   விடை: 2,400 M × 8 byte = **19.2 GB/s**; clock = 2,400 ÷ 2 = **1,200 MHz**.

2. **CL 16, 2,400 MT/s — CAS நேரம் எவ்வளவு ns?**
   விடை: clock 1,200 MHz → காலம் 1 ÷ 1.2 GHz ≈ 0.833 ns; 16 × 0.833 ≈ **13.3 ns**.

3. **DDR5-இன் ஒரு module-இல் இரண்டு சுதந்திரமான 32-பிட் subchannel-கள். 6,400 MT/s-இல் ஒவ்வொரு subchannel-இன் உச்சம்? இரண்டும் சேர்த்து?**
   விடை: 32 bit = 4 byte; 6,400 M × 4 = **25.6 GB/s** ஒவ்வொன்றும்; சேர்த்து 51.2 GB/s — 64-பிட் அகலத்துக்குச் சமம், ஆனால் இரண்டு சுதந்திரமான கோரிக்கை ஓட்டங்களாக.

4. **அணுகல் 60 ns, அணுகலுக்கு 64 byte, channel உச்சம் 32 GB/s (எடுத்துக்காட்டு மதிப்புகள்). உச்சத்தை அடைய எத்தனை ஒரே நேரக் கோரிக்கைகள் வேண்டும்?**
   விடை: ஒரு கோரிக்கை = 64 ÷ 60 ns ≈ 1.067 GB/s; 32 ÷ 1.067 ≈ **30 கோரிக்கைகள்**. (சரிபார்ப்பு: 32 GB/s × 60 ns = 1,920 byte பறந்துகொண்டிருக்க வேண்டும்; 1,920 ÷ 64 = 30.)

5. **"புதிய நினைவகம் இருமடங்கு bandwidth, எனவே என் நிரல் இருமடங்கு வேகமாக ஓடும்." எந்த வகை நிரலுக்கு இது தவறு?**
   விடை: ஒவ்வொரு அணுகலும் முந்தையதன் முடிவைச் சார்ந்திருக்கும் நிரல்களுக்கு (எ.கா. linked list-ஐப் பின்தொடர்தல்) — ஒரே நேரத்தில் ஒரு கோரிக்கை மட்டுமே பறக்கும், எனவே அவை latency-ஆல் வரம்பிடப்படுகின்றன; மேலே கண்டதுபோல் latency அரிதாகவே மாறியது.
