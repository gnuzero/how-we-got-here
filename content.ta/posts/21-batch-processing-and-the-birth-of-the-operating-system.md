பதிவு 18-இன் mainframes நாம் அறிந்த அர்த்தத்தில் operating system ஓட்டவில்லை. யாரோ ஒரு நிரலை ஏற்றி, ஓட்டி, காத்திருந்து, அடுத்ததை ஏற்றினர். ஒரு பயனருக்கு முழு அணுகல் இருந்தால் அது வேலை செய்கிறது. பல வேலைகள் விலையுயர்ந்த இயந்திரத்தைப் பகிர வேண்டிய தருணத்தில் — mainframe செலவைக் கொடுத்தால் உடனடியாக நடந்தது — அது உடைகிறது.

## Idle நேரமே கட்டுப்பாடு

தொடக்க இயக்கம் என்றால் மனிதன் punch-card deck ஏற்றுவது, ஓட்டுவது, வெளியீட்டைச் சேகரிப்பது, அடுத்ததை ஏற்றுவது — ஒவ்வொரு setup மற்றும் teardown-இலும் CPU idle ஆக அமர்ந்திருந்தது. Batch processing *வரிசைப்படுத்துதலை* தானியக்கமாக்கியது: வேலைகளின் அடுக்கைச் சமர்ப்பியுங்கள், resident நிரல் (தொடக்க "monitor") ஒவ்வொன்றையும் மனிதன் இல்லாமல் ஏற்றி ஓட்டும்.

அந்த resident monitor தான் operating system-இன் நேரடி முன்னோடி. குறுகிய வேலை — ஏற்று, தொடங்கு, முடிவைக் கண்டறி, அடுத்ததை ஏற்று — ஆனால் அது எந்தப் பயனர் நிரலிலிருந்தும் வேறுபட்ட *system* மென்பொருளின் முதல் துண்டு: எந்த வேலை இயங்குகிறதோ அதன் சார்பாக இயந்திரத்தை நிர்வகிக்கத் தொடர்ந்து ஓடுகிறது.

## Scheduling கொள்கையாகிறது

Batch அமைப்புகள் முதிர்ச்சியடைய, job control மொழிகள் சமர்ப்பிக்கப்பட்ட வேலைக்கு வளங்கள், தோல்வி கையாளல், வெளியீட்டு வழிகாட்டலைப் பெயரிட அனுமதித்தன; வரிசைகள் வேலைகளை கண்டிப்பான சமர்ப்பிப்பு வரிசைக்குப் பதிலாக முன்னுரிமைப்படுத்த அனுமதித்தன. Priority, வள ஒதுக்கீடு, மற்றும் scheduling கொள்கை இங்கே உண்மையான OS கவலைகளாகத் தோன்றுகின்றன — உத்தியோகபூர்வமற்ற operator தீர்ப்பு அல்ல.

## Batch கொடுக்க முடியாதது

ஊடாடுதல் இல்லை. ஒரு வேலை தொடக்கத்திலிருந்து முடிவு வரை இயங்கியது — இடையில் தலையிட, இடைநிலை நிலையை ஆய்வு செய்ய, அல்லது திசை திருப்ப வாய்ப்பில்லை. பிழை பெரும்பாலும் முழு ஓட்டத்திற்குப் பிறகுதான் தெரிந்தது — சில நேரம் மணிக்கணக்கில் பின்னர், விலையுயர்ந்த ஒதுக்கீட்டை எரித்த பிறகு. ஆய்வு வேலைக்கு அந்தத் திரும்பும் நேரம் கடினமான உற்பத்தித்திறன் கூரை.

**இப்போது முயல்க.** கீழே உள்ள VM-ஐ boot செய்து, திரையைக் கிளிக் செய்து, பிறகு `whoami`, `uname`, மற்றும் `ls` ஓட்டுங்கள். அந்த prompt ஒரு batch deck-இன் எதிர் — நீங்கள் *இப்போது* தலையிட்டு, நிலையை ஆய்வு செய்து, திசை திருப்புகிறீர்கள். Time-sharing (அடுத்த பதிவு) இந்த மாயையைப் பகிரக்கூடியதாக்கியது.

அதைத் தீர்க்க batch கட்டமைப்பு கொடுக்க முடியாத ஒன்று தேவைப்பட்டது: பல பயனர்கள் *ஒரே நேரத்தில்* செயலில், ஒவ்வொவருக்கும் தனிப்பட்ட session-இன் மாயை. அதுதான் time-sharing — வேலை வரிசைப்படுத்தலைத் தானியக்கமாக்குவது மட்டும் அல்ல, ஒரே நேரத்தில் செயலில் உள்ள நிரல்களை மாறுதல் கண்ணுக்குத் தெரியாத அளவுக்கு இடைசெருகுதல். அடுத்த பதிவு அங்கிருந்து தொடர்கிறது.
