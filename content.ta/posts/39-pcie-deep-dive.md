பதிவு 32 PCIe ஏன் serial மற்றும் point-to-point ஆனது என்பதை உள்ளடக்கியது. இந்தப் பதிவு அந்த இணைப்புகளில் ஒரு பரிமாற்றம் *எப்படி* அமைக்கப்படுகிறது — fabric-ஐப் பேச வேண்டிய வன்பொருளைக் கட்டுபவர்களுக்கு முக்கியமான அடுக்கு, இந்தத் தொடர் மீண்டும் வரும் Nitefury-அடிப்படையிலான GPU நினைவக வேலை உட்பட.

> **தமிழ் இடைவெளிக் குறிப்பு:** PCIe lane-கள், TLP அடுக்குகள் பற்றித் தமிழ் எழுத்து விளக்கம் இல்லை; காணொளிச் சான்று YouTube தேடல் முடிவுகள் மட்டும் — காணொளிகள் பார்க்கப்படவில்லை. TLP-இன் புல அளவுகள் Xilinx white paper WP350 (v1.2, 28 October 2014, "Understanding Performance of PCI Express Systems") தரும் Gen 2 TLP வரைபடத்திலிருந்து சரிபார்க்கப்பட்டவை; Gen 3 / Gen 5 x16 bandwidth எண்கள் ஆங்கிலப் பதிவிலிருந்தும் PCI-SIG FAQ-இலிருந்தும். Payload அளவுகள், கோப்பு அளவுகள் "எடுத்துக்காட்டு மதிப்புகள்". இந்தப் பதிவுக்கு lab இல்லை; காகிதப் பயிற்சிகள் கீழே.

## முதலில் சொற்கள்

- **Transaction Layer (பரிமாற்ற அடுக்கு):** படி, எழுது, நிறைவு (completion) கோரிக்கைகள் உருவாகும் அடுக்கு — மென்பொருள் சிந்திக்கும் நிலை.
- **Data Link Layer (தரவு இணைப்பு அடுக்கு):** வரிசை எண், CRC, மீள் அனுப்புதல் மூலம் நம்பகமான விநியோகம்.
- **Physical Layer (இயற்பியல் அடுக்கு):** differential pair-கள், குறியாக்கம், serialization — கம்பி.
- **TLP (Transaction Layer Packet):** வகை, முகவரி, நீளம், (எழுதுதலில்) payload கொண்ட PCIe-இன் அடிப்படை அலகு.
- **Payload (சுமை):** TLP உண்மையில் நகர்த்தும் தரவு; மற்ற எல்லாம் மேல்செலவு (overhead).
- **CRC / LCRC (சுழற்சி மிகைமைச் சோதனை):** பிழையைக் கண்டறியும் சரிபார்ப்பு எண்; LCRC = ஒவ்வொரு இணைப்பிலும் தரவு இணைப்பு அடுக்கு சேர்ப்பது.
- **Replay buffer (மீள் அனுப்பு இடையகம்):** ஒப்புதல் (ACK) வரும் வரை அனுப்பிய TLP-களின் நகலை வைத்திருக்கும் இடம்.
- **Root complex / endpoint:** CPU-நினைவகப் பக்கத்தில் PCIe மரத்தின் வேர் / மரத்தின் இலைச் சாதனம் (GPU, NIC, FPGA அட்டை).

## நோக்கம், நம்பகத்தன்மை, எலக்ட்ரான்கள்

மூன்று அடுக்குகள், மூன்று வேலைகள். **Transaction Layer** ஒரு read, ஒரு write, அல்லது ஒரு completion பிறந்து இறக்கும் இடம் — மென்பொருள் சிந்திக்கும் அடுக்கு. **Data Link Layer** வழங்கலை நம்பகமாக்குகிறது: sequence எண்கள், CRC, ஒரு packet சிதைந்தால் retransmission. **Physical Layer** கம்பி: differential pairs, stream மீட்கக்கூடியதாக இருக்க encoding, செம்பின் மீது serialization. அவ்வாறு பிரிக்கப்பட்டது ஒரு தனிப்பயன் வடிவமைப்பு எலக்ட்ரான்களை மீண்டும் கண்டுபிடிக்காமல் *நோக்கத்தை* வெளிப்படுத்த முடியும்படி.

நம்பகத்தன்மையின் கணக்கு (எடுத்துக்காட்டு): அனுப்புபவர் TLP 1–5-ஐ அனுப்பி, ஒவ்வொன்றின் நகலையும் replay buffer-இல் வைக்கிறார். WP350-இன் வரைபடம் காட்டுவதுபோல், பெறுபவர் ஐந்துக்கும் சேர்த்து ஒரே ஒரு "ACK 5" அனுப்பலாம் — அப்போது ஐந்து நகல்களும் விடுவிக்கப்படுகின்றன. TLP 3-இன் LCRC பொருந்தவில்லை என்றால், அது ஏற்கப்படாது; அனுப்புபவர் buffer-இல் உள்ள நகலிலிருந்து 3-ஐயும் அதன்பின் அனுப்பியவற்றையும் (3, 4, 5) மீண்டும் அனுப்புகிறார். மேலிருந்து பார்க்கும் மென்பொருளுக்கு இது எதுவும் தெரியாது — ஒரு நம்பகமான எழுதுதல் மட்டுமே.

## Packet தான் ஒப்பந்தம்

அலகு Transaction Layer Packet. ஒரு TLP வகையைப் (memory read அல்லது write, I/O, configuration) பெயரிடுகிறது, முகவரி, நீளம், மற்றும் — write-இல் — payload. Link layer அதை sequence மற்றும் CRC-உடன் மூடுகிறது; தொலைவு பக்கம் சரிபார்த்து தேவைப்பட்டால் retry செய்கிறது. மேலிருந்து, அது நம்பகமான read அல்லது write போல் தெரிகிறது. நம்பகத்தன்மை மந்திரம் அல்ல. அது அந்த மூடல்.

## ஒரு TLP-இன் byte கணக்கு

WP350 தரும் Gen 2 TLP அமைப்பு, கம்பியில் வரும் வரிசைப்படி:

| புலம் | அளவு | சேர்க்கும் அடுக்கு |
|---|---|---|
| Start | 1 byte | Physical |
| Sequence (வரிசை எண்) | 2 byte | Data Link |
| Header | 12 byte (32-பிட் முகவரி) அல்லது 16 byte (64-பிட் முகவரி) | Transaction |
| Payload | 0–4,096 byte | Transaction |
| ECRC (விருப்பத்தேர்வு) | 4 byte | Transaction |
| LCRC | 4 byte | Data Link |
| End | 1 byte | Physical |

64-பிட் முகவரியுடன், ECRC இல்லாமல் மேல்செலவு = 1 + 2 + 16 + 4 + 1 = **24 byte**. (WP350: தலைமுறை, முகவரி அகலம், ECRC பொறுத்து 20 முதல் 30 byte.) Payload அளவைப் பொறுத்து செயல்திறன் (எடுத்துக்காட்டு மதிப்புகள்):

| Payload | செயல்திறன் = payload ÷ (payload + 24) |
|---|---|
| 64 byte | 64 ÷ 88 ≈ 72.7% |
| 128 byte | 128 ÷ 152 ≈ 84.2% |
| 256 byte | 256 ÷ 280 ≈ 91.4% |
| 4,096 byte | 4,096 ÷ 4,120 ≈ 99.4% |

சிறு TLP-கள் மேல்செலவில் மூழ்குகின்றன; பெரியவை குறியாக்க, ACK போன்ற பிற செலவுகளால் வரம்பிடப்படுகின்றன (WP350 இதையும் குறிப்பிடுகிறது).

## Lanes அகலத்தை அளவிடுகின்றன; Generations வீதத்தை அளவிடுகின்றன

ஒரு lane ஒவ்வொரு திசையிலும் ஒரு differential pair — சிறிய இணைப்பு. Bandwidth பெருக்க lanes-ஐப் பிணையுங்கள் (x1…x16). ஒவ்வொரு generation-ம் per-lane வீதத்தை தோராயமாக இரட்டிப்பாக்குகிறது (உயர்ந்த signaling, இறுக்கமான encoding). அதே x16 slot, Gen 5 எதிர் Gen 3: சுமார் 4× unidirectional bandwidth (~64 GB/s vs ~16 GB/s) கூடுதல் கம்பிகள் இல்லாமல். பதிவு 32-இன் serial பந்தயம் அந்த ஏற்றத்தைச் சாத்தியமாக்கியது.

அதே x16 slot, இரண்டு தலைமுறைகள் — ஆங்கிலப் பதிவின் எண்கள் (ஒரு திசை): Gen 3 ~16 GB/s, Gen 5 ~64 GB/s. 8 GB model எடைகளை GPU-க்கு ஏற்ற (எடுத்துக்காட்டு மதிப்பு): Gen 3 → 8 ÷ 16 = 0.5 s; Gen 5 → 8 ÷ 64 = 0.125 s — கூடுதல் கம்பி இல்லாமல் 4 மடங்கு வேகம். ஒவ்வொரு தலைமுறையும் lane வீதத்தை சுமார் இருமடங்காக்குவதால்: Gen 3 → Gen 4 → Gen 5 = 2 × 2 = 4.

## தனிப்பயன் Fabric ஏன் கவலைப்படுகிறது

ஒரு FPGA நினைவக-fabric அட்டை இந்த stack-இல் வாழ வேண்டும்: root complex மற்றும் பிற endpoints ஏற்கும் TLP-களை உருவாக்கவும், மற்றும் நிறுவப்பட்ட IP link நம்பகத்தன்மையையும் physical layer-ஐயும் கையாள அனுமதிக்கவும். GPUDirect-பாணி peer-to-peer (பதிவு 37) அதே யோசனை மேலும் எடுக்கப்பட்டது — இரண்டு endpoints இடையே முகவரியிடப்பட்ட TLP-கள், data path-இலிருந்து CPU வெளியே.

## காகிதப் பயிற்சிகள் (விடைகளுடன்)

1. **32-பிட் முகவரியுடன் (12 byte header), ECRC இல்லாத Gen 2 TLP-இன் மேல்செலவு எவ்வளவு?**
   விடை: 1 + 2 + 12 + 4 + 1 = **20 byte** — WP350 சொல்லும் 20–30 வரம்பின் கீழ் முனை.

2. **1 MB (1,048,576 byte) தரவை 128 byte payload TLP-களில் எழுத எத்தனை TLP-கள்? மொத்த மேல்செலவு (24 byte / TLP)?**
   விடை: 1,048,576 ÷ 128 = **8,192 TLP-கள்**; 8,192 × 24 = 196,608 byte ≈ **192 KB** — தரவின் சுமார் 18.75%.

3. **அதே 1 MB-ஐ 256 byte payload-இல் எழுதினால்?**
   விடை: 4,096 TLP-கள்; 4,096 × 24 = 98,304 byte = 96 KB ≈ 9.4%. Payload இருமடங்கு → மேல்செலவு பாதி.

4. **Gen 3 x4 SSD ஒரு திசையில் எவ்வளவு பெறலாம் (PCI-SIG: Gen 3 lane ≈ 1 GB/s)?**
   விடை: 4 × ~1 GB/s = **~4 GB/s** (TLP மேல்செலவுக்கு முன்).

5. **FPGA அட்டை வடிவமைப்பவர் ஏன் தரவு இணைப்பு, இயற்பியல் அடுக்குகளைத் தானே எழுதுவதில்லை?**
   விடை: அவை வரிசை எண், LCRC, மீள் அனுப்புதல், குறியாக்கம் போன்ற நிலைத்த, தரப்படுத்தப்பட்ட வேலைகள்; நிறுவப்பட்ட IP அவற்றைச் செய்கிறது. வடிவமைப்பவர் சரியான TLP-களை — நோக்கத்தை — உருவாக்குவதில் கவனம் செலுத்துகிறார்; ஆங்கிலப் பதிவு சொல்லும் "எலக்ட்ரான்களை மீண்டும் கண்டுபிடிக்காமல் நோக்கத்தை வெளிப்படுத்துதல்".

**Door out:** The PCI Express Base Specification (PCI-SIG) — இந்தப் பதிவு பெயரிடும் lanes, TLP-கள், மற்றும் அடுக்கு stack-க்கு வாழும் முதன்மை (பதிப்பு செய்யப்பட்டது; Base Spec, உறைந்த paper அல்ல).
