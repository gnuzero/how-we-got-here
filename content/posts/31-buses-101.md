Every previous phase built something — logic, a CPU, an operating system. This phase is how those pieces *talk*. A bus is the shared path among CPU, memory, and I/O, and its design decides how fast a system can move data between the parts Phase 3 and Phase 4 treated as simply "connected."

## Three Signals, One Set of Wires

A classic system bus carries three kinds of signal on shared physical wires. The **address bus** names the target — its width is the address-space ceiling (32 bits → 4 GB, the wall 32-bit systems hit as memory grew). The **data bus** carries the value — its width is bandwidth per transaction. The **control bus** coordinates: direction, validity, clock, interrupts.

## Why Sharing Needs a Master

A bus is shared by definition. CPU, DMA controller, I/O device may all want to start a transfer; only one can drive the wires or the voltages fight. Arbitration picks a bus master for the next transaction — request and grant, sometimes with priority so a latency-sensitive DMA is not starved by everyone else. Same fairness problem as Phase 4's schedulers, one layer down, in hardware.

## The Constraint: One Transaction at a Time

Total bandwidth is a hard ceiling the whole machine shares. More devices means more waiting, and less effective bandwidth anyone sees under contention. That is not an implementation detail. It is the constraint the rest of this phase works around — first by making the shared parallel bus faster, then by abandoning the shared wires entirely. Post 32 is that escape: from one parallel bus toward point-to-point serial links that do not force every device to compete for the same copper.
