මෙම මාලාවේ මාතෘකාව *රිලේ සිට අවධානය දක්වා* ය. මෙතෙක් ආ සෑම දෙයක්ම විශාල පරිමාණ matrix multiplication ප්‍රායෝගික කළ දිගු භෞතික සහ ගෘහ නිර්මාණ මාර්ගයයි. මෙම පරිච්ඡේදය එම මාර්ගය මඟින් හැකි වූ ඇල්ගොරිතමික ගමනාන්තයයි.

2017 දී **Vaswani et al.** "Attention Is All You Need" ප්‍රකාශයට පත් කළහ. එම පත්‍රිකාව Transformer හඳුන්වා දුන් අතර *self-attention* අනුක්‍රම ආකෘතිකරණය සඳහා ප්‍රාථමික යාන්ත්‍රණය කළේය — RNN සහ LSTM වල අනුක්‍රමික පුනරාවර්තනය වෙනුවට සෑම පිහිටීමක්ම එකවර බලාගත හැකි සම්පූර්ණයෙන් සමාන්තර කළ හැකි මෙහෙයුමක් ඉදිරිපත් කරමින්.

## Self-Attention කරන්නේ කුමක්ද

Token embeddings ලබා දුන් විට, self-attention සෑම පිහිටීමක් සඳහාම සියලු පිහිටීම්වල values වල බර තැබූ සංයෝජනයක් ගණනය කරයි. බර ලැබෙන්නේ *query* එකක් (වත්මන් පිහිටීම) සහ *keys* (සෑම පිහිටීමක්ම) අතර සමානතාවයෙනි. අනුකෘති ස්වරූපයෙන්:

\[
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
\]

- \(Q\), \(K\), සහ \(V\) යනු ආදානයේ රේඛීය ප්‍රක්ෂේපණයි.
- \(\sqrt{d_k}\) මඟින් පරිමාණය කිරීම මානය විශාල විට softmax සංතෘප්ත වීම වළක්වයි.
- ප්‍රතිඵලය සමාන දිගක අනුක්‍රමයකි — සෑම පිහිටීමක්ම දත්ත-නිර්භර ආකාරයෙන් අනෙක් සෑම එකකින්ම රැස් කළේය.

Op එක matmuls එකතුව softmax නිසා, එය පෙර පරිච්ඡේදවල දෘඪාංගයට map වේ: ඉහළ-throughput MAC ඒකක, විශාල on-chip මතක, activations සහ බර චලනය කරන interconnects.

## Multi-Head Attention

එක් head එකක් එක් වර්ගයේ සම්බන්ධතාවක් ඉගෙන ගැනීමට නැඹුරු වේ. Multi-head attention කිහිපයක් සමාන්තරව ධාවනය කරයි (විවිධ ඉගෙන ගත් ප්‍රක්ෂේපණ) සහ concatenate කරයි — එකම layer එක තුළ syntactic, semantic, positional, දිගු- සහ කෙටි-පරාස.

මුල් Transformer heads 8 ක් භාවිතා කළේය. නවීන LLM සාමාන්‍යයෙන් layer එකකට query heads දස ගණන් සිට අඩු සිය ගණන් දක්වා භාවිතා කරයි (උදා. GPT-3: 96; Llama 3 405B: 128) layers දස ගණන් සිට ~100+ දක්වා හරහා (Llama 3 405B: 126) — දෙකෙන් එකක් නිතිපතා "සිය ගණන්" නොවේ.

## එය ප්‍රමුඛ වූයේ ඇයි

1. **සමාන්තරතාව** — RNN මෙන් නොව, සෑම පිහිටීමක්ම එකවර ධාවනය විය හැක. Training throughput අනුක්‍රම දිග සහ දෘඪාංග matmul ධාරිතාව සමඟ පරිමාණය වේ, අනුක්‍රමික පියවර සමඟ නොවේ.
2. **දිගු-පරාස රඳා පැවැත්ම** — මූලධර්මයෙන් ඕනෑම token එකක් අනෙක් ඕනෑම එකකට සෘජුවම attend කරයි, quadratic attention matrix සහ ප්‍රායෝගික context windows මගින් සීමා වේ.
3. **දෘඪාංග සම්බන්ධතාව** — ප්‍රමුඛ වැඩ ඝන matrix multiplication ය — ටෙන්සර් cores, systolic arrays, සහ නවීන GPU මතක ධුරාවලි ප්‍රශස්ත කළ දේම (Posts 55–58).

සම්පූර්ණ attention හි quadratic පිරිවැය තවමත් සැබෑ ය — එබැවින් sparse, linear, sliding-window, සහ අනෙක් ආසන්න කිරීම්. මූලික අවබෝධය තවමත් රැඳේ: සරල, සමාන්තර කළ හැකි attention යාන්ත්‍රණයක් පුනරාවර්තනය ප්‍රතිස්ථාපනය කළ හැකි විය.

## චාපය වසා දැමීම

Boolean තර්කය ක්‍රියාත්මක කළ විද්‍යුත් චුම්බක relays සිට, tubes, ට්‍රාන්සිස්ටර, pipelines, caches, GPU, සහ ටෙන්සර් cores හරහා, දෘඪාංග ගමනාගමනය මාරුව, ගබඩාව, සහ අංක ගණිතය වේගවත්, ඝන, සහ වඩා කාර්යක්ෂම කළේය. Attention යනු අනුක්‍රම ආකෘතිකරණය සඳහා එම දෘඪාංගයෙන් වර්තමානයේ වඩාත්ම වටිනාකම උපුටා ගන්නා ඇල්ගොරිතමික ව්‍යුහයයි.

භෞතික සීමාවන් වෙනස් වෙමින් පවතී (මතක bandwidth, op එකකට ශක්තිය, interconnect latency). ඉංජිනේරු ප්‍රතිචාරය මෙම මාලාවේ ආරම්භයේ සිටම එම රටාවයි: බඳින සීමාව නිශ්චිතව නම් කරන්න, පසුව එකම බිත්තියට එරෙහිව තදින්ම තල්ලු කිරීම පමණක් නොව ගෘහ නිර්මාණය වෙනස් කරන්න.

එය රිලේ සිට අවධානය දක්වා අඛණ්ඩ නූලයි.

## ගැඹුරින්: attention අංකවලින්, පියවරෙන් පියවර

> **සිංහල මූලාශ්‍ර පිළිබඳ සටහන:** 2026 සැප්තැම්බර් සමීක්ෂණයේදී Transformers/attention ගැන සිංහල YouTube වීඩියෝ කිහිපයක් (සමහරක් දීර්ඝ; එකක් හැර අනෙක් සියල්ලටම නැරඹුම් 200කට අඩු) හමු වූ නමුත්, attention ගණිතය පියවරෙන් පියවර, වැඩ කළ අංක සමඟ පැහැදිලි කළ **ලිඛිත** සිංහල මූලාශ්‍රයක් (විකිපීඩියා ලිපියක්, පාසල්/විශ්වවිද්‍යාල සටහනක්, බ්ලොග් ලිපියක්) හමු නොවීය. මෙම පොතේ ගමනාන්තය මෙය වන බැවින්, මෙම කොටස හිතාමතාම දිගු ය. පහත අංක **ඉගැන්වීම සඳහා අප විසින් සාදාගත් ඒවා** ය — සැබෑ ආකෘතියක බර නොවේ; නමුත් සියලු ගණනය කිරීම් නිවැරදිව පරීක්ෂා කර ඇත.

### 1. මූලික පද

- **Token (ටෝකනය):** ආකෘතිය සකසන පෙළ කැබැල්ලක් — වචනයක්, වචන කොටසක් හෝ අක්ෂරයක්. මෙහි සරල බව සඳහා වචනයක් = token එකක් ලෙස ගනිමු.
- **දෛශිකය (vector):** අංක ලැයිස්තුවක්, උදා. [1, 0].
- **Embedding (කාවැද්දීම):** token එකක් නියෝජනය කරන, ඉගෙන ගත් දෛශිකයක්. අර්ථයෙන් සමාන token වලට සමාන දෛශික ලැබීමට නැඹුරු වේ.
- **තිත් ගුණිතය (dot product):** [a₁, a₂] · [b₁, b₂] = a₁b₁ + a₂b₂. දෛශික දෙකක් එකම දිශාවට යොමු වන තරමට එය විශාල වේ — "සමානතා ලකුණක්" ලෙස භාවිත කළ හැක.
- **Softmax (සොෆ්ට්මැක්ස්):** ඕනෑම අංක ලැයිස්තුවක් එකතුව 1 වන ධන "බර" බවට හරවන ශ්‍රිතය: සෑම අංකයකම eˣ (e ≈ 2.718) ගෙන, ඒවායේ එකතුවෙන් බෙදයි.
- **Query (විමසුම, q), Key (යතුර, k), Value (අගය, v):** සෑම token එකකටම දෛශික තුනක් සාදනු ලැබේ. පුස්තකාලයක් සිතන්න: query = "මම සොයන්නේ කුමක්ද", key = "සෑම පොතකම පිටකවරයේ ලේබලය", value = "පොතේ අන්තර්ගතය". Query එක සෑම key එකක් සමඟම සසඳා, ගැළපෙන තරමට එම value එකෙන් වැඩි කොටසක් ගනී.

### 2. Softmax අතින්

ලකුණු [2, 1, 0] softmax කරමු:

| පියවර | token 1 | token 2 | token 3 |
|---|---|---|---|
| ලකුණු x | 2 | 1 | 0 |
| eˣ | 7.389 | 2.718 | 1.000 |
| එකතුව | 11.107 | | |
| eˣ ÷ එකතුව | **0.665** | **0.245** | **0.090** |

බර තුනේ එකතුව 1 යි (0.665 + 0.245 + 0.090 = 1.000). විශාලතම ලකුණට විශාලතම බර ලැබේ, නමුත් අනෙක් ඒවා ශුන්‍ය නොවේ — එය "මෘදු" (soft) max එකකි.

### 3. කුඩා self-attention උදාහරණයක්

වාක්‍යය: **"මම බත් කෑවා"** — token 3ක්. සරල බව සඳහා d_k = 2 (එනම් key/query දෛශිකවල අංක 2ක්). ආකෘතිය ඉගෙන ගෙන ඇතැයි සිතමු:

| Token | Key k | Value v |
|---|---|---|
| මම | [1, 0] | [10, 0] |
| බත් | [0, 1] | [0, 10] |
| කෑවා | [1, 1] | [5, 5] |

"කෑවා" token එකේ query එක q = [2, 0] යැයි සිතමු. පියවර:

1. **ලකුණු (scores) = q · k** සෑම token එකකටම:
   - මම: 2×1 + 0×0 = **2**
   - බත්: 2×0 + 0×1 = **0**
   - කෑවා: 2×1 + 0×1 = **2**
2. **√d_k න් බෙදන්න:** √2 ≈ 1.414 → [2/1.414, 0, 2/1.414] = [**1.414**, **0**, **1.414**]
3. **Softmax:** e^1.414 ≈ 4.113, e⁰ = 1 → [4.113, 1, 4.113], එකතුව 9.227 → බර [**0.446**, **0.108**, **0.446**]
4. **Values හි බර තැබූ එකතුව:**
   - 0.446 × [10, 0] + 0.108 × [0, 10] + 0.446 × [5, 5]
   - = [4.46, 0] + [0, 1.08] + [2.23, 2.23]
   - ≈ [**6.69**, **3.31**]

"කෑවා" සඳහා නව නියෝජනය [6.69, 3.31] — එය "මම" සහ "කෑවා" වෙතින් වැඩිපුරත් "බත්" වෙතින් අඩුවෙනුත් තොරතුරු මිශ්‍ර කළ දෛශිකයකි. වෙනත් query එකක් q = [1, 1] නම්: ලකුණු [1, 1, 2] → පරිමාණය [0.707, 0.707, 1.414] → බර [0.248, 0.248, 0.503] → ප්‍රතිදානය ≈ [5.0, 5.0]. **Query එක වෙනස් වූ විට, "අවධානය" යොමු වන තැන වෙනස් වේ** — attention යන නම එයයි. සැබෑ ආකෘතියක q, k, v ඉගෙන ගන්නේ training මගිනි (Post 46).

### 4. එකම දේ matrix ලෙස

ඉහත ගණනය token එකකට පමණි. සියලු token එකවර ගණනය කිරීමට q දෛශික පේළි ලෙස තබා Q matrix එකක් ද, එලෙසම K සහ V ද සාදයි. එවිට:

```
Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V
```

1. **Q·Kᵀ** — සෑම query එකක් සමඟ සෑම key එකකම තිත් ගුණිතය: token n ක් නම් n × n ලකුණු වගුවක්. (Kᵀ = K හි පේළි සහ තීරු මාරු කිරීම, transpose.)
2. **/ √d_k** — සෑම ලකුණක්ම බෙදයි.
3. **softmax** — එක් එක් පේළිය වෙන වෙනම (එක් එක් query එකට බර).
4. **· V** — බර values සමඟ matrix ගුණ කිරීම.

Q, K, V එන්නේ කොහෙන්ද? Embeddings matrix එක X නම්: Q = X·W_Q, K = X·W_K, V = X·W_V — ඉගෙන ගත් බර matrices තුනකින් ගුණ කිරීම් තුනක්. එනම් **attention හි බර වැඩ කොටස matrix ගුණ කිරීම්** ය — Post 57 හි MAC සහ Post 58 හි systolic arrays කෙළින්ම යොදා ගත හැකි දේ. මුල් ලිපියම කියන පරිදි, dot-product attention "ඉතා ප්‍රශස්ත කළ matrix ගුණ කිරීමේ කේතය" භාවිතයෙන් ක්‍රියාත්මක කළ හැකි නිසා ප්‍රායෝගිකව වේගවත් ය (3.2.1 කොටස).

**පිරිවැය ගණන් කිරීම:** n = 1024 token, d_k = 64 නම්, Q·Kᵀ පමණක් = 1024 × 1024 × 64 = **67,108,864 MACs** එක් head එකකට, එක් layer එකකට. ලකුණු වගුවේ අංග 1024² = 1,048,576. Token ගණන දෙගුණ කළ විට මෙම කොටස හතර ගුණයක් වේ — මුල් ලිපියේ Table 1 හි self-attention සඳහා O(n²·d) ලෙස දක්වා ඇත්තේ මෙයයි, සහ ඉහත "quadratic පිරිවැය" යන්නේ අර්ථයත් එයයි.

### 5. √d_k න් බෙදන්නේ ඇයි?

ලිපියේ පාදසටහන (footnote 4) තර්කය: q සහ k හි සංරචක මධ්‍යන්‍යය 0 සහ විචලතාව (variance) 1 ඇති ස්වාධීන අහඹු විචල්‍ය නම්, q · k හි මධ්‍යන්‍යය 0 සහ **විචලතාව d_k** වේ. එනම් සම්මත අපගමනය (standard deviation) √d_k. d_k = 64 නම් ලකුණු සාමාන්‍යයෙන් ±8 පමණ පරාසයක පැතිරේ.

එය වැදගත් වන්නේ ඇයි? ලකුණු [16, 8, 0] softmax කරමු:

- e¹⁶ ≈ 8,886,111, e⁸ ≈ 2,981, e⁰ = 1 → බර ≈ [**0.99966**, 0.00034, 0.0000001]

එක් token එකකට සියල්ල; අනෙක්වාට කිසිවක් නැත. Softmax මෙසේ "සංතෘප්ත" (saturated) වූ විට එහි අනුක්‍රමණ (gradients) අතිශයින් කුඩා වන නිසා ආකෘතියට ඉගෙනීම අපහසු වේ (ලිපිය 3.2.1). √64 = 8 න් බෙදූ විට: [16, 8, 0] / 8 = [2, 1, 0] → බර [**0.665**, **0.245**, **0.090**] — 2 වන කොටසේ අප අතින් කළ softmax එකම! පරිමාණය කිරීම ලකුණු නැවත "සංවේදී" පරාසයකට ගෙන එයි.

### 6. Multi-head: කුඩා attentions කිහිපයක් සමාන්තරව

මුල් Transformer හි d_model = 512 (token දෛශිකයේ ප්‍රමාණය) සහ **h = 8** heads. සෑම head එකකටම d_k = d_v = 512 / 8 = **64** (ලිපිය 3.2.2). එනම් එක් විශාල attention එකක් වෙනුවට, තමන්ගේම W_Q, W_K, W_V ඇති, 64-මාන attentions 8ක් සමාන්තරව ධාවනය වේ; ප්‍රතිදාන 8 concatenate කර (එකට යා කර) තවත් matrix එකකින් ගුණ කරයි. මානය අඩු කළ නිසා, සම්පූර්ණ ගණනය කිරීමේ පිරිවැය සම්පූර්ණ-මාන තනි head එකකට සමාන වේ. සෑම head එකකටම වෙනස් "සම්බන්ධතා" (උදා. ක්‍රියාපදය ↔ කර්තෘ) ඉගෙන ගත හැක.

### 7. Causal mask: අනාගතය නොබැලීම

පෙළ නිපදවන (decoder) ආකෘතියක්, token එකක් පුරෝකථනය කරන විට, ඊට පසු එන token නොබැලිය යුතුය. ලිපිය (3.2.3) මෙය කරන්නේ softmax එකට පෙර "නීති විරෝධී" සම්බන්ධතාවල ලකුණු **−∞** ලෙස සැකසීමෙනි; e^(−∞) = 0, එබැවින් එම බර හරියටම 0 වේ.

උදාහරණය: "බත්" token එක (2 වන ස්ථානය) බැලිය හැක්කේ "මම" සහ "බත්" පමණි. එහි query q = [0, 2] නම්:

1. ලකුණු: මම 0, බත් 2, කෑවා 2 → පරිමාණය [0, 1.414, 1.414]
2. Mask: කෑවා → −∞ → [0, 1.414, −∞]
3. Softmax: [1, 4.113, 0] / 5.113 = [**0.196**, **0.804**, **0**]
4. ප්‍රතිදානය: 0.196 × [10, 0] + 0.804 × [0, 10] ≈ [**1.96**, **8.04**]

"කෑවා" හි value එකෙන් කිසිවක් කාන්දු නොවීය.

### 8. පැන්සලෙන් අභ්‍යාසය (මෙම පිටුවට lab එකක් නැත)

ඉහත වගුවේ K සහ V ම භාවිත කරන්න.

1. q = [0, 2] (mask නැතිව) සඳහා බර සහ ප්‍රතිදානය ගණනය කරන්න.
2. ඉහත [16, 8, 0] උදාහරණයේ d_k = 64 වෙනුවට d_k = 256 නම්, පරිමාණය කළ ලකුණු මොනවාද?
3. n = 2048 token, d_k = 64 නම් එක් head එකක Q·Kᵀ සඳහා MAC කීයද?

(පිළිතුරු: 1 → ලකුණු [0, 2, 2] → පරිමාණය [0, 1.414, 1.414] → බර [0.108, 0.446, 0.446] → ප්‍රතිදානය ≈ [3.31, 6.69]; 2 → √256 = 16, [1, 0.5, 0]; 3 → 2048 × 2048 × 64 = 268,435,456 — n = 1024 ට වඩා 4 ගුණයක්.)
