මෙම අවසාන අදියර නවීන AI workloads සඳහා ගොඩනැගූ දෘඪාංගයයි. චිප නිර්මාණය මෙතරම් දැඩිව මෙම දෙසට නැමුණේ ඇයිද යන්න පැහැදිලි වන්නේ "AI workload" එකක් අංක ගණිත මට්ටමේ ඇත්තටම අඩු වන්නේ කුමක්දැයි කී විට ය — වාක්‍යාංශය යෝජනා කරනවාට වඩා පටු සහ යාන්ත්‍රික ය.

## Layer එකක් ගණනය කරන්නේ කුමක්ද

Fully connected layer එකක forward pass යනු matrix multiplication එකකි: activations වාර බර, පසුව ලාභ elementwise nonlinearity එකක්. Convolutions matmul ලෙස ප්‍රතිසංස්කරණය වේ (im2col). Attention — බොහෝ විශාල භාෂා ආකෘති පිටුපස transformers හි හදවත — එලෙසම එහි ගණනය කිරීමේ හදවතේ matrix multiplies ය: query-key scores, පසුව බර තැබූ values. මෙය ඉගැන්වීමේ සරල කිරීමක් නොවේ. නවීන deep learning හි, training සහ inference දෙකෙහිම, අමු cycles වල අතිමහත් බහුතරය matrix multiply-accumulate ය — විශාල පරිමාණය, නිරන්තරයෙන් පුනරාවර්තනය වේ.

## දෘඪාංගය අනුගමනය කළේ ඇයි

Phase 3 CPU core එකක් ගොඩනැගෙන්නේ අත්තනෝමතික අනුක්‍රමික කේතය සඳහා ය — branches, විවිධ මතක ප්‍රවේශය, අනපේක්ෂිත control flow. එම සාමාන්‍යත්වය එක් නිත්‍ය මෙහෙයුමකින් පාලනය වන workload එකකට අවශ්‍ය නොවන යන්ත්‍රණය (prediction, out-of-order, සංකීර්ණ caches) මත ප්‍රදේශය සහ බලය වියදම් කරයි.

Matmul AI compute හි ප්‍රමුඛ කොටස ලෙස හඳුනා ගත් පසු, ඒ සඳහා විශේෂීකරණය වටී විය: සාමාන්‍ය-අරමුණු යන්ත්‍රණය මඟහැර එහි අයවැය MAC throughput මත වියදම් කරන සිලිකන්. Tensor cores (Post 55) එම අදහස තවමත් සාමාන්‍ය GPU එකක් ඇතුළත කාවද්දයි. ඊළඟ පෝස්ට් එක තව දුරටත් යයි — systolic array — එම අවබෝධය වටා මුළු ගෘහ නිර්මාණයම විශේෂීකරණය කරමින්.

## නැවත නැවත එන රටාව

මෙය Post 17 හි superscalar-to-multicore හැරීම සහ Post 49 හි planar-to-FinFET-to-GAA පරිණාමය වැනි *වර්ගයේ* කතාවකි, දැන් මුළු-චිප ගෘහ නිර්මාණයේ: workload එකක හැඩය හොඳින් තේරුම් ගෙන ප්‍රමාණවත් තරම් ප්‍රමුඛ වූ පසු, එම හැඩය සඳහා විශේෂිත දෘඪාංගය එය බොහෝ අවස්ථා අතර එකක් ලෙස සලකන සාමාන්‍ය-අරමුණු දෘඪාංගයට වඩා ජය ගනී. Matmul හි ප්‍රාධාන්‍යය නිසා මෙම අදියරේ බොහෝ දේ අරමුණු-නිර්මිත සිලිකන් වේ — වැඩිදුර CPU, හෝ පවා සාමාන්‍ය GPU, වැඩිදියුණුව පමණක් නොවේ.

## ගැඹුරින්: matrix multiplication මුල සිට, දෘඪාංග ඇසින්

> **සිංහල මූලාශ්‍ර පිළිබඳ සටහන:** Matrix ගුණ කිරීම *ගණිතයක්* ලෙස (පාසල් සහ උසස් පෙළ සංයුක්ත ගණිතය) සිංහල YouTube පාඩම්වල ඇත. නමුත් එය neural network layer එකකට සම්බන්ධ වන ආකාරය, MAC මෙහෙයුම, ගණිතමය තීව්‍රතාව (arithmetic intensity) සහ එය චිප නිර්මාණය හැඩගැස්වූයේ ඇයි යන්න සිංහලෙන් පැහැදිලි කළ මූලාශ්‍රයක් 2026 සැප්තැම්බර් සමීක්ෂණයේදී අපට හමු නොවීය.

### 1. මූලික පද

- **දෛශිකය (vector):** අංක පේළියක් හෝ තීරුවක්, උදා. x = [1, 2, 3].
- **Matrix (න්‍යාසය):** අංක සෘජුකෝණාස්‍රාකාර වගුවක්. "2×3 matrix" යනු **පේළි (rows)** 2ක් සහ **තීරු (columns)** 3ක් ඇති එකකි.
- **තිත් ගුණිතය (dot product):** එකම දිගැති දෛශික දෙකක අනුරූප අංක ගුණ කර එකතු කිරීම. [1, 2] · [5, 7] = 1×5 + 2×7 = 19.
- **MAC (multiply-accumulate, ගුණ කර-එකතු කිරීම):** `acc = acc + a × b` — එක් ගුණ කිරීමක් සහ එක් එකතු කිරීමක්. තිත් ගුණිතයක් යනු MAC දාමයකි. AI දෘඪාංගයේ මූලික "ගඩොල" මෙයයි.
- **FLOP (floating-point operation):** දශම සංඛ්‍යා මෙහෙයුමක් (ගුණ කිරීමක් හෝ එකතු කිරීමක්). එක් MAC = FLOP 2.

### 2. Matrix ගුණ කිරීම පියවරෙන් පියවර

නීතිය: C = A × B හි C[i][j] අංගය = A හි i වන පේළිය · B හි j වන තීරුව.

```
A = | 1  2 |      B = | 5  6 |
    | 3  4 |          | 7  8 |
```

| C අංගය | පේළිය · තීරුව | ගණනය | අගය |
|---|---|---|---|
| C[0][0] | [1,2] · [5,7] | 1×5 + 2×7 | **19** |
| C[0][1] | [1,2] · [6,8] | 1×6 + 2×8 | **22** |
| C[1][0] | [3,4] · [5,7] | 3×5 + 4×7 | **43** |
| C[1][1] | [3,4] · [6,8] | 3×6 + 4×8 | **50** |

```
C = | 19  22 |
    | 43  50 |
```

MAC ගණන් කරන්න: අංග 4ක්, එක් එකකට MAC 2ක් → **MAC 8**. සාමාන්‍යයෙන් n×n matrices දෙකක් ගුණ කිරීමට අංග n² ක් සහ එක් එකකට MAC n ක් → **n³ MACs**. n = 1024 නම් 1024³ = **1,073,741,824** — එක් ගුණ කිරීමකට MAC බිලියනයකට වැඩි ප්‍රමාණයක්. විශාල භාෂා ආකෘතියක් (LLM) එක් token එකක් නිපදවීමට මෙවැනි ගුණ කිරීම් විශාල සංඛ්‍යාවක් කරයි.

### 3. Neural network layer එකක් = matrix ගුණ කිරීමක්

**Neuron (නියුරෝනය)** එකක් යනු ආදාන දෛශිකයක් සහ **බර (weights)** දෛශිකයක තිත් ගුණිතය, **නැඹුරුවක් (bias)** එකතු කර, **සක්‍රීයන ශ්‍රිතයක් (activation function)** හරහා යැවීමකි. Neurons කිහිපයක බර පේළි ලෙස තැබූ විට එය W matrix එක වේ, සහ මුළු **layer (ස්ථරය)** එකම `y = activation(W·x + b)` වේ.

වැඩ කළ උදාහරණය (අංක ඉගැන්වීමට තෝරාගත් ඒවා): ආදාන 3ක්, neurons 2ක්.

```
x = [1, 2, 3]
W = | 0.5  -1   2 |     b = [0, 1]
    | 1     0  -1 |
```

1. Neuron 1: 0.5×1 + (−1)×2 + 2×3 + 0 = 0.5 − 2 + 6 = **4.5**
2. Neuron 2: 1×1 + 0×2 + (−1)×3 + 1 = 1 − 3 + 1 = **−1**
3. **ReLU** (rectified linear unit) සක්‍රීයනය: ඍණ අගයන් 0 කරයි, ධන අගයන් එලෙසම තබයි → y = [**4.5**, **0**].

MAC ගණන: 2 × 3 = 6. ReLU "ලාභ" ය — සංසන්දනයක් පමණි. වැඩේ බර කොටස matrix ගුණ කිරීමයි. එකවර ආදාන (batch) 1000ක් සැකසීමට x දෛශිකය 3×1000 matrix එකක් වේ, සහ layer එක සම්පූර්ණ matrix-matrix ගුණ කිරීමක් වේ. Post 63 හි attention ද Q, K, V ගණනය කිරීමට සහ QKᵀ ගණනය කිරීමට මෙයම භාවිත කරයි.

### 4. සාමාන්‍ය CPU එකකට මෙය "මිල අධික" වන්නේ ඇයි?

සාමාන්‍ය CPU එකක සෑම ගුණ කිරීමක්ම fetch-decode-execute චක්‍රයක් (Post 12) ගෙවයි — උපදෙස් කියවීම, decode කිරීම, රෙජිස්ටර් කියවීම, ප්‍රතිඵලය ලිවීම. ඒ සියල්ල ඇත්තේ ඕනෑම වැඩසටහනක් ධාවනය කළ හැකි වීම සඳහායි. Matmul හි ඊළඟ මෙහෙයුම සැමවිටම දැනටමත් දනී — එයට branch prediction (Post 14) හෝ out-of-order (Post 16) අවශ්‍ය නැත.

### 5. දැන්ම උත්සාහ කරන්න: Mini-CPU එකෙන් ගුණ කිරීම

මෙම Mini-CPU එකේ ගුණ කිරීමේ උපදෙසක් **නැත** — ඇත්තේ `ADD` සහ `SUB` පමණි. 3 × 4 ගණනය කිරීමට 3 හතර වතාවක් එකතු කළ යුතුය. පහත වැඩසටහන පහත lab එකේ Assembly කොටුවට පිටපත් කර (එක් පේළියකට එක් උපදෙසක්) **එකලස් කරන්න** ඔබා, **පියවර** හෝ **ධාවනය** ඔබන්න:

```
LDI 3
STA 15
ADD 15
ADD 15
ADD 15
OUT
HLT
```

1. `LDI 3` — accumulator A = 3.
2. `STA 15` — 3 මතක ලිපිනය 15 හි ගබඩා කරයි.
3. `ADD 15` තුන් වරක් — A = 6, 9, **12**.
4. `OUT` — 12 පෙන්වයි; `HLT` — නවතී.

එක් ගුණ කිරීමක් (එක් MAC එකක අඩක්) සඳහා උපදෙස් 5ක් (LDI සිට ADD තෙවැන්න දක්වා), එක් එකක්ම සම්පූර්ණ fetch-decode-execute චක්‍රයක්. 1024×1024 matmul එකකට MAC බිලියනයකට වැඩි ප්‍රමාණයක් අවශ්‍ය බව මතක් කර බලන්න. (8-bit Mini-CPU එකේ අගයන් 255 ඉක්මවූ විට carry flag එක සැකසේ, එබැවින් විශාල ගුණ කිරීම් එයට කළ නොහැක.) AI දෘඪාංගය කරන්නේ මෙම "උපදෙස් වියදම" ඉවත් කර, සිලිකන් MAC ඒකක දහස් ගණනකින් පුරවා, ඒවා එකවර ධාවනය කිරීමයි.

### 6. ගණිතමය තීව්‍රතාව (arithmetic intensity): matmul දෘඪාංගයට "කැමති" ඇයි

**ගණිතමය තීව්‍රතාව** = FLOPs ÷ මතකයෙන් ගෙන යන bytes. එය අඩු නම් chip එක මතකය එනතුරු රැඳී සිටී (Post 35 හි මතක බිත්තිය); වැඩි නම් ගණනය කිරීමේ ඒකක කාර්යබහුලව තබා ගත හැක.

**n = 1024, FP16 (අංකයකට bytes 2) matmul:**

- FLOPs = 2 × n³ = 2 × 1,073,741,824 = **2,147,483,648**
- දත්ත = matrices 3ක් (A, B, C) × n² × bytes 2 = 3 × 1,048,576 × 2 = **6,291,456 bytes**
- තීව්‍රතාව ≈ 2,147,483,648 ÷ 6,291,456 ≈ **341 FLOP/byte**

**සසඳීමට, n = 1024 දෛශික එකතු කිරීම (c = a + b):**

- FLOPs = n = 1024; දත්ත = 3 × 1024 × 2 = 6144 bytes
- තීව්‍රතාව ≈ **0.167 FLOP/byte**

Matmul හි සෑම අංකයක්ම n වාරයක් නැවත භාවිත වේ (A හි අංගයක් B හි සෑම තීරුවක් සමඟම ගුණ වේ). එම **නැවත භාවිතය (reuse)** නිසා, දත්ත chip එක මත රඳවා තබා ගත හැකි නම්, මතකයෙන් byte එකකට ගණනය කිරීම් සිය ගණනක් කළ හැක. (මෙය අවම දත්ත ප්‍රමාණය උපකල්පනය කරයි — සෑම matrix එකක්ම එක් වරක් පමණක් කියවීම/ලිවීම; සැබෑ chips මෙයට ළඟා වීමට "tiling" භාවිත කරයි.) දෛශික එකතු කිරීමට කිසිදු නැවත භාවිතයක් නැත — එය සැමවිටම මතකයෙන් සීමා වේ. **ඉහළ තීව්‍රතාව + නිත්‍ය රටාව + ප්‍රමුඛත්වය** — මෙම තුනම නිසා matmul එකකට විශේෂිත සිලිකන් සැලසුම් කිරීම වටී විය. ඊළඟ පිටුවේ systolic array එම reuse එක කෙළින්ම සිලිකන් බවට පත් කරයි.
