Batch processing (Post 21) throughput විසඳුවේය — මිල අධික CPU රැකියා අතර කාර්යබහුලව තබන්න. එය අන්තර්ක්‍රියාකාරීත්වය සඳහා කිසිවක් නොකළේය. 1960 ගණන්වල මුල් සිට මැද භාගය දක්වා මතු වූ Time-sharing වෙනස් සීමාවක් විසඳුවේය: බහු පරිශීලකයන්ට *එකවර* අන්තර්ක්‍රියා කිරීමට ඉඩ දෙන්න, එක් එක් කෙනාට යන්ත්‍රය තනිවම ඇති මායාව සමඟ.

## මූලික උපක්‍රමය: වේගවත් මාරුවීම

CPU එකක් මිනිස් ප්‍රතිචාර කාලයට සාපේක්ෂව වේගවත්ය. බහු පරිශීලකයන්ගේ processes තත්පරයකට බොහෝ වාරයක් අතර මාරු වන්න — එක් එක් කෙනාට කුඩා කැබැල්ලක් ලැබේ — සහ කිසිවෙකුට හිඩැස් නොදැනේ. Post 9 හි clocked logic එකේ මෘදුකාංග-scheduling සමානකය: විවික්ත, වේගවත් මාරුවීම *අඛණ්ඩ* ලෙස පෙනේ, එක් තනි core එකක ඕනෑම මොහොතක එක් process එකක් පමණක් ධාවනය වුවත්.

Multics (MULTiplexed Information and Computing Service), 1964 සිට සැලසුම් කර 1965 දී ප්‍රසිද්ධියේ විස්තර කළ ඒකාබද්ධ MIT / Bell Labs / GE ව්‍යාපෘතියක්, අතිශය අභිලාෂකාමී විය — hierarchical file systems, dynamic linking, දශක ගණනකට පසුවත් වෙනත් තැන්වල සම්මත වූ fine-grained access control. එය බොහෝ ගිණුම් අනුව එකල දෘඪාංගයට over-engineered වූ අතර වාණිජව අරගල කළේය.

## Multics සිට Unix දක්වා

Bell Labs 1969 දී Multics වෙතින් ඉවත් විය. එහි වැඩ කළ Ken Thompson සහ Dennis Ritchie බොහෝ කුඩා පරිමාණයකින් නැවත නැවත ක්‍රියා කළහ — හිතාමතාම සරලව, බොහෝ අඩු බලවත් දෘඪාංගය මත (මුලින් spare PDP-7 එකක්). ප්‍රතිඵලය Unix විය: composable අදහස් කුඩා කට්ටලයක් වටා ගොඩනැගූ time-sharing OS එකක් — "සියල්ලක්ම file එකකි," pipes මගින් සම්බන්ධ වූ කුඩා තනි-අරමුණු වැඩසටහන්, සහ C භාෂාවෙන් නැවත ලිවීමෙන් පසු portable නිර්මාණයක් (Post 27 එම භාෂාව ආවරණය කරයි, බොහෝ දුරට එම මිනිසුන්ම විසින්).

Portability වැදගත් විය. Unix බොහෝ සමකාලීනයන් මෙන් එක් නිෂ්පාදකයෙකුගේ පෙට්ටියකට අගුළු දමා නොතිබූ නිසා, සුළු porting උත්සාහයකින් vendors හරහා පැතිරිය හැකි විය — තනි නිෂ්පාදන රේඛාවකට බැඳුණු පද්ධතිවලට වඩා ව්‍යුහාත්මක වාසියක්.

**දැන් මෙය උත්සාහ කරන්න.** පහත VM එක boot කරන්න, යතුරුපුවරු අවධානය සඳහා කළු තිරය ක්ලික් කරන්න, පසුව `uname`, `whoami`, සහ `ls` ධාවනය කරන්න — එකක රූප සටහනක් නොව, ජීවමාන Unix-පෙළපත් shell එකක්.

## බෙදීම: BSD සහ System V

Unix හි licensing ඉතිහාසය දඟලන සුළුය (AT&T හි antitrust-සම්බන්ධ සීමා මගින් දිගු කාලයක් Unix නිදහසේ වාණිජකරණය කිරීමට නොහැකි වූ අතර, එය පරස්පර විරෝධී ලෙස පුළුල් ශාස්ත්‍රීය බෙදාහැරීම දිරිමත් කළේය). එය අවසානයේ ප්‍රධාන පෙළපත් දෙකකට බෙදුණේය: BSD (Berkeley Software Distribution), Phase 6 හි TCP/IP stack බොහෝමය ඇතුළුව සැලකිය යුතු නව කාර්යය සමඟ, සහ AT&T හි වාණිජ System V රේඛාව. දෙකම වසර ගණනක් හරස්-පරාගණය විය. නවීන පද්ධති තවමත් එක් ශාඛාවකට හෝ අනෙකට නිර්මාණ තීරණ අනුගමනය කරයි — macOS හි kernel එකට ගැඹුරු BSD පෙළපතක් ඇත; බොහෝ enterprise Unix වඩාත් සෘජුව System V වෙතින් පැවත ආවේය.

## මෙය ගෙන යන්නේ කොහේද

Unix හි අදහස් — සහ අවසානයේ Unix-ව්‍යුත්පන්න හෝ Unix-ආනුභාවිත කේතය — Linux සහ macOS යන දෙකෙහිම සෘජු පූර්වජයාය, ඒවා දෙක අතර අද servers, workstations, සහ වැඩි වැඩියෙන් mobile සහ embedded උපාංගවලින් අතිමහත් බහුතරය ධාවනය කරයි. "AT&T හි හිමිකාර Unix" සිට "අන්තර්ජාලයේ බොහෝමය ධාවනය කරන නිදහස්, විවෘතව සංවර්ධිත Linux" දක්වා යාමට වෙනම දෘෂ්ටිවාදී සහ නීතිමය ව්‍යාපාරයක් අවශ්‍ය විය — GNU ව්‍යාපෘතිය — ඊළඟ පෝස්ට් එක ආවරණය කරයි. ඒ දෙක අවසානයේ එක් ප්‍රමුඛ තොගයකට ඒකාබද්ධ වුවත්, Unix හි තාක්ෂණික පෙළපතෙන් වෙනස් කතාවකි.

## ගැඹුරින්: Time-sharing සහ Unix අංකවලින් — 1974 ලිපියේ සංඛ්‍යාලේඛන, i-node, pipes

> **සිංහල මූලාශ්‍ර පිළිබඳ සටහන:** A/L ICT විෂය නිර්දේශය මෙහෙයුම් පද්ධති (operating systems) ආවරණය කළත්, Unix ඉතිහාසය, i-node හෝ pipes පිළිබඳ ගැඹුරු සිංහල පැහැදිලි කිරීමක් අපට හමු නොවීය; "unix history sinhala" සෙවුමෙන් YouTube හි ලැබුණේ ඉංග්‍රීසි වීඩියෝ පමණි (2026 සැප්තැම්බර්). පහත සංඛ්‍යා Ritchie සහ Thompson ගේ 1974 ලිපියෙන්මය (පිටු අංක *Communications of the ACM* පිටු). Round-robin උදාහරණයේ අංක ආදර්ශ පමණි.

### 1. මූලික පද

- **කාල බෙදාගැනීම (time-sharing):** එක් CPU එකක් පරිශීලකයන් කිහිප දෙනෙකු අතර වේගයෙන් මාරු කරමින්, එක් එක් කෙනාට යන්ත්‍රය තමන්ටම ඇති මායාව දීම.
- **ක්‍රියාවලිය (process):** ධාවනය වන වැඩසටහනක්. Ritchie සහ Thompson ගේ භාෂාවෙන්, process එකක් යනු **image** එකක ("core image", register අගයන්, විවෘත files, වත්මන් directory) ක්‍රියාත්මක කිරීමයි.
- **කාල පෙත්ත (time slice / quantum):** process එකකට වරකට ලැබෙන CPU කාලය.
- **සන්දර්භ මාරුව (context switch):** එක් process එකක registers සහ තත්ත්වය සුරකිමින් තවත් එකක් පූරණය කිරීම; එයට CPU කාලය වැය වේ.
- **i-node සහ i-number:** file එකක විස්තරය (හිමිකරු, ආරක්ෂණ බිට්, තැටි ලිපින, ප්‍රමාණය…) ඇති වාර්තාව *i-node* ය; එහි දර්ශක අංකය *i-number* ("index number") ය.
- **සබැඳිය (link):** directory එකක ඇති නමක් සහ i-number යුගලයක්. එකම file එකට නම් කිහිපයක් (links) තිබිය හැකිය.
- **පයිප්පය (pipe):** එක් process එකක ප්‍රතිදානය තවත් එකක ආදානයට සම්බන්ධ කරන නාලිකාව; **filter** යනු ආදානය කියවා, සකසා, ප්‍රතිදානයට ලියන වැඩසටහනකි.
- **fork / exec:** `fork` process එකක් සර්වසම කොටස් දෙකකට බෙදයි; `exec` (1974 ලිපියේ `execute`) process එකක ඇති වැඩසටහන වෙනත් එකකින් ප්‍රතිස්ථාපනය කරයි.

### 2. මායාව ක්‍රියා කරන්නේ ඇයි — Bell Labs හි 1974 සංඛ්‍යා

ලිපියේ 9 වන කොටස (පිටුව 375) Bell Labs හි PDP-11/45 Unix පද්ධතිය ගැන මෙම සංඛ්‍යා දෙයි (144K bytes core මතකය, Unix විසින්ම 42K bytes — පිටුව 365):

| මිනුම | අගය |
|---|---|
| පරිශීලක ජනගහනය | 72 |
| උපරිම එකවර පරිශීලකයන් | 14 |
| දිනකට CPU පැය (background හැර) | 4.3 |
| දිනකට සම්බන්ධතා පැය (connect hours) | 70 |
| දිනකට විධාන | 1800 |
| දිනකට logins | 75 |

දැන් ගණනය කරමු:

1. **සාමාන්‍යයෙන් සම්බන්ධ වී සිටින අය:** 70 පැය ÷ 24 පැය ≈ **2.9 දෙනෙක්** ඕනෑම මොහොතක.
2. **CPU කාර්යබහුලත්වය:** 4.3 ÷ 24 ≈ **18%** (ඉතිරි කාලය "background" process එකක් උරා ගනී — ලිපිය කියන පරිදි e − 2 හි ඉලක්කම් මිලියනයක් ගණනය කිරීමට එය භාවිතා විය).
3. **සම්බන්ධ පැයකට CPU කාලය:** 4.3 ÷ 70 × 60 ≈ **මිනිත්තු 3.7** — එනම් පරිශීලකයෙකු සම්බන්ධ වී සිටින කාලයෙන් 6% ක් පමණ පමණක් CPU භාවිතා කරයි. ඉතිරි 94% ඔහු සිතමින්, ටයිප් කරමින්, කියවමින් සිටී.
4. **විධානයකට CPU:** 4.3 × 3600 ÷ 1800 ≈ **තත්පර 8.6** (සාමාන්‍යයක් — C compiler වැනි බර විධාන සහ `ls` වැනි සැහැල්ලු ඒවා මිශ්‍රයි).

**පාඩම:** time-sharing ක්‍රියා කරන්නේ මිනිසුන් CPU එකට සාපේක්ෂව *අතිශය මන්දගාමී* නිසාය. එක් පරිශීලකයෙකු 6% ක් පමණක් භාවිතා කරන්නේ නම්, CPU එකට න්‍යායිකව දහසය දෙනෙකුට පමණ (100 ÷ 6) සේවය කළ හැකිය — ලිපියේ "උපරිම එකවර 14" ට කිට්ටුයි (මෙම සංසන්දනය අපේ).

### 3. Round-robin කාල පෙති (ආදර්ශ අංක)

(පහත අංක **ආදර්ශ පමණි** — 1974 Unix හි සැබෑ කාල පෙති ප්‍රමාණය ලිපියේ නැත.) පරිශීලකයන් 14 දෙනාම එකවර CPU ඉල්ලන *නරකම* අවස්ථාව සිතන්න; කාල පෙත්ත 20 ms, සන්දර්භ මාරුවක් 1 ms:

- ඔබේ ඊළඟ වාරය දක්වා උපරිම රැඳීම: 13 × (20 + 1) = **273 ms** — මිනිසෙකුට තවමත් "ක්ෂණික" ආසන්නයි.
- මාරු කිරීමේ අපතේ යාම: 1 ÷ (20 + 1) ≈ **4.8%**.
- කාල පෙත්ත 10 ms දක්වා අඩු කළොත්: රැඳීම 13 × 11 = 143 ms (වඩා හොඳයි), නමුත් අපතේ යාම 1 ÷ 11 ≈ **9.1%** (වඩා නරකයි).

මෙයයි scheduler නිර්මාණයේ මූලික වෙළඳාම: කෙටි පෙති = වඩා හොඳ ප්‍රතිචාරය, දිගු පෙති = වඩා අඩු අපතේ යාම.

### 4. "සියල්ලම file එකකි": directory, i-node, links

Unix හි directory entry එකක ඇත්තේ **නමක් සහ i-number එකක් පමණි** (පිටුව 368). i-number එක i-list නම් වගුවකට දර්ශකයකි; එහි ඇති i-node එකේ ලිපිය ලැයිස්තුගත කරන කොටස් නවය (පිටු 368–369):

| # | i-node හි ඇති දේ |
|---|---|
| 1 | හිමිකරු (owner) |
| 2 | ආරක්ෂණ බිට් (protection bits) |
| 3 | අන්තර්ගතයේ භෞතික තැටි/පටි ලිපින |
| 4 | ප්‍රමාණය |
| 5 | අවසන් වෙනස් කිරීමේ වේලාව |
| 6 | **links ගණන** — file එක directories වල කී වතාවක් පෙනේද |
| 7 | directory එකක්ද යන්න දැක්වෙන බිට් එක |
| 8 | විශේෂ file එකක්ද (උපාංගයක්) යන්න දැක්වෙන බිට් එක |
| 9 | "විශාල" ද "කුඩා" ද යන්න දැක්වෙන බිට් එක |

**නම i-node හි නැති බව සලකන්න.** එබැවින් එකම i-node එකට නම් දෙකක් තිබිය හැකිය. link එකක් සෑදීම = නව directory entry එකකට i-number පිටපත් කර links ගණන 1 කින් වැඩි කිරීම; නමක් ඉවත් කිරීම = links ගණන 1 කින් අඩු කිරීම, සහ එය 0 වූ විට පමණක් තැටි blocks නිදහස් කිරීම (පිටුව 369).

**විශේෂ files:** සෑම I/O උපාංගයක්ම `/dev` යටතේ file එකකි; ලිපියේ උදාහරණය — paper tape punch කිරීමට `/dev/ppt` වෙත ලියන්න (පිටුව 367). එකම `read`/`write` කැඳවීම් තැටි files, උපාංග සහ pipes යන සියල්ලටම ක්‍රියා කරයි.

### 5. ආරක්ෂණ බිට්: 1974 දී හතක්, අද වැඩි ගණනක්

1974 Unix හි සෑම නව file එකකටම **ආරක්ෂණ බිට් හතක්** ලැබිණි (පිටුව 367): හිමිකරුට සහ "අනෙක් සියලු දෙනාට" වෙන වෙනම read, write, execute (2 × 3 = 6), සහ හත්වැන්න **set-user-ID** — වැඩසටහනක් ධාවනය වන අතරතුර පරිශීලක හැඳුනුම එහි නිර්මාතෘගේ හැඳුනුමට තාවකාලිකව මාරු කරයි (උදා. අනෙක් අයට කියවිය නොහැකි ගිණුම් file එකක් යාවත්කාලීන කරන වැඩසටහනක්).

අද Linux හි (ඉහත lab එකේ `ls -l` පෙන්වන පරිදි) හිමිකරු, **කණ්ඩායම (group)**, අනෙක් අය සඳහා බිට් 3 බැගින් = 9 ක් පෙනේ. අෂ්ටක (octal) ඉලක්කමකින් බිට් 3ක්: r = 4, w = 2, x = 1.

| octal | බිට් | `ls -l` හි පෙනීම |
|---|---|---|
| 644 | 110 100 100 | `rw-r--r--` |
| 640 | 110 100 000 | `rw-r-----` |
| 755 | 111 101 101 | `rwxr-xr-x` |

### 6. Pipes, filters, fork සහ exec

ලිපියේ උදාහරණය (පිටුව 371): directory ලැයිස්තුව තීරු 2 කට පිටු ගසා (`pr -2`) මුද්‍රණයට යැවීම (`opr`):

```
ls | pr -2 | opr
```

pipes නැතිව එයම තාවකාලික files දෙකකින් කළ යුතුය:

```
ls >temp
pr -2 <temp >temp2
opr <temp2
```

ලිපිය එම විකල්පය "clumsier" (වඩා අපහසු) ලෙසද, `ls` තුළම පිටු ගැසීම වැනි විකල්ප ගොඩනැගීම "unwise" ලෙසද හඳුන්වයි. `pr` වැනි stdin → stdout වැඩසටහනක් **filter** එකකි.

shell එකක් විධානයක් ධාවනය කරන්නේ (§6.5, පිටුව 372; ප්‍රාථමික කැඳවීම් §5, පිටුව 370): `fork` කැඳවා process එක දෙකට බෙදා, *child* process එක `execute` මගින් අදාළ වැඩසටහන පූරණය කර, *parent* (shell) child එක අවසන් වන තුරු `wait` කරයි. pipe එක `fork` හරහා parent සිට child දක්වා උරුම වන විවෘත file එකක් පමණි.

**කාර්යක්ෂමතාව — ලිපියේම මිනුමක් (පිටුව 370):** පේළි 7621 ක වැඩසටහනක් assemble කිරීමට තත්පර 35.9 ක් ගත විය:

- වේගය: 7621 ÷ 35.9 ≈ **පේළි 212 / තත්පරය**
- assembler ක්‍රියාත්මක වීම 63.5% ≈ **22.8 s**; පද්ධති overhead 16.5% ≈ **5.9 s**; තැටිය සඳහා රැඳීම 20.0% ≈ **7.2 s**

### 7. දැන්ම උත්සාහ කරන්න: ඉහත VM එකේ i-node සහ pipes

ඉහත vm-terminal lab එකේ VM එක boot කර, තිරය ක්ලික් කර, පහත විධාන එකින් එක ටයිප් කරන්න:

```
cd /tmp
echo hello > a.txt
ln a.txt b.txt
ls -li a.txt b.txt
```

`-i` මගින් පළමු තීරුවේ i-number පෙන්වයි: **a.txt සහ b.txt දෙකටම එකම අංකය**, සහ links ගණන (අවසර තීරුවට පසු අංකය) **2**. දැන්:

```
rm a.txt
ls -li b.txt
cat b.txt
```

links ගණන **1** දක්වා අඩු වී ඇති නමුත් `hello` තවමත් පවතී — ඉවත් කළේ *නමක්* පමණි, file එක නොවේ. ඉතිරි උත්සාහයන්:

- `chmod 640 b.txt` ඉන්පසු `ls -l b.txt` → `-rw-r-----`
- `echo hello | wc -c` → **6** (අකුරු 5 + පේළි අවසන් අක්ෂරය)
- `ls -l /bin/ls` → `/bin/ls -> busybox`: මෙම කුඩා Linux එකේ `ls`, `ln`, `wc`, `ps` යනාදිය BusyBox නම් *එකම* වැඩසටහනකට යොමු වන සංකේතාත්මක සබැඳි (symbolic links) වේ.

### 8. පැන්සලෙන් අභ්‍යාසය

1. ලිපියේ සංඛ්‍යා භාවිතයෙන්: දිනකට logins 75 ක් සහ සම්බන්ධතා පැය 70 ක් නම්, login එකක සාමාන්‍ය කාලය මිනිත්තු කීයද? පරිශීලකයෙකුට දිනකට විධාන කීයක්ද (දිනකට වෙනස් පරිශීලකයන් 30)?
2. කාල පෙත්ත 50 ms සහ සන්දර්භ මාරුව 1 ms නම්, එකවර පරිශීලකයන් 10 දෙනෙකු සඳහා නරකම රැඳීම සහ අපතේ යාමේ ප්‍රතිශතය කීයද?
3. `rwxr-x---` octal වලින් කීයද?
4. file එකකට links 3 ක් ඇත. `rm` දෙවරක් කළ පසු එහි දත්ත තවමත් තැටියේ තිබේද?
5. 1974 ආරක්ෂණ බිට් 7 ට හැකි සංයෝජන කීයක්ද? අද 9 බිට් සඳහා?

(පිළිතුරු: 1 → 70 × 60 ÷ 75 = **මිනිත්තු 56**; 1800 ÷ 30 = **විධාන 60**. 2 → 9 × 51 = **459 ms**; 1 ÷ 51 ≈ **2.0%**. 3 → 111 101 000 = **750**. 4 → **ඔව්** — links ගණන 1 යි; තවත් `rm` එකකින් 0 වූ විට පමණක් blocks නිදහස් වේ. 5 → 2⁷ = **128**; 2⁹ = **512**.)

Brewer ගේ ඉලෙක්ට්‍රොනික ප්‍රතිනිර්මාණය: <https://dsf.berkeley.edu/cs262/unix.pdf>) — පිටුව 365 (PDP-11/45, 144K / 42K bytes), පිටුව 367 (§3.3 විශේෂ files `/dev/ppt`; §3.5 ආරක්ෂණ බිට් හත සහ set-user-ID), පිටු 368–369 (§4 i-number, i-node කොටස් නවය, links), පිටුව 370 (§4.1 පේළි 7621 / තත්පර 35.9; §5 images, processes, `fork`, pipes), පිටුව 371 (§6.2 `ls | pr -2 | opr`, filters), පිටුව 372 (§6.5 shell එකේ fork–execute–wait), පිටුව 375 (§9 සංඛ්‍යාලේඛන).
